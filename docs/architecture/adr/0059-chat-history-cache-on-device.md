# ADR-0059 手机本机存聊天记录：往上翻本机有的直接用，没有才向电脑要；接不上、回退、彻底删除就作废

状态：已定（"往上翻时本机有缓存就用、没有才向电脑要、要来的存下"是用户 2026-11-09 提的；存什么、怎么认信不信得过、怎么作废、上限是 457 号票实现时定的，上限的默认值等用户定）。和 [ADR-0048](0048-open-snapshot-on-device-batch-catch-up.md)、[ADR-0058](0058-open-events-on-device-refold-after-update.md) 并列：那两条管打开时界面的样子和会话以外的频道，这条管会话历史。

## 背景

- 会话频道冷打开只补最近一页（`conversation/history.ts` 的 `firstReplayAfter`），更早的往上翻时经 HTTP 一页页取（`historyPage`）。取来的只在内存里，本机快照也只留最近一页，452 存在本机的事件不含会话频道。关了页面再往上翻还要向电脑要：手机多半经隧道，慢；没网就看不了。
- 会话历史不是只增不改的：会话回退、切换分支会换当前分支（`session_branch` 带整棵树）；彻底删除会改写原来的事件（`messages_purged` 通知前端）；删任务、删项目整个负责人会话改写成"已删除"；移除插件连数据删会改写它拥有的事件（语音插件的语音对象就在会话频道上）；数据目录恢复过订阅回 `resync`。本机存的一旦漏看了其中一样，就会显示错的历史（删掉的话又冒出来、旧分支上的话出现在当前分支）。用户的要求是宁可多向电脑要一次，也不能显示错的。

## 决定

1. **存协议的样子，不存状态层折出来的**（`state/chat-cache.ts`）：历史分页里的一条消息（`HistoryMessage`）、时间线记录、阶段开始的记号按会话里的序号存，语音对象、agent 语音对象按 id 存（版本新的才盖）。本机拼出来的是一页 `HistoryPage`，和向电脑要来的一样交给状态层。网页换了一版照样能用，协议版本、存的格式变了才整份删。
2. **来源两处，按"段"记哪里是全的**：WebSocket 上会话频道的事件（补发的最近一页、实时收到的）照收到的存；往上翻向电脑要来的一页存下。每个会话记几段 `CachedSpan`（序号 lo..hi 里当前分支上的消息、记录、阶段记号一条不缺）：向电脑要来的一页给"这一页第一条消息（更早没有了的从 1）到 before - 1"——守护进程 `historyPage` 就是按这个范围取的；WebSocket 上一条不漏收到的那一段整段都在（所有分支的都在，什么树都对）。
3. **往上翻先问本机**（`store.tsx` 的 `loadOlder` → `app/chat-cache.ts` 的 `page`）：盖住 before - 1 的那一段里照 `historyPage` 拼一页（before 之前当前分支上最近 limit 条；记录、阶段记号同一个范围；消息引用的语音对象一起带上）。这一段里不够一页、又不是从头起的，交回有的几条、说"更早还有"，下次往上翻向电脑要的（before 是本机最早那条）正好是缺的那一截。消息引用的语音对象本机缺了、又没记着它本来就没有（向电脑要来的那一页里守护进程没带回的记成"本来没有"）就不拼。拼不出、信不过、读不了才向电脑要，要来的存下（要的路上作废过的不存）。
4. **信不信得过**：每个会话记一个 `through`——这个序号之前会话频道上的事件（彻底删除、会话树、语音对象新版本）本机都照着改过了。这次打开一条不漏收到的那一段得接得上：热打开带游标 c 订阅（守护进程补 c 之后的全部），c ≤ through 才用；冷打开（游标 0，网页换了一版也是）守护进程从最近一页的开头 S 起补（前面先补的会话树、语音对象按"序号断开"认出来，不算），S ≤ through + 1 才用。接不上的——中间那截没看到，可能有彻底删除——这个会话整个删掉，从这次收到的起重新存。之后这次打开里一条不漏，through 跟着往后。
5. **作废**：
   - 会话树换了（`session_branch`）：两棵树的当前路径从某个序号 d 起才不一样（`pathDivergence`），d 之前每个序号在不在当前分支上两棵树说的一样，各段截到 d 之前；这次一条不漏收到的那一段照旧算。回退只是把当前分支变窄，切回一条废弃分支会把本机没存的那一段（向电脑要来的几页只有当时当前分支上的）变到当前分支上，所以一律截。
   - 有消息被彻底删除（`messages_purged`，序号在 through 之后的才算新的）、移除插件时连数据删了（`plugin_data_purged`，记着插件频道上处理到哪一条）、订阅回 `resync`（任何一个频道：数据目录恢复过）：整份作废。彻底删除除了消息还会改写操作记录、范围记录的时间线记录、语音对象，不照着一样样改，整份重来。
   - 删任务（任务自己的负责人）、删项目：负责人的会话整个删掉，这次打开也不再存它。
   - 协议版本、存的格式变了：打开时整份删掉。回到配对页（还没配对、被吊销、过期）：整份删掉，之后这个页面不再存（和本机快照一样）。
6. **怎么写**（`app/chat-cache-idb.ts`）：单独一个 IndexedDB 库 `ergo-chat`（不和 `ergo-page` 混：两边各升各的版本，456 号票同时在改那份），表 `meta`（每个会话一份说明，键是会话频道；整份一份，键 `#`）、`entries`（一条一个键 `[会话, 种类, 序号或 id]`，删一个会话是删一段键）。攒着等闲下来（最后一次变化之后 1 秒，最多攒 5 秒）写，切到后台、关页面、要作废时马上写；一次写一个事务，条目和说明一起，后端写的时候按实际增减算字节数、条数。拼一页只按写成了的那一份（写成之后又作废了、还没写进去的不用），读也是一个事务。
7. **几个标签页**（鸿蒙 App 的浏览侧边栏也是一个）：每个会话的说明带一个版本号 `rev`，写的时候本机存着的不是这个页面上次写的那一版（别的标签页改过、删过）就不写，这次打开不再存也不用这个会话；读的时候同样核对。
8. **上限**：默认 50 MB（`CHAT_CACHE_MAX_BYTES`，按存进去的 JSON 的 UTF-8 字节算）。写完超了按"最久没用过"（往上翻、收到新消息、存下一页都算用过）整个会话删，删到上限的八成；正在用的那个自己就超了也删，从现在起重新存。存了几个会话、多少条消息、多大在 Debug 工具集"连接"里。
9. **原型、开发服务器不存**（和本机快照同一个条件）。读写都包着：没有 IndexedDB、打不开、读坏了、写不进去就当没有，这个页面不再存，往上翻照旧向电脑要。

## 后果

- 往上翻过的会话，关掉再开（热打开、网页换了一版、关掉期间来的不到一页）往上翻不用等电脑，没网也能看。页面测试里关掉重开往上翻到头一次都不向电脑要。
- 关掉期间来了一页多再冷打开（网页换了一版那种）、热打开时本机存的落在快照后面（上次关得急没写进去），都信不过、整个会话重来——不知道中间那截里有没有彻底删除。要少作废得让守护进程告诉页面"这段里有没有改写过"（比如往上翻的接口带一个这个会话最后一次改写的序号），这里没做。
- 彻底删除、移除插件连数据删、数据目录恢复一次，整份作废，之后往上翻又要向电脑要一遍。这几样很少，按"宁可多要一次"取舍。
- 手机上多存了一份个人数据（往上翻看过的聊天记录，最多 50 MB），只在这台设备的浏览器存储里，吊销、回到配对页时删。没打开过的被偷的手机上会一直留着，直到被打开（和本机快照一样）。
- 删任务、删项目那一下页面要是没看到（那次打开死了、下次打开是新设备那样的冷补发且被合并掉了），那个已经删掉的会话会在本机留着，界面上进不去、按最久没用过淘汰。
- 换了数据目录、序号又比本机的大（认不出来的 `resync`）时和本机快照一样认不出，见 ADR-0048 的后果。
- 等价性由测试锁住：`packages/web/test/app/chat-cache.test.ts`（照 `historyPage` 的假守护进程）、`packages/daemon/test/conversation/chat-cache-equivalence.test.ts`（真的事件库、`historyPage`、`firstReplayAfter` + `replayPins`）里几轮打开关掉、回退、切换分支、正在回复的一轮、重新识别、彻底删除交替着来，每轮"本机存的 + 向电脑要的"和一台新设备全部向电脑要的看到的一样；`packages/web/test/chat-cache-page.test.ts`（真 Chrome）。

## Considered Options

- **按 before 存向电脑要来的整页**：最简单，可下次打开最近一页的起点变了，before 对不上，几乎用不上；实时收到的也接不进去。
- **存进本机快照那一份**（会话不只留最近一页）：快照按网页版本作废，一天部署好几次就几乎留不住；而且快照是整份重写的，会话一长写一次就很大。456 号票同时在改那份。
- **不认"接不接得上"，只靠事件作废**：冷打开时补发从最近一页起，中间那截里的彻底删除页面根本收不到，删掉的话会从本机冒出来。
- **彻底删除照着一条条改本机存的**（照状态层那样换成"已删除"）：彻底删除还会改写操作记录、范围记录连带的时间线记录、语音对象，前端拿不到全部改写了什么，照着改会漏。整份作废简单、不会错。
- **一个会话自己超了上限就删它最早的那些**：要按序号扫条目算字节，还要改"段"；超 50 MB 的会话很少，整个删掉从现在起重新存更简单。
- **换版本后会话频道的最近一页也先用本机的、只向电脑要新的**（票里"顺带"那一条）：状态层里会话的样子不只是消息、记录（排队、正在回复的一轮、回合开始和结束、分段……），本机存的拼不出和守护进程冷补发一样的那一页，拿不准等价，这次不做，照旧从头要最近一页。
