# ADR-0063 一台电脑可以配置多份二狗：一份 = 一个数据文件夹，各份互相隔开

状态：已定（468）。

## 背景

二狗原来一台电脑只有一份：数据目录 `~/.ergo`（`ERGO_DATA_DIR` 能换位置），服务管家里登记成固定的 `ergo-daemon`，端口 8810 / 8811。要能在同一台电脑上配置多份，各份的数据、端口、设备和凭证互相隔开，都由同一个服务管家托管、都能开机自启；隔开做到"守卫规则 + 各自凭证"，不另开 Windows 账号。

## 决定

1. **一份 = 一个数据文件夹。** 文件夹本身就是这一份的数据目录（各区照 `dataDirLayout()`，和默认那份一样）。默认那份照旧在 `~/.ergo`（或 `ERGO_DATA_DIR`），什么都不用改。别的各份由 `ergo init` 在一个**空**文件夹里建：文件夹根部放实例标记文件 `ergo-instance.json`（`format`、名字、登记 id），配置 `config/ergo.json` 写这一份的端口，数据目录的骨架和守护进程第一次起来时建的是同一套（`config.ts` 的 `prepareDataDir`）。要空文件夹：二狗的数据会放满它，和用户自己的文件分开。不能建在别的一份的文件夹里、服务管家和程序的目录里。
2. **认哪一份**（每条 ergo 命令都按这个顺序，`cli/instances.ts` 的 `resolveInstance`）：`--dir <文件夹>`（命令前后都认）> `ERGO_DATA_DIR` > 当前目录或它的上级里有标记文件的那一份 > `~/.ergo`。认出来的文件夹有标记文件就是那一份（登记 id 照标记），没有就是默认那份——所以用 `ERGO_DATA_DIR` 换过位置的老用户照旧是 `ergo-daemon`。标记文件在却读不了、内容不对，命令不做（免得认错一份去停、改别的），`help`、`version`、`init`、`list` 照常。`ergo init` 只看 `--dir` 和当前文件夹。
3. **登记 id**：默认那份 `ergo-daemon`；别的是 `ergo-<名字>`。名字只许小写字母、数字、连字符，不以连字符开头结尾、不连写两个（服务管家用 `--` 分名下的服务：`ergo-a--b` 会被当成 `ergo-a` 名下的），最长 32 个字符，`daemon` 留给默认那份。默认取文件夹名（大写换小写），不合规时有终端问一句、没终端要 `--name`。和服务管家里已有的登记重名（文件名、登记里的 id，不分大小写）拒绝。登记的 env 多写一项 `ERGO_SERVICE_ID`（默认那份不写，登记一字不差），守护进程按它认自己（`ownServiceId`：`ERGO_SERVICE_ID` > 服务管家注入的 `LSM_SERVICE_ID` > `ergo-daemon`），体检、守卫、服务管家工具、设置 · 服务一页都按它。
4. **端口**：`ergo init` 自动挑一组（本机、外网各一个，8820/8821、8830/8831……步长 10），跳过服务管家登记里已占的、各份配置里的（含默认那份）、管理器的、此刻有人在用的（本机连得上或绑不上）；`--port` 指定本机端口时外网用 +1，被占了拒绝。
5. **服务管家里的登记**：`ergo init` 照 `ergo start` 的写法写登记（不启动），第一次登记时经 `lsm autostart <id> on` 加进开机自启名单——只加它自己，名单里别的不动。默认那份照旧"第一次 start 写一份只含它的名单，之后再也不碰"；默认那份以外的不写这份默认名单（里面的 `ergo-daemon` 没登记时服务管家会报"名单里的不存在"）。先建了别的一份、后来才第一次起默认那份时，名单照旧不碰，只说一句怎么加。场景 `ergo`：登记里自带 `profiles: [ergo]`，服务管家算场景成员时和 `manager.yaml` 里列的合在一起，所以不改 `manager.yaml`，拿掉登记也就出了场景。
6. **`ergo list`** 以服务管家的登记为准（注册表顶层里 id 是 `ergo-daemon`、或 env 里 `ERGO_SERVICE_ID` 写的就是自己 id 的登记），加上默认那份（登记了、或者 `~/.ergo` 在）和这条命令认的那一份（有标记却没登记）。**`ergo unregister`** 停掉、移出开机自启、拿掉登记，文件夹和数据原样留着；再 `ergo start` 就重新登记、加回开机自启。默认那份不许，要用 `ergo uninstall`。
7. **换版本、卸载管到各份**：一份程序给各份用。`ergo update / rollback` 换完版本，服务管家里登记的每一份的登记都按新版本重写（不管在不在跑），在跑的都等空闲再停、切完都重起；等不到就都不切，已经停了的照原样起来。`ergo uninstall` 逐份列出、都停掉、登记都拿掉，各份的文件夹逐份问删不删（默认留；`--yes`、`--delete-data` 不替它们答；只删标记还对得上的）。
8. **守卫：各份互相隔开**（`GuardPlaces.otherInstances`，守护进程从服务管家的注册表现读、留 3 秒，`lsm/other-instances.ts`）：
   - 其他各份的数据文件夹、服务管家日志目录里属于它们的日志（`<id>.*`、它们名下服务的 `<id>--*`）：读写一律硬拒绝（`other_instance`，和密钥区同一级别），授权的文件夹、目录授权都不放开；上级目录被搜、找、复制、删、挪、看不出读写的程序碰到（`grep -r`、`rg`、`find`、`cp -r`、`rm -rf`、`tar`……）也拒，只列一层的（`ls`、`cd`）照旧；没法确定的路径、拆不开的命令里写着它们的文件夹名或日志文件名的也拒。
   - 其他各份的端口（本机、外网）：http 请求、网络命令、浏览器工具、任何工具参数里写着的本机地址、拆不开的命令里写着的端口、跑的脚本里写着端口又用到联网的库，一律硬拒绝。
   - 停、杀其他各份（2026-11-25 定：一律拒绝，不是先问）：它们的守护进程进了受保护的进程（`role: "instance"`：服务管家记的它们登记的 pid、它们数据目录里 `daemon.pid` 记的，启动时间对不上的不算），按进程号、按名字、连同子进程杀上级、杀所有进程会杀到它们的硬拒绝；杀进程、按端口杀（`kill-port`、`fuser -k`）、服务管家的命令（`lsm stop / restart`、`ergo --dir <另一份> stop`、`ergo svc`）、发往管理器的改动请求、拆不开的命令里写着杀进程的，写着它们的端口、登记 id、文件夹、守护进程的进程号的，也硬拒绝（bash 拆出来的还看整条命令：`netstat … | grep <端口> | … | xargs kill`）。认不出是谁的杀进程照 419 的规矩。
   - **批准改变不了这些**：审批卡是这一份的用户点的，点的人可能就是从外面进了这一份的人，不能替另一份做主。所以原来"先问"兜着的写法，碰到另一份的一律改成拒绝。
   - 服务管家：agent 直接发往管理器端口的请求查询也拒（419 时 GET 放行，没有正当用途——秘书看状态、日志有服务管家工具，别的 agent 没有要看服务管家的事；管理器的 `/api/state`、`/api/logs` 回的是所有服务的详情、登记和日志），用浏览器打开它的页面也拒。配置了多份时，拆不开的命令里写着管理器端口的也拒。
   - ergo 命令：`init`、`unregister` 和 419 的停止、重启、升级……一样一律拒。作用在某一份上的（`status`、`logs`、`start`、`list`……）只有一份时照旧；配置了多份时拒：agent 的环境里没有 `ERGO_DATA_DIR`，不在这一份的文件夹里跑就会管到默认那份，认不准。
   - 秘书的服务管家工具（`lsm_*`）：其他各份的登记和它们名下的服务不列出来，点名、按场景会碰到它们的一律拒绝，日志也不给看。运营接口自动转的 MCP（`ERGO_OPS_MCP_*`）本来就只连这一份自己的端口、只管自己的项目，不用改。
9. **整机共用、不分的**：服务管家本身（端口、数据目录、计划任务 `LocalServiceManager`）、语音合成服务（audio.cpp，默认都连本机 8090）、ego 浏览器、程序目录和 PATH、这个 Windows 账号的用户级环境变量和 Claude Code / Codex 的登录。别的按份分开：端口、数据目录里的一切（备份的锁和本机备份区、配对的设备、凭证）；Codex 接入的命名管道每次随机取名。

## 后果

- 老用户、只用一份的什么都不用改；默认那份的登记、开机自启名单、端口和以前一字不差。
- 只用一份的 agent 也少了一样：直接访问服务管家端口的查询、打开它的页面改成拒绝（叫它用服务管家工具）。
- 守卫挡不住的写法和密钥区一样有：拼出来的端口、路径（变量从文件读、算出来的）、脚本里间接读的；记在 468 的 Comments。
- 备份的"另存到"文件夹是各份自己配的，几份配成同一个会互相盖掉（按日期放），手册里写明各选各的。公网入口（`ergo-tunnel`、VPS 的 18811）是按默认那份写的，另一份要从外面连得另配。
