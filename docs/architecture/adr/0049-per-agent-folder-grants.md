# ADR-0049 每个 agent 一份目录授权：读、写、删分开，可过期，可查

状态：已定

## 背景

- 用户要给某个 agent 多一个目录，以前只有两条路：对话里每次弹审批卡（"越出项目目录"先问），任务里写进计划的授权项。既烦，又看不出"某个 agent 到底能碰哪些目录"。
- 已有的"授权的文件夹"（[ADR-0041](0041-authorized-folders-read-only-in-guard.md)）是一份全局清单：所有 agent 都能读，只放开读。
- 已有的授权项（`guard/grants.ts`）是计划里的：属于某个任务的某个阶段，有次数和有效期，执行中只能收窄。
- 守卫的判定是纯函数（不读文件、不看时钟），名单、真实路径、现在几点都要调用方交进来。

## 决定

1. **谁有表**：秘书一份（agent id `secretary`）；每个项目一份（项目负责人的 id，项目的负责人在各段都用：工单段、对话段、定时运行）；每个任务一份（任务负责人的 id）。子 agent、评审子 agent 不继承（隔离换自由）；记忆管理员没有。运行时按发起调用的 agent id 取，子 agent 一律不给。
2. **每条授权**：目录（登记时的真实路径，`fs.realpathSync.native`；要在、要是目录，不能在数据目录、二狗程序目录里）、操作（读、写、删可组合；删单独勾，勾了删不带写）、到期时间（不写是长期有效，界面上醒目地标"长期有效"）、为什么给、谁什么时候加的（设置里加的、审批卡上点"以后都允许"的）。同一个 agent 同一个目录只有一条。存在配置区的 `folder-grants.json`，只由运行时写；agent 没有改它的工具，配置区本来就是受保护区域。
3. **判定**（`guard/judge.ts`，`GuardInput.folderGrants`，调用方每次判定现读这个 agent 的那一份，像授权的文件夹一样作为环境事实交进来；过期按 `input.now` 算）。只在路径**越出了这个 agent 自己的范围**（草稿区、项目档案和工作目录）、又不是读授权的文件夹时才看它：
   - 目标的**真实路径**落在一条有效的登记目录里、做的是登记了的那种操作，才放开——不落入"越出项目目录"，文件工具写也不再硬拒绝（围栏）。删除另要写的路径本身也在登记目录里：删的是目录项，从别处指进来的链接删掉的是别处那个链接；
   - 只认文件工具（读、写、编辑、列、搜）和 bash 拆出来的读、写（重定向）、列、搜、复制、移动、建目录、删除。看不出读写的程序、跑脚本、git、带类型的 bash 工具、MCP、代为执行的工具不算；bash 拆出来的不只是读的（`cd`、别的程序的路径参数、`awk -f`）、写着 `..` 的、拿到了守卫看不见的输入的（管道喂来的、`xargs` 补的参数）不算；展不开的通配符不算；取不到真实路径的不算；
   - 数据目录、受保护区域（含程序目录）、备用数据流，写和删 git 的配置和钩子，就算在登记目录里也不算；
   - **唯一新增的拦截**：有效的登记目录里名字像密钥的文件（`.env` 和变体、`*.key`、`*.pem`、`secrets*`、`id_rsa*`、`credentials*`、`.ssh` 下的；`secret-files.ts` 的 `isSecretLikeFile` 在 `isSecretFile` 之上补齐，只看登记目录下面那一段的名字）读、写、删都硬拒绝（`secret_file`），理由写"密钥类文件"。没登记、过期了的目录里照旧，不是新的拦截；
   - 没放开时说明里补一句为什么：没登记（在设置 · 目录授权里登记）、登记了只读没登记写、已过期、这种调用不按目录授权算。没有表的 agent 说明和以前一字不差。
4. **先后**：受保护区域（写入永不）、密钥区（连读都拒）、子 agent 写项目档案、git 控制文件这些先判，目录授权改变不了；然后才是"越出项目目录"——授权的文件夹（只读、所有 agent）先看，再看这个 agent 的目录授权；都没放开的照旧落入"越出项目目录"，接着对话里按"先问我"（对话审批的开关照旧管它），任务里按"计划里列了才做"去找计划的授权项（`grants.ts`，一点没变）。v1 模板（项目外的 `rm -rf` 一律禁止、删除或覆盖项目里的东西之前须已备份）、"删除或覆盖"类别、联网开关、两条底线照旧，目录授权不碰它们。
5. **和计划授权项的关系**：目录授权是"这个 agent 长期能碰哪些目录"，跟着 agent 走、用户直接给、可过期；计划授权项是"这个任务这个阶段要做的这几件事"，跟着计划走、确认计划时一次给、有次数。目录授权放开了的，就不落入"越出项目目录"，任务里也就不需要为它写授权项；没放开的（没登记的操作、不算的调用）照旧要授权项。流程的逐步比对（`plan-monitor.ts`）不看目录授权：步骤外会改东西的照旧问。
6. **审批卡上的"以后都允许"**：对话里（不属于任务）、这个 agent 有表、要问的只有"越出项目目录"（判断不了的不算）时，判定顺带给出"登记了就会放开的"路径（真实路径、是不是目录、要的操作）。运行时取它们所在的目录（几处的取最上面那个，别的都要在它里面）、按这次要的操作在表里加上它再判一遍，会执行才在卡上给"以后都允许（登记这个目录）"。点了先登记（长期有效；已有的操作取并集），登记不成就不批准、回原因；登记成了和"批准这一次"一样放行。
7. **过期**：到期自动失效（判定按 now 算，不用谁去删）；界面标"已过期"。到期前 3 天在待办里提示一次（`folder_grant_expiring`，起来时、每天 09:00、加了一条之后各看一次，提示过的记在授权上）。
8. **使用记录**：因为目录授权放行、执行了的调用，碰到的每个路径记一条（guard 频道的 `folder_grant_used`）：agent、授权、登记的目录、路径、操作、工具、时间；文件工具的写记写进去的字节数、读记交回的字节数；bash 拆出来的只记守卫看得到的路径参数，不是程序实际读写了哪些文件，设置页上如实写。
9. **界面**：设置 · 目录授权（数据与设备组，排在授权的文件夹后面）一处列出全部：最上面"所有 agent · 只读"是授权的文件夹，下面每个 agent 一组，能逐条删、整组清、一次清掉全部已过期的；最后是最近的使用记录。秘书、项目、任务各自的 ⚙ 里能加、删自己的。

## 后果

- 给 agent 多一个目录不用再每次问，也看得清谁能碰哪里、碰过什么。
- 放开的范围比以前大：文件工具写登记目录不再硬拒绝。只有用户能登记，agent 自己改不了。
- **已知的限制**：
  - 整目录搜索（`grep -r`）、`cp -r` 会碰到登记目录里的密钥文件，守卫只认路径参数，认不出来（和授权的文件夹一样）；
  - `cat x | tee 登记目录/a`、`xargs rm` 这类拿到守卫看不见的输入的照旧问，哪怕路径在登记目录里；
  - 8.3 短路径写的删除不放（要写的路径本身也要在登记目录里，短路径字面上不在），换成完整路径就行；
  - 项目外的 `rm -rf` 照旧"永不"（v1 模板），登记了删也一样；要放宽得另说；
  - 流程的规划审查（`workflow-plan.ts`）还不看目录授权：步骤落在登记目录里的照旧标"越出项目目录"、推出授权项。
  - Claude Code 跑的负责人：拉起时交给它的只读放行只有授权的文件夹；登记目录的读写靠它再问时的 `canUseTool`（守卫放行过的直接放行）。

## 考虑过的

- **全局一份、按目录列谁能用**：用户的说法是"给这个 agent 多一个目录"，按 agent 列更直接；子 agent 不继承也更好说清。
- **子 agent 继承负责人的**：子 agent 是负责人临时拉起来做一小段的，隔离换来的是能放手让它跑；要它碰别的目录就写进它的指令、让负责人做。
- **勾了删就带上写**：删和写的后果不同（删了要找回、写了能改回），分开勾；移动要删和写都登记了。
- **按写的路径比**：符号链接、目录联接、8.3 短名都能绕出去。按真实路径比，登记时也存真实路径；判定时不再现取登记目录的真实路径——登记之后被换成链接的，里面的东西按真实路径比就不在了。
- **登记目录里的密钥文件也放开**：用户给的是目录，不是说里面的密钥可以发给模型服务。和授权的文件夹同一个理由，这里更进一步直接拒绝，因为登记了写和删。
- **过期了自动删掉**：留着才看得到"已过期"、能一键重新登记，所以只是不算，清不清由用户定。
