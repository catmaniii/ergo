# ADR-0038 语音合成默认推荐 Fish S2 Pro，不打包、下载前确认许可，已有手动配的不覆盖

状态：已定

## 背景

- 语音回复一直靠用户手动装 audio.cpp、手动在服务管家登记 `audiocpp`（8090 端口）。组件清单里 `tts` 只是个占位（`pending: audiocpp`），组件页写着装不了。开源版要做到"装完就能用"，语音合成得能在组件页一键装。
- 要先定装哪个模型。定下：默认推荐和自己用的一样的 **Fish Audio S2 Pro**（`fish-audio-s2-pro-q8_0.gguf`，6.3 GB）。这个模型的效果是亲自验过的；别的模型没有等量的使用经验。
- 这个模型**不是开源许可**：Fish Audio Research License（39 AI, INC.，2026-03-07 更新）。下面是读条款的理解，不是法律意见：
  - 研究和非商业免费，个人爱好算非商业；
  - 商业使用要另外和 Fish Audio 签书面协议（business@fish.audio），公司内部运营、任何相关的创收都算商业；
  - 再分发要带协议副本、Notice 文件，并显著标注 "Built with Fish Audio"；
  - 模型输出归使用者所有，不算衍生作品；不能用它训练别的基础模型；要遵守可接受使用政策。
- 程序 audio.cpp 是 Apache-2.0，随便用；语音识别也要用同一个程序。
- 用户自己的机器上已经有手动登记的 `audiocpp`，8090 也在用。"一键装"不能把它盖掉。

## 决定

1. **二狗不打包、不做镜像这个模型。** 不进发布包，也不放到任何二狗自己的下载站；用户点下载时从上游拉（`audio-cpp/audio.cpp-gguf`，钉到一个提交；hf-mirror 是 Hugging Face 的公共代理，只是换个地方下，内容按 sha256 核对）。这样二狗不是再分发方，不背上"带协议、带 Notice"的再分发义务，也不替用户判断他算不算商业使用。
2. **下载前必须让用户看到并确认。** 清单里 `license` 写名字、一句话、原文链接、`confirm`：
   - 确认框显示名字、大小（6.3 GB，Windows 里显示 5.88 GB，两个都写，免得以为下错了）、许可、"个人非商业免费；商业使用要另外向 Fish Audio 取得授权"、原文链接；
   - **接口要带确认标记**（`licenseAccepted`），没带回 400、一个字节都不下，不只靠界面拦；`ergo components add tts` 没加 `--accept-license` 时把许可打出来、不下载；
   - 确认过的记在组件区的 `licenses.json`（组件 id、许可名字、`revision`），不再问；许可换了版本要重新确认。删了组件再装不用重新确认；
   - 离线导入也算用它：导入凑齐了但没确认过的，停在"出错了"，写明要先确认。
3. **组件页这一行显示 "Built with Fish Audio"**（清单 `license.attribution`，不翻译）。二狗不再分发、严格说不触发这条，但二狗是在拿它做产品功能，标出来是该有的礼数，也省得以后要不要标再讨论一次。
4. **程序和模型是两个组件。** `audiocpp`（程序，按有没有 N 卡挑 CUDA 版或 CPU 版）、`tts`（模型，`dependsOn: audiocpp`）。语音识别模型用同一个程序，只要再写一条带 `serve` 的组件。id 还叫 `tts`：灰掉"用语音回复"、点去装，指的都是它。
5. **audio.cpp 的包不由二狗提供，只从上游 GitHub Release 下载**：不做镜像、不进发布包，安装脚本也不下载它。下载失败时（国内访问 GitHub 可能慢或不通）组件页列出还差的文件和下载地址，自己下好了用组件现有的"从文件导入…"，按校验值认。
   **CUDA 版的运行库包必须一起下。** v0.9.3 的 `release.yml` 写明 Windows CUDA 版把 CUDA 运行库放在单独的 `cudart` 包里（`bin` 包是不带 CUDA DLL 的薄壳）；本机旧版的运行库包 README 也写明这些 DLL 要放在 exe 旁边。所以 CUDA 版是两个 zip，一共约 853 MB，运行库按文件名找到 `audiocpp_server.exe` 放在它旁边，不写死 exe 在包的最外层。
   **v0.9.3 包内的结构没有核对过**（开发这边不下真包，用户在另一台机器上装一次验证），所以：解完找不到 `audiocpp_server.exe` 就不换上、报清楚（在下 6 GB 的模型之前）；清单里写了 CUDA 版程序旁边应该有的运行库（`expects`，带 `*`），缺了**只提示不挡启动**，名字对不上时不能把本来能跑的挡住，真起不来时这句话连在错误后面。用 13.3 不用 12.4：小 190 MB，缺点是要 NVIDIA 驱动 580 或更新、不支持 GTX 10 系这类老卡。起不来时组件页写原因；这种机器现在得自己手动配，以后再说要不要按驱动版本挑包。
6. **装完自动接上，失败回滚。** 生成 `components/audiocpp-service/server.json`（只绑 127.0.0.1、端口 8090、`lazy_load` 开、模型 id 用配置里的 `voice.speech.model`）→ 经 `lsm/link.ts` 登记（名下的服务，全名 `ergo-daemon--audiocpp`）→ 启动 → 等 `GET /health` → 进开机自启名单。哪一步失败都撤掉这次的登记和生成的配置，写清哪一步、什么原因；程序和模型的文件留着，点重试不用重新下载。配置不放程序目录：更新程序时那个目录整个换掉。
7. **已有手动配的服务不覆盖。** 下面任何一条成立就算"已有自己配的"：两个组件都显示"已有自己配的语音合成，在用它"，不能从这里装，接口也拒绝：
   - 配置里的 `voice.speech.url` 不是这个端口；
   - 8090 上已经有人听（健康检查通的说"在用它"，不通的说"端口上已经有别的程序"）；
   - 服务管家里 8090 已经登记给别人了；
   - 名下已经有同名的登记、却不是我们生成的（我们生成的认 `server.json` 在不在）。
   接入协议碰不到手写在注册表里的服务，手写的 `audiocpp` 停着时端口也没人听，只有 `services.put` 回的 `port-conflict` 看得出来：点安装时空跑一次登记，登记得上马上撤掉。这样 6.3 GB 下载之前就知道。
8. **没接上服务管家不让装。** 语音服务只能由服务管家托管（一个服务只能有一个管理者），二狗不是由服务管家拉起时下完也接不上，点安装就说清楚。
9. **数据目录路径带中文的不让装。** audio.cpp 读不了这种路径（`voice/speech.ts` 也因此不发请求），下完 6.3 GB 才发现太晚了。

## Considered Options

- **打包或者放镜像，下载更快**：要带协议和 Notice、成了再分发方；商业用户拿到手就可能违约。不要。
- **默认推荐一个开源许可的模型（比如 Kokoro、Piper）**：许可干净，但中文克隆效果没有验过，第一次听到的声音决定用户对这个功能的印象。定了 Fish S2 Pro。其他模型不进清单，手动配置的路径保留。
- **只在界面上拦确认，接口不查**：CLI、脚本、以后的向导都能绕过去。确认标记放在接口上。
- **发现手动配的服务时询问要不要接管**：接管要停用户的服务、改用户的登记，出错了用户的语音就没了。要改用这里装的，用户先自己撤。
- **语音服务跟着守护进程起**（不经服务管家）：规矩是常驻服务只由服务管家托管；开机自启、看日志、强制停止也都在那边。

## Consequences

- 没装也没配语音合成的机器，"用语音回复"这个功能现在真的显示没法用、点去装（以前 `voice-speech` 只看配置写没写地址，默认就写着，永远算有）。
- 组件页取清单时多探一次本机端口（最多 1.5 秒），只在页面取清单、点安装时探，平时不探。
- 手写的服务停着时，点安装会有一次"登记再撤掉"，服务管家的审计日志里看得到。
- 发布包里到底有什么（`audiocpp_server.exe` 在不在最外层、DLL 的名字、解开多大）是从上游的 `release.yml` 和本机旧版包读出来的，没有下 v0.9.3 的真包核对：程序按文件名在目录里找、不写死层数，`unpackedSize` 是估的（只用来查磁盘空间）。真实验证由用户在另一台机器上装一次。
- 商业用户的合规由用户自己负责：确认框写明了，二狗不查也不拦。
