# ADR-0042 组件查更新：只取发布页上签过名的版本清单，有新版本只提醒，点了才换

状态：已定（"不自动替换""失败不打扰""说明查的是哪里"是需求，其余是实现时定的）

## 背景

- 组件清单（`components/manifest.json`）随版本发布，以前只有升级二狗本身才会看到新版本的组件。要组件页能"检查更新"、每晚查一次、有新版本提醒用户，**不自动替换**，查失败不打扰。
- 清单决定下什么、校验值是多少：下载器"只认清单里的校验值"，所以新清单从哪来、信不信，决定了下载下来的东西能不能信。
- 用户在乎隐私，要写明查的是哪里、发了什么。

## 决定

1. **查的是发布页上的版本清单：** 发版时把这一版的组件清单和签名放到发布目录（`components-manifest.json`、`.minisig`，`build/release.ts`，GitHub Release 的附件）。默认取 `<仓库>/releases/latest/download/components-manifest.json`；`ERGO_RELEASE_URL`、安装时记下的 `source.url`（自己搭发布地址的）优先，和 `ergo update` 一样。
2. **只有两个 GET，不带任何用户信息：** 清单和签名，地址没有查询串，请求头只有下载那一层一直在用的 `User-Agent: ergo-components`，走系统代理。对方看得到的是一次普通的下载（和网络地址）。组件页写明地址和这一点。
3. **签名按发布公钥验，验不过、程序里没有公钥都不认。** 和验发布包同一把钥匙。随程序的清单没签名时照用（已经在程序里了），但网上取来的不行：它能指定下载地址和校验值。所以没带公钥的构建（开发、没签名的发布）查更新永远写"核对不了"，组件只跟着二狗升级。
4. **新旧看清单的 `release`（发版时写进去的版本号，`stageVersion`）：** 比随程序的新，这个组件的版本又不一样，才算有新版本。防止用的版本比发布页还新（源码装的、回滚过的）时提示"更新"成旧的。清单里多出来的组件、要的依赖这一版没有的、换了安装位置的不提示：要升级二狗本身才行。
5. **有新版本只是显示：** 正在用的那一条一个字节不动，状态写"有新版本"。点"更新"才按新条目下，下到临时目录、校验过才换上（原来的流程）；失败、取消了旧版本照常用，对应的功能不灰。新条目的许可换了版本要重新确认（`licenseAccepted` 那一套），绕不过去。没装的组件查到新版本不提醒，点安装时装的就是新的。
6. **换上的那一条记进 `installed.json`（`entry`、`entryRelease`）：** 重启后随程序的清单还是旧的，按记下的认，不会又说"有新版本"，看"装好了没有"的（语音服务）也不会因为文件名变了以为没装。升级二狗后随程序的清单赶上来（`release` 不比它旧），就回到随程序的。
7. **上次查到的存在组件区（`latest-manifest.json` 和签名，重启时重新验签），上次查的结果在 `update-check.json`。** 查到的不进配置、不进事件日志。
8. **每晚一次是内部作业（`component_update_check`，04:20，错过了开机补一次）：** 查到装着的组件有新版本，待办里放一条提醒（`component_update_available`，不卡任务）；同一个组件的同一个版本只提醒一次，换上之后自动归档。手动点"检查更新"不放提醒（人就在页面上）。
9. **没查成不打扰：** 接口还是 200，原因只写在组件页那一行（`updates.error`，普通的字，不是红字），不进待办。上次查到的还算数。发布页上还没有这份清单（清单本身 404，老的发布都这样）连没查成都不算（`updates.notPublished`），页面写"这个版本还没有组件更新信息"。清单在、签名没有的还是没查成：那不是"还没发"，是发了却核对不了。

## Considered Options

- **另搭一个放版本清单的地址：** 要多维护一个站，还多一方看得到请求。发布页本来就有。
- **查到就自动下载，点更新时只是换上：** 语音模型 6 GB，用户没点就下不合适；明确不做。
- **不验签，靠 HTTPS：** 镜像、代理、自己搭的发布地址都可能在路上；清单决定下什么，不能信路上的东西。发布钥匙还没定时查更新就是用不了，宁可这样。
- **按组件的版本号比新旧：** 组件版本有的是提交号（`4de13258`），比不出大小。比清单的 `release`。
- **一查到就把新条目换成"现在用的"：** 写起来最省（状态自然变成 update），但新版本改了文件名或者大小时，看"装好了没有"的会以为没装，下载失败了语音就断了。所以新条目单放（`offered`），换上之后才转正。
- **npmmirror 也查：** 平台包的 tgz 里才有这些文件，只为取一个小文件要下整个发布包；`/files/` 接口没验证过。先不做，国内访问 GitHub 不通时组件页写"没查成"，组件照常用。

## Consequences

- 发版要多传两个文件；发布页上没有这份清单时，组件页写"这个版本还没有组件更新信息"，不影响别的。
- 发布钥匙定下来之前（`RELEASE_PUBLIC_KEY` 空着、发版没带 `--sign-key`），查更新永远写"核对不了签名"，提醒不会出现。
- 国内访问 GitHub 不通的机器查不到更新，只能跟着二狗升级。
- `installed.json` 多了两个字段，老版本读到不认也不坏事（读记录时只看认得的字段）。
- 真实的发布页、真实的钥匙没有跑过：测试用本机假下载站和测试钥匙。
