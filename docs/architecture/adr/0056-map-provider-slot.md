# ADR-0056 地图服务做成插槽，地图页能手动切换

状态：已定（445，用户 2026-11-08："海外能集成谷歌地图吗？如果可以的话，做成插件""到时候在国内和国外都可以在可用的地图之间切换"）。不改 ADR-0051、0053、0055 的决定："自动"时国内高德、国外 OpenStreetMap，挑法一样；只是把写死的两家改成按插槽登记的两家，再让别的插件能登记。

**451 修订**（[ADR-0058](0058-map-one-current-map.md)）：插槽多了 `regionPriority`、`lookupRegions`、`staticMap`；高德大陆外也管底图（优先级 30），"自动"在大陆外是 谷歌 > 高德 > OpenStreetMap。

## 背景

- 地图插件里写死了两家：底图在网页里按"在不在大陆、高德能不能用"挑（`chooseBasemap`），查询在守护进程里按"高德能不能用"给 `[高德, OpenStreetMap]` 或 `[OpenStreetMap]`。接谷歌（446）要再写死第三家，而且谷歌要做成独立插件——停用、移除时自动退回。
- 用户还要能手动切换：国内、国外分开选，只列能用的。
- 两条规矩不变：某一家查来的结果只画在它自己的底图上（高德协议 4.12.4，谷歌同样）；用户的足迹一律 OpenStreetMap，不加载商业地图的脚本。

## 决定

1. **守护进程一半是地图插件提供的服务 `MAP_PROVIDERS`**（`map/api.ts`）：`register(MapProvider)` 交回撤销函数。别的插件 `needs` 它、在 `setup` 里 `ctx.effect(() => slot.register(…))`——停用、移除时宿主替它撤掉；地图插件停了，登记了的插件跟着停（`needs` 的规矩）。没做成内核的贡献点：地图是插件，插槽跟着它走；内核不认得"地图"。
2. **一家写明**：`regions`（"自动"时管的区域：`mainland` 中国大陆、`abroad` 大陆以外，按点在不在大陆分；以后要更细再加）、`manualRegions`（手动选它时还能用的区域：谷歌在大陆也能选，它自己转 GCJ-02；高德大陆外不列——世界地图要提工单）、`priority`（同一区域里数大的先：高德 100、OpenStreetMap 0，谷歌 50 就是"大陆外、高于 OpenStreetMap"）、`ownBasemapOnly`、`basemap()`（此刻能不能用、浏览器用的 Key）、`lookup()`（能查交回 `LookupProvider`，不能查交回给模型的原因）、`usage`（每月用量，地图插件替它在体检登记"<编号>-usage"）、`toolNote`（工具说明里讲它的半句）。都是"此刻"的，每次用时现调。查询的统一外形 `LookupProvider`、出错 `MapLookupError` 从 `map/api.ts` 转出来，别的插件只 import 这一个文件。
3. **高德、OpenStreetMap 改成照插槽登记的两家**（`map/service.ts`），还在地图插件里。"自动"的先后是按优先级排、`covers` 按登记的区域收窄（`map/providers.ts`），只有这两家时和 433 完全一样；按名字找、没有参照点时"带汉字的当在大陆找、不带的当在大陆外找，管那一边的先问"——两家时就是原来的"带汉字照原来的先后、不带的倒过来"。
4. **网页一半是网页插槽 `mapBasemaps`**（`MapBasemapSlot`：名字、`prepare(key)` 加载外站脚本、交回建引擎的函数）。引擎和画什么的类型挪到核心 `model/map.ts`（插槽的条目要用它，插件之间不互相 import）。地图插件自带的两种照插槽登记（`plugins/map/basemaps.ts`）。守护进程报的 `providers`（`GET /api/map/config`，组合根把 `providerViews()` 拼进去；旧的守护进程没有时页面按 `amapKey` 当两家）加上网页这边登记了没有、这一页加载失败了没有，一起决定能不能用。
5. **手动切换记在这台设备上**（`localStorage` 的 `ergo-map-choice`，`{ mainland?, abroad? }`），国内国外分开；只列这个区域能用的几家，这台设备加载失败的标"连不上"。记着的那一家用不了（Key 坏了、插件停了、加载不上、不管这个区域）就把这个区域退回"自动"、说一句。看足迹时不管选了谁一律 OpenStreetMap。守护进程不存手动选择：它不知道"这台设备"是哪台。
6. **查询跟着地图走**：查地点、地址、路线的四个工具多一个可选参数 `map`——用户地图上现在用的那家（444 的地图旁聊天带地图的上下文时写进去：上下文的 `basemap` 是真画着的那一家的编号，地图插件交给秘书的输入附注叫它把 `map` 写成这个编号；base/map-ui 合并时接上。开着足迹时底图一律 OpenStreetMap，上下文不跟着写 `osm`，写这个区域手动选的那家、没选过是"自动"挑的那家，用户 2026-11-08 定、447 附带改）。写了就先问它（它手动能用的区域也算它管）；它查不了、管不了这几处时照"自动"挑，回答里说一句用了谁。不写（语音、没开地图页）就是"自动"。没做成"地图页把选择报给守护进程"：一个秘书对着好几台设备，守护进程分不清是哪台在问。
7. **只画在自己底图上的**：OpenStreetMap 以外的来源一律当"只画在它自己的底图上"（卡片不画缩略图，地图页只在底图是它时画；不是时说为什么，能换的给"换成它"）。不知道条款的新来源也这样，宁严勿松。

## 后果

- 446 的谷歌地图插件照 `packages/daemon/test/helpers/fake-map-provider.ts`（测试用的假"第三家"）写守护进程一半，网页一半登记 `mapBasemaps` 的 `google`；秘书工具不用新增。
- 页面的 `GET /api/map/config` 多了 `providers`；原来的 `amapKey`、`amapProblem` 照旧给。
- 手动选的那一家只在这台设备上：换一台设备是"自动"。秘书只有在消息里带了地图上下文时才知道你选了谁，别的时候按"自动"查，查到的可能画不到你选的那家底图上（地图页会说为什么、给"换成它"）。
- 地图插件停用会连带停掉登记了的插件，再启用地图插件时它们要各自再启用（宿主的规矩）；直接启用它们会连地图插件一起启用。
