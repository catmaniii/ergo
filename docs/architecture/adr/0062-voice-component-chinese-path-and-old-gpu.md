# ADR-0062 语音组件照顾中文用户名和老显卡：程序和模型改放到 ProgramData，参考音色发相对路径；按驱动挑 CUDA 13.3 / 12.4 / CPU

状态：已定（351，用户 2026-11-12："尽量捋顺"；"要定的"两条由做票的先实测、再定一个最稳的）。改了 [ADR-0038](0038-default-speech-model-and-license.md) 第 9 条（数据目录带中文不让装）。

## 背景

- Windows 用户名是中文的人，数据目录默认是 `C:\Users\张三\.ergo`。345 号票时 audio.cpp 读不了带中文的路径，组件页就不让装，语音回复也不发请求（`voice/speech.ts`）。这在中文用户里不少见。
- 345 号票只放了 CUDA 13.3 的包：要驱动 580 或更新、显卡算力 7.5 起，GTX 10 系这类老卡、没更新驱动的机器只能看报错后手动配。

## 实测（2026-11-12，本机 ACP 936 的中文 Windows，上游 8 月版 CPU 程序，Fun-ASR Nano 模型，临时端口）

| 带中文的是 | 结果 |
|---|---|
| 程序所在目录 | 能起、能用 |
| 工作目录、`--config` 的路径（相对、绝对都试了） | 能起、能用 |
| `server.json` 里模型的路径 | 不行："model path does not exist" |
| 请求里参考音色的路径（`voice_ref`） | 不行："could not open WAV input" |
| 模型写相对路径（工作目录是中文的） | 不行：过了存在检查，读 GGUF 时还是打不开 |
| 参考音色写相对路径（工作目录是中文的） | **能读**：相对路径按工作目录解 |
| 照服务管家的起法（`cmd /d /s /c`、工作目录中文、日志在中文目录）+ 程序和模型在英文目录 + 参考音色相对路径 | 识别、读参考音色都对 |

原因（读 v0.9.3 源码对上了）：程序的 `main` 收的是 ANSI 代码页的参数，中文系统上中文能过；`server.json`、请求是 UTF-8 的，按 ANSI 解就错了；模型路径先 `weakly_canonical` 成绝对路径再转成 ANSI 交给 ggml，ggml 又按 UTF-8 解，所以相对路径也救不回来；参考音色路径是对着宽字符的工作目录解的，相对的能读。

短路径（8.3）帮不上：中文名在中文系统上的短名照样是中文（"张三""用户张三"不生成短名，"长长的中文用户名"的短名是"长长的~1"）；D 盘这类还常常关了短名。

## 决定

1. **数据目录的路径 audio.cpp 读不了时，语音的程序和模型装到 `%ProgramData%\ergo\<指纹>`**（`audiocpp-host.ts` 的 `voiceFallbackRoot`，指纹是数据目录路径的 sha256 前 8 位）：
   - 不要管理员权限：普通用户能在 ProgramData 下建目录，建的人对它有完全控制；这个路径本身是英文的。
   - 按数据目录分开：同一台电脑几个用户、几个数据目录各用各的。
   - 只放公开下载的程序和模型。下了一半的也放那边（`.staging/`，同一个盘，换上是改名）。装着的记录、许可确认、生成的 `server.json`（服务的工作目录）还在数据目录。
   - 组件页"装在"那一行写那边的路径和一句为什么（`ComponentView.locationNote`）。
   - 连 ProgramData 也读不了（没有这个环境变量、它自己带中文）才照旧不让装。不是 Windows 的平台没有这个问题（audio.cpp 按 UTF-8 读路径），清单里也没有那些平台的包。
2. **参考音色发相对工作目录的路径**：调的是组件页装、我们接上的那个服务（`audioCppWorkingDir`：组件区有我们生成的 `server.json`、它写的端口和地址对得上；只看文件，守护进程刚起来、组件服务还没建时接着合成也认得）时，`voice_ref` 带中文就改发相对 `components/audiocpp-service/` 的路径（`..\..\voices\v-xxxx\reference.wav`，参考音色的目录、文件名本来就是英文）。用户自己配的服务不知道工作目录，照旧不发请求、写明（文案改成"改用组件页装的"）。参考音色是用户的录音，不复制到 ProgramData。
3. **按显卡和驱动挑版本**（`components/nvidia.ts`，纯函数）：
   - `nvidia-smi --query-gpu=name,driver_version,compute_cap` 问一次（老驱动不认 compute_cap 就只问型号和驱动，再不行看 `-L`；老驱动的 nvidia-smi 在 `Program Files\NVIDIA Corporation\NVSMI` 也找）。几块卡取算力最低的。
   - CUDA 13.3（`cuda`）：驱动 580 或更新、算力 7.5 起（上游 v0.9.3 的 `docs/build/windows.md` 写的）。
   - CUDA 12.4（`cuda12`）：驱动 551.78 或更新、算力 6.1 起。算力按上游 `release.yml` 的 `CMAKE_CUDA_ARCHITECTURES`（`61-virtual;70;75;…`）。驱动按 CUDA 12.4.1 自己要的 551.78 算，比 12.x 兼容模式的 528.33 严：6.1 的卡只带了 PTX、要驱动现编译，兼容模式不管这种，一条线最稳。
   - 都用不了（驱动更旧、显卡更老、查不到）用 CPU 版。组件页"用哪一版"那一行写为什么：驱动低于多少、显卡太老、查不到；模型那一行写"显卡用不上，会很慢"。
   - **要求写在代码里、按版本 id 认，不加进清单的 `when`**：老版本的二狗查更新时也读发布页上的新清单，`when` 多一个字段整份清单就不认了（schema 不许多字段），连 Claude Code 这些组件的更新也查不到。清单只多一个 `cuda12` 版本（老版本二狗按先后挑 `cuda`，和现在一样）。换 audio.cpp 版本时对一下 `CUDA_BUILDS`。
4. **更新了驱动能换**：装着的是清单里排在后面的一版、这台电脑现在能用排在前面的（CPU → 显卡版、12.4 → 13.3），状态是"有新版本"，点"更新"就换（同一个版本号，按新的那版下、换上、服务重启）。反过来（这次 nvidia-smi 没回话）不算，装着的照用，"用哪一版"写装着的那版。
5. **已有手动配置不动**：判断"已有自己配的"、`voice.recognizer`、手动配的服务都没改。改放、相对路径只在我们自己装、自己接上的服务上发生；ASCII 路径的数据目录一个字节都不变。

## Considered Options

- **用 Windows 短路径（8.3）**：中文系统上中文名的短名还是中文，不少盘关了短名。实测排除。
- **把模型路径写成 ANSI（GBK）编码塞进 `server.json`**：存在检查过得去，交给 ggml 时又按 UTF-8 解，还是打不开；GBK 以外的字（生僻字、别的语言）也表示不了。
- **整套（连配置、工作目录）都放 ProgramData，参考音色复制过去**：参考音色是用户的录音，ProgramData 下别的 Windows 用户读得到；改了、删了还要同步。不要。
- **装到盘根（`C:\ergo`）**：普通用户也能建，但盘根下建的目录别的登录用户默认有"修改"权限，比 ProgramData 宽。
- **12.4 的驱动线用兼容模式的 528.33**：RTX 卡在 528–551 的驱动上大概率能跑，可 6.1 的卡要现编译 PTX，兼容模式不保证；为一条线写两套门槛不值。驱动太旧的先用 CPU 版，写明更新驱动后能换。
- **驱动要求写进清单的 `when`**：数据驱动更干净，但会让老版本二狗查更新整份失败（见决定 3）。

## Consequences

- 中文用户名的机器上 ProgramData 下多一个目录，删组件时跟着删；只删数据目录、不在组件页删的，会留在那边。
- ProgramData 的默认权限下，别的登录用户能在我们建的目录里**新建**文件（改不了已有的）。理论上能往程序旁边放 DLL。按"功能先跑通、安全后接"，先记在这里不做；要做就是建目录时收紧权限（只留自己、SYSTEM、Administrators）。
- 驱动版本、算力只在守护进程起来后问一次：开着二狗更新了驱动，要重启二狗才看得到"有新版本"。
- CUDA 12.4 版两个包一共 1023.5 MB（13.3 版 813.3 MB），解开后的大小是估的（1.3 GB、1.1 GB），只用来查磁盘空间。
- v0.9.3 的真包、ProgramData 下真的装、老显卡真机都没跑过：本机测的是 8 月版程序（和 v0.9.3 源码的读路径方式对过），用户在中文用户名、老显卡的机器上确认。
