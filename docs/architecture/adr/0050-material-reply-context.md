# ADR-0050 素材挂前文：每晚判、事件派生，证据原文不改，前文不算用户说的

状态：已定

## 背景

- 用户在会话里说的话采成素材时只存本人的原话。"好""就这么办""不用，周末别叫"这类回复单独看没信息，整理时还可能被读歪：回的是谁、回的什么都没有。
- 自己开的新话题，这一句就够；接着对方的话说的，要把前文的意思带上，但不要全文。
- 素材只由守护进程从事件日志产生，`materials.db` 是派生的（[ADR-0006](0006-materials-two-sources-of-truth.md)）；"别推断"由记忆命令事件派生，重建时照样标上。
- 推理图谱的唯一写入口不许改证据原文：证据原文只有忘掉时能清空（[ADR-0030](0030-memory-keeper-maintains-reasoning-graph-through-write-gate.md)）。
- 只有本人的话能推断用户（[ADR-0032](0032-memory-reasoning-rules.md)）。

## 决定

1. **哪些素材**：会话里本人说的话——用户发言、投喂的材料，秘书、负责人、记忆管理员的会话都算；出处是会话里的一条消息、有本人的文字。不判：数据源导入的（另开票）、标了别推断的、了解你访谈里的（管理员问的那一句已经作为上下文排在前面）、澄清问题的回答（不在会话里，回答里本来就写着问题）。
2. **前文是哪句**：这句之前、同一会话当前分支上最近一条不是用户说的（agent 的回复、通知、卡片的纯文本降级）；用户连着说的往前跳过，只有工具调用、推理这类看不见的跳过，"清空当前对话"的分隔线前面的不算。连着那一段对方说的一起给模型（最多 4 条，太长留结尾）。不按时间间隔判：隔几小时才回秘书的问题照样交给模型。
3. **判定和总结一起交给模型**：会话第一句不问模型；别的一批 10 句问一次整理同一个模型（DeepSeek，包了档案那一层，号码、住址不进请求）。接着回的写一两句前文的意思（谁说的、问了 / 提议了 / 汇报了什么，不抄原文，≤80 字），新话题不挂。模型没判出来的不记，下一夜再判。
4. **什么时候做**：每晚整理之前，不拖慢聊天。每晚最多交给模型 240 句（没判出来的也算，手动整理一次和 03:00 那次算同一夜），新的先判；以前的素材就这样分批补上。判的调用算进这一夜的 `modelCalls`、从整理的预算里先扣。
5. **怎么存**：一批的结果是素材频道上的一条 `material_replies` 事件（素材 id、会话、哪种：`reply` / `new_topic` / `first` / `cleared`、总结、前文是哪条消息、这一批交给模型几句）。素材库照它在素材上标（`Material.reply`，`materials.db` 里的 `material_replies` 表，按素材 id 记）：同"别推断"，不进原文副本（原文副本只存本人的话），`materials.db` 删掉重建后照样回来。表是新加的、库的版本不升：退回旧版不碍事，只是不挂。
6. **读成证据**：原文后面接一行"［前文，不是用户说的］…"（同数据源素材的场景一行）。它只用来读懂用户这句：
   - 规则版的解析（抽事实、认变化和纠正的说法、读回答是 / 不是、约束和难处、认人物信息、场景）一律只看用户自己的话；
   - 交给模型的照样带着这一行，抽事实、出假设、判证据、往上抽、复核、判预测的提示词里讲明规矩：前文里说用户怎样都不是用户说的，不能单独支持或反驳结论；用户这句表示同意、拒绝、回答的按用户这句的意思读；
   - 模型版抽事实另有一道硬关：原文片段（span）只出自前文的事实、关系写入前丢掉，别名的两个叫法要在用户自己的话里。
7. **证据原文不改**：还没判、两天以内的候选先不读成证据，判完带着前文读；更早的、模型出错没判出来的照常不带前文读（不一直压着）。已经进了推理库的旧证据**不补前文**：唯一写入口不许改原话，补前文要先撤证据，依赖它的结论会成片加复核标记，代价不值。以前的素材补上前文以后，记忆页、读素材看得到；推理库重建时读进去的带前文。顺口问的回答白天马上读成证据，同样不补（它和问题已经由回答记录连着）。
8. **删除**：忘掉、彻底删除时素材上挂的一起删；彻底删除改写判它的那条事件里这一项的总结（换成删除标记，别的项不动）；别推断时整条不读成证据，前文也就不进推理库。删任务、删项目连会话一起删时，那个会话里挂的前文撤掉：判它的事件里这几项的总结换成删除标记、追加一条 `cleared`；推理库里带着前文的证据照彻底删除撤掉（删任务、删项目是用户发起的），下一夜不带前文重读。
9. **界面**：记忆页素材详情的"内容"上面一行小字"回的是：……"；总结里说到秘书的换成名字占位，显示用户起的名字。

## 后果

- 短回复读得懂了：前文提议周六去爬山、用户回"好"，读成用户答应周六去爬山。
- 多一类模型调用，每晚最多 24 次（10 句一批），在整理的预算里。
- 今天说的话、判之前的那一小会儿不进推理库（最多压两天）；平常一夜就判完。
- 已经进了推理库的旧证据不带前文，要带只能重建推理库。
- 模型照样可能读歪前文：提示词和原文片段那道硬关挡住大部分，评测里核"有没有把前文当成用户说的"。
- 数据源导入的回复（发出的邮件回的是哪封）不在这一步。
