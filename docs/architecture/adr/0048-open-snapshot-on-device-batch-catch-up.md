# ADR-0048 打开页面：补发攒着一次放，本机存快照只补增量

状态：已定（"存一个最新的快照"是用户 2026-11-03 提的；快照放页面本机、回到配对页时删掉、不改守护进程的补发是 388 号票定的，其余是实现时定的）

## 背景

- 网页打开时订阅十几个频道，游标全是 0。守护进程补发时会话频道只补最近一页，别的频道从第一条起全部补。用久了的二狗是一万多条、十来 MB（用户那台：看板 4548 条 / 7.9 MB、活动状态 2487、已读位置 2176、待办 798、卡片 746 / 1.4 MB……），手机多半还经公网隧道拉。
- 页面每收到一帧就交一次状态层。WebSocket 的每条消息是单独的任务，React 合不了批，中间状态一帧帧画出来：卡片出现又消失、待办冒出来又被处理掉。用户看到的就是"打开就闪，像把数据全部过一遍"。补发推完有回执（`synced`），但界面没等它。

## 决定

1. **补发攒着一次交（`app/ws-connection.ts`）。** 有回执还没到时，收到的帧（补发的，连同夹在中间的实时帧，保持先后）、订阅回的要重新同步的频道、被拒的请求都先攒着；回执到了作为一个 `batch` 输入一次交给状态层，主订阅的后面接着 `synced`。状态层按先后归并（`reduce` 的 `batch`），React 只画一次。断了先把攒着的交掉（游标已经推过去了，不交就丢），再报断开。连接状态、网页的版本照旧马上交。打开、重连、多订阅一个负责人的会话都一样。攒了 10 秒回执还没到（网很慢、补得很多）就先交一次、接着攒，不至于一直空着。
2. **本机快照（`state/open-snapshot.ts`、`app/open-snapshot.ts`、`app/open-snapshot-idb.ts`）。** 状态层里由事件折出来的那部分，连同各频道的游标，存在这台设备的 IndexedDB（一个库、一个键，整份换）。下次打开先读它（页面脚本一开始就读，和问"被信任吗"同时），能用就先画出来，订阅带它的游标，守护进程只补增量。
   - **存哪些：** 落盘事件折出来的（会话、卡片、待办、任务和提醒、定时作业、活动状态、已配对设备、项目、工单、范围记录、工作日历、关注类别、名字、语言、已读位置……），和守护进程订阅时总会补推一次的"现在的样子"（插件的状况、两个开关、项目的服务：先照上次的画，补推的一到就换掉）。不存：发送中的、卡片上点了还没回的、弹窗、被拒的提示、正在生成的回复、干活中的进度、新到的语音、连接状态、经 HTTP 取的（我的名字、角色、语音模型、日历的各月、取回的废弃分支）。
   - **会话只留最近一页：** 当前分支上最近 `HISTORY_PAGE_SIZE` 条消息起的那一段，更早的连同它们的语音对象不留，还能往上翻（和第一次补发的一页一样）。
   - **什么时候存：** 补完了、连着，要存的那几样（按引用比）变了才存；攒着等闲下来（最后一次变化之后 3 秒，最多攒 30 秒）写一份，写的时候取最新的；切到后台、关页面时马上写。
   - **作废：** 网页版本（构建产物的哈希）、协议版本、快照格式有一样对不上就不用、当场删掉；读坏了、读不出来、1.5 秒没读出来当没有。订阅回 `resync` 的频道（守护进程那边序号比快照小，数据目录恢复过）照旧清掉、从头补。回到配对页（还没配对、被吊销、过期）时删掉，之后这个页面上不再存。
   - **都不抛错：** 存不了、读不了就照从头补。原型、开发服务器的页面（没有网页版本）不用快照。
   - **多台设备、多个标签页各存各的，不互相同步：** 同一台设备上的几个标签页（鸿蒙 App 的浏览侧边栏也是一个页面）谁后写用谁的。每一份都是某一刻完整的样子连同它的游标，从哪一份补增量补出来的都一样。
3. **补得久时轻轻提示：** 打开、重连上之后过了 0.8 秒还没补完，会话输入框上方写一行"正在同步最新的内容…"；很快补完的不出（不然它自己也闪一下）。Debug 工具集的"连接"里写最近一次补了几帧、多少字节、多久补完，打开时先用了本机快照没有。

## 后果

- 合成数据（11,460 帧、10.5 MB，照用户那台的量级）上量过：冷打开 React 提交从 98 次降到 9 次，补发在路上时从 93 次降到 0~3 次（连上、"正在同步"）；热打开只补关掉之后的 17 帧（7.9 KB），0.1 秒补完（CPU 降速 4 倍时 0.6 秒；改之前热打开和冷打开一样，4 秒）。冷打开要补的帧数、字节没变（这一条留给"服务端按频道折快照"，见下）。
- 手机上多了一份个人数据（上次的样子）。只在这台手机的浏览器存储里，回到配对页时删；手机丢了在电脑上吊销它，下次打开就删。没打开过的那台被偷的手机上会一直留着，直到被打开——这一条和浏览器缓存的页面一样。
- 状态层加字段时要想一下它是不是事件折出来的、要不要进快照（`SNAPSHOT_KEYS`）；形状变了的照"网页版本对不上就不用"作废，不用另做迁移。
- 先用快照再补增量和从头补的结果一样，由录下的真实事件流在每个切点上核对（`test/state/open-snapshot.test.ts`）。真 Chrome 里的冷、热打开、网页升级、吊销由 `test/open-snapshot-page.test.ts` 查。
- 同一个来源（主机加端口）后来换了一个数据目录、而新的那个的序号比快照的还大时认不出来（`resync` 只认"比守护进程的还大"）。重装、换数据目录多半换了版本（网页版本对不上就不用）；没换版本又换数据目录的，要清掉浏览器里这个网站的数据（或者升级一次二狗）。

## Considered Options

- **守护进程按频道折快照、只发结果：** 冷打开也快，但要在守护进程里为每个频道写一份和前端状态层一样的折叠，两边会走样。票里定了先在页面这边做，冷打开量下来还太慢再开票。
- **按帧时间切成几批交：** 一次交在一万多帧时页面卡 0.1~0.4 秒（CPU 降速 4 倍时），能接受；切批又会把中间状态画出来几次。
- **用 localStorage 存：** 只有 5 MB 左右、只能存字符串、读写都在主线程上同步做；快照有几 MB。
- **每个标签页一份：** 新开的标签页、App 重新打开都是新的一页，找不到自己的那份，等于没有。
