# ADR-0053 地图查地点、算路线：数据源"高德地图"的按需查，统一外形、只现查不存

状态：已定（432，用户 2026-11-07 定的方向：国内用高德查；只在用户问的时候把起点、终点、"附近"那个点发给高德，每天的轨迹、照片地点不外发）

## 背景

- 地图插件（ADR-0051）已经有数据源 `amap`"高德地图"，能填 Web 服务 Key，但不用。用户要能问"从家到公司多久""附近的咖啡店"，查到的以后画在二狗的地图上（431）、国外换成 OpenStreetMap（433）。
- 高德官方的 stdio MCP（`@amap/amap-maps-mcp-server`，调研方案零）能让秘书用文字回答，但调的是老接口、搜索结果不带坐标、步行公交不回折线，画不了图；Key 还要写进环境变量。
- 高德协议不许存、不许缓存查到的结果；个人认证档每月免费量有限（搜地点约 5,000 次）。
- "家""公司"在手机插件的常去的地方里（WGS-84），"附近"只有手机交来的位置点；秘书原来读不到这两样。

## 决定

1. **做成数据源的按需查**（`usages.query`，默认开），不另开一条路：内核只在按需查开着、地图插件在运行、`amap` 连着时把工具给秘书，关掉、Key 失效就收回；Key 只在守护进程里，从密钥区现取。没选高德官方 MCP：拿不到坐标和折线，画不了图（只在用户急着要、这票还没上线时可以当过渡，没做）。
2. **工具只认一个统一外形**（`map/lookup.ts` 的 `LookupProvider`：搜地点、周边、地理编码、逆地理编码、一种走法的路线；坐标进出一律 WGS-84）。高德是其中一家（`map/amap-lookup.ts`，调 Web 服务的 v5 搜地点和路线规划、v3 地理编码，进出转 GCJ-02），按点在不在中国大陆挑；433 再加一家 OpenStreetMap，工具不用改。
3. **五个工具**（`map/lookup-tools.ts`）：搜地点、算路线（开车带用时和分段路况、公交带换乘、步行）、地址 → 位置、某处 → 地址，登记成联网（`network`）、只往下拉（`pullOnly`）、只读只看，带出去的查询词登记成对外内容；外加不联网的"看常去的地方"（秘书原来读不到）。`defineHostTool` 因此能写 `network`、`pullOnly`。
4. **"家""公司""附近"由守护进程换成坐标**：名字对上手机插件起了名的常去的地方，"当前位置""附近"用手机最近交来的一个点（地图插件 `wants: [PHONE]`，手机插件只多给 `namedPlaces`、`latestPoint` 两样，不给轨迹）。没起名的"家"不拿去高德瞎找，如实说去哪起名。用户自己的坐标不写进给模型的结果（模型那边也是外面的服务），只写名字和哪来的。
5. **只现查不存**：查到的不写事件、不进素材、不落盘（工具结果照常在聊天记录里，和别的工具一样）；能画的那一份只在内存里留两小时、最多 30 份（`map/lookup-results.ts`），编号写进工具结果给 431 的"画在地图上"用。结果写明"数据来自高德"，商家写的名字地址夹在外部数据标记之间。
6. **用量按月数**：搜地点、地址和路线分两类（高德个人档也是这么分的），只记次数、存插件自己的存储 `map/amap-usage.json`；到个人档免费量的 80% 体检提示注意、100% 算坏了（409 的插件体检项，`map/doctor.ts`）。查的时候高德说 Key 不认，数据源的连接状态变成出错、要重新填（`amap.ts` 的 `serviceReply`），用量到上限、太频繁照样连着、写原因。
7. **"试查一下"是数据源的 live**：搜固定的地点（北京天安门，和 429 测 Key 同一处，不是用户的位置），设置里那一块和数据源详情的"现在能查到的"共用。

## 后果

- 秘书能用文字回答路线和附近的地点，查到的带坐标、折线，431 能直接画；433 只加一家服务。
- 每次问路线要好几次请求（公交要两头的城市编码，常去的地方要先逆地理编码），都算地址和路线那一类，免费量很宽。
- 高德的 v5 接口字段只照文档读过（文档页没有现成的 JSON 样例），没拿真 Key 调过；几处两种写法都认，真回应对不上的话改 `amap-lookup.ts` 的读法。
- Web 端 Key 出错时 `amap` 整个报出错，查地点的工具也跟着收回（哪怕 Web 服务 Key 是好的）——两组 Key 共用一个连接状态，以后要分开再议。
- 插件宿主没有 `ctx.doctor` 时（432 的分支早于 409）体检项不登记；合进有 409 的 main 以后自动登记上。
