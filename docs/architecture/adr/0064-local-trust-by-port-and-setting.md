# ADR-0064 本机信任从"按端口"变成"按端口 + 设置"：本机来的也要配对、本机程序令牌

状态：已定（469）。补充 [ADR-0026](0026-features-first-security-later.md)（本机端口不认 Origin 就信任，留到接安全机制时再看）、[ADR-0043](0043-project-service-events.md) 和 [ADR-0045](0045-project-ops-auto-mcp.md)（两个自带 Bearer 的本机接口）。和 [ADR-0063](0063-multiple-instances-one-data-folder-each.md)（一台电脑上配置多份）配合：那边各份的文件夹、端口互相挡开，这边是各份的本机端口自己的门。

## 背景

- 网关两个端口：外网端口永远不享受本机信任，每个请求都要设备凭证；本机端口只看从哪个端口进来，不看来源，自动信任。
- 同一台电脑上有多个实例或者别的程序时，本机端口的这份信任谁都能用：本机上的任何程序直接访问本机端口就进去了，外网那道门（各管各的设备凭证）拦不住它。
- 要一个开关：打开后本机来的也要配对。不能把这台电脑上的浏览器、不带浏览器的本机程序（服务管家的健康探针、`ergo` 命令行、项目的服务、二狗自己起的子进程、冒烟脚本）弄坏，也不能让打开它的人把自己关在外面。

## 决定

1. **设置项，默认关。** 配置 `pairing.localRequestsNeedPairing`（只认 true / false，写错拒绝启动），设置 · 设备配对里开关，写回配置文件、马上生效（网关每个请求现取，`pairing/local-access.ts` 的 `LocalPairingSetting`）。关着时网关的行为一个字节不变。
2. **开着时本机端口和外网端口同一套规矩**（`gateway.ts` 的 `deviceGate`，两个端口共用）：没凭证的 HTTP 只放页面、`/api/access`（多带 `local: true`，配对页据此写明这是这台电脑上的二狗和退路）、配对接口；WebSocket 握手要凭证。Host、Origin 的校验照旧。
3. **本机端口上的 cookie 名带端口**（`localCookies(port)`：`__Host-ergo-device-l<端口>`、`__Host-ergo-pairing-l<端口>`）。cookie 不分端口，同一台电脑上几份二狗都在 127.0.0.1 上，同名会互相覆盖；一份认不出另一份的凭证时还会让浏览器删掉它。仍以 `__Host-ergo-` 开头，转发给项目的服务时一样去掉、服务也写不了。Chrome、Edge 在 http://127.0.0.1 上收、带 Secure 的 cookie（实测）。
4. **配对请求的来源按 TCP 对端**：本机端口上不信任客户端写的 X-Real-IP（限频照样按来源算，本机来的共用一份），卡片、设备列表上写"本机端口 · 这台电脑"，不写"认不出"。这样配上的设备记成本机的（`PairedDevice.local`）：不算设置向导里"手机配好了"，体检里不算"有外网入口"。
5. **不带浏览器的本机调用方各有各的办法，不靠"本机就信"：**

   | 调用方 | 办法 |
   |---|---|
   | 服务管家的健康探针 | `GET`、`HEAD /healthz` 照放，只放这一个 |
   | `ergo components`、`ergo local-pairing` | 本机程序令牌（下一条） |
   | `npm run smoke:page` | 本机程序令牌（按 `ERGO_DATA_DIR` 找），只发给要打开的地址，发往别处的请求拦下 |
   | 守护进程自己截服务首页（无头浏览器经本机端口的 `/apps/`） | 本机程序令牌，只加在发往本机端口这个源的请求上（`PageOptions.originHeaders`） |
   | 项目的服务报事件（`ergo notify`、服务自己 POST） | 自带服务的 Bearer，`/api/service-events` 交给接口自己认 |
   | 项目自动转的 MCP 的转发程序 | 自带项目的 Bearer，`/api/project-ops-mcp` 交给接口自己认 |
   | agent 运行时（pi、Claude Code、Codex）、用户登记的 MCP | 走 stdio、命名管道，不经网关，不受影响 |
   | 体检的端口探测、停止钩子、恢复命令、单实例检查 | 只做 TCP 连接，不发 HTTP，不受影响 |
   | `ergo start / stop / status / logs / open / onboard / update …` | 只和服务管家、文件打交道，不发 HTTP；`open` 打开的浏览器照常配对 |

6. **本机程序令牌**：守护进程每次起来生成一份新的（256 位随机值），写进这一份数据目录的密钥区（`secrets/local-token`，`dataDirLayout().localTokenFile`），请求和握手带在 `x-ergo-local-token` 里。内存里只留摘要、定长比较；原值不进日志、事件、错误信息，不进守护进程的环境（子进程、agent 拿不到）；密钥区 agent 读不到（守卫拒）。只在本机端口、只在设置开着时看它；外网端口永远不认。转发给项目的服务时去掉这个头。
7. **打开时不把自己关在外面**：`PUT /api/local-pairing`。本机端口上靠端口被信任的浏览器去打开时，网关先替它配上对（`PairingService.pairDirectly`：等待首次使用的设备，凭证放进这次响应的 cookie），回 `pairedThisBrowser`、还不打开；浏览器带着凭证、`confirm` 再来一次，网关看到凭证真的带回来了才打开（存不下 cookie 的浏览器回 400、照旧关着）。以前开过一次、还带着这一份本机端口上有效凭证的浏览器直接打开，不再多配一台。已配对的设备、本机程序直接开关（本机程序不替它配对）。打开的那一刻本机端口上没凭证的 WebSocket（连同转发给服务的）断开（`WS_CLOSE_UNPAIRED`），页面重新问自己被不被信任。
8. **退路**：`ergo local-pairing off`（管哪一份照 ADR-0063 的认法：`--dir` > `ERGO_DATA_DIR` > 所在文件夹的那一份 > 默认那份；令牌、配置都读认出的那一份的）。二狗在跑时带着令牌请它关（马上生效）；连不上就直接改这一份的配置文件（下次起来是关着的）；被拒（比如没有这项设置的旧版本）也改配置，说一句要重启。命令行只能关，打开只在网页上（那里有自动配对）。守卫把 `local-pairing` 当服务管家的命令（`ERGO_OPS`）硬拒绝：agent 不能替用户关，和停二狗同一级别。

## Considered Options

- **按来源 IP、按进程认本机程序**：本机来的 TCP 对端都是 127.0.0.1；按进程认要查端口归属，Windows 上慢且不稳。不要。
- **令牌长期不变**：命令行跨重启也能用，但泄露一次一直有效。每次起来换一份，代价只是重启的那一刻正在跑的命令要重跑。
- **本机程序也走设备配对**：命令行、冒烟脚本每跑一次就多一台"设备"，设备列表被淹掉。不要。
- **健康探针也带令牌**：服务管家的探针按登记的地址发裸的 GET，没有地方带头；放行 `/healthz` 一个接口，它只说秘书和网页的状况。
- **smoke:page、截缩略图用 `extraHTTPHeaders` 发给所有请求**：页面引用的外站资源也会带上令牌。截缩略图改成按源加头；smoke:page 拦下发往别处的请求（二狗的页面本来就不请求外部地址）。
- **打开时直接打开、不确认凭证**：浏览器不让存 cookie 时，打开的人当场被关在外面，只能用命令行退回。多一来一回不贵。

## Consequences

- 开着时这台电脑上每个浏览器都要配对一次；清了 cookie、换了端口、用 `localhost` 而不是 `127.0.0.1` 打开的要重新配对。
- 本机来的配对请求共用一份限频（同一来源 10 分钟 5 个）。
- 秘书的 `web_fetch`、agent 在 bash 里 `curl` 本机端口（ADR-0026 记的那条）开着时被拒；关着时照旧。
- 体检的端口探测、服务管家的接入层都不经本机端口的 HTTP，不受影响。服务管家从外面验收隧道（`vps/verify.mjs`）只认"不带凭证时 `/api/access` 回 local"为接错了端口；开着时本机端口回 `none`（带 `local: true`）且 `/healthz` 回 200，判成"像外网端口、可中间有东西不对"、照样不算通过，不会误报成通过。
- 本机程序令牌和别的密钥一样：同一个 Windows 账户下能读密钥区文件的程序能冒充本机程序（ADR-0043 记过同样的取舍）。各份二狗的数据文件夹互相隔开靠守卫。
- 没在 Firefox 上试过 http://127.0.0.1 上的 Secure cookie；打开时的确认那一步会挡住存不下 cookie 的浏览器，不会锁人。
