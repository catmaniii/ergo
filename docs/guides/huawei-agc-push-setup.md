# 华为 AGC 推送开通指南（二狗鸿蒙客户端）

> 用途：二狗 v2 实施阶段，由用户本人手动完成。完成前，二狗只保留推送接口（见 §6），鸿蒙推送适配器处于关闭状态。
> 依据：`docs/research/07-push-harmonyos-android.md`。华为文档取的是 2026-09-29 的版本，本指南未在真机上验证；带【未核实】的条目需要在操作时留意。
> 最后更新：2026-10-07

## 1. 为什么需要它

- 鸿蒙上的第三方 App 退到后台后很快会被冻结，**没有合规的方式让 App 一直挂着连接等消息**。
- App 不在运行时，想让手机弹出通知，唯一的路是华为的系统推送 **Push Kit**（相当于 iPhone 的 APNs）。
- AGC（AppGallery Connect）是华为的开发者后台：开通推送、拿密钥、申请通知分类都在这里。

消息的走向：

```
二狗守护进程 ──(JWT 鉴权的 REST 调用)──> 华为推送服务器 ──> 手机系统通知
                                                              │ 用户点击
                                                              ▼
                                         二狗鸿蒙 App（ArkWeb 外壳）→ 打开对应的审批 / 任务页面
```

## 2. 先知道这些（限制与代价）

| 事项 | 事实 |
|---|---|
| 费用 | 免费 |
| 上架 | **不需要**。调试签名的 App 装在自己手机上就能收推送 |
| 证书期限 | 实名开发者的调试证书有效期 **1 年**，未实名只有 **14 天**。过期后 App 无法启动，**每年要续签一次** |
| 通知分类（最关键） | 没有"自分类权益"时，所有推送都被当作**营销消息**：静默（不响铃、不亮屏、不弹横幅），只进"更多通知"，**每台设备每天 2 条**。所以要申请 `WORK` 分类 |
| 横幅 | 即使 `WORK` 批下来，**横幅通知默认关闭**，需要你手动去设置里打开 |
| 按钮 | Push 通知**没有按钮**。审批必须点开 App，再用生物识别确认 |
| 夜间 | 系统会预测你的睡眠时间，睡着期间的通知先压着，醒后再送 |
| 实况窗 | 正式权限要求应用已上架、月活 ≥1000，**基本用不上** |
| 区域 | 手机推送只支持中国境内，数据处理位置必须选中国 |
| 消息大小 | 不含 Token，最大 4096 字节。载荷里只放不透明的 ID，不放任何内容秘密 |

## 3. 操作步骤

### 步骤 1：确认开发者账号已实名

- 登录[华为开发者联盟](https://developer.huawei.com/consumer/cn/)，检查账号是否完成实名认证。做 AgentSense 时应该已有账号。
- 不实名的话，调试证书只有 14 天有效期，不可行。

### 步骤 2：在 AGC 创建项目和应用，开通推送

1. 进入 [AppGallery Connect](https://developer.huawei.com/consumer/cn/service/josp/agc/index.html)，新建**项目**，再在项目下新建 **HarmonyOS 应用**。
   - 应用的包名（bundleName）要和二狗鸿蒙外壳工程的 `app.json5` 一致。外壳还没建的话，先定一个，例如 `com.<你的标识>.ergou`，之后外壳照这个写。
2. 进入"**增长 > 推送服务**"，点击"**立即开通**"。推送权益是**项目级**的。
3. **数据处理位置**选**中国**。
4. 在"项目设置"里记下 **`projectId`**（发送接口要用），以及 **`clientId`**（撤回接口要用）。

### 步骤 3：配置调试签名（二选一）

- **方式 A：自动签名（推荐）**
  - 需要 DevEco Studio 6.0.0 Beta5 及以上。
  - 在 DevEco 的签名配置里勾选 **Associate with registered application**（关联注册应用），然后勾选 Push Kit。
  - 注意：Push Kit 开放能力**接入后不可取消**。
- **方式 B：手动签名**
  1. 申请调试证书。
  2. 在 AGC 注册你的手机。
  3. **开通推送之后，重新**申请调试 Profile。之前的 Profile 不含推送权益。

- **只有关联了 AGC 应用的签名才能拿到 Push Token**。未关联的自动签名大概率拿不到【推断，未实测】。
- 拿 Token 时报 `1000900010`（App 身份验证失败），一般就是签名或权益配置的问题。

### 步骤 4：创建服务账号密钥

1. 进入 [API Console](https://developer.huawei.com/consumer/cn/console/api/myApi)，为该项目创建"**服务账号密钥**"，下载 JSON 文件。
   - 文件里有 `project_id`、`key_id`、`private_key`、`sub_account`、`token_uri` 等字段。
2. **私钥华为不保存**，丢了只能重建，下载后自行妥善保管。
3. 这个 JSON 放进二狗**个人数据目录**的 secrets 子目录（具体路径以「部署、数据目录与备份」票的结论为准），**绝不能进代码仓库**。

### 步骤 5：申请 `WORK` 通知分类（自分类权益）

1. AGC：**增长 > 推送服务 > 配置**，选中应用，点自分类权益后面的"**申请**"。
2. 消息类型选 **`WORK`（工作事项提醒）**。官方说明是"用户下一步需要做某件事项的提醒、待处理的业务流程"，例子有待办提醒、审核进度提醒、工单处理。
3. 消息示例按真实场景写，例如：
   - "任务'整理发票'有 1 项操作等待你确认，点击查看"
   - "二狗有一个问题需要你回答：周五的出行你更看重时间还是价格？"
   - "长程任务'整理相册'已完成，共处理 1,204 张照片"
4. （可选）同时申请 **`ACCOUNT`（账号动态）**，用于安全事件，如新设备注册、设备密钥变更。
5. **审核约 3 个工作日**，通过后 5 分钟生效。
6. 注意：
   - **不要选 `IM`**。它要求是"用户间点对点聊天"，agent 发给你的消息有被判误分类违规的风险。
   - 未上架的个人应用能否批下 `WORK`，官方没有写明【未核实】。被拒的话，把拒绝理由记下来，留给「推送与远程审批通道」决定兜底方案。

### 步骤 6：手机上的设置

1. 首次打开二狗 App 时，**允许通知**。App 的通知开关默认是关的。
2. 进入"**设置 > 通知和状态栏 > 二狗**"：
   - 手动打开**横幅通知**；
   - 确认铃声、振动、锁屏显示的设置。
3. 手机所在网络要放通 5223 和 443 端口（家用网络一般默认放通）。

### 步骤 7（可选）

- **消息回执**：在 AGC 配置回执 URL，放在 VPS 上，要求 HTTPS 并且是商用 CA 证书。Let's Encrypt 是否算商用 CA【未核实】。用于确认消息是否送达。
- **实况窗**：申请"实况窗服务权益"，再按 Push Token 把自己的手机加进"实况窗-调测设备管理"。能否获批、能否长期使用【未核实】，暂不建议花时间。

## 4. 验证推送链路

前 4 步完成后，即使 `WORK` 还在审核，也可以先用**测试消息**调通链路：

- 请求里带 `pushOptions.testMessage: true`。每个项目每天 1000 条，不受"每天 2 条"的限制。
- 注意：测试消息**只解决条数，不解决静默**。分类没批下来之前，通知照样是静默的。
- 发送接口：`POST https://push-api.cloud.huawei.com/v3/{projectId}/messages:send`
  - 请求头：`Authorization: Bearer <JWT>`、`push-type: 0`。
  - JWT 用服务账号私钥按 PS256 签名，不需要换 access token。
  - 示例代码见 `docs/research/07-push-harmonyos-android.md` §1.4。
- 成功的返回是 `{"code":"80000000","msg":"Success"}`。401 表示鉴权失败，503 表示流控。

## 5. 维护日历

| 时间 | 事项 |
|---|---|
| 每年（调试证书到期前） | 续签调试证书和 Profile，重新安装 App |
| 换手机或重装 App 后 | Push Token 会变。二狗会在 App 启动时自动重新上报，确认一下"设备管理"里的新设备 |
| 重建服务账号密钥后 | 替换个人数据目录里的 JSON，重启二狗守护进程（经 LSM） |

## 6. 二狗这一侧留好的接口（实施前的约定）

> 草案。最终形态以「推送与远程审批通道」「移动端外壳」两张票的结论为准。

**守护进程配置**（放在个人数据目录，不进仓库）：

```yaml
push:
  harmony:
    enabled: false                 # 完成本指南前保持 false，适配器不加载
    projectId: ""                  # 步骤 2
    clientId: ""                   # 步骤 2，撤回接口用
    serviceAccountKey: secrets/huawei-push-service-account.json   # 步骤 4，相对个人数据目录
    category: WORK                 # 步骤 5 获批的分类；未获批时消息会被当成 MARKETING
    testMessage: true              # 分类获批前用 true
```

**守护进程内部**：
- 业务层只产生"通知意图"（待审批、澄清问题、任务完成或失败、安全事件……）。
- 由通知服务分发给各渠道适配器：`HarmonyPushProvider`、`WebPushProvider`、`NtfyProvider`，以及远期的 `TelegramProvider`。
- `harmony.enabled=false` 时，鸿蒙渠道直接跳过，其他渠道不受影响。

**鸿蒙外壳**：
- 启动时调用 `pushService.getToken()`，把 Token 上报给守护进程，完成设备注册。
- 点击通知后，根据通知里的 `route`（如 `/approvals/<id>`）打开 Web UI 中对应的页面。
- 审批要先经过生物识别。

## 7. 完成后请记录

完成后在 `.scratch/ergou-v2/` 的「推送与远程审批通道」票里补一条，记下：
- `WORK`（以及 `ACCOUNT`）是否获批、审核用了几天、被拒的话理由是什么；
- `projectId` 和 `clientId` 已经填进配置（不要把值本身写进票里）；
- 测试消息是否送达、有没有声音和横幅；
- 调试证书的到期日。
