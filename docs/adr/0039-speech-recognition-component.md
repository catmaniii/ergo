# ADR-0039 语音识别能从组件页装：audio.cpp 加 Fun-ASR Nano，按严的许可处理；已配的不动，录音转成 WAV

状态：已定（用户 2026-10-31 定方向；346 号票）

## 背景

- 语音识别一直要用户自己装 Python 和 faster-whisper，组件清单里卡在 `pending: python`。用户定：要可安装，模型可以安装后在网页里下载。
- 语音合成（ADR-0038）已经有了一键装的 audio.cpp。它的服务也有 `POST /v1/audio/transcriptions`。用同一个程序的话，语音只需要一个服务，也不用打包 Python。
- 拿 22 句合成配音（小满 5 句、年轻男声 12 句、别的声音 5 句，一共 417 字）比过。程序是本机 8 月版的 audio.cpp，不是 v0.9.3：

  | | 字错误率 | 一句话（中位） | 冷启动 |
  |---|---|---|---|
  | Fun-ASR Nano q8，显卡 | 2.64% | 0.12 秒 | 5.2 秒 |
  | faster-whisper large-v3，显卡 | 2.64% | 0.40 秒 | 9.0 秒 |
  | Fun-ASR Nano q8，CPU（其中 8 句） | 1.20% | 1.23 秒 | 2.5 秒（磁盘缓存热的） |
  | faster-whisper small，CPU（同样 8 句 5.99%，22 句 6.71%） | 5.99% | 1.32 秒 | 4.2 秒 |

  都是干净的合成配音，绝对值不代表真人录音；两边用同一批音频，比较有意义。显存约 2 GB，和 large-v3 差不多。
- 许可有矛盾：源模型标 Apache-2.0，GGUF 仓库写 FunASR Model Open Source License Agreement v1.1。下面是读 v1.1 原文的理解，不是法律意见：
  - 可以自由使用、复制、修改、分享（§2.1）；使用、分享时都要注明来源和作者、保留模型名称（§2.2）；
  - 没有单独的商业条款，既没禁止也没要求另签授权；但 §3 写着"仅作为参考和学习使用"（在免责一节，可以读成只是免责，也可能被读成用途限制）；
  - 对模型无端诋毁、恶意抹黑自动失去许可（§4.2）；违反任何一条自动终止（§5）；修订发在官方仓库、继续用算同意（§6）；管辖法律还是没填的占位符（§7）。
- audio.cpp 的这个接口**只收 WAV**（文件名不是 `.wav` 回 400，内容不是 WAV 回 500；v0.9.3 也一样，可选模块只多收 MP3 和 FLAC）。浏览器录的是 webm、ogg、mp4，只有鸿蒙 App 录的是 WAV。faster-whisper 自己解码，以前没碰到过。

## 决定

1. **新增第三种接入 `voice.recognizer.mode: "audiocpp"`，`spawn`、`lsm` 两条保留。** 实现同一个 `Recognizer` 接口，服务地址就是 `voice.speech.url`，模型 id 固定 `asr`。状态机、超时语义、串词过滤和调 LSM 那条共用（`createServiceRecognizer`），接口差别在 `ServiceProtocol` 后面。
2. **默认的接入方式不变，还是 `spawn`。** 只有用户在组件页装了语音识别模型、服务接上了，才把配置里的 `mode` 写成 `audiocpp`，语音插件当场换、不用重启；删掉模型时撤掉这一项。组件默认也还是"问了再装"。组件页里能装的语音识别换成了这一个（`asr` 组件不再是 faster-whisper）。
3. **已配的不动。** 下面任何一条成立就算"已有自己配的语音识别"：`mode` 是 `lsm`；手写了 `audiocpp`；配置写了 Python 的路径而且文件在；默认的 `python` 在 PATH 上而且真的装了 faster-whisper（只找包、不加载，问一次记住）。这时组件显示"已有自己配的语音识别，在用它"，不能从这里装，接口也拒绝，配置文件一个字节都不碰。**光是 PATH 上有个 Python 不算**：不然大多数 Windows 电脑都装不了（商店的占位程序也算 Python）。8090 上已有手动配的 audio.cpp 时同样不覆盖，写明可以在它上面自己加一个 id 为 `asr` 的模型、再手写 `mode: "audiocpp"`。
4. **许可按严的（v1.1）处理，也走确认框。** 虽然没有 Fish 那样的商业限制，但 §3、§4.2 这些不是常规开源条款，确认一下的成本很小。不打包、不做镜像，点下载时从上游拉（`FunAudioLLM/Fun-ASR-Nano-2512-GGUF`，钉到提交；hf-mirror 是公共代理，内容按 sha256 核对）。§2.2 要求使用时也要标来源，组件页这一行显示 `Fun-ASR-Nano-2512 · FunAudioLLM / Alibaba Group`。
5. **录音转成 WAV，两层：**
   - 网页：守护进程经 `VoiceModelsView.recognizerInput: "wav"` 说只认 WAV，浏览器录完先解码、转成 16 kHz 单声道 WAV 再传（`OfflineAudioContext`，不加依赖）。别的接入照旧传浏览器录的格式，不改用户现在的录音。按住说话、Debug 页、悬浮按钮都走同一个录音器，都带上。转不了照原样传，录音不丢。
   - 守护进程：收到不是 WAV 的（走 audio.cpp 之前录的旧语音重新识别、老版本页面）用本机的 ffmpeg 转（参考音色导入已经在用）。没有 ffmpeg 就这一条失败、写明原因，服务还算好的。**这是唯一还会碰到 ffmpeg 的地方，不打包它。**
6. **模型不支持的就不传：** 给模型的提示（`initialPrompt`）不传；语言只认 `auto`、`zh`、`en`、`ja`，`zh-CN` 算 `zh`，别的不传、让它自己判断（传了回 500）。没有时间戳，整段算一个分段。
7. **预热发一小段静音。** 服务没有"模型加载了没有"的接口，只能让它顺势加载，结果扔掉（静音会幻听出个字，所以结果不能用）。服务被服务管家重启过的话模型要重新加载，从外面看不出来，所以一次识别的超时总是留着冷启动的时间。

## Considered Options

- **打包 Python 和 faster-whisper**：几百 MB 到几 GB，还要处理 CUDA 版本；验证下来 Fun-ASR Nano 不差，不值得。票里明确不做。
- **默认就改成 Fun-ASR Nano、已有的自动迁过去**：用户自己的机器就配着 `lsm`，用了很久，换引擎的风险不该由自动迁移来背；而且这个结论是合成配音测出来的，没有真人录音的数据。不改。
- **所有浏览器录音都先转 WAV**：不用看接入方式，简单；但会改用 faster-whisper 的人现在存的录音格式和上传大小（webm 约 4–16 KB/秒，WAV 32 KB/秒）。只在需要时转。
- **把 ffmpeg 也做成组件，或者打包一个解码器**：可以彻底不靠本机的 ffmpeg，但多一个下载和依赖，而现在只有旧录音、老页面会走到这里。留给主会话决定，先不做。
- **语音识别单独起一个 audio.cpp 服务**：两个服务抢显卡、多占端口，用户也多管一个；同一个服务按模型排队就够了（各模型的锁是分开的）。

## Consequences

- 没有 ffmpeg 的新机器上：网页和鸿蒙 App 新录的语音能识别；**走 audio.cpp 之前录的、浏览器转不了的**（极少见）识别不了，写明原因。
- 组件页取清单时，默认的 `python` 第一次要真跑一下它（最多 5 秒，平时不到 1 秒），之后记住。
- 语音识别和语音合成共用一个服务：装、删任何一个模型都会重启服务，正在用另一个的那一下会失败，语音消息按 208 号票自动重试。
- 显存：语音合成约 7.3 GB 加识别约 2 GB；`lazy_load` 不卸载，显存小的卡可能放不下两个，加载失败时在组件页和设置 · 语音写明。
- 程序和模型的实际表现是用本机 8 月版的 audio.cpp 验的，接口对照过 v0.9.3 的文档和代码，没有跑过 v0.9.3 的真包。真实验证由用户在另一台机器上装一次。
- 真人录音（噪声、口音）的效果没有数据，用的时候才知道；不满意的话 `spawn`、`lsm` 两条都还在。
