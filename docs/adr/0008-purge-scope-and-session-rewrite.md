# 彻底删除改写哪些东西、怎么改：消息整条换成标记，别的只换带原话的字段；会话文件在子进程那一层改；删除本身记成事件

规格第 15 节要求"彻底删除"连会话原文一起删，事件日志不可修改的唯一例外只开给它；ADR-0006 定了"已删除"标记的格式，并要求忘掉、别推断先记一条事件再动素材。21 号票做删除时发现，用户的一句话在系统里不止原始消息事件一份：07 号票的守卫接入把每次工具调用的参数摘要和结果摘要写进聊天（会话频道上的工具调用记录）和效果日志（`guard` 频道），秘书检索素材的结果里有素材的摘录，提议"记住"的参数和结果里有要记住的话，用户拒绝审批时写的说明也进了工具调用记录的结果摘要；秘书子进程的 pi 会话文件里也有原话，pi 压缩上下文时还会把原话写进摘要；附件在媒体库里另有一份。评审后定成：

- **删除记成事件**：每条记忆命令（记住、忘掉、彻底删除、别推断；聊天里的和设置里批量的都算）是守护进程内部 `materials` 频道上的一条 `memory_command`（按命令种类分两种形状：记住带内容和来源，删除类带素材 id 和出处）。素材模块把它当采集规则处理：产生"显式记忆命令"素材，并删掉（或标记）已有的素材；`memory.db` 里另记墓碑（`material_marks`），重放、补采、从原文副本补回时跳过。删除类命令的事件本身永不改写：它只有素材 id，是"这些被删了"的记录，改写了重建时素材会回来。
- **不改坏状态**：只有消息事件（用户的消息）整条换成"已删除"标记；别的事件按事件类型字段级改写——只把带原话的文本字段（说明、参数里的原话、结果摘录）换成删除标记文字 `PURGED_TEXT`，id、状态、决定这些结构字段原样保留。改写函数按事件类型登记成一张表（`memory/rewriters.ts`），由拥有这类事件的模块写：消息（工具调用记录只换参数摘要和结果摘要）、卡片（负载按卡片类型登记的 `purge`，用户在卡上写的说明）、卡片被关闭和长期没处理、"记住"的命令、审批决定、效果日志、操作记录。**没登记改写函数的事件类型彻底删除时整个被拒**。改写后派生视图整体重放：审批表重放出来仍是已批准或已拒绝，卡片仍是已处理，效果日志的条数和先后不变。
- **改写的范围**（`memory/purge.ts`）：素材的原始事件；"记住"来的素材连同它的记忆命令、操作记录、快速动作卡的每个版本、提议它的那次工具调用的记录（按卡上记的工具调用 id 找）和紧跟着的效果日志；素材卡片上用户写的说明；审批决定那次工具调用的记录（会话文件里那次调用的结果也改，模型收到的是"用户拒绝了这次调用：<说明>"），挂起之后才拒绝时递给 agent 的那条通知；检索素材那次调用的记录（按素材 id 找）和紧跟着的效果日志、提到素材 id 的效果日志；列出过这些素材的卡片（记忆删除卡的摘录）。改写在同一个事务里（`EventStore.appendBatch(events, { purge })`），会话里被改写的消息另追加 `messages_purged`（整条删掉的只给消息 id，字段级改写的给出改写后的样子），改写过的卡片追加一个改写后的新版本，开着的页面据此换掉手里的东西。**派生视图从不收到"已删除"标记**，各视图不用认它。
- **SQLite 不留残余**：`ergou.db` 和 `memory.db` 的写连接开 `secure_delete`，彻底删除后各做一次 `wal_checkpoint(TRUNCATE)`。
- **媒体文件**：被删的消息引用过的附件，没有别的（未删的）消息、也没有素材还引用同一个哈希，就删掉媒体文件（连同派生文件）。由 `messages_purged` 驱动，启动时再对一遍。
- **会话文件在子进程那一层改**（和 ADR-0004 的关系）：会话文件是 pi 的格式，按 ADR-0004 pi 的形状只出现在 `agent-child/` 里，所以改写逻辑放在 `agent-child/session-rewrite.ts`，用 pi 的类型做类型检查；守护进程以一次性子进程（`agent-child/rewrite-main.ts`，经 agent 管家的 `rewriteSessions`，进 Job 对象、只给显式的环境）的方式调用它，宿主协议里只多了二狗自己的请求和结果形状（`SessionRewriteRequest` / `SessionRewriteResult`）。改写范围：带输入标记（`ergou-input` 自定义条目）的用户消息；提议"记住"和审批决定那几次工具调用的参数和工具结果；素材检索结果里提到被删素材的行；被改的条目落在某次压缩覆盖的范围里（在它保留的第一条之前）时，那段压缩摘要整段换成"（这段摘要含已彻底删除的内容，已移除）"，在被改条目之后的分支摘要也一样。改写哪些由记忆模块从 `messages_purged` 生成；秘书只负责停、改、拉起：子进程内存里还有原文，所以等手头这一条处理完，停掉子进程、改写（保留文件的修改时间）、接着同一个会话重新拉起。agent 子进程还活着时管家拒绝改写；没在跑的 agent（以后的维护者）可以直接改，不用等下次唤起。守护进程启动时把以前的 `messages_purged` 再对一遍。会话文件的格式由契约测试守着（`session-rewrite.contract.test.ts`）。

## Consequences

- **删不掉的，如实告诉用户**（设置页和记忆删除卡上都写，`PURGE_LIMITS`）：秘书回复里转述过的话（它自己的正文，以及检索时写的查询词）；秘书看任务看板时看到过的等我原因（22 号票的看板变化消息进了秘书的会话文件、查看板的结果进了工具调用记录，都带着任务等我的说明；23 号票的"中断：不确定 X 是否已执行"带着调用摘要，任务事件里的这段说明会改写，这两处不改）；备份快照里仍有一份，随快照轮换消失（本机约 7 天，同步目录最长约 5 周）。另外：审批卡和审批请求里 agent 要做的那次调用的参数摘要不改（那是 agent 的请求，不是用户的话）；本票之前的会话文件里没有输入标记的消息找不到。要删干净秘书的转述，得让秘书的每条输出都能追溯到它引用的素材，第一阶段不做。
- **以后的票接入新的素材来源，要给它的事件类型登记改写函数**，负载里会有用户原话的卡片类型要写 `purge`；否则彻底删除到它时整个被拒。80 号票给 12、14、58 号票漏登记的计划的决定、提问卡的回答、授权续期的决定补上：只换打回或拒绝时写的话、每题的答案（提问卡上记的答案一起），连带交给 agent 的那条通知（同审批的"挂起之后才拒绝时递给 agent 的那条通知"）；续期的决定没有用户写的话，原样登记；确认计划时在卡上改的假设栏、加的关注类别已是确认的计划的一部分（维护者照它做、守卫照它判），不改写，写进 `PURGE_LIMITS`。
- **会话文件的改写依赖 pi 的会话格式**：JSONL、`custom` 条目、`message` 条目里 `role` 为 `user` / `assistant`（工具调用块）/ `toolResult`、`compaction` 和 `branch_summary` 条目、`continueSession` 按修改时间挑最近的文件。升级 pi 时契约测试会发现格式变了。
- **新的事件类型和条目永久留在个人数据里**：`memory_command`、`messages_purged`、`quick_action_executed` 和会话文件里的 `ergou-input` 条目，以后改形状要兼容旧的。

## Considered Options

- **原始事件以外的记录也整条换成标记**（21 号票第一版）：简单，但审批决定、卡片的旧版本换成标记后，派生视图重放时状态丢了（审批又变回待处理），等于改坏了状态。
- **只改写原始消息事件**：最小，但 07 号票之后同一句话还在工具调用记录、效果日志、卡片和会话文件的摘要里，前端和备份里都看得到，算不上"彻底"。
- **按原话的文字全局搜索替换**：能覆盖秘书转述的话，但会误伤（同样的字出现在别处）、也找不全（转述往往不是原样），而且要在事件负载内部按文字改，不知道改的是不是结构字段。
- **会话文件在守护进程里按 JSON 形状改**（21 号票第一版）：不引用 pi 也能改，但 pi 的形状就漏到了 `agent-child/` 之外，pi 改格式时类型检查发现不了，违反 ADR-0004。
- **不停子进程，只改会话文件**：子进程内存里还有原文，下一轮照样交给模型，等于没删。
- **删除命令不记事件，直接删 `memory.db` 和原文副本**：重建时素材从事件日志或原文副本回来，违反 ADR-0006。
