# 项目维护者的会话分段：每段一个 pi 会话，由事件日志记着、拉起时按名字明确指定；写回靠进展文档的内容哈希和摘要检查

规格第 11 节：项目维护者的会话分段，每段是一个新的 pi 会话，从固定上下文（工具包说明、项目规范、项目档案快照、上一段的摘要、这次的工单）重新开始，更早的分段不进上下文；每张工单一段，维护者手上没有工单时用户直接说话开一个对话段；每段结束时维护者把新的理解写回项目档案、写这一段的摘要，没写回就催，这段不算完成、工单不结束；用户可以重置维护者，新开一段、旧会话保留可查。15 号票之前，agent 子进程总是接着会话目录里"修改时间最近的那个"会话（`continueSession`）。16 号票定成：

- **段是事件日志里的状态**：维护者会话频道上的 `segment` 事件（`MaintainerSegment`：段号 `<维护者>-sN`、种类、所属工单和任务、会话的名字、是不是重置开的、状态 `open` / `closing` / `closed`、开段时进展文档的内容哈希、摘要、工单要以什么结局结束、没写回就结束的原因），派生视图 `maintainer_segments`。哪一段是当前段、下一段的"上一段摘要"是哪段的，都从这里查，不看会话文件。
- **每段一个会话，按名字明确指定**：宿主协议 8 的装配参数 `session`（会话的名字），子进程有这个名字的会话就打开它接着、没有就用这个名字新开；`ready` 报回这次打开的会话的名字。会话文件放在哪、叫什么、长什么样只有子进程那一层认（ADR-0004），守护进程只说名字。新段的名字就是段号。第一段对话段要接着这个维护者以前的会话（任务转为项目、16 号票之前就有的项目）：这一段带 `continueEarlier`，拉起时同时给 `continueSession`——这个名字还没有会话时，子进程接着目录里最近的那个，报回它的名字，项目维护者模块记进这一段（`segment` 事件的 `session` 变化），之后拉起都按它打开。这是唯一还按"最近修改"挑会话的地方，而且挑的是子进程。重置维护者只是新开一段（`reset: true`，不接以前的），旧会话原样留着。
- **换段 = 重新拉起**：子进程按哪一段、项目的什么样子拉起的记在项目维护者模块里；交下一条输入之前发现过时了（`AgentSession` 的 `outdated`），就停掉、按新的一段重新拉起。固定上下文拼在系统提示后面，每次拉起现算（读项目档案）。
- **写回检查是机械的**：段该结束时（工单的活做完了、对话段闲置退出或有工单在等）转收尾中，`progress.md` 的内容哈希和开段时一样、或者没写摘要（`write_segment_summary`），就往会话里放一条催促的通知。两样都有了段才结束，工单随之结束，下一张工单才开始。收尾中的段仍占着维护者。起草计划的工单段只读，进展经 `write_progress` 写回（整份换掉，旧版本留进历史区）。
- **催到了次数转为用户拍板**（2026-10-08 用户定，规格第 12 节）：催写回最多催第 8 节的催促阈值那么多次（默认 3），还没写回就在待我处理里放一条"卡住求助"，这一段以"催了还没写回档案"结束，工单照常结束并标出来，时间线上记一笔，项目的队列接着走。
- **写回中途重置照常算完成**（2026-10-08 用户定）：段在收尾中时用户重置维护者，这张工单照常以原来的结局结束，标"重置时这段没写回档案"（工单上、时间线上）。

## Consequences

- 一个维护者的会话目录里有很多个会话；彻底删除（ADR-0008）改写的是目录里的全部会话文件，删除项目（ADR-0010）删整个目录，都不用改。
- 段的事件在维护者会话频道上：删除项目时随整条会话换成"已删除"标记，不用另登记改写函数；前端不用它，分隔线是会话里的工单分隔 part。
- "写回了"只看进展文档变没变、摘要有没有，不判断写得好不好；维护者乱改一个字也算写回。规格要的是"没写回就催"，判断质量留给以后的范围审视（18 号票，在写回检查之后、段结束之前加）。
- 催不动、或者写回中途被重置的段，理解可能没留在项目档案里：下一段只能从档案和上一段的摘要重建。这时如实标出来（工单、段、时间线），由用户决定要不要让维护者补写进展或再重置一次；运行时不替它写。
- 工单段收尾时它的任务已经离开了执行中（计划交了是待确认，执行的已经结束），任务状态机不许从这些状态转等我，所以"卡住求助"不改任务的状态，只放进待我处理。
- 以后换掉 pi 时，新的运行时也要支持"按名字打开或新开一个会话，没有时可以接着最近的那个，并报回名字"。

## Considered Options

- **段记在会话文件里（比如 pi 的分支、会话里的标记条目）**：一个文件里拼多段，模型上下文要靠截断才能"更早的分段不进上下文"，压缩时还可能把上一段的内容带进摘要；查当前段要读会话文件，绕过了"会话文件的形状只在子进程那一层认"（ADR-0004）。
- **守护进程自己挑会话文件、把文件名交给子进程**（16 号票最初的做法）：守护进程要知道会话文件放在哪、扩展名是什么，违反 ADR-0004；改成守护进程只给名字、要不要接以前的，挑哪个由子进程定、报回名字。
- **接着"修改时间最近的那个"**：重置维护者、对话段和工单段交替之后，最近修改的不一定是当前段（彻底删除改写会话文件时保留修改时间，但别的工具碰一下就变）；15 号票交接时已经点名不能再这样。
- **按摘要和进展的内容由模型判断写得够不够**：多一次模型调用，结果还不稳定；规格只要求检查有没有写回。
- **催不动就一直卡着这个维护者，等用户介入**（16 号票最初的做法）：项目的队列会因为一段没写回而一直停着；评审后用户定成转为用户拍板（卡住求助）、这一段如实标着结束、队列接着走。
