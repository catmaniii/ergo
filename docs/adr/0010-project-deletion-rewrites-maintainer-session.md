# 删除项目：二次确认放在待我处理；先停维护者、复查、再改写事件、最后删文件；属于项目的原话都改写，素材留着

规格第 11 节：删除只能从已归档发起，要二次确认；删除时删掉项目档案和维护者会话，但用户在里面说过的话作为素材保留（用户故事 93、131）。第 15 节：事件日志不可修改，例外只有两个——彻底删除（改写成删除标记，ADR-0008），和删除项目时改写该项目维护者会话及立项书的原话（结构字段和状态保留，用户说过的话照样作为素材保留；规格在 15 号票评审后补上了第二个）。维护者会话在二狗里有两份：pi 的会话文件（会话区 `sessions/<维护者>`）和事件日志里的会话频道 `maintainer:<维护者>`（消息、回合、工具调用记录）。项目的原话还散在别处：立项书（`charters` 频道的事件和立项书卡）、这个维护者的审批（审批请求、审批卡、审批决定）和效果日志、待我处理里属于项目的事项。15 号票评审后定成：

- **二次确认是待我处理里的一条通知**：项目页上的"删除"（`project_action` 的 `delete`）只在已归档时可用，不马上删，往待我处理放一条 `project_delete` 通知（"确认删除" / "不删了"，带项目编号），同一个项目已有没处理的就用它。
- **顺序**（`projects/deletion.ts`）：
  1. 先停维护者：马上不再接输入、之后来的输入也不唤起它，等子进程退出（内存里的原文随之没了）；
  2. 复查：停下来的这段时间里用户取消了归档（或者项目已经不在了）就整个中止，什么都不删，维护者恢复成能唤起；
  3. 没变就在同一个事务里追加项目的 `deleted`、改写属于项目的事件（见下）；
  4. 最后删项目档案目录和会话区里维护者的会话文件（pi 的会话文件整个删掉，不逐条改写）。到这一步项目已经删了，不再回头。
- **改写，不删行**：和彻底删除走同一个口子（`EventStore.appendBatch(events, { purge })`），事件日志的行、频道、序号、类型、时间都在，只换负载（规格第 15 节的第二个例外，机制和第一个一样）；派生视图整体重放，提交后 `wal_checkpoint(TRUNCATE)`，连接开着 `secure_delete`，原文不留在 WAL 和空闲页里。
  - 维护者会话频道上的事件整条换成 `DeletedEventPayload`（消息留下 id 和时间）；
  - 立项书正文、维护者的审批和效果日志、待我处理里属于项目的事项：用记忆模块的改写函数表（`memory/rewriters.ts`）按事件类型字段级改写，原话换成删除标记，状态不变（立项书卡还是已处理、审批还是已批准、二次确认还是"确认删除"）。为此登记了 `charter_submitted`、`approval_requested`、`inbox_item` 的改写函数，`charter_decided` 的改写函数和立项书卡、审批卡的 `purge` 连立项书正文、参数摘要一起换掉；
  - 改写过的卡片追加一个改写后的新版本（开着的页面据此换掉手里的卡）。
- **素材不删**：用户在维护者会话里说过的话在素材库里，本人的原文另有一份不可修改的副本（ADR-0006）。删项目不追加 `messages_purged`、不写墓碑，素材模块不把它当"忘掉"；以后从事件日志重建素材时这些话从原文副本补回。外部工作目录（绑定的外部路径）不动。

## Consequences

- 删掉的项目的维护者会话频道上永远留着一串"已删除"标记（只有序号、时间、消息 id）。前端靠项目列表频道上的 `deleted` 把项目和它的会话从界面上拿掉；有人再订阅这个频道，只拿到标记。
- 项目列表频道上的项目事件（名字、一句话目标）不改写：它们是项目列表的历史，不是会话里的原话。
- 任务转为项目的，维护者会话里转之前的任务对话也一起删掉（是同一个会话）。原任务的看板事件不动；首个建设任务的说明不写立项书正文（只说"见项目档案里的立项书"），所以看板上没有立项书正文。
- 待我处理事项的改写没有追加新版本（事项的更新只能改标题这类状态，正文改不了）：开着的页面要重新同步才看到删除标记。
- 备份快照里仍有删除前的一份，随快照轮换消失（同 ADR-0008）。
- 以后在维护者会话频道上加新的事件类型，不用为删项目登记改写函数（整条换成标记）；属于项目的别的事件类型（以后的工单、定时作业……）要登记改写函数并加进 `deletion.ts` 的范围，否则删除时整个被拒。

## Considered Options

- **删掉整个频道的行**（15 号票第一版，`appendBatch` 加 `dropChannels`）：最干净，但删行是比改写更重的一种口子（事件日志里连"这里曾经有过什么"都没了），彻底删除也不这么做；频道序号从 1 重来，带着旧序号的前端要重新同步。
- **只删会话文件和项目档案，事件留着**：不碰事件日志，但用户在维护者会话里的原话、立项书正文还在 `ergou.db` 里，前端订阅得到，算不上"删掉"。
- **先删文件、再改写事件**（15 号票第一版的顺序）：中途出错会留下"项目档案没了、项目还在"的半截状态；改写事件之后再删文件，最坏是"项目删了、档案目录还留着"（不再有东西用到它，日志里有记录，可以手动清）。
- **在项目页上弹窗确认**：原型这么画的；但规格把要用户拍板的事都放进待我处理，弹窗关了就没了，也留不下"谁在什么时候确认删的"。
