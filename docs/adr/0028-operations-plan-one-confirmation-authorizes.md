# 运营方案：维护者起草、用户确认一次就授权，项目里重复的定时、事件触发的任务不再只能由用户在对话框里建

2026-10-17 用户报："AI 简报站"项目做完后没法自动转运营——维护者和秘书都没有建重复的定时任务的工具，维护者只好写一份《运营-定时任务建议.md》让用户照着点三步、粘两段提示词，日报因此晚了 15 小时；用户在维护者对话里问"你能不能创建一下定时任务？"，回答是建不了。原来的规矩（ADR-0025 之后的代码里）：**重复的定时、事件触发的任务只有用户在"发起任务"对话框里能建**，秘书和维护者只能建"某个时间做一次"的。

用户定："以后项目做完之后只要我确认一下就可以自动转运营，运营模式不限"；之前还说过"最好立项的时候就规定好项目做完的运营模式，一次性授权"。

## 决定

- **运营方案**：项目转入使用后怎么运转，由项目的维护者起草（`propose_operations`，一次交完整的一份），用户在卡上**确认一次就全部生效**。确认就是授权，之后照方案跑，不再逐项问。
  - 建设期间交的出现在"首版做完了"卡上，主按钮"确认并转入使用"：项目进入使用中、方案里每一条生效、项目上记下现在生效的那一份，同一事务做完；
  - 使用中（或已停用）的项目交新的一份：运行时和现在生效的比出差异，出"运营方案变更"卡，确认后照差异生效（加上的建、只改了重复的时间表的就地改、别的改动撤了重建、去掉的取消、照旧却没跑着的重新开起来），拒绝什么都不动。
- **这条规矩改了**：项目里重复的定时、事件触发的任务，除了用户在对话框里建，还能随运营方案建——维护者起草、用户确认后建成**这个项目的内部任务**（ADR-0023 的规矩不变：执行者是项目的维护者，只在这个项目里看得到）。不属于项目的重复任务照旧只有用户在对话框里建；秘书收到给项目开定时、改运营的要求，转给项目的维护者（现有的秘书 → 维护者通道 `tell_project`），由维护者出卡，不再回"建不了"。
- **运营手段登记表（"运营模式不限"靠它落实）**：方案里每一条用一种手段，每种登记校验、给人看的说法、生效、撤销、就地改、暂停和恢复。照 ADR-0027，内核的由组合根注册，插件经插件宿主的 `ctx.operationMeans` 注册、停用时撤掉。
  - 现在登记：定时触发的任务、事件触发的任务（做法是普通任务或流程），生效成项目的内部任务；
  - 二狗现在还做不了的（项目自己的服务登记到 LSM、公网入口，规格写明属第二阶段）也登记着，标成不能替用户做：维护者照样写进方案、写清要用户手动做哪几步，卡上标"这一项二狗现在还做不了，需要你手动：……"，确认时不假装生效。
- **每一条要的能力不能超出项目的工具包**（联网、bash、skill、MCP、给秘书发消息），交的时候超了整份退回、写明哪一条超了什么；确认时项目的工具包已经收窄了的，那一条记"没生效"和原因，别的照常。
- **流程的那几条**交的时候就照 `propose_plan` 先检查、再审查修补（守卫眼里执行它的是项目的维护者），审查要用户逐项确认的事项勾完才能确认；确认运营方案时这个流程一起授权——流程计划卡建出来就是已处理（"随运营方案一起授权"），不再单独出一张让用户授权。
- **立项书的"运营方式"**（选填）只是个大概，不算授权；真正的授权在项目做完时那一次确认（用户想要的"立项时一次性授权"做不到：立项时具体时间表、步骤、要的能力都还不知道）。
- **部分失败、幂等**：某一条生效出错（手段撤掉了、能力超了、校验不过），别的照常、项目照常进入使用中，项目上记下原因、维护者收到通知；卡片动作带幂等键，同一次确认重发不再建一遍。
- **停用、重新启用**：定时、事件触发的那几条由触发底座按项目的状态暂停、恢复（照旧）；登记了暂停、恢复的手段（以后项目自己的服务）由运营方案模块在项目停用、重新启用时叫。

## Considered Options

- **给维护者、秘书一个"建重复的定时任务"的工具，每建一个出一张计划卡授权**：和现有的流程计划卡一致，但一个项目有几条就要确认几次，改个时间又是一张；用户要的是"确认一下就行"。不选。
- **立项时就授权运营**：用户提过。立项时只知道个大概，时间表、步骤、能力都没定，授权对象说不清；留成立项书里选填的"运营方式"，做完时交方案、确认那一次才算。
- **运营方案自己跑一套（不建任务）**：要重做触发、名额、运行记录、暂停恢复、失败处理。不选：照用触发底座和项目内部任务，运营方案只管"起草、确认、生效成什么、比差异"。

## Consequences

- 用户确认一次，就授权了方案里每一条之后的每一次运行（定时、事件触发的任务授权一直有效，直到暂停或取消）。卡上把每一条的触发、做什么、要的能力列清楚，流程的那几条能展开步骤，要用户逐项确认的事项照样要勾。
- 秘书仍然没有建重复任务的工具；项目的事经维护者出卡，不属于项目的照旧请用户在对话框里建（以后要不要放开，另议）。
- 项目页多一节"运营方案"，列现在生效的每一条和状态（在跑、暂停、没生效及原因、要你手动）；"定时触发的任务"那一节照旧列这个项目的全部触发登记（包括用户在对话框里建的）。
- 删除项目时，交过的运营方案、用户的决定整条换成"已删除"标记，"运营方案变更"卡一起删掉，项目上记着的运营方案文字换成删除标记。

- 2026-10-18 补记（133 号票）：项目自己的服务不再是"要你手动"——运营手段"服务"确认后由二狗经 LSM 的接入协议（名下的服务，见 packages/supervisor/docs/link-protocol.md §7）登记、启动、开机自启，有网页的经二狗转发、项目卡上有入口；LSM 版本不支持名下服务时照这里的规矩标"要你手动"，不假装生效。停用、重新启用时撤下、重新上线走的就是上面写的"登记了暂停、恢复的手段由运营方案模块叫"。公网入口仍要用户手动。
- 2026-10-18 补记（141 号票）：运营方案里的一条生效成的内部任务也上任务看板（在对应的组里，卡上标属于哪个项目；秘书的查看板也列出、标项目名，秘书的任务工具照旧管不了），和项目页、项目卡是同一个任务。项目没归档时用户对它只能暂停、恢复——取消、归档换成"这是项目「X」运营方案里的一条，要去掉请让项目维护者改运营方案"，守护进程同样拒绝；要去掉走运营方案变更。项目归档时它们跟着归档（记下原来的状态），取消归档时回到原来的状态；项目删除时照彻底删除的口径随项目删掉。别的项目内部任务照旧不上看板（ADR-0023）。
