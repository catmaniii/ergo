# ADR-0032 记忆推理照推理图谱的规矩

状态：规矩已定（用户 2026-10-27 定 328 号票的规矩）；329 号票实现了状态和传播这一部分（R1、R2、R4、R7、R8、R9、R11、结构检查、R16 ①）；330 号票实现了 R3、R5、R6、R10、R12、R13、R14、R15 和矛盾根源（用户选 A）。333 号票实现了 R16 ②（全量重判一次），在真库的副本上跑过、等用户看前后对照点头再上真库。329 票上的五处疑问：Q1、Q2、Q4、Q5 主会话 10-27 按已定规矩答了，Q3 用户 10-27 定了（选 A），见最后"329 号票的五处疑问怎么定的"。334 号票（用户 10-27 定）实现了"前后两句对不上"（选 A）和"每晚的预算"（选 A+B），见这两节。

## 背景

- 记忆系统的推理图谱照推理图谱方法本身的规矩（状态怎么迁移、不确定性怎么传、证伪怎么往回打）做，但 328 号票对照下来很多地方对不上：
  "待复核"占着真值状态、身份（kind）来回改（326 号票"拿不准降成假设、冲突解决升回结论"）、已验证的推断能压在拿不准的前提上、
  前提一降级下游就转待复核然后被撤或被悄悄换依据、猜测不能往上推、用户确认过的需求前提一塌就永远卡在待复核（328-audit-table.md 的实测 A1 A2 A4 B B2 C D E probe3）。
- 用户定了一份规矩（内部记录 328-rules，要点见下文），照原始推理图谱的状态机走，只有几处有意不同（见"和原始不同"）。这份 ADR 记规矩落到代码里的样子和实现时定的细节。
- ADR-0030（唯一写入口）不变；它第 2 条里"依据被改或被删时依赖它的转成待复核""前提里有拿不准的事实只能是假设"、第 5 条"不合格的转待复核"以这份为准。

## 决定（规矩）

1. **身份和状态分开（R1）**。结论的身份（`kind`）建号时定、以后不改：`conclusion` 是从用户明说起的，`hypothesis` 是推断起的。真值状态只有三种：**已验证**（`active`）、**猜测**（`contested`，没验证，按把握分高低）、**撤回**（`retracted`）；另有**被取代**（`superseded`）。"待复核"不再是状态，是单独的**复核标记**（`claims.needs_review` 列、`Claim.needsReview`）：依据刚变了、等下一次整理重判，不改真值状态。
2. **已验证 = 证据达标（R2）**。几次互相独立的观察都指向它、对立的猜测被比下去（沿用分贝计分：领先第二名 6 分贝、有别的假设没有的强支持）；用户亲口确认最有分量。推出来的结论要已验证，还得它的前提都已验证（R4），或者有直接证实（R7）。推出来的已验证把握最多 medium（Q1）。
3. **往上推和传播铁律（R4）**。猜测（把握 low 的、还在竞争的）都能当往上抽、联动的输入，推出来的是猜测。已验证的不能依赖没验证的：前提降成猜测（拿不准的事实也算没验证）→ 依赖它的已验证降回猜测，**前提照挂、结论保留**，不转复核、不撤、不悄悄换依据，一路往下传。
4. **证实不靠前提（R7）**。一条结论被直接证实——用户亲口确认，或者有不靠前提的独立证据达标——依据改挂到这份直接证实上，原来的推理链记作历史；以后前提被推翻，它照样成立；前提不因此变已验证。证实它的那份东西没了，退回原来的推理链（别的依据也不够就是猜测）。
5. **推翻往上传（R8）**。被证伪（决定性反证；330 号票 R14 起只有当面的才算决定性，见"矛盾"一节）或被用户亲口否掉（包括用户纠正了它的前提事实）→ 撤回，墓碑（`retractedBy`）只指真正推翻它的东西。建在它上面的（传递）：有直接证实的留下，**没有的一律撤回**，不留悬空的猜测，以后证据够了重新推；它底下的事实不动。不管被撤的原来是猜测还是已验证，都扫下游。
6. **削弱不撤（R9）**。只是被削弱（一条不太支持的观察、没说它错）→ 不撤，只降把握；削弱以后还够已验证的门槛就照样已验证，不够就成猜测（Q4）。
   **组不成立了也不撤（Q2）**：往上抽的条件不够了、场景只剩一种、联动组（对比模式、矛盾根源）这次没再出来、观察不够两条——都没有推翻者，是证据变少（原始的 undercut 回未验证，只有 rebut 才撤）。组撤下，组里的结论留成猜测、把握降一档、推理链照挂；撤回只留给真有推翻者的（R8）。
7. **复活（R11）**。推翻它的东西自己被推翻（反证、否认的那句被忘掉、被纠正，被纠正的事实又回来）→ 回到猜测、加复核标记；因 R8 被连带撤回的跟着回来。
8. **结构检查**。图谱自检补"前提还在（不留悬空）""推论有前提"；写入口也查依赖不绕圈。
9. **老库迁移一次（R16 ①）**：状态按新规矩重算、恢复被 326 改过的身份、待复核改成标记（见"实现"第 9 条）。

## 实现（329 号票，2026-10-27）

1. **编码**。`active` = 已验证、`contested` = 猜测，`CLAIM_STATUSES` 去掉 `needs_review`。复核标记是 `claims.needs_review` 列（打开库时没有就补，`ALTER TABLE … DEFAULT 0`）；没升 `SCHEMA_VERSION`（守护进程遇到版本不对就不开库）。推断的状态多一种 `history`（被直接证实以后的原来那条推理链）；推断的 `needs_review` 现在只表示"前提被彻底删除、停用着等整理重推"。
2. **身份冻结**（R1 里"冻结还是并进 epistemic 由实现定"）：选冻结、保留 `kind`，只表示来源。写入口的"永远不做"拦改 `kind`；只有规矩迁移能把 326 改过的改回建号时的那个。326 号票的自动降级（写入口 `hypothesisRule`、每晚校验降成假设、`followFact` 改身份）全部去掉。`need`、`value` 只能从推断起（kind 只能是 `hypothesis`）照旧。
3. **已验证的前提**：事实成立或被新值取代（在它的有效期里仍算对）、证据有效、结论已验证。拿不准（真冲突里的一边）的事实没验证；被纠正、撤回的不在。判断写在 `rg/graph-rules.ts`（`premiseVerified`、`unverifiedPremises`、`premiseHolds`、`isDangling`、`lacksPremises`），写入口和图谱自检共用。
4. **状态维护**写在 `rg/status-keeper.ts`（`StatusKeeper`，`engine.rg.keeper`）：`downgradeDependents`（R4）、`retractDependents`（R8）、`sourceLost`（来源失效）、`reinstateDependents` / `reinstate`（R11）、`directBasis` / `attachDirect` / `restoreChain`（R7）、`rejudge`（整理末尾重判标着复核、不在活着的组里的）、`flag`（复核标记）。同一层先把直接证实都看好再改（一组里几条都依赖同一条前提时，结果不因先后不同）。
5. **独立证据怎么算**（R7 的"独立证据达标"，规矩没写细，实现定）：前提闭包（推理链的前提一路往上；明说的结论背后的那条事实；闭包里结论的支持目标；事实背后的原话）之外、已验证的支持和反证，按同一套 `decideGroup` 在组里判；全部证据判成立、只算独立证据也判成立，才算直接证实。直接证实的推断理由以"直接证实："开头（`DIRECT_BASIS`），用户确认认的是"用户确认："开头的决定性支持。只要整理定状态时看到有直接证实就改挂（不等前提倒了）。
6. **几种"不成立"分开**：
   - 证伪、用户否掉、用户纠正了前提事实 → R8 撤回往上传；
   - 忘掉、彻底删除、别推断 = 来源失效（原始 LIFECYCLE §1 的"evidence 来源失效 → 降级"）：依赖它的加复核标记、已验证的降回猜测；前提一条都不在了的撤回（墓碑指那条不在了的前提），再往下照这样传；彻底删除时前提不在库里，墓碑没处指，推断停用、结论先当猜测标着复核，等整理重推；
   - 明说的结论跟着它那条事实走：事实拿不准 → 猜测（真冲突的另一边一建出来就是猜测）；事实被纠正 → 撤回、墓碑指纠正的话；证据被忘掉 → 撤回、墓碑指那条事实；事实回来 → 复活。
   - 墓碑分两种：指它推理链上前提的（连带撤回、来源失效），那条前提回来就复活；指推翻它的东西的（反证、否认），那份东西被忘掉、被纠正就复活。只认这条结论上真有指向它的反证的。
   - 决定性的反证要"落地"才能推翻：拿不准的事实（真冲突的一边）当不了推翻（`scoring.ts`）。
7. **重推 = 新建一条**（原始"撤旧建新"）：撤回以后同一组又推出来的，建新的一条，旧的墓碑移出组（`registry.removeMember`），追问的 `discriminates` / `ifFound` 改指新的。
8. **复核标记**谁加、谁摘：用户说拿不准、对抗复核判 no、每晚校验点名（违反铁律的除外）、失效传播拿掉了它的关联、来源失效、档案换值让依据的事实到期、彻底删除、复活，都加标记；整理时那组按证据定完、明说的跟着事实走、整理末尾 `rejudge`，摘掉。失效传播、彻底删除当场重定那一组时真值状态当场跟着证据走、标记留着到下一次整理。329 号票时标着复核的先不进用户模型、简报、需求和价值的检索、交互策略的依据（策略暂停）；330 号票起照真值状态进、标出来，策略不再因此暂停（见"猜测怎么用、怎么问"）。
9. **规矩迁移**（`rg/migrate-rules.ts` 的 `migrateToRules`，写操作 `migrate`，夜班）：① 状态还是 `needs_review` 的改成复核标记，真值状态回到转待复核之前的那个（修订日志里找，找不到算猜测，前提有没验证的照铁律算猜测），当时一起停用的推断前提都还在库里的恢复成立；② 修订日志里改过 `kind` 的改回建号时的；③ 用户确认过、还没改挂的改挂到确认上；④ 照铁律降到不动为止；⑤ 悬空的、推论没前提的加复核标记，下一次整理 `rejudge`（悬空的撤回）。一条结论一次写，一条被拒只记进报告。跑两遍结果一样。**被错撤的（墓碑指着只是拿不准的前提）不在这里复活**，留给 333 号票的全量重判（R16 ②）。329 号票只写代码和测试，没接进守护进程、没在真库上跑：333 号票先在副本上跑、出前后对照，用户点头再上真库（先备份）。
10. **写入口**（`rg/write-gate.ts`）：这次写让它成了已验证（新建、改了状态）或动了它的推断的，查它自己（铁律、已验证要有成立的依据）；依据在这次写里成了没验证、撤回、删了的，依赖它的已验证要在同一次写里降回猜测或改挂依据，前提都不在了的要在同一次写里撤回或加复核标记（不留悬空）；这次写的推断不能让依赖绕圈（`cycle`）；改身份拒（`never`）。只加复核标记、改把握的写不查（老库里不合规矩的留给自检和迁移）。
11. **图谱自检**（`rg/graph-check.ts`）查 `readable`、`exists`、`cycle`、`dependents`（铁律，交回要降回猜测的 `downgrade`）、`dangling`、`premise`；标着复核的不查悬空和推论没前提（等整理重判）。**每晚校验**（`rg/nightly-validate.ts`）把违反铁律的降回猜测（往下跟着降），别的问题加复核标记，整理报告和整理记录分开记。
12. **事实层的冲突**：抽事实时旧事实因真冲突变成拿不准，同一次写里以它为前提的已验证降回猜测（`engine.extractFacts`）；写回、忘掉让事实恢复成拿不准时也一样。
13. **接口和网页**：协议包的结论状态去掉 `needs_review`、结论多一个 `needsReview`、推断状态多 `history`、写操作多 `migrate`；网页状态的说法改成"已验证 / 猜测 / 已撤回 / 已被取代"，状态筛去掉"待复核"那一格（330 号票起结论一行上有醒目的"已验证 / 猜测"小签，标着复核的再加"复核中"）。记忆管理员的 `review_memory_claim` 参数照旧用 `needs_review` 表示"拿不准"，现在是加复核标记。

## 预测落空往回打（R10，330 号票）

1. **预测做成节点**。原来的预测账本（表 `predictions`，226 号票）就是节点表（照"一类对象一张表"，不塞进结论表——预测不是关于用户的结论，不进用户模型）：加四列 `premise_ids`（从哪几条结论推出来的，依赖边；第一条就是原来的 `claim_id`）、`derivation`（推法：`deductive` 演绎 / `defeasible` 可废止，照模板词汇起名）、`retracted_by`（墓碑）、`blame`（落空以后往回打来源的结果）。状态照原始：`open` 未验证；`hit` 应验（已验证，依据就是那条观察）；`miss` 落空（撤回，墓碑指证伪它的那条观察）；`void` 来源被撤回、跟着撤（R8，墓碑指来源；来源复活它回到 `open`，R11）；`unclear` 说不清。老库打开时补上这几列（来源 = `claim_id`、推法 `defeasible`、落空的墓碑 = 当时判它的证据），不升表版本；老账本里已经落空的不追溯着往回打（留给 333 号票的全量重判）。什么结论记预测照 226 号票不变（已验证、把握不低的需求和价值观，写了 `predicts` 的）。
2. **谁能标演绎**（"实现定"，原始：缺省按弱的算）：
   - 结论自己的推断（出假设、往上抽、联动）一律不标演绎——都是从观察归纳、溯因来的（`induction` / `abduction`），没有哪处产出 `deduction`；
   - 规则版的预测模板都是倾向（"接下来两周……还会"），记 `defeasible`；
   - 模型版往上抽时，提示词让模型给预测写 `derivation`：只有结论本身是"每次、从不、一定"这种全称、预测是其中具体的一次时写 `deductive`。代码再核一遍：结论陈述里没有全称说法（`UNIVERSAL_MARKERS`：每次、每回、总是、总会、从不、从来、一律、一定会、一向、永远、无论……都）的，`deductive` 一律当 `defeasible`（`predictionDerivation`）；
   - 一条结论写了几条预测、合成一个节点时，每条都是演绎才算演绎。
3. **判**：判预测的模型只看本人有效的新证据（R3：别人转述的证伪、证实不了关于用户的预测，不喂），要它说凭的哪条证据（`evidence_id`，只认喂进去的；不给按最新那条）。
4. **落空往回打**（`rg/falsify.ts` 的 `PredictionBackprop`（`engine.rg.backprop`），在判它的那一次写里）：先撤预测（`miss`），再回头打来源——
   - **可废止**：落空不牵连来源的真假（原始：判断错了不代表前提错），每条还活着的来源挨一条**弱**反证（"按现在的计分"：一条旁证的分量，约 3 分贝；同一个目标已经挂着更重的不压低），它那组当场按证据重定（R9：削弱只降把握）；
   - **演绎**：modus tollens，照原始"先怀疑前提"的顺序（§6b 第一阶段、第二幕 A 的排除法）——来源里只有一条没验证（猜测）、别的都已验证（或者只有这一条来源）→ 它就是错的那条：挂一条**决定性**反证（墓碑指证伪它的观察），在活着的组里由那组重定（决定性反证就撤）、不在组里的直接撤，再按 R8 往上传；没验证的不止一条（Duhem-Quine）→ 判不出，**一条都不撤**，每条嫌疑往问题箱出一个问题（"这一条现在还对吗"，记成 `prediction_violation`）；来源都已验证（原始 §6：前提全真，只能是漏了条件或反证有误）→ 不撤，每条挨一条**强**反证（有分量的反例，R12 接着管）、出问题；有来源不在了（被取代、删了）的排除法不成立，按判不出办；明说的结论跟着用户那句话走，当嫌疑时只问不撤；
   - **每晚再看一遍判不出的**（`reassess`，判预测之前）：嫌疑里有一条撤回了（比如用户答了"不对了"）→ 就是它，别的嫌疑逃过一劫、照旧是猜测；用户确认了几条、没验证的只剩一条 → 排除法落到它，撤回；嫌疑都确认还对了 → 不撤来源，记成"例外"。
5. **应验**：只刷新预测这一条（`hit`），来源不加支持、不因此变已验证（证实的不对称：结论真推不出前提真）；应验本身就直接证实了来源的情形（用户亲口确认、追问找到的独立证据）走原来的 R7 那几条路。
6. **预测跟着来源走**（R8、R11）：唯一写入口在每次写的末尾（检查之前、同一次写里）看这次状态变了的结论——撤回了的，以它为来源、还开着的预测作废；又活过来的，因它作废、来源都还活着的预测回到开着（`predictionsFollowSources`）。放在写入口而不是每个撤回的地方，免得漏。图谱自检加一样 `prediction`：预测字段合格，开着的预测来源都还在。
7. **解释和报告**：`explainClaim` 列出从它推出来的预测和结局；整理报告、整理记录（`predictions.backprop`）、管理员的整理日记多一行"落空往回打：撤了几条错的前提、挨反证几条、判不出几条、前提都已验证挨反例几条"。

## 猜测怎么用、怎么问（R5、R6、R15，330 号票）

1. **猜测照样给、标明是猜测（R5）**。用户模型快照的 `uncertain` 每条带真值状态、把握、谁说的；标着复核的照真值状态进快照、简报、需求和价值的检索（带 `needsReview`），不再整条拿掉。给模型看的记忆简报、每条消息的记忆简报把状态写成"已验证 / 猜测"，标着复核的加"复核中"，抬头写清"猜测可以照着说、拿来推荐，说清是猜测，把握低的留余地，别说成用户说过的"。醒来简报另给最多 3 条需求、价值观里的猜测（已经在"还拿不准"那几组里的不重复）。任务建议第 ④ 层原来的"还拿不准的（不用来做决定）"改成"猜测（可以参考、推荐……）"，每条写明是猜测、把握多少。助理的提示词加同样一句。解释里"为什么还是猜测"用 `guessReason`（没证实的前提、证据哪里不够），网页的结论详情显示它。
2. **长期做法可以建在猜测上（R6）**（`rg/strategies.ts`）：
   - 能当依据：活着的（已验证、猜测都行）、在有效期里；复核标记不看。编新的提议只从把握不是 low 的编（实现定：低把握的猜测不拿来请用户点头；编出来以后依据掉到 low 也不停）。
   - 建在猜测上（`onGuessAt`）= 依据里在用的那几条都是猜测；快照、建议、简报、网页都标出来。照旧要用户点头才生效。
   - 依据变成猜测、把握掉到 low、标着复核、过了有效期，都不再暂停（329 号票以前会暂停）。老库里暂停着的，依据还活着就在同步时恢复。
   - 依据都不在了（`basisGone`：撤回、被取代、删了）：用户点过头的不自动暂停、不自动撤，照旧在用、标"理由没了"；问题箱出一条 `strategy_basis`："之前说好「…」。当时的理由现在不成立了，这条还要照旧吗？"（问题的目标是这条做法，`QuestionTarget.kind = "strategy"`）。答得明确的：还要 → 记成重新确认（确认的证据换成这句，以后不再问，`StrategyBook.answerBasisGone`）；不要了 → 撤回（墓碑是这句话）；说不清的不动，以后再问。点头在依据没了之后的（知道理由没了还要）不问（`basisQuestionDue`）。还没点头的提议依据都没了就收回（`retracted`）——原始 LIFECYCLE §2：拍板之前的候选不算决策。
   - 已验证的依据被推翻也一样问（R6 字面只说"底下的猜测被推翻"；原始 §2 决策的前提被撤一律触发复审、不分原来是不是已验证，照原始）。
3. **问的节奏（R15）**：
   - 平时聊天一次对话最多顺口问一个（`woven-questions.ts`）：挑问题之前从助理会话末尾往回读到这一次对话的开头，看有没有标过的 `mark_woven_question`，有就不挑，问题留在问题箱。在守护进程里数、不存状态（重启照样认）。"一次对话"（实现定）：新的一段会话开始（压缩、清空、换模型新开、回退切换分支，同记忆简报的"同一段对话"），或者前后两句隔了一小时以上（`CONVERSATION_IDLE_MS`）。原来的每天最多一个照旧，两条一起管。
   - "刚好用到某条猜测才顺口问"：沿用 198 / 264 号票的"话题对上了才问"（问题的话题、领域、场景、词和这句话对得上），没另加"这一轮的回话真的用到了哪条猜测"的判断。

## 别人转述的（R3，330 号票）

1. **能起猜测**（`rg/relayed.ts`，整理时和明说的结论同一步 `syncRelayed`）：知识图谱里出处是别人转述（`third_party_reported`）的、关于用户的偏好、不喜欢、近期状态（和明说的结论同一类事实），转述的那句还在，用户自己没说过同样的、也没说过相反的 → 起一条猜测：`hypothesis`、推断出来的、溯因、把握 low，成立推断的前提是那条转述的事实、理由以"别人转述："开头（`RELAYED_BASIS`），依据只当背景（`context`，计分不算）。同一条转述的事实只起一次（撤了的不重起）。
2. **出问题**：转述起的、还是猜测的，问题箱出"听别人说你……，是这样吗？"（问题来源 `relayed`）。答是 → 用户确认（直接证实、已验证）；答不是 → 用户亲口否掉、撤回（R8，墓碑是那句回答；不在组里的直接撤）。
3. **永远到不了已验证**：转述的事实、别人转述的证据不算已验证的前提（`premiseVerified` 看 `GraphLookup.relayed`，写入口、图谱自检、状态维护共用），计分本来就不算它们——只有转述的，再来几条也还是猜测；只有本人的话（回答、确认、自己说的）能让它已验证。
4. **跟着走**：用户自己说了同样的话 → 转述起的猜测被明说的那条取代（`superseded`）；说了相反的 → 撤回（墓碑指他那条事实）；转述的那句被忘掉、纠正 → 来源失效，悬空撤回。
5. **打不下已验证的，最多一个问题**：转述和用户自己说过的、已验证的明说结论对着干（同一个宾语，喜欢对不喜欢）：不起猜测、不记反证、不改状态（知识图谱这一层本来就不让转述取代、冲突本人的事实），问题箱出一个"有人说你……，你之前说过……。现在还是你说的那样吗？"（每条转述的事实最多一个）。答是 → 那条记成你确认过；答不是 → 你那条事实到期，明说的结论跟着走。
6. 还没做：转述去削弱已有的猜测（R3 只说能起猜测、打不下已验证的，没说能不能削弱猜测——这次不让它动别的结论，只起新的、出问题）。

## 矛盾（R12、R13、R14，330 号票）

1. **什么算决定性（R14）**（`rg/link-sources.ts`、`rg/scoring.ts` 的 `effectiveWeight`）：当面的才算——用户确认、否认（表态，说法开头"用户确认：""用户否认："）、回答了解你问题（"回答了解你问题"）、演绎预测落空撤错的前提（"演绎预测"）、明说的结论跟着它自己那条事实（"用户明说："）、背后的证据是用户的纠正（`kind = correction`，或者纠正了某条事实的那句）。别的"决定性"（模板给用户随口明说的事实的、模型判的）计分时按**强**的算（6 分贝；实现定：按强、不按弱——用户自己的话照样有分量，只是不能一句推翻）。关联照原样存（不改库），解释、演示里写成"决定性，按强的算（不是当面确认的）"。周末社交案例因此变了：第 4 条"我不反感见朋友"不再撤回"不喜欢社交"，它降成把握 low 的猜测、回答里列在"还没完全排除"；用户再纠正一句（"我不是不喜欢社交"）才撤回。
2. **已验证碰上有分量的反例（R12）**：
   - 有分量的反例 = 落了地、按 R14 算下来是强的反证（决定性的照旧直接推翻）。计分时记下来（`Tally.counterexamples`），证据够已验证、却有没弄清的反例的 → 猜测、加复核标记，修订写"碰上有分量的反例……先降回猜测、等弄清"（`Decision.counterexample`）。以前"净分领先 6 分贝就照样成立、反例只记一笔"去掉了。
   - 弄清了的三种结局：**只是例外**——反例以后（按证据发生的时间）又来的支持合起来到 6 分贝（`LEAD_DB`，实现定），或者用户当面确认过（确认、回答"是例外"；当面确认的最有分量）→ 已验证、摘标记；**要分场合**——支持和反例按事实、证据自己带的场景标签在某个维度（一天是哪种、在哪方面、出行是哪种）上分得开（两边每条都写了这个维度、没有交集，`separatingTags`）→ 结论层收窄（`narrowClaim`）：新建一条"……（只在周末）"、场景加上那几个标签、抄成立的推断和关联，场合外的反例在新结论上只当背景，同一组里接替原结论（同一个模板）；原结论"被取代"、指向新的，依赖原结论的照铁律降回猜测（R4，不悄悄换依据）；**真错**——用户当面否掉（表态"不对"、回答"不是例外"）→ 撤回（R8）。
   - 问题箱出 `counterexample`："「你……」平时还对吗？10 月 3 日那次（……）算例外？"答是 → 当面确认，已验证；答不是 → 撤回。"等后面的观察"只认上面那种"又来了够分量的支持"，没有让后面的观察自动判成真错（撤回只留给当面的、决定性的）。
3. **两条打架都已验证（R13）**：两条结论互相竞争（`competesWith`，哪边写的都算）、在不同的组里、场合对得上（`contextsCompatible`），单看各自那组的证据都够已验证 → 两条都降回猜测、加复核标记（同组的本来就只能一条领先）。先试收窄：两边的支持按场景标签分得开（一边都在周末、一边都在工作日）→ 各自收窄，两组都重定，收窄以后场合对不上、不再打架；分不开 → 问题箱出一个（来源 `contradiction`，key `verified-conflict:<a>|<b>`）："「A」和「B」对不上，现在更接近前一个吗？"答是 → A 当面确认、B 撤回；答不是 → 反过来。用户亲口确认过的那条赢，另一条照常按证据定。图谱自检加第 8 样 `conflict`：互相竞争、场合对得上的两条都已验证就报出来（跨组也查）。
4. **说的和做的对不上（R14）**：联动发现说做对不上（`say_do`）的当下，两边的事实互相记一笔 gap（`ref` 是这个矛盾的 key，`JointReasoner.markSayDoGaps`），不等根源定。"记一笔"记成什么实现定：沿用 199 号票知识图谱这一层的事实标记（`fact_marks` 的 `gap`），不另建一条事实或一条猜测——它说的是这两条事实之间的关系，不是关于用户的新判断；网页、简报照旧能读到。哪边都不自动赢：明说的那条结论（它那条事实有没弄清的 gap）先当猜测、加复核标记（`openSayDoGap`）；用户当面确认这条明说的结论，或者确认了这个矛盾的某条根源 → 回到已验证。做的那边是观察到的事实，不动。根源确认以后写回（199）的 gap（`ref` 是那条根源）另记一笔，两笔都留着。

## 前后两句对不上（334 号票，用户 2026-10-27 选 A）

背景（334 号票排查的"机制 2"，规矩改之前就有）：事实层的变化判定以前是"不在同一天说的就按先后、后说的赢"；模型又常把说现在的话的 `valid_from` 给成 `null`（= 一直），于是 10-18 的"有点想回去读博了"被排到 08-04 的"不再读博了"之前、标成被取代、到期日比它自己说话那天还早——新说法被旧说法吞掉，R12、R13、R14 都轮不到。

1. **生效日期不早于说话那天**（`kg/graph.ts` 的 `addFact`）：一句话抽出来的状态类事实（喜欢、不喜欢、在做……），抽取器给了 `null` 或者比说这句话那天（证据的 `eventTime`，没有就 `observedAt`）早的开始，而这句话自己没说从什么时候起（没有时间说法，没说"以前、一直、从小"，`kg/signals.ts` 的 `statesOwnStart`）→ 按说话那天算开始。同一天早几个钟头的不挪；抽取器说它在说话之前就结束了的（`validTo` 不晚于说话的时候，说的是以前）不动。规则版本来就这样（没有时间说法用发生时间），只有模型版受影响。抽取提示也改了一句（说现在的感受、打算写这句话的时间，原话说了"一直、从小"才写 `null`），但以代码为准。
2. **前后两句意思相反、后说的那句没自己说"变了"**：当矛盾（R13 / R14），哪边都不自动赢——事实层两条都 `contested`（`kg/change.ts` 的 `classifyChange` 判成 `conflict`），明说的结论跟着事实两条都是猜测、互相竞争；问题箱出一个"现在更接近哪个"（`question-sources.ts` 的"矛盾"那一路，问法带上两句各是哪天说的："关于读博：你 8 月 4 日说过……，10 月 18 日又说……。现在更接近后一种吗？"；答"是"新的定下来、旧的到期，答"不是"反过来），节奏照 R15。简报（D）里两条结论都在、各带原话和日子，矛盾根源那一组（199）也列出"想法变过：先是……，10-18 起是……"这类猜测；用户模型快照的 `uncertain` 里两条都在、互相是竞争者、各带原话的证据。"观点变化按日子先后、后说的赢"那条路在这种情况下不再走（`classifyChange` 不再看"是不是同一天"）；"反常输入"（`out_of_character`）只剩老库里以前按日子先后接上的。
   **同一处矛盾只留这一个问题（334b，用户 10-27 定）**：矛盾根源那组（199）的两边里有一对正是这里要问的（事实层真冲突、两条都还拿不准），它的追问（"是不同场合吗""有一条记错了吗""想法后来变过吗"……）不再另出问题——R15 要少问，R13 也只说"分不清再问你"。根源组照旧建、照旧计分（还是猜测，简报里照样列着），只是不进问题箱（`question-sources.ts` 的 `askedAsContradiction`，出问题时记进 `dropped`）；用户答了"现在更接近哪个"，事实层定下来、矛盾不在了，根源组按 Q2 撤下。说的和做的不一样（`say_do`）、两边不是一对还拿不准的事实的根源组照旧出问题。
3. **后说的那句自己说了变化**：这是用户亲口说的变化，不是矛盾，照旧新取代旧——开始得早的那条到期（`validTo` = 新那条的开始，也就是说话那天）、被取代。**"后说的"按有效期开始的先后认**；新来的说的是更早的事时，后说的是已有的那条，看它背后的原话。
4. **怎么区分"说了变化"和"只是相反"**（细化，见下面的标注）：只认原话里明说变化的说法（`kg/signals.ts` 的 `explicitChangeSignals`）——
   - 不再、再也不、已经不、否定后面同一个小分句以"了"收尾（"不读博了""没兴趣了"）；
   - 改成、改为、换成、转而、变成、变得、越来越、渐渐、开始、从此、从…起；
   - 搬家、换工作这类状态变化（搬到、搬去、搬家、换了工作、跳槽、辞职、离职、转行）；
   - 一句话里先说以前（以前、原来、之前、过去、曾经……）、后说现在（现在、如今、后来、目前），这一种在整条证据里看（跨分句），别的在抽出这条事实的那段原话里看（模型版的 `span`、规则版的分句）。

   拿不准的一律不算，按矛盾处理（宁可多问一句，也不吞掉新说法）：只说"现在、最近、这阵子"，"想…了""又想…了""喜欢上…了"这类只是新说法的，都可能是变了、也可能只是这一阵的说法。**模型的 `change` 字段不算数**：334 号票拿 16 句合成的话问了真 DeepSeek（8 句明说变化、8 句只是新说法）——原来的提示词下，只是新说法的 8 句里 5 句它标了 `change: true`（"最近有点想学钢琴""现在挺喜欢跑步的""又想去爬山了""好像喜欢上徒步了"，p3 那句"有点想回去读博了"抽出的两条一条 true 一条 false），分不清"说了变化"和"只是相反"；提示词改成"自己明说了变了才写 true"以后这 16 句和词表一致，但只是一次小样本，不拿来定谁取代谁（提示词照改，`change` 只当参考）；规则版宽的变化信号（`changeSignals`，含"现在、最近"）也不用来定谁取代谁（它照旧管矛盾根源里"时间变了"的证据、反常输入的判断）。
   > **标注（给用户过目）**：第 3、4 条是主会话按原始推理图谱（`LIFECYCLE.md` §6b：反例的处理不许"信先到的、信后到的"）和用户的规矩（"宁可多问一句"）补的细化，用户 10-27 选 A 时没单独说；334 号票 Comments 里同样标出来了。
5. **代价**：以前"不在同一天说的相反的话"直接按后说的算，现在多了一个问题（只这一个，见上面 334b）；评测里这类题回答会说"以前说……、最近又说……，现在更接近哪个还没问清"，不再直接说成后说的那句。
