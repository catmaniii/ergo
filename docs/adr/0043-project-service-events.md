# ADR-0043 项目的服务报事件：走事件触发的任务，凭证按服务发，事件名要先写进运营方案

状态：已定（357 号票。"自建小服务盯数据、异常才叫醒负责人""要在二狗内部闭环"是用户 2026-11-01 定的；下面的取舍是主会话定的，用户不同意再改）

## 背景

有些项目要一直盯着数据（评论、价格、日志），大部分时候什么事都没有。让维护者定时醒来看，每次都花 token；用户想要的是自建一个不用大模型的小服务，用普通代码盯着，发现异常才叫醒维护者，维护者平时休眠不花钱。

用户特别强调闭环："如果不在二狗内部不能闭环的话，相当于我就没有办法让二狗自己生长出来新的这种服务的群了"。所以不只是加一个接口：二狗里的维护者只靠系统内的说明和工具，就要能写服务、起草方案、被叫醒，不靠外部 Claude Code，也不靠用户手改配置。

已有的路：事件来源登记表（ADR-0025）、事件触发的任务和排队合并（运营手段 `event`，ADR-0028）、连续失败自动暂停、项目服务经 LSM 上线（`from: file` 注入密钥）。缺的是"项目的服务"这个来源，以及服务怎么证明自己是谁。

## 决定

1. **第三种事件来源"项目的服务"（`service`）。** 事件名由服务自己定（中文可以），登记表里只算一种事件（`reported`），名字写在过滤条件 `name` 里，必填。字段是事件名、服务名、数据。它标了 `planOnly`：只能写在运营方案里，发起任务对话框和简单提醒选不了，建的时候也拒。
2. **走事件触发的任务，不插进会话。** 服务报的事件进 `ScheduledJobs.fire`，和文件夹变化走同一条路：排队合并、不并行、一次运行一张工单、连续失败自动暂停，全部沿用。接口发完就回，不等维护者做完。
3. **不走 `sendMessage`。** 那条路是"用户说的话"：会被当成用户本人的指令、算用户授权，还会进素材和记忆。服务报来的数据可能带着外面来的原文（评论里写"忽略之前的指令"）。所以数据只放在这次运行里（`JobRun.events`，删项目时跟着删），不进素材和记忆，交给 agent 时写明是数据不是指令，也不算用户授权。
4. **凭证按服务发。** 服务上线时二狗注入地址（`ERGO_NOTIFY_URL`）和专属凭证（`ERGO_SERVICE_TOKEN`，放在密钥区 `secrets/service-tokens/<应用名>.token`，经 `from: file` 注入）。凭证只能叫醒自己项目的事件触发任务。撤下的要求一落盘就作废（不等 LSM 撤完），项目停用、归档、删除同样；重新上线发新的。
5. **事件名要先写进运营方案。** 接口只认用户确认过的方案里等着的名字；没人等的回明确的错（写明现在能报哪些），不叫醒任何 agent，不花钱。这条用户问过，原因是：
   - 运营方案是用户确认的那份授权（ADR-0028）。什么事能叫醒维护者、让它花钱，也属于"项目怎么运转"，卡上写着"项目的服务报事件「评论异常」"，用户看得懂、能拒绝。
   - 服务的代码是维护者写的，改代码不经过用户。如果名字不用进方案，服务（或者服务里的 bug）报什么都能叫醒人，用户的确认就管不住花钱了。
   - 名字写错（"评论异长"）时当场回错，调试时不用猜；不会变成一次白跑的运行。
6. **防乱烧钱。** 排队合并沿用；另加每个服务的限速（默认每分钟 30 次，超了回 429、记日志）和单条数据大小上限（默认 8 KB，超了回 413：一批事件都要进上下文，大了就是烧钱，原文放进文件让维护者自己读）。常量在 `event-sources/thresholds.ts`，配置 `eventSources` 能改。
7. **本机接口加一层命令。** `POST /api/service-events` 只在本机端口开，外网端口一律拒（带设备凭证也拒）。`ergo notify <事件名> [--data <JSON>]` 包一层，退出码 0 报上了、1 被拒、2 用法不对、3 连不上。用户定过不用命令行操作二狗，这条是给服务用的，不算违反。
8. **闭环靠三处说明和一个查询工具。** 维护者的系统提示写清整个做法（三步、事件怎么写、Python 和 Node 各一行、命令），运营方案工具的手段说明写清字段；项目页这一条列最近收到的事件；维护者用 `recent_service_events` 查（运行记录里没有没叫醒的那些，所以另加一个只读工具）。

## Considered Options

- **让服务调 `sendMessage` 给维护者发消息：** 最省事，但会被当成用户的话、进记忆、算授权。数据里的"忽略之前的指令"就成了用户的指令。不要。
- **开 webhook、对公网开口：** 平台的推送由用户自建的服务收，再调 `ergo notify`。二狗不对公网开口。
- **所有服务共用一个凭证：** 分不清是谁报的，也没法只作废一个；撤下一个服务要换所有服务的。
- **凭证写在 LSM 定义里（literal）：** 会落进 LSM 的注册表；LSM 本来就拒绝这样写看名字像密钥的变量。
- **按运营方案校验事件名之外再让服务先"登记"：** 多一步，也绕不开用户确认。方案本身就是登记。
- **离线缓存（二狗停着时存下来，起来再补）：** 要多一个文件或服务端，还要去重、过期。服务发现二狗停着（退出码 3）自己决定要不要重报更简单；不做。
- **最近收到的记进事件日志：** 超限速的一阵也写日志太重，还要写清除规则。放一个小文件（`event-sources/service-events.json`），每个服务 10 条，只有名字、时间、结局，不存数据，删项目时删。
- **对话框也能选"项目的服务"：** 对话框建的任务不一定属于项目，凭证又只认自己项目；而且绕过了"用户确认过的方案"这一条。不给选。

## Consequences

- 升级后第一次接上 LSM，已经在线的项目服务定义里多了两个环境变量，会被重启一次（和换 Node 时一样，324 号票的那条路）。
- 备份恢复到别的机器、密钥区没跟着来时，凭证文件不在：接上 LSM 时发新的，在跑的服务重启一次拿到。
- 服务的 `PATH` 是 LSM 启动时的快照，刚装完没重新登录时可能还没有 `ergo`；用 `git clone` 跑的机器上本来就没有。所以说明里让服务代码优先发请求（两个环境变量总在），命令是给脚本方便的。
- 守护进程停着时服务报不进来，这段时间的事件没了，由服务自己决定怎么办。
- 接口不验来源 IP，只认凭证和本机端口；本机端口的信任规则没动（ADR-0026 的"功能先跑通"照旧）。本机别的程序读得到密钥区文件的话也能冒充，这和其他密钥一样。
- 新 skill 进库的路（维护者现在提不了）另算，不在这里。
