# ADR-0034 记忆是可替换的一个插件

状态：已定（337 号票；用户 2026-10-28）

## 背景

- 记忆系统现在的实现（会意 / Subtext）和内核长在一起：数据在 `db/rg.db`、`db/memory.db`，实现是 `@ergo/memory`，宿主接线散在 `daemon.ts` 和 `memory/*`。只有网页那一半是插件。
- 用户要"以后再换一套记忆系统、只做插件化、不真接第二套"，而且要"换插件时数据库、设置、界面整套一起换"。
- 记忆不是可以叠加的东西：两套一起写会把同一件事记两遍、删除漏一套就是隐私问题、也答不出"到底记得什么"。

## 决定

1. **记忆是一个槽**：`packages/protocol/src/memory-provider.ts` 定接口 `MemoryProvider`（`info/start/stop/observe/remember/search/forget/health` + 可选 `brief/consolidate/callTool` 和 `capabilities`），宿主 `packages/daemon/src/memory/provider/host.ts` 保证**同一时间只跑一个**；配置里 `memory.provider` 记 id（默认 `subtext`）。
2. **数据归插件**：每个插件的数据目录是 `<数据目录>/memory/<id>/`，内核只按整个目录做备份、恢复、迁移，不读里面的格式。会意的推理库按 ADR 之后的 338 号票迁进 `memory/subtext/`；素材库 `db/memory.db` 和事件日志仍归内核。
3. **工具面固定**：模型看到的记忆工具由宿主实现、转给当前插件；插件要加工具必须在 `capabilities.tools` 里声明并带前缀。这样换插件不改变模型对工具的认知。
4. **条目必须带出处**：`MemoryItem.sources` 是必填，指向能跳回的原话（会话/消息/素材/工具调用）。没有出处的条目不进简报——用户要的是"有依据的判断"。
5. **不并存**：切插件 = 停旧的、起新的；旧数据留着、能切回来，不迁移、不双写。对照实验只在离线用影子模式跑。
6. **生产里只有会意**：它是自研、标"实验性"。别的记忆系统（例如 Mem0）只在本机验证"换一套很容易"，不纳入开源范围。

## 后果

- 记忆从"内核的一部分"变成"一个可以换掉的东西"；代价是多了一层接口和宿主，以及必要的数据迁移（338）。
- 内核不再知道记忆的具体形状（证据、结论、竞争解释），只知道通用条目——会意自己的这些能力靠可选能力、额外工具和它自己的页面暴露。
- 简报、去重、用量记账、超时这些"宿主怎么用记忆"的逻辑留在内核，插件的 `brief` 只负责"给一段文本"，这样换插件不会改变这些行为。
- 换插件时设置各存各的（用户 2026-10-28 选 A）：切回来还是原来的值，代价是要重设一遍。
