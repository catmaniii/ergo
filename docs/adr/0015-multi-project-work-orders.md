# 涉及多个项目的任务：计划逐行建工单、工单有两种还没派出的状态、回执在工单结束时送达

规格第 8、11、12 节：涉及多个项目的任务在建卡时产生自己的维护者，工具包固定为读项目档案、派工单、汇总回执；规划时只读、不发工单，计划里逐行列出每个项目改什么；用户确认计划时这些改动建成工单（各带验收标准），所属阶段开始时才派出；项目维护者完成或退回时交回执；某阶段回执全部到齐且都完成才跑本阶段的验收，任一张退回或做不了本阶段不通过，调整做法算一次验收退回；计划外的工单要用户确认。17 号票定成：

- **计划里一行就是一张工单**：`PlanProject` 加可选的 `stageId`（所属阶段）和 `acceptance`（这张工单的验收标准），计划卡版本 4；多项目任务的计划每一行都要写这两样，同一阶段同一项目只写一行。确认计划时每一行建成一张工单（同一事务），计划变更确认、自行调整计划后新出现的行照样建，返工按依赖重开的阶段重建。计划内外只按"阶段 + 项目"判断，重新派单可以改写内容。
- **"涉及几个项目"建卡时定下、存在任务上**（17 号票评审后改定）：`Task.projectScope`（`none` / `single` / `multi`）。选了两个以上项目的是多项目任务；建卡时没写项目、第一版任务书里写了的，那一刻定下（和 16 号票交给项目维护者同一个时机）。之后不随计划改动重新判断：多项目任务的计划里只剩一个项目也还是多项目任务（工具包固定、回执门槛照样、剩下的工单照样管）；单项目任务、不涉及项目的任务的计划写不进别的项目（提交、计划变更、自行调整都拒绝，要涉及别的项目就重新发起任务）。
- **工单多两种还没派出的状态**：`planned`（等阶段开始）、`awaiting_confirm`（计划外的待你确认）。它们不在收件维护者的队列里、不在项目的工单流水线上（`workOrderLane` 给不出），但在任务详情的工单列表里、算项目"有工单没结束"（不能归档）。所属阶段在做时派出（`dispatched`，记 `dispatchedAt`）。拒绝的以新结局 `declined` 结束。
- **计划外工单的确认走守卫的判定函数**：一次计划外的派单作为伪工具调用 `work_order:unplanned` 交给 `judgeToolCall`（"计划外工单"类别，任务里默认先问我；用户只能往严里调，自定义类别按工具名也能匹配），不另写一套类别规则——和快速动作同一种做法。要确认的出工单卡（就是这次的确认，不另出审批卡），卡上的决定是"审批决定"素材。
- **回执随工单结束送达**：项目维护者交回执只是记下结局和说明、让这一段收尾；写回检查通过、段结束、工单结束之后，回执才作为一条通知进任务维护者的会话（订阅工单结束事件，幂等键按工单）。
- **阶段的回执门槛在执行控制器外面，只看现行计划**：执行控制器只问一句 `stageGate(task, stageId)`（不让宣布完成时给原因，不算一次），看现行计划里这一阶段的每一行（取最新那张，拒绝的不算）和计划外确认派出的；计划变更、自行调整之后去掉了的行，它的工单不再挡（时间线上记一笔）。调整做法——重新派单，或者改计划去掉退回、做不了的那一行——时派单器调执行控制器的 `countReturn`，和脚本、评审的退回同一份 `returns` 计数和阈值。
- **阶段的验收看得到回执，不用脚本**（17 号票评审后定）：交付件在各项目那边。评审子 agent 拿到本阶段的工单和回执，能只读访问涉及的各项目的档案和工作目录；由用户验收时待我处理里写着它们。验收脚本在任务的产出区里跑、碰不到各项目，所以多项目任务的计划里阶段的验收**不用脚本**（计划检查直接拒绝），而不是给脚本另开一份回执文件——最保守的做法。

## Consequences

- 计划卡版本从 3 升到 4：只认得旧版的前端把计划卡降级成纯文本加"去 Web 处理"；老的计划（没有 `stageId` / `acceptance`）照旧能读，只是多项目任务的检查要它们。
- 工单状态和结局多了值：派生视图、流水线的分栏、"维护者空着没有"都要先问"派出了没有"（协议包 `isUndispatchedWorkOrder`）。
- 一个阶段同一项目只有一行、同一时刻只有一张没结束的工单（重新派单要等上一张结束），"本阶段这个项目现在算数的那张"才有确定的答案；要在同一阶段给同一项目并行派两件事，得写进一行里或拆阶段。
- 回执要等写回之后才到：项目维护者交了回执、迟迟不写回，任务维护者就一直等（写回催满了照 16 号票转用户拍板，段照常结束、回执照常送达）。
- 计划外工单的处置跟着关注类别设置走：用户把"计划外工单"在全局调成"永不"，多项目任务的维护者就派不出计划外的工单，只能走计划变更加一行。
- 任务涉及几个项目定下之后改不了：单项目任务半路发现要动别的项目，只能重新发起一个多项目任务；多项目任务改到只剩一个项目，仍由任务自己的维护者靠工单做，不会交回给项目的维护者。
- 多项目任务的阶段只能由评审或用户验收：机械可查的标准写进各张工单自己的验收标准，由项目维护者在自己的工作目录里对照。

## Considered Options

- **计划里的项目行只写改动，确认时由运行时按阶段的交付件猜所属阶段**：猜不准，前置阶段没验收时后面的工单可能提前进了项目的流水线；让维护者写明最直接。
- **确认计划时直接派出所有工单、项目维护者自己等前置阶段**：工单会出现在项目流水线上却做不了，还占着"一次只做一件"的位置；规格要的是"所属阶段开始时才派出"。
- **计划外工单出一张审批卡**（和别的"先问我"一样）：再出一张工单卡就是两张卡问同一件事；工单卡本身就是这次的确认，判定仍然交给守卫。
- **回执由交回执的工具直接送给任务维护者**：送达时项目还没写回，任务维护者可能马上宣布阶段完成、开始下一阶段，而这张工单的写回检查还在进行；等工单真正结束再送，阶段门槛和工单状态一致。
- **"涉及多个项目"按计划现算**（17 号票第一版的做法）：计划变更删到只剩一个项目时任务的性质跟着变——工具包放开、回执门槛消失、剩下的工单没人管；建卡时定下更稳。
- **多项目任务的验收脚本另给一份回执文件**：脚本仍碰不到各项目的交付件，只能核对回执里的说法，等于没验；不如直接不用脚本。
