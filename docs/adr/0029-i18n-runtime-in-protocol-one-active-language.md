# 多语言：运行时和自带的语言文件放在共享协议包里，每个进程（页面）只有一种"正在用的语言"，t() 直接取它

2026-10-19 用户要多语言："界面支持中文、英文，而且要支持其他语言的扩展，最好是增加或者修改一些配置文件，就能够改掉这个语言。"定了三条：范围是界面文字、二狗生成给用户看的话、秘书和维护者用所选语言回答（系统提示和工具说明是写给模型看的，照旧中文，只加一句"用 <语言> 回答用户"；以前的聊天、卡片保持原来的语言）；中英自带，往 `~/.ergo/locales/` 放语言文件就能加新语言、改译法，不用重新打包，缺的句子用中文补；全局一个语言，所有设备、秘书都用它。

这是一次横跨全仓的改动（网页约 4400 处写死的中文、守护进程约 4800 处，其中一部分是给模型看的；共享协议包约 1000 处），按 expand–contract 分 8 张票：168 号票做底子和外壳，169–174 号票按区域并行迁，175 号票做鸿蒙 App 原生的文字和收尾。底子的几个取舍会决定后面 7 张票怎么写，所以记在这里。

## 决定

- **运行时和自带的语言文件放在共享协议包里**（`packages/protocol/src/i18n/`、`packages/protocol/locales/<语言>/<区域>.json`），网页、守护进程、协议包自己都从 `@ergo/protocol` 取 `t`。运行时只用 `Intl`，不加依赖：`t(key, params)`（`{name}` 插值）、单复数（key 后缀 `_one` / `_other`……按 `Intl.PluralRules` 挑，参数 `count` 定挑哪种）、`tParts`（句子中间放元素）、`tTable`（常量表写成 key、取值时现查）、`formatDate` / `formatNumber` / `formatList` / `formatRelativeTime`。读目录（fs）在守护进程（`packages/daemon/src/i18n/`），网页打包自带的用 Vite 的 `import.meta.glob`（`packages/web/src/app/locale-bundle.ts`）。
- **每个进程（每个页面）同时只有一种"正在用的语言"**（`setActiveLocale`），`t()` 直接取它，不经依赖注入。谁来换上：守护进程的语言设置（启动时、改了设置、`~/.ergo/locales` 里的文件变了）；网页一打开装上这台设备上次用的、连上后换成守护进程给的；单元测试由 vitest 的 setupFiles 装上自带的中文；别的 Node 入口要用 `t()` 的先 `installBuiltinLocales()`。守护进程停下时装回自带的中文。
- **语言文件按区域分文件**，文件名就是 key 的第一段（`shell.json` 里只有 `shell.*`），每个区域归一张迁移票，并行迁的票只碰自己区域的文件，合并时不打架；写死中文的棘轮的基线也是每个区域一个文件。
- **网页的词典从守护进程取完整的一份**（自带 + `~/.ergo/locales` 里的，合好的，只有网页用到的区域），**垫在打包进去的自带语言上面**：守护进程比网页旧（`npm run build:web` 之后还没重启守护进程）时，网页新加的句子照样有。换了语言、语言文件变了，守护进程在语言频道上推临时事件 `locale`（带词典的版本），开着的页面重取、整棵树重画，不刷新就换过来。
- **全局语言设置照个人助理的名字（43 号票）存和推**：配置区的 `language.json` 是真相，改动是语言频道上的 `language` 事件。实际在用的那种不在了（`~/.ergo/locales` 里删了）先用中文，设置不动。
- **给模型看的中文不翻**：只在每个 agent 的系统提示末尾加一句"用 <_meta.json 里给模型的语言名> 回答用户，给用户看的报告、文件也用它"，在 agent 管家拉起时接在前缀后面一起加（各种 agent 一处管到）。改了语言：秘书手头这一条处理完按新的提示重新拉起（同改名）；维护者交下一条输入之前看一眼拉起时的语言，换了就重新拉起。
- **守护进程里给模型看的、日志怎么排除出"写死的中文"**：白名单就是代码里的 `@i18n-ignore <原因>` 标注（原因只能是 model / log / fixed / data），日志调用（`log(…)`、`console.*(…)`）里的自动不算；`npm run i18n:check -- --ignored` 列出全部。

## Considered Options

- **新开一个工作区包 `packages/i18n/`**：最干净，但新工作区包要改 `package-lock.json`、在每个工作槽和主仓库里重新 `npm install`/`npm ci`（每套约 780 MB），部署的主仓库合并后不装就起不来。协议包本来就是守护进程和网页共用的那一个包，放在里面零成本；以后要拆出去，只动 import 路径。选放协议包。
- **t() 经依赖注入传给每个模块**：可测、不怕一个进程里起两个不同语言的守护进程。但守护进程约 4800 处、要穿过几十个模块的构造参数，迁移票改不过来；二狗是单用户、一个数据目录一个守护进程、全局一个语言，进程级的"正在用的语言"正好对应这件事。不选。代价见下。
- **守护进程只给网页覆盖的那几句（自带的网页自己有）**：省流量，但票面写明网页从守护进程取"完整的词典（自带 + 覆盖，合好的）"；而且守护进程的自带语言是它启动时读的、网页的是构建时打的，两边都留着、按先后垫起来，任何一边旧了都不缺句。选取完整的一份再垫上打包的。
- **ICU MessageFormat（`{count, plural, one {…} other {…}}`）**：表达力强，要自己写解析器；key 后缀的写法（i18next 同款）够用、翻译的人看得懂、检查工具好比。不选。
- **用 fs.watch 盯 `~/.ergo/locales`**：Windows 上编辑器存文件时事件重复、时有时无。改成每 2 秒看一眼目录里 .json 的路径、大小、修改时间（同网页的版本号，116 号票），变了再读、内容真变了才推。
- **排除给模型看的中文用一张集中的白名单表**：并行的迁移票都要改同一张表，合并打架；标注写在代码旁边，自己说明自己。选标注。

## Consequences

- **模块顶层不能调 `t()`**（那时可能还没装上语言），常量表用 `tTable` 包一层；`useMemo`、`memo` 了的组件里用 `t()` 的要自己订阅换语言（`useLocale()`）。写进 `docs/developer-guide.md` 的"多语言"一节。
- 同一个进程里同时起两个不同语言的守护进程不支持（测试里没有这种用法；起了守护进程的用例按它的设置换，停下装回中文）。
- 守护进程生成后存进事件的话按生成时的语言写死，以前存下的不跟着换；从结构化的数据现拼的界面文字（标签、状态名）跟着换。
- 网页的页面里打进了中文、英文两份网页用到的句子；以后自带的语言多了，页面跟着大。
- 守护进程的 agent 子进程（`runtime/agent-child/`）目前不装语言（里面没有给用户看的话）；174 号票迁到那里要用 `t()` 时，子进程入口先 `installBuiltinLocales()`，语言随拉起参数传过去。
