# 先把功能跑通、安全机制后接：对话里的"先问我"靠开关关掉、秘书能联网；任务和流程的计划授权、受保护区域照旧

用户 2026-10-10 定：**先把功能全面跑通，后续再接入安全机制**；已经实现的安全机制代码保留，按下面的范围关闭使用（调研 [17](../research/17-auto-mode-reviewer-agent.md) 的"用户已定"一节：以后普通对话参考 Claude Code 的 auto mode，加一个独立上下文的审查 agent，"先问我"仍一定问、新加的"先审查"一档才交给审查；秘书直接联网，加污染标记和审查）。在那之前，70 号票定成：

- **对话里的"先问我"关掉，一个开关管**：配置 `guard.conversationApprovals`，`"off"`（默认）或 `"on"`。关着时，不属于任务的调用里处置为"先问我"的依据一律按"直接做只记录"——关注类别照常命中、照常写进工具调用记录、效果日志、完整内容，依据上记 `approvalsOff`；对话里不出审批卡。开着时一切照原样。判定函数本身从严：输入里不传按 `on`，只有守卫接入按配置传。
- **起草计划算对话**（评审后主会话定）："不属于任务的调用"一刀切，除了秘书会话、项目维护者的对话段，还包括任务维护者起草计划、项目维护者起草计划的工单段——它们原来就按对话里的处置判（计划确认之前不属于任务）。
- **关掉的只有"先问我"这一档**：硬拒绝（文件工具写围栏外、密钥区连读都拒绝、联网开关关着时联网、工具包没给的工具、子 agent 写项目档案）、按规则退回、"永不"（受保护区域写入、对外内容含密钥、读过密钥文件之后往外送、一律禁止的时序规则）、"交给我做"（花钱、付款和改密码这条底线）、"做完告诉我"都不变。
- **牵涉密钥和受保护区域、判断不了的照旧先问**（评审后定）：用户的保留项"不读密钥文件""不许改二狗自己的数据库和配置"不随对话审批关掉。下面这几种依据上记 `keepAsking`，对话审批关着也照旧先问、对话里仍会出审批卡：
  - 要写（或看不出读写）的路径没法确定（`cp a "$T/ergo.json"`、`rm -rf "$T"`：可能落在受保护区域里）；
  - "读过 .env 或密钥文件之后不许往外送""对外内容不许含密钥"这两条 v1 模板判断不了（比如之前读过路径不明的文件，这次要发 POST）；
  - 脚本里写着受保护区域的路径（守卫看不出脚本是读还是写，原来按"未知的写操作"先问）。

  别的"判断不了"照开关走：只读的路径没法确定（`cat "$F"`）、删除或覆盖之前缺 git 事实、拆不开的命令里没写着受保护区域的路径，关着时都直接做。
- **任务和流程不受这个开关影响**：计划、授权项、本任务的关注类别、执行时的时序规则和逐步核对（58、59 号票）、任务里的处置都照旧；定时作业的一次运行带着作业的授权，也照旧。快速动作的确认也不接这个开关：秘书推断出来的快速动作照旧出卡请用户确认——那是确认用户的意图，不是安全审批。
- **秘书能联网**：去掉写死的"秘书一律按联网关着判"（守卫）和 `network: false`（装配），秘书的联网开关开着（`secretary.ts` 的 `SECRETARY_NETWORK`）：守卫不再拒绝秘书联网的工具和命令，bash 起的进程不再设无效代理。联网关着时的那一套（守卫拒绝、脚本扫描、无效代理）代码都还在，联网开关关着的维护者照旧用它。起草计划时的工具包（`PLANNING_TOOLKIT`）也开了联网：起草时没有 bash、MCP，会联网的只有下面两个工具。涉及多个项目的任务的维护者的固定工具包（`MULTI_PROJECT_TOOLKIT`）和它同一份，起草和执行时都能联网（评审后主会话定：符合"先跑通功能"）。
- **所有 agent 配上联网搜索、读网页**：二狗自己的两个工具 `web_search(query, n?, time?, engine?, region?, tavily?, json?)`、`web_fetch(url, max?)`，守护进程代为执行，登记在框架自带的工具注册表里（来源 `web`：只看、只往下拉、不落入任何类别，要联网）。秘书、任务维护者（起草和执行）、项目维护者、定时作业的维护者、子 agent 都有；评审子 agent 没有。它们和口语总结一起放在"每个会话都配的工具"这一个装配用的对象里（`conversation/session-tools.ts`），不一样样穿过各模块的选项。做法照用户的 web-search skill：playwright-core（写死 1.61.0）驱动系统装的浏览器真实渲染，不下载浏览器；搜索 DuckDuckGo → Bing → Google 回退，选项和 `search.mjs` 逐个对齐（用户要求：指定引擎、地区、Tavily、JSON）；Tavily 要 API key，只从守护进程的环境变量 `TAVILY_API_KEY` 取（LSM 从数据目录密钥区的文件注入），代码、配置、仓库里都没有 key，没配时工具说清楚去 LSM 里加。读网页先直接请求（有超时、正文有大小上限）、被拦了或超时了换浏览器。浏览器在哪只探测一处（`browser-path.ts`：`AGENT_BROWSER_EXECUTABLE_PATH` → agent-browser 自带的签名 Chrome → 系统 Chrome，跳过没有签名的；一个进程只探一次，没找到也记住），只多一处：用户在二狗的配置里显式写了 `web.browserPath` 时它排最前；拉起 agent 时同一个路径放进 bash 的环境（`AGENT_BROWSER_EXECUTABLE_PATH`），agent-browser 这类 skill 直接能用。
- **grep、find 给所有 agent**：原来联网开关关着的会话装配时去掉它们（怕第一次用时 pi 去下载 rg、fd）；子进程的环境本来就固定带 `PI_OFFLINE=1`，pi 找不到 rg、fd 时不下载、工具出错，所以照给。

## Consequences

- 对话里的保护只剩硬拒绝、永不、交给我做，以及牵涉密钥和受保护区域、判断不了的先问：秘书和维护者在对话里读草稿区外的文件、在 bash 里碰别处的（确定的）路径、发非 GET 的请求、用通用 bash 做拆不开的事，都直接做，事后只能从工具调用记录、效果日志和关注类别标注里看。要回到原样把 `guard.conversationApprovals` 写成 `"on"`。
- 秘书读得到全部记忆又能联网，"不给它往外发东西的口子"（规格第 7 节原来的理由）不再成立：读过外部内容之后往外送、GET 里夹带数据都不拦（"对外内容含密钥"和"读过密钥文件之后往外送"仍是永不）。污染标记和审查 agent 到接入安全机制时再做（调研 17 §3.4、§5）。
- `web_fetch` 是守护进程自己发的请求，能读到本机端口（含二狗自己的本机端口，它不认 Origin 就信任本机）；这和开了联网的 agent 在 bash 里 `curl` 本机一样，没有另加限制，留到接入安全机制时一起看（只记录，不实现）。
- 浏览器路径一个进程只探一次：改了 `web.browserPath`、装了浏览器要重启二狗才认。
- 定时作业的维护者每次运行的装配里也有了口语总结（"每个会话都配的工具"是同一个对象；项目里的定时作业原来就有）。
- 测试里联网搜索、读网页一律是假的（不起浏览器、不连真网络），浏览器路径也是假的；真网络只有手动跑的冒烟脚本 `npm run smoke:web`。测试底座默认把对话审批打开（审批、"等你"、被杀后恢复这些用例测的就是这套机制），测关掉的用例显式写 `off`。
- 秘书的系统提示里草稿区外的说法跟着开关写（71 号票会把系统提示挪进 md 文件）。

## Considered Options

- **删掉审批的代码**：用户定了代码保留、以后一个开关就能打开；而且任务和流程还在用同一套审批。
- **关掉对话里的全部处置（连"交给我做""永不"一起）**：花钱照旧交给用户做，受保护区域、密钥照旧硬挡，用户明确只关"先问我"。
- **只给秘书联网，维护者起草时照旧不联网**：票面要任务维护者起草和执行都配上联网工具，起草时联网关着的话工具配上了也用不了。
- **只关"先问我"、判断不了的也一律放开**：评审实测读过路径不明的文件之后发 POST、`cp a "$T/ergo.json"` 都直接执行了，等于用户定的保留项（不读密钥文件、不许改二狗自己的数据库和配置）在对话里失效。
- **联网工具按联网开关决定配不配**：工具包变了要重新装配才有；现在一律配上，联网开关关着时守卫拒绝、说明写明怎么开，和别的联网工具一个口径。
- **联网工具不进框架自带的注册表、按宿主工具登记**：流程的步骤里就写不了它们（步骤只能写框架自带的工具），详情页的效果记录也认不出网址；和带类型的 bash 工具一样登记在框架里。

## 补充：对话审批关着时的范围（2026-10-12 用户定，101 号票）

用户 2026-10-12："现阶段安全不要搞得太敏感，超出了授权范围内的，如果是任务的 agent 的话先不管，因为他能访问到的数据有限，但是那个二狗秘书，稍微管一下特别敏感的操作，要我授权。"（之前主会话提的"用户在场直接下的指令就是授权、按这一轮是不是用户发的消息来分"随之不要了。）`guard.conversationApprovals` 关着（默认）时改成按发起调用的 agent 分两套，开着时一切照原样：

- **任务的 agent**（秘书以外的 agent：任务的维护者执行、定时 / 事件触发的运行、子 agent、评审子 agent、项目维护者的执行工单段；项目维护者的对话段、起草计划也按这一套）：超出授权的一律不拦——"先问我"类别、"计划里列了才做"没被授权项覆盖的（超出授权、没预料到的类别）、上面那几种判断不了的（`keepAsking`）和时序规则判断不了的、对被判过"永不"的对象再做对外动作、流程执行时计划外会改东西的和超出步骤写的对象，都按"直接做、照常标出"（依据记 `beyondGrant`，"任务 agent 超出授权先不管，照常标出"；工具调用记录上带 `beyondGrant`，详情里写明）；用到别的阶段的授权项不拉回；计划外的工单直接派出。任务和流程因此也受这个开关管（原来"任务和流程不受这个开关影响"那一条作废）。
- **秘书**：大部分直接做、照常标出，含上面那几种判断不了的（原来照旧先问的，现在只作标记）；**特别敏感的要用户授权**（出审批卡，批了才做）：以我的名义对外发送或发布、账户与安全（凭据、权限、全局装软件）、不可逆的提交、写（含删除、覆盖）草稿区之外——删除或覆盖的路径没法确定的也算（可能在草稿区外）；秘书的文件工具写草稿区外原来是硬拒绝，改成这一档。
- **都不变的**：三条硬底线（写二狗自己的受保护区域、读密钥区、已经确定要把密钥内容往外送）、别的硬拒绝、永不（含用户在关注类别里设的）、交给我做（花钱、付款转账、建账户、改密码或两步验证——用户自己动手的事）、做完告诉我；判断出来确实违反的时序规则（要问的问、退回的退回）、流程的步骤先后和自动纠偏（保证照计划做事，不是权限）照旧。

这样一来，用户定的保留项"不读密钥文件""不许改二狗自己的数据库和配置"主要靠三条硬底线守：读过路径不明的文件之后往外送，关着时任务的 agent 和秘书都直接做。要回到原样把 `guard.conversationApprovals` 写成 `"on"`。

评审后（2026-10-12）补了一条原则：凡是原来因为"可能碰到硬底线"才问的，秘书和任务的 agent 都照旧问或拒，只放开和硬底线无关的问——要写（或看不出读写）的路径没法确定的（只读的照放开）、带通配符的路径（展开后逐个比，展不开的看通配符之前那段目录）、看不透的命令（`powershell -Command`、`python -c`、`node -e`……）里写着数据目录或受保护区域的路径（含 `~`、`$HOME`、环境变量拼出来的和短名）、确实读过 .env 或密钥文件之后又有看不透可能往外送的调用。秘书的特别敏感另补上看不透的命令和看不出读写的程序碰草稿区外、看不透的命令往外送；发往本机（127.0.0.1、localhost、::1）的请求不算对外。秘书交给普通任务去做就绕开了特别敏感，这是用户选的（任务的 agent 放开），接受，任务里照样守硬底线。

## 补充：联网搜索、读网页接入 DeepSeek 的 Search / Fetch 接口（2026-10-18 用户定，154 号票）

用户 2026-10-18："deepseek 提供了新的能力：请参考并接入"，随后补充"deepseek 的这两个工具作为一种选择，不作为唯一方式"。

- **几种方式并列，一个都不去掉**：联网搜索有浏览器（DDG → Bing → Google，照旧）、DeepSeek 的搜索接口（`POST /v1/tools/search`）、Tavily（照旧）；`web_search` 的 `engine` 能指定任何一种（`deepseek`、`browser`——浏览器的整条回退链、`ddg` / `bing` / `google`——只用这一个、`tavily`），指定了就只用它、没成就报。
- **"默认用哪种"是设置里的一个选项**（设置 · 浏览与填框，存在数据目录配置区的 `web-settings.json`，所有设备一样）：DeepSeek 还是浏览器。配了 DeepSeek 的 key 时初始默认 DeepSeek，用户随时能切回浏览器；没 key 时只能是浏览器。默认那种没搜成时换另一种（另一种是 DeepSeek 时要配了 key），结果里写明"DeepSeek 没搜成（原因），这次用的是浏览器"或反过来。
- **读网页**：DeepSeek 读网页接口（`POST /v1/tools/fetch`，回 Markdown）是 `web_fetch` 的一种方式，设置里能单独关掉：开着是"直接请求 → DeepSeek → 浏览器"，关着（或没 key）是原来的"直接请求 → 浏览器"。本机、内网的网址不交给 DeepSeek。
- **key 和模型共用同一份**（环境变量 `DEEPSEEK_API_KEY`，LSM 从数据目录密钥区注入，守护进程每次现取），只在守护进程里用；代码、配置、仓库里没有 key。
- **守卫的归类不变**：DeepSeek 的两个接口是守护进程代为执行 `web_search`、`web_fetch` 时调的，归类照联网工具（只看、要联网、不落入任何关注类别），没有新工具。
- **花钱的照账本记**：DeepSeek 只对成功、有结果的调用计费（每 1000 次 5 元），每次成功的记一条（账本频道的 `web_call`），记在发起调用的 agent 名下（和它的 token 用量同一套归属），消耗页另起一节"联网搜索、读网页（按次计费）"。

### Consequences

- 搜索结果的样子多了一种：DeepSeek 的每条写站点、日期、"优质"（相关度 ≥ 1.5）、"权威"（权威度 ≥ 3）和长摘要；`json` 给 DeepSeek 原样的字段。工具说明写清各种方式什么时候用、DeepSeek 的搜索语法（`site:`、`lang:`、`after:`……）。
- 账号级限速（Search、Fetch 各每秒 5 次）在守护进程里各一个限速器，所有 agent 共用；408、429、5xx 等一下重试，最多两次；402 余额不足不重试、直接换浏览器，设置页上写明"DeepSeek 余额不足"（只在内存里记，守护进程重启、之后成功一次就清掉）。
- 默认设成浏览器而浏览器没搜到时，配了 key 也会换 DeepSeek（花钱）；用户要完全不花钱时把 key 去掉，或者以后再加一档"只用浏览器"。
- 测试里 DeepSeek 一律是本机临时端口上的假服务（`startTestDaemon` 默认把地址指向连不上的本机 1 号端口），不用真 key；真的调用只有手动跑的 `npm run smoke:web -- --deepseek`。

### Considered Options

- **DeepSeek 作为唯一的搜索方式、浏览器只当回退**：票面最初是这样写的；用户补充"作为一种选择，不作为唯一方式"，改成并列加设置项。
- **查询超过 128 字截短再发**：截短可能把搜索语法截坏，改成不发、换浏览器并写明。

## 补充：联网搜索改成三种方式的队列（2026-10-18 用户定，162 号票）

用户 2026-10-18："把搜索与填框里面的选项改成这种形式：这三种方式的名称、特点作为一个标签。三个标签在一个队列里面排序（可以手动改变顺序，拖动或者上移下移的按钮都可以）。需要用的时候，排最上面的最优先。这三个也可以 disable，但是不能全部 disable，至少要保留一个。enable 的搜索方式，如果第一个失效，就转而使用下一个，按顺序切换。"三种方式：DeepSeek 付费搜索、二狗自带的浏览器搜索、agent-browser（模型自己在 bash 里操控 Chrome）。特点和初始顺序照 161 号票的对比报告（[调研 20](../research/20-search-methods-benchmark.md) §6）。

- **一个队列代替 154 号票的两个设置**：设置里存三项 `{ method, enabled }`，排前面的先用；初始 DeepSeek → 浏览器 → agent-browser，都启用（DeepSeek 要配了 key 才实际用上，没 key 时那一项不能启用，存着的不变）。至少留一个启用而且用得上的，不合规的存不进去。154 号票的"默认用 DeepSeek 还是浏览器""读网页用不用 DeepSeek"不再单独有：旧设置文件读成队列（默认浏览器的浏览器排第一、DeepSeek 第二），"读网页用不用 DeepSeek"并进 DeepSeek 的启用开关（启用着就搜索、读网页都用）。
- **按队列依次试、失效了换下一个**：`web_search` 不指定方式时依次试启用的（出错、超时、没结果、余额不足都算失效），结果里写明用了哪种、前面的为什么没成；`web_fetch` 先直接请求，被拦了按队列换 DeepSeek 读网页、浏览器。154 号票的"默认那种没搜成换另一种"是它的特例。
- **agent-browser 在队列里，但工具做不了它**：它是模型自己在 bash 里操作的，位置写进各 agent 的上下文（`web_search` 的说明，这个 agent 有 bash 时）：排第一时先用它，排中间时 `web_search` 试到它前面为止、停下让模型用它，排最后时都没成再用它，停用时别拿它搜索（skill 照旧能操作网页、下载文件），只启用它时 `web_search` 回"联网搜索现在只用 agent-browser"；都附上"别用管道接它的输出，重定向到文件"（调研 20 §5.1）。`web_fetch` 没有指定方式的参数，agent-browser 不打断它，都没读到时提示用它。
- **显式指定方式也受队列管**（161 号票报告 §6.3，主会话 2026-10-19 定，改了票面"engine 显式指定时照旧只用那种（不受队列影响）"的口径）：工具说明和 `engine` 的可选值只写启用着、用得上的方式，Tavily 配了 key 才写；指定了启用着的方式照旧只用那一种、没成不换；停用了的、没 key 的硬写过不了参数校验，会话还是旧说明时回"这种方式已停用"。Tavily 不在队列里，照旧只在指定时用。

### Consequences

- 工具说明跟着设置变：每次装配时现写，设置改了常驻的秘书手头这一条处理完按新的重新装配（接着同一条主线会话，前缀缓存失效这一次），维护者、子 agent 下次唤起就是新的；执行中途改了设置的，那一段的说明还是旧的，调用时照最新的设置判。
- 全部停用 DeepSeek 就完全不花钱（154 号票 Consequences 里"以后再加一档只用浏览器"由此做到）；代价是搜和读平均慢一倍（调研 20 §6.1）。
- 只启用了 DeepSeek、key 后来又没了时，实际临时用浏览器（不让 agent 一种都搜不了），设置页上写明；改任何一处时浏览器一并存成启用。

### Considered Options

- **显式指定照旧不受队列影响**（票面原来的口径）：调研 20 里模型看到说明里有 `deepseek` 就自己去指定，正式运行时会绕过队列直接花钱，用户停用了也拦不住。
- **agent-browser 排中间时 `web_search` 跳过它接着试后面的**：简单，但不是用户要的"按顺序切换"；`web_search` 有 `engine` 参数，停下让模型先用 agent-browser、再指定后面的能照顺序来。`web_fetch` 没有这个参数，所以它不停。

## 补充：队列加第四种"鸿蒙 App 的内置浏览器"（2026-10-19 用户定，182 号票）

用户 2026-10-19："现在有四种办法……第四个就是二狗鸿蒙客户端内嵌浏览器。"队列多一种方式：秘书在用户从浏览侧边栏、悬浮按钮跟它说话的那一轮，用 browse_* 工具（147、149、164 号票）在用户手机上的浏览器里打开搜索结果页（用那台设备"浏览"里设的搜索引擎）看、点。初始排最后、启用；162 号票存的三项读的时候把它加在最后，认不得的方式跳过。它和 agent-browser 一样是模型自己操作的：别的轮次（和别的 agent）跳过它；那一轮排在前面时 `web_search` 试到它为止、停下并给出结果页的地址，排第一时一种都不试（agent-browser 排第一时调了 `web_search` 就接着往后试——说明是装配时写的、不分哪一轮，靠 `web_search` 停下来告诉秘书这一轮该先用它）。工具说明只给有 browse_* 工具的秘书写它的位置、写明只在那一轮算数，不按轮换说明（换说明要重新装配、前缀缓存失效，147 号票为此工具列表固定），那一轮交给秘书的输入后面另加一句。停用它只是不拿它来搜索，用户要的网页操作照旧。守卫的归类不变：还是这两个联网工具和 147、164 号票的网页工具。

## 补充：新装时收紧、设置里能关（2026-10-27 用户定，315 号票）

开源后第一次装二狗的人，对二狗和自己接的模型还没建立信任。用户 2026-10-27："风险和任务预算的事情，做成一个设置吧。默认收紧，如果用户觉得比较难受，它可以自己关掉。"

- **新装时**（守护进程起来时数据目录里还没有事件库）把对话审批（`guard.conversationApprovals: "on"`）和任务的预算控制（`tasks.thresholds.budgetControl: true`，93 号票"先不做预算控制"的那一项）明着写进配置文件，已经写了的键不碰。
- **代码里的默认值不变**（照旧 `off`、`false`）：已有的数据目录里没写这两项的照旧关着，用户自己的二狗升级前后一样。
- **设置 · 关注类别最上面两个开关**（"有风险的事先问我""任务超预算就停下"），每个下面一句写开着、关掉各会怎样；改了写回配置文件、马上生效（守卫、预算核对、系统提示都现取）。319 号票的设置向导复用同一对接口（`GET / PUT /api/safety-settings`）。
- 秘书联网、起草计划时联网、浏览侧边栏点"提交 / 运行"这几项不收（收了核心功能就断，风险靠上面的开关和以后的污染标记 / 审查 agent）。
