# ADR-0033 安装布局、版本切换和发布包签名

状态：已定（318 号票；切版本那一条用户 2026-10-27 改过一次）

## 背景

- 开源后不装 Node 的人也要能装：发布包自带一份官方 Node（ADR-0031），网页预构建好，第三方包按平台带上，用户机器上不用 `npm ci`、不用编译。
- 升级要能"新版本进新目录、空闲时切、旧版本留一份能回滚"，还要不碰数据（数据一直在 `%USERPROFILE%\.ergo`，服务管家的在 `%LOCALAPPDATA%\ergo\supervisor`）。
- 第一版不买代码签名证书（用户 2026-10-26 定），所以安装这条链要能在"未知发布者"的警告下走通：不要求管理员、走用户目录和用户 PATH。

## 决定

1. **布局**：`%LOCALAPPDATA%\Programs\ergo\`
   - `versions\<版本>\`：一个版本一个目录（`ergo.json` 版本信息、`node\` 或 `node.path`、`app\`（转好的 JS + 第三方包 + 网页 + 服务管家）、启动器、许可证清单）；
   - `current`：**一行文本**，写着在用的版本目录名；
   - `bin\`：只放 `ergo.exe` / `ergo.cmd`，加进用户 PATH 的就是这一个目录；
   - `install.json`：在用的、上一个版本、发布来源。
2. **切版本就是改 `current` 那一行**（先写 `.tmp` 再改名）：**不建目录联接**。原来用联接，但经启动器（PowerShell → `ergo.exe` → node）跑 `ergo update` 时建联接会被安全软件按进程链拦（EPERM），直接用 node 跑却能切——2026-10-27 用户定改成写文件。老安装的联接照样认，第一次切换时换成文本。
3. **启动器**：`ergo.exe` 用 Windows 自带的 C# 编译器编（只做一件事：读 `current`、找 `node`、跑 `app\packages\daemon\src\cli\main.js`，参数和退出码原样传）；编不了或被杀毒软件拦了就退到功能相同的 `ergo.cmd`。不做 SEA 单文件 exe（原生库塞不进去，ESM 还要额外打包）。
4. **签名**：发布钥匙是兼容 minisign 的一对（Ed25519 + BLAKE2b），发版时签 `SHA256SUMS` 和组件清单；安装脚本和 `ergo update` 先验签再往下走（公钥随程序发布，另有环境变量可覆盖，给自建发布地址的人用）。私钥不进仓库；存在哪一步由用户定。
5. **服务管家登记**：每次 `ergo start` 按 `current` 指向的那个版本目录重写登记，所以升级后重起就是新版本，不用手动改登记。
6. **源码装和发布包共用同一套构建脚本**（`stage.ts`）：`npm run build` 摆开发镜像、`npm run ergo:install` 装进同一个布局，`--link` 只把版本目录联到开发镜像上。

## 后果

- 升级/回滚不碰数据；旧版本留一份，删不动（被占用）的留到下次再删。
- 切版本不再依赖目录联接，安全软件按进程链拦的概率消失；代价是"在用的版本"多了一个小文件要维护（手改错了要能看出来：`ergo version`、`ergo update` 会说找不到装好的版本）。
- 没买代码签名证书：安装时可能看到"未知发布者"，360 一类还可能删掉 `ergo.exe`（有 `ergo.cmd` 兜底）；用户手册"出问题怎么办"里写了三条出路（加信任、用 `ergo.cmd`、改用 npm 装）。
- 发布包的校验只到"发布钥匙签过"这一层，没有 Windows 的 Authenticode，所以"谁签的"要靠公钥可信，不是系统信任链。
