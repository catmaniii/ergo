# 0019 两种任务：流程和长程任务

日期：2026-10-09
状态：已采纳（推翻 issue 12"统一成一种计划"）

## 背景

issue 12 定过"任务只有一种计划"：维护者把工作拆成阶段，逐阶段执行和验收。用户 2026-10-09 要求照搬 AgentSense 的两种模式，"几乎一模一样"：

- 固定阶段的任务（用户叫 workflow）；
- 动态阶段、分多个 milestone 的长程任务。

调研见 `docs/research/15-agentsense-zoom-detail-task-modes.md` 第 4 节。

- AgentSense 的"里程碑计划"就是二狗现在的任务。
- AgentSense 的"固定计划"是：
  - 模型按用户的需求现场排出一串步骤，每步是一次工具调用（工具 + 参数），连同每一步要满足的条件（时序规则）；
  - 审查修补后一次授权；
  - 执行时每次调用都和计划比对，偏了能修的自动修回；
  - 没有逐步验收。

问"流程的阶段从哪来"时，用户的回答是：参照 AgentSense 里根据用户需求定固定流程和步骤的做法，每一步、连同每一步要满足的条件（时序逻辑）都要写出来。可复用的流程模板不是用户要的。

## 决定

任务分两种，建卡时定下，之后不能换：

- **流程**：照搬 AgentSense 的固定计划。
  - 维护者起草的计划是一串**步骤**：每步是一次工具调用（工具和参数）和它要满足的条件。条件用二狗已有的时序规则表达（ADR 0005：之前必须做过、之前不能做过、当下必须满足、一律禁止）。
  - 计划先过审查修补，再由用户在计划卡上一次授权。
  - 执行时，守卫把每次调用和计划比对：计划外、超范围、顺序错、重复、禁止。能修的自动修回（改回参数、引回前置步骤），每步有上限；修不了的再问用户。
  - 一轮要收工时还有没做的步骤，就提醒一次。
  - 不逐步验收，执行中不能改步骤。
- **长程任务**：二狗原来的任务，计划由阶段组成，逐阶段验收、可以计划变更。原有的任务都算这一种。

**发起**：只有用户点明了才发起。点明包括：

- 在消息里说"发起任务""长程任务""按流程做"之类；
- 输入 `/流程`、`/任务`；
- 在发起对话框里选了种类。

没点明的一律按普通对话处理。秘书觉得该发起时，最多给一张建议卡，上面两个按钮："作为流程""作为长程任务"。这取代了原来的"用户要秘书去做某件需要任务的事，这个要求就是授权"。

定时作业、快速动作、简单提醒、立项都不归入这两种，照旧。

## 后果

- 守卫要多一层"和流程计划比对"。AgentSense 的 `guard.ts`、`planguardReviewer.ts`、`planguardMonitor.ts` 是参照。二狗已经搬了时序规则的引擎核心（ADR 0005），比对和修回要新写。
- 二狗的工具粒度比 AgentSense 的场景工具细（bash、读、改文件），流程里的步骤按二狗的工具写。带类型的特殊 bash 工具（28 号票）能让步骤写得更具体。通用 bash 的步骤，参数比对只能比到命令这一层。
- 术语表把"长程任务"从避免用词里拿出来，新加"流程""长程任务""步骤"；"阶段"只用于长程任务。
- 秘书多一个 `start_workflow` 工具。`create_task` 专管长程任务。"建议发起任务"卡变成两个按钮。
