# 工具调用的完整参数和返回：调用结束时擦过、截过另存进事件日志，不去读 pi 的会话文件

规格第 19 节（会话区照搬 AgentSense）要详情页列出工具调用的完整参数和返回。之前事件日志里只有工具调用记录的摘要（参数 160 字、结果 200 字），完整的只在 pi 的会话文件里。53 号票让守护进程按调用 id 给出完整内容，要求和摘要一样经过 `CallPrivacy`、单个值太长截断并注明、二进制不内联、重启后照样取得到、彻底删除时一起删，怎么拿由实现定。定成：

- **在 `tool_call_end` 时另存一份**（`guard-runtime/tool-call-details.ts`）：守护进程内部频道 `tool_calls` 上的 `tool_call_detail` 事件，负载就是协议包的 `ToolCallDetail`；排在这次调用的工具调用记录之前（前端看到记录时就取得到，也不插在记录和紧跟着的效果日志之间）。经守卫的调用都有：秘书、维护者、子 agent、评审，被拦下的、出错的也有。
- **写之前处理好**：同一份 `CallPrivacy`（必给；读过的密钥值、认得出的密钥形态——守卫的 `SECRET_PATTERNS`，评审后加，工具调用记录的摘要也用这一套——换成"（密钥）"，读了密钥文件的不记返回）；返回的文字、参数里的每个字符串各算一个值，超过 200KB（UTF-8）的只留开头、末尾注明已截断和原长，`truncated` 按 JSON Pointer 列出；先擦再截。图片这类非文字的块本来就不过宿主协议，子进程在 `tool_call_end.media` 里说明是什么、多大（宿主协议 11）。
- **按调用 id 取**：派生视图 `tool_call_details` 记调用 id → 事件的全局序号，外加工具、agent、会话、项目；`GET /api/tool-calls/<调用 id>` 读回事件；同一个 id 有几份取最后一份。
- **归属**：和工具调用记录同一份（判定那一刻的任务、项目、阶段）。评审子 agent 的调用不在任何会话里，接守卫时也带上它评审的任务、阶段和项目（评审后加），删除项目时靠它找到。
- **彻底删除照 ADR-0008 的口径**：字段级改写（参数里的文字、返回换成删除标记，`purged: true`，工具、结局、归属不变）。改写哪些跟着已有的范围走：调用记录、执行记录被改写的那些调用；另外检索素材的调用按完整返回里提到的素材 id 找（摘要只有开头）：先按视图的工具列筛出检索调用，只看这些的负载。删除项目（ADR-0010）时，项目维护者会话里的（含子 agent 的）、维护者的、归属这个项目的（含评审子 agent 的）一起改写；66 号票起还有项目之外读过这个项目的（秘书会话里的、跨项目任务的维护者和评审的：读项目档案的按返回开头的项目编号，别的按碰到的路径和项目档案、工作目录有包含关系找，见 ADR-0010；先按视图的几列和效果日志筛，再逐条读负载），删除项目时改写的另记 `purgedBy: "project_deletion"`（详情页写"已随项目删除"）；被删掉的完整内容不再留过了保留期清掉的说明。

## Consequences

- 事件日志（和备份快照）多存一份工具调用的内容，单次最多大约两个 200KB 再加参数里别的字符串；pi 自带的工具结果本来就截在 50KB 左右，多数调用只有几 KB。按调用 id 取靠派生视图；彻底删除、删除项目按视图的列（调用 id、工具、会话、agent、项目）先挑出那几条再读负载，不整频道读，也不逐字扫全部完整内容。总量上限和保留期见 ADR-0024（65 号票：过了保留期、超出总量上限的换成只剩摘要的精简版）。
- 完整内容和摘要一样"擦得到的才擦"：读过的值只在擦得到的时候（同一任务、同一段会话，守护进程没重启过）换掉，密钥形态只认正则认得出的；这些限制写在 30 号票，这里不加新的。密钥形态的擦除同时用在工具调用记录、效果日志、审批、"交给我做"上（同一份 `CallPrivacy`）。
- 只靠完整内容找到的检索调用，会话频道上的 `messages_purged` 不会列出（它的工具调用记录没改）：前端不要缓存完整内容，每次打开详情现取。
- `tool_call_detail` 永久留在个人数据里，以后改 `ToolCallDetail` 只加可选字段（协议上也承诺"宽松、向后兼容"）。本票之前的调用没有完整内容，接口回 404，详情页退回摘要。
- 彻底删除时只要一次检索结果里列出过被删的素材，这次检索的完整内容整条换成删除标记，同一次检索里别的素材的摘录也看不到了（不逐行改：和会话文件里按行改不同，这里宁可多删）。

## Considered Options

- **读 pi 的会话文件**：不多存一份，但隐私处理做不到——读过的密钥值只在守护进程内存里，重启后再读会话文件就擦不掉了；会话文件是 pi 的格式，只能在 `agent-child/` 里读（ADR-0004），HTTP 请求里起一次性子进程、还得先知道调用在哪个 agent 的哪个会话文件里；评审子 agent 的会话不留，删项目时维护者的会话文件整个删掉，那些调用就取不到了。
- **完整内容直接放进工具调用 part**：消息事件会推给前端、进历史分页和重连补发，每条工具调用都带着几百 KB；规格要求消息里的 part 照旧只有摘要。
- **另开一张不从事件来的表或一组文件**：事件日志是唯一真相，备份、恢复、彻底删除（同一事务改写、`secure_delete` 和 WAL 检查点）都围着它转；另起一份存储要把这些各做一遍。
- **整段参数序列化后截断**：结构就坏了，详情页没法按字段画；按字符串截保住结构，截掉的位置用 JSON Pointer 说清。
