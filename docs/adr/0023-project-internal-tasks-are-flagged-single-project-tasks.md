# 0023 项目内部任务是带 internal 标记的单项目任务，事件照旧在看板频道，"只在项目内部可见"由看的地方按同一个标记过滤

日期：2026-10-09
状态：已采纳（64 号票）

## 背景

用户 2026-10-09 定：项目的维护者也能在自己项目里用流程或长程任务做代码维护，由它自己执行；发起的规矩和秘书一样（用户在项目会话里点明，或维护者给建议卡、用户点了才发起）；后来又定：**只涉及一个项目的任务一律建成这个项目的内部任务**，不管从哪个入口发起（"发起任务"对话框里选了一个项目、建议卡上写了一个项目、秘书那里点明），流程和长程任务都一样，全局看板只放跨项目的和不属于任何项目的任务；不上全局任务看板，只在项目页和项目会话里看得到，计划卡、审批、卡住求助照常进待办；秘书看不到它的细节；结束了的由用户在项目页上归档；它计划里的定时作业不上全局看板的"运营中"，在项目页里；删除项目时它的内部任务一起删掉（规格第 8 节"项目内部任务"）。

二狗已经有"只涉及一个项目的任务由这个项目的维护者起草并执行"（16 号票）：任务书交给项目的维护者变成起草计划的工单，确认计划后派执行工单，会话分段（ADR-0012）、范围审视（ADR-0016）、全局执行名额、token 账本、被杀后的恢复都按任务走。任务的每次变化是看板频道上的一条 `task` 事件，任务模块、执行控制器、派单器、名额、项目维护者模块、前端都订阅它。

## 决定

- **规则只有一条：只涉及一个项目的任务就是这个项目的内部任务**。任务模块建卡时（`buildCreate`）涉及的项目认出来恰好一个、建卡时没写项目而第一版任务书只涉及一个项目（`settledByBrief`，和交给项目的维护者同一条事件）都按这一条标上；首个建设任务也一样。之前建的单项目任务没有标记，照旧在全局看板上（不改写旧数据）。
- **规则只管"建的时候"**（2026-10-10 用户定）：建卡时定下是跨项目的任务，后来计划里缩到只涉及一个项目的，留在全局看板，照旧做完，不中途转成内部任务。
- **立项书确认之前不能建**（规格第 11 节）：项目还在立项时，从对话框、秘书、建议卡（以及第一版任务书只写了它）都建不成它的内部任务，回一句"项目「X」还在立项，确认立项书后再发起"；只有首个建设任务例外，它在确认立项书的那一刻建出。
- **项目内部任务就是一个单项目任务，多一个标记 `internal: { projectId, projectName }`**：执行的维护者是项目的维护者，涉及的项目只有它（`projectScope: "single"`）。之后的派工单、计划卡、一次授权、执行（流程照计划逐步核对、长程任务逐阶段验收）、名额、用量、被杀后的恢复全部沿用，不另起一套。建卡时定下，不能换。
- **跟着它的东西带同一个标记**：它的待我处理事项（计划卡、审批卡、卡住求助……建的时候标上；调用的来处 `CallOrigin` 也带着，审批卡、"交给我做"、中断不确定从这里取）、它计划里的定时作业、项目的维护者给的建议卡。**判断只有协议包的 `isProjectInternal` 一个**：列任务、列事项、列作业、检索的地方都用它，不各自去猜（按任务编号、按来源文字去认会漏掉起草段的审批卡、卡住求助这类没有任务编号的事项）。
- **事件照旧在原来的频道**，"不上全局看板"由看的地方过滤：前端的看板、秘书的查看板和看板变化不放项目内部的任务和作业；秘书列出待我处理只写"项目「X」内部的事项"一行，这些卡片放不进秘书的聊天；任务控制快速动作、秘书的提问卡和写任务书、每周的归档清单都不认它；项目页的"内部任务"一栏、定时作业和任务详情照常显示。待我处理里的事项来源写明"项目「X」内部"。
- **秘书检索素材时检索不到项目内部的记录**：素材属于的任务、引着的审批或卡片是项目内部的（内部任务的结局、计划和审批的决定、验收、提问卡的回答、建议卡被关掉……）。用户自己说过的话（发言、投喂的材料、记忆命令）照常检索得到——素材是用户的记忆（ADR-0006），不按任务隔离。
- **任务书由项目的维护者自己写**（`write_task_brief`，带着写的人）；秘书写的认不出项目内部任务。不是维护者自己建的（秘书那里点明、建议卡、"发起任务"按钮），同一事务通知维护者、不通知秘书：秘书只知道"已在项目「X」里建了内部任务"。通知带着任务编号，只在维护者的对话段里处理——它正在做工单时排着（工单段里没有写任务书的工具），空下来开一个对话段交给它。之后秘书的查看板只看得到每个项目里有几个进行中的内部任务（2026-10-10 用户定的最小一步：不给标题、进展、计划），用户问起时引导他到项目页。例外是建卡时没写项目的：秘书照常澄清、写第一版任务书，这一版只涉及一个项目时任务交给项目的维护者、成了内部任务，秘书从此看不到它。
- **归档**：项目内部任务结束之后由用户在项目页上归档（`task_action` 的 `archive`，只对项目内部任务）；全局任务照旧在每周的归档清单上归档。
- **删除项目时一起删掉**：看板频道上它们的任务事件、定时作业事件按字段改写（文字换成删除标记，行留着：任务、作业的编号接着往下排），没结束的同一事务取消；任务书、计划等 tasks 频道上的事件和它们的卡片整条换成"已删除"标记；它们的工单、子 agent 并行的提议和决定换掉文字（工单连标题、任务名）；待我处理里项目内部的事项改写后追加一版删掉的（不会一直卡着）；调用的来处里的任务名也去掉。

## 后果

- 16 号票"秘书建的单项目任务上全局看板、由秘书澄清和写任务书"那一套被这一条替代：单项目任务的澄清、任务书都在项目的维护者会话里做，用户在项目页上看；看板上只剩跨项目的和不属于项目的任务。
- 任务模块、执行控制器、派单器、名额这些不用知道项目内部任务的存在；新加一个"看任务、看事项、看作业、检索"的地方（比如以后的全景）要记得用 `isProjectInternal` 过滤，否则会把项目内部的东西带出去。新加一种会进待我处理的事项，在项目内部任务的上下文里产生时要带上标记（任务的用 `taskInboxOrigin`，调用的从 `CallOrigin.internal` 取）。
- 前端照旧订阅看板频道就拿得到项目内部任务和作业（项目页、任务详情要它们）；"秘书看不到细节"靠秘书那几样工具过滤，不靠频道隔离。用户在项目会话里说过的话照旧能被秘书检索到；秘书替用户建内部任务时自己会话里的那次工具调用（用户要做的事的概括）也留在秘书会话里。
- 项目内部任务不进每周的归档清单（清单卡的文字秘书看得到），在项目页上归档。日历照常列出项目内部的作业（用户自己的视图）。
- 删除项目后，任务、作业编号不回收；被改写成删除标记的任务行、作业行留在派生视图里。素材库里已经采集的内部任务的记录（结局、决定的说明）不在这次改写里——它们对秘书检索不可见；删除项目时随项目彻底删掉，已在 66 号票完成（用户本人说过的话不删，见 ADR-0010）。

## Considered Options

- **另开一个"项目内部任务"频道**（或者放进项目列表频道）：频道本身就隔离了可见范围，但任务模块、执行控制器、派单器、名额、前端的任务详情都按看板频道上的 `task` 事件工作，要么每处都订阅两个频道，要么复制一套，改动面大、容易漏。
- **项目内部任务另做一种实体**（不算任务）：计划、授权、执行、名额、用量都得再接一遍，和"计划、审查、计划卡、一次授权、执行时比对、阶段验收都和普通任务一样"的要求相反。
- **只在任务上标、事项按任务编号去认**（第一版的做法）：起草段的审批卡、催写回到了次数的卡住求助没有任务编号，整条交给了秘书；评审后改成事项、作业、建议卡都带标记，判断只用一个函数。
- **删除项目时把它们的任务事件整条换成"已删除"标记**：派生视图重放后任务行没了，新任务的编号（按行数）会和留着的旧任务撞号。

- 2026-10-18 补记（141 号票）：例外是运营方案里的一条生效成的内部任务，上任务看板、标属于哪个项目，秘书的查看板也列出它们（判断是协议包的 `internalTaskOnBoard`），见 ADR-0028 的补记。
