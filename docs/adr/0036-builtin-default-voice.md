# ADR-0036 开源版自带一条内置的默认参考音色

状态：已定（用户 2026-10-30）

## 背景

- 语音回复（32 号票）要有一条**参考音色**才能出声：一段干净录音加它的逐字稿，agent 照它的声音合成。参考音色一直是用户自己导入的（**设置 · 角色与声音**），一条都没有时语音回复退回只发文字，待办里提示"要合成语音，得先导入参考音色"。
- 开源版的目标是拿走就能用。第一次装好、按住说话、听到秘书用声音回一句，是这套东西最直观的"它活了"；而现在第一件事是**先去录一段 5–15 秒的干净人声**——门槛高，而且很多人手边没有合适的录音，试两下就走了。
- 不能拿真人录音当默认：仓库要对所有人公开分发，真人录音牵扯声音权、肖像权，随时可能被要求撤回；而且选谁的声音都是一种冒犯（开源项目不该拿真人的声音当默认）。
- 合成这条路是通的：audio.cpp 上的 FireRedTTS3-Instruct 是 voice design（不是克隆真人），上游 FireRedTeam/FireRedTTS3 是 Apache-2.0；用一句 instruct 合成出来的童声不含任何真人录音。用户已经把一段合成好的素材交过来了：24 kHz 原产物整体降 2 个半音，8.5 秒。

## 决定

1. **内置一条，随程序打包，不下载。** 素材放 `packages/daemon/src/voice/default-voice/`（`reference.wav`、`reference.txt`、`README.md`）：构建时把 `src` 里非 `.ts` 的文件原样复制进版本目录（`build/transpile.ts`），所以 `npm run build` / `npm run release` 出来的包里就有它。266 KB，不值得做成组件（组件是几百 MB、按需下载的大件，见 CONTEXT"组件"）。
2. **素材就是最终格式：16 kHz、单声道、PCM16。** 和"用户导入的录音在导入时被 ffmpeg 转成什么"是同一种格式。装的时候不转码——首次启动不依赖本机 ffmpeg、不依赖识别进程、不联网，也不会因为转码失败装不上。24 kHz 的原产物用 ffmpeg 重采样一次（`aresample=resampler=soxr`），没有别的处理；做法和校验值写在素材目录的 README 里。
3. **固定 id `v-default`，`voice.json` 加 `builtin: true`。** 目录名和文件名只用英文（audio.cpp 读不了带中文的路径，和导入时一样）；"这是开源版自带的，不是用户导入的"靠这个字段认，HTTP 的参考音色列表也带着它（以后要在设置页标"内置"直接用）。显示名**每次现查 `t()`**：中文"小满"、英文"Xiaoman"（`voice.reference.builtinName`），换了语言设置页跟着变；`voice.json` 里存的名字只是给用户翻数据目录时看的。名字是编的，不是任何真人。
4. **什么时候装：语音插件装配时（守护进程起来就装），两个条件都成立才装。**
   - `voices` 区里**一条列得出来的参考音色都没有**（有坏掉的目录不算——它列不出来、用不了；装内置的不覆盖任何东西）；
   - 没有"装过"的标记。
   装的过程和导入一样：先写进 `voices/.installing-<随机>`，写全了再改名成 `voices/v-default`（半截的目录不会被列出来）；`current.json`（选中它）和标记文件走 `util/atomic-file.ts`。装不上（素材不全、磁盘满、被杀毒占着）**不拦启动**：记一行日志，什么都不留。
5. **删除语义：用户删了就是用户的意思，不再自动长回来。** 在**装的时候**写标记 `voices/.default-voice-installed.json`（`{ format: 1, voiceId, installedAt }`），之后每次启动看到标记就什么都不做；用户从设置页删、或者直接删掉目录，都不影响启动，只是那条音色不再有。
   - 为什么不用"把它当普通音色，删了就是没了"：那就是这套规则本身——普通音色删了不会回来，内置的也一样。标记的作用是分辨"从来没装过 + 现在一条都没有"（比如用户一上来就自己导入了音色、后来删光）和"装过，用户删了"：前一种照"一条都没有就装"办，后一种不办。只靠目录分不出这两种。
   - 为什么标记在装的时候写、而不是在 `remove()` 里写：删的路径不止一条（设置页、资源管理器、整个备份还原），把"装过"当成事实记下来最省事；装一半失败不算装过（标记写在最后）。
   - 代价：删掉以后想找回内置的那条，得自己重新导入（用户手册里说明了）。这是有意的——"我删了它，它又回来了"是更糟的体验。
6. **为什么是合成音、为什么是童声。** 开源版分发真人声音有上面说的那些问题；纯模型合成、Apache-2.0 模型，许可上干净。童声和"家里人"的语气贴合二狗这个助理的定位（秘书跟用户说话），也给"这是我自己的音色"留出替换空间——用户导入自己的之后选中就换掉了。降 2 个半音是为了让它不像任何具体的、听得出是谁的人。
7. **以后怎么换出厂默认**：换掉素材目录里的两个文件（逐字稿必须和录音一字不差）、更新 README 里的时长和 sha256，`test/voice/default-voice.test.ts` 会核对这三样。已经装过的用户不受影响（他们数据目录里那条是当时那份，`importedAt`、`sha256` 都记着）；要让现有用户也换，得换 id（`v-default-2`）再做一次迁移，这一版不做。

## 后果

- 新装的数据目录里，第一次启动之后 `voices/` 下多了 `v-default/`（录音、逐字稿、`voice.json`）、`current.json` 和 `.default-voice-installed.json`；设置 · 角色与声音 里就能看到"小满"，语音回复直接有声音。
- 已经自己导入过音色的用户一个字节都不动（连 `current.json` 都不碰）。
- 备份快照、插件"移除时连数据一起删"照旧处理整个 `voices` 区（内置的那条也是数据目录里的普通一条）。连数据删完再启用语音插件，等于回到"没装过"，会重新装上内置的那条。
- **默认状态下没有 audio.cpp 的人会看到一条说明**：有了参考音色，语音回复就会真去合成；本机没装/没开 audio.cpp 时，每次语音回复在会话里写一条"语音没合成出来（连不上语音合成服务（…）），这次只发文字"，待办里也有提示。以前这条只在"导入了音色但服务没开"时出现，现在默认状态就撞上——这是既有行为的自然结果，不是这次新加的规则；要改成"没有合成服务就不尝试"是另一件事，留给孩子票。
- 发布包大 266 KB；`stage.test.ts` 里加了对这三个素材文件的检查，"打包时漏了它"会红。
