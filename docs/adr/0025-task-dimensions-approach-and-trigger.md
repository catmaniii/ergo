# 0025 任务分两个维度：做法（普通任务、流程、长程任务）× 触发（一次性、定时、事件）

日期：2026-10-10
状态：已采纳（扩展 ADR 0019 的两种任务；ADR 0017 定时作业的运行机制保留复用，但定时作业不再写在长程任务的计划里）

## 背景

ADR 0019 之后，任务只有流程和长程任务两种。定时作业只能写在长程任务的计划里，用户确认计划卡时一起确认，发起对话框里没有入口，用户一直没找到。条件触发完全没有。另外，用户在对话里交代一件要花时间的事，助理只能自己在对话里做，没有"交给一个 agent 在后台做、上看板"的轻量做法。

用户 2026-10-10 提出：任务应该分两个维度。

- 做法：普通任务（像普通 agent 一样跑 agent loop，不检查）、固定步骤的流程、长程任务；
- 触发：一次性、定时、条件触发。定时其实也是一种条件触发，只是条件是时间。

## 决定

**做法**（建卡时定下，之后不能换）：

- **普通任务**（新）：有任务卡、有自己的 agent，在后台用 agent loop 直接做；不规划、不授权、不检查（受保护区域和密钥的硬拒绝照旧）。助理可以自己决定把一件事交出去建成普通任务，告诉用户一声，不必等用户点明。做完自动算完成；用户在任务详情里接着说话，它就接着做，重新变成进行中。归档照旧由用户手动。
- **流程**、**长程任务**：照 ADR 0019；仍然要用户点明才发起。

**触发**：

- **一次性**：现在做一次。
- **定时**：按时间表（含工作日历）触发。
- **事件**：靠事件推送触发。事件来源做成登记表，第一批接二狗内部事件（任务、流程结束或失败等）和本机文件夹变化；以后接别的来源只加一项。时间到了也看作一种事件，定时和事件共用一套触发底座。

**组合**：普通任务、流程三种触发都能用；长程任务只做一次性（逐阶段验收的工作不适合反复跑）。简单提醒保留，作为最轻的一种（不用 agent，只发通知），能挂定时和事件触发。

**反复运行**：

- 每次触发是这个任务的**一次运行**。同一个任务的各次运行接着用同一段会话（上下文），后面的运行知道前几次的情况；会话长了靠 pi 的压缩。
- 触发时上一次运行还没结束：**排队合并**。等这次结束再跑一次，期间来的多个事件合成一批交给它；不并行，不丢事件。
- 流程挂反复触发：计划卡授权一次，之后每次运行都按步骤核对。步骤的参数可以写成事件里的值的占位（比如"事件.文件路径"），计划卡上照这样显示，执行时代入这次事件的值，核对按代入后的值比。

**定时作业并进来**：不再有单独的"定时作业"。它就是"定时触发的普通任务或流程"，在发起对话框里直接建；长程任务的计划里不再写定时作业。ADR 0017 的机制照旧复用：作业自己的维护者、会话接着用、属于项目的每次运行是项目维护者的一张工单、运行记录、开始时才占名额、暂停、恢复、取消。

## 后果

- 术语表：任务的定义改成三种做法，新加"普通任务""触发方式""一次运行""事件来源"；"定时作业"改成避免用词。
- 发起对话框改成两步：先选做法，再选什么时候做；"只提醒我"也在这里。
- 已有的定时作业（如果有）迁移成定时触发的普通任务，保留它的维护者、会话、授权和运行记录。迁移不能改写事件日志（不开第四个例外），用新事件或派生视图表达。
- 普通任务不检查，和 ADR"先跑通功能、安全机制后接"一致；以后接安全机制时，它和普通对话按同一套处置走。
- 拆成三张票：普通任务（一次性）→ 触发底座和定时触发（并入定时作业）→ 事件触发。

## 考虑过的选项

- **条件用定时轮询检查**（每隔一段时间用脚本或便宜模型判断条件）：实现简单，定时是它的特例；用户选了事件推送，更及时，事件来源逐个接。
- **三三得九全都能组合**：长程任务定时触发等于每次到点发起一个新的长程任务，每次都要规划、可能要确认计划，不像"反复做同一件事"。
- **两套并存**（长程任务计划里仍能写定时作业）：同一件事两个入口，用户已经找不到现在这个入口了。
- **上一次没跑完就跳过、或者并行再起一个**：跳过会丢事件；并行占名额，同一个任务的两次运行还会抢同一段会话。
