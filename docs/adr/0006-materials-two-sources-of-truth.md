# 素材的两份真相：事件日志和本人素材的原文副本；memory.db 是能整个重建的派生

规格第 15 节要求素材"由守护进程从事件日志确定性地产生"，08 号票的验收标准要求"清空 `memory.db` 后从事件日志重建，得到相同的素材"。同时规格要求删项目时维护者会话一起删，而用户在里面说过的话作为素材保留（「项目生命周期、工作空间与维护者」、记忆子地图「素材管理」§1）。只靠事件日志做不到后一条：会话事件删了，重建时这些素材就采不回来了。所以 08 号票（评审后）定成：

- **事件日志是素材的来源**：素材模块订阅事件存储，按登记的采集规则（`materials/capture.ts`）从事件产生素材；采到事件日志的哪一条（全局序号）和素材写在 `memory.db` 的同一个事务里，停着时追加的事件启动时补采。
- **原文副本是本人素材的真相**：本人素材（来源本人，或者里面有本人的话）连同整个信封（素材 id、类型、说或做、时间、来源会话、任务或项目、来源等级、指向原始记录的引用、情境标签、切段——本人切段里就是原文）存成素材区的一个文件 `originals/<年-月>/<素材 id>.json`。只用"不存在才创建"的方式写，写完设只读：不可修改、只追加、只有用户能删。
- **`memory.db` 是派生的**：重建 = 从事件日志采出的素材 ∪ 原文副本里事件日志已经没有的本人素材，按素材 id 去重。每次启动都会把"原文副本里有、`memory.db` 里没有"的补回来。agent 的产出、附件、外部内容和系统观察到的回避信号只在事件日志里，没有第二份。
- **素材 id 由事件算出来**：`mat-` 加 sha256（频道、频道内序号、事件时间、采集规则的名字、第几条）的前 24 位。不用全局序号：`ergo.db` 换成更早的版本时，新事件会重用旧的全局序号，撞上已有素材的 id。原文副本的文件名就是素材 id，所以**算法和采集规则的名字定了就不能改**。
- **一条事件一条素材**（一条消息、一次反应），信封里带切段，每个切段有自己的来源等级；信封的来源等级是"这件事是谁做的、谁说的"。
- **彻底删除的标记现在定格式**（21 号票做删除）：事件的频道、序号、类型、时间不变，负载整个换成共享协议包的 `DeletedEventPayload`：`{ deleted: true, deletedAt, messageId?, messageTime? }`（原来是消息的，留下消息 id 和时间给界面显示"已删除"），原文一个字不留；认它用 `isDeletedEventPayload`。素材采集遇到它一律跳过，不产生素材，也不写原文副本。

## Consequences

- **删项目（15 号票）可以删掉维护者会话的事件**：本人素材已经在原文副本里，`memory.db` 重建时照样在、照样能检索（向量在后台重算）。维护者的回复、附件内容这些不是本人的东西，随会话一起没了，素材里的引用指向的东西也就没了。
- **删除素材都要动两处真相**（21 号票）：
  - "彻底删除"：把事件日志里的原始事件改写成"已删除"标记，并删掉对应的原文副本（先去掉只读属性）和 `memory.db` 里的素材；
  - "忘掉"、按会话或时间段删除：事件日志里的原文保留（聊天里还看得到），所以要先追加一条事件记下"这些素材被忘掉了"（素材模块把这类事件当采集规则处理：删掉素材），再删掉原文副本。否则重建时会从事件日志或原文副本把它采回来；
  - "别推断"：同样记一条事件，由素材模块打标记。
- **原文副本是第一次采到时的样子**：以后采集规则改了，重建时 `memory.db` 里是按新规则从事件日志采的；事件日志里已经没有原始事件的，用原文副本里的旧样子。
- **采集规则必须是确定性的**：只看事件本身，不读时钟、不读会变的派生视图。需要的信息放进事件负载（08 号票给 `card_dismissed` 加了用户的说明 `note` 和卡片的纯文本降级 `cardText`，给消息事件加了可选的 `taskId`、`projectId`）。
- **`memory.db` 丢了、坏了、表结构要大改，都可以删掉重来**；备份（11 号票）要备份原文副本（它不能从别处重建），`memory.db` 备份只是为了恢复得快。

## Considered Options

- **只有事件日志是真相，`memory.db` 能从它重建**（08 号票第一版）：简单，但删项目时删掉会话事件，本人素材在重建时就丢了，违反"删项目也保留本人的话"。
- **`memory.db` 是独立的真相、不能重建**：素材写进去就只在那里。删除简单，但"清空后重建得到相同的素材"做不到，`memory.db` 坏了也没有退路。
- **原文副本只存原文（一个切段一个 `.txt`）**：08 号票第一版这样做。只有原文没有信封，事件没了以后不知道这句话是在哪个会话、什么时候、作为哪类素材说的，重建不出素材。
- **素材 id 用全局序号**（`mat-<全局序号>`）：短、好读。但只恢复 `ergo.db` 时会撞 id。
- **一个切段一条素材**：来源等级在信封上只有一个值，按来源筛最直接。但一条消息被拆成几条素材，"忘掉这句话"要一起删，检索结果也缺上下文；记忆子地图定的是"每条消息、每次反应各一条"。
