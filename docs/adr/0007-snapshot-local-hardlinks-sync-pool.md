# 快照分两层：本机备份区用硬链接，同步目录用按内容的公共池

规格第 18 节要每晚一份一致性快照：SQLite 用 `VACUUM INTO`，其余文件增量复制，媒体按内容哈希只存一份；本机留 7 份，同步目录留每日 7 份、每周 4 份；保留期内任一日期都能单独恢复，更早的被清掉后也一样（11 号票）。同步目录由同步客户端（本机是华为家庭存储的客户端）同步到别处，而同步客户端不认硬链接：链接的文件会被当成独立文件各传一份。所以"只存一份"在两层用两种做法（2026-10-08 定，评审后改过一次）：

```
本机备份区（数据目录的 backups/）            同步目录（配置 backup.syncDir）
  2026-10-08/                                2026-10-08/
    manifest.json                              manifest.json
    data/   数据目录的完整镜像                    data/   只有小文件（< 64 KB）
                                             pool/<sha256>   较大的文件（含数据库、媒体），各天的清单共用
```

两层共用：

- **清单**（`manifest.json`）：格式版本、日期、时间；每个文件的大小、内容 sha256、复制时源文件的大小和修改时间；哪些是数据库；哪些放在公共池里（`pooled`）；哪些源文件本来就是只读的（`readOnly`，比如素材区的原文副本，恢复出来照样只读）。恢复、校验都按清单走。
- 不进备份的东西只有一份定义（`nonBackupEntries`：密钥区、临时区、本机备份区、pid 文件、模型区），快照和恢复共用。
- **数据库每次重新生成**（`VACUUM INTO`，单文件、非 WAL）。
- **先写进 `.<日期>.partial`，清单最后写，整个改名成日期目录**：日期目录在，就是完整的。
- 到点的和开机补做的备份只补齐当天缺的，不覆盖已有的当天快照；手动的"立即备份"（含"备份失败"上的"重试"）才换掉。

本机备份区：

- **每个日期目录自成一体**，增量靠硬链接：源文件的大小和修改时间都和上一份清单里的一样，就硬链接到上一份里的同一个文件；内容一样的较大文件（≥ 64 KB）也换成硬链接。硬链接按引用计数，删掉旧快照不影响新的。做不了硬链接（跨盘、文件系统不支持、链接数到顶）时整份复制，记一条日志。
- **快照文件都设成只读**：一份存储可能同时属于好几天的快照，就地改写会连带改坏别的日期。Windows 上删掉只读文件的一个链接（按 POSIX 语义删）不会去掉别的链接的只读属性；恢复时复制出来的文件要去掉只读。

同步目录：

- **不用硬链接**。较大的文件（≥ 64 KB，含数据库和媒体）按内容放进公共池 `pool/<sha256>`：池里有了就不再复制，所以云端也只存一份；日期目录里只有清单和小文件。先写池里的临时文件，算完 sha256 再改名。
- **清理日期目录之后回收公共池**：删掉不再被任何清单引用的文件。有读不出清单的日期目录时这次不回收（不知道它引用了什么，宁可多留）。
- 恢复要"清单 + 公共池"一起：日期目录不再能单独拷走使用。
- 周日那份当时没写进同步目录（目录不在等）的，之后写得进去时从本机备份区补写最近缺的那个周日快照，免得少一份周快照。

## 考虑过的做法

- **两层都用硬链接**（最初的做法）：同步客户端会把每个链接当成独立文件上传，云端存 11 份完整的数据目录。评审时否掉。
- **两层都用公共池**：本机备份区也就不能单独拷走一个日期目录了；本机层用硬链接已经够省，还能直接打开看。
- **每天整份复制**：同步目录要存 11 份完整的数据目录，媒体多了吃不消，也不是规格说的"增量"。
- **打包成一个压缩文件**：没有增量，恢复单个文件也要整包解开。

## 后果

- 本机备份区的快照里的文件一律只读，谁要改（比如人为损坏来测试校验）得先去掉只读，而且会连带改到同一份存储的其他日期。
- 同步目录的日期目录不能单独使用，要连同 `pool/` 一起；手动从同步目录挑一天拷走时得按清单取池里的文件（恢复命令 `--from <目录>` 指向同步目录就行）。
- 清单带格式版本（`format: 1`）。以后要改格式，恢复命令得继续认得旧格式（同步目录里的周快照会留一个月）。
- 符号链接和目录联接不进快照（不跟进，也不记下）：外部工作目录因此不会被带进来；15 号票如果要用联接表示外部工作目录的绑定，绑定关系本身要另记在项目档案里，恢复后据此重建。
