## 0. 决策相关要点(TL;DR)

1. **四层 + 置信天花板是核心骨架,可以直接搬**:L1 表象(说/做/回避/情境,`verified`)、
   L2 这一次的动机(`unverified`)、L3 跨情境不变的需求(`conditional`)、L4 内核:经历/价值观/风险偏好/关系模式
   (`conditional`)。**L2 以上永远不得 `verified`**,理由是认识论的:用行为推动机、再拿行为验动机是循环
   (`<SK>\docs\LAYERS.md`「置信天花板的推导」)。
2. **用户的论点在这套方法里有明确的落点**:当事人对自己动机的说法**是一条 L1(speech),不是结论**
   (`<SK>\docs\LAYERS.md` 末节)。"说"与"做"分开记,二者不一致之处是"分析的入口"
   (`<IM>\game_of_thrones\extraction\INSTRUCTIONS.md` §1.1)。价值观层的证据甚至要**排除本人自陈**
   (`<IM>\dream_of_the_red_chamber\REPORT.md` §6 第 4 条)。
3. **相对小说,活人场景有三个结构性红利**:① 可以问当事人(`where: subject`);② 能拿到与言辞正交的证据
   (他实际花了多少时间/钱、接受/返工/放弃了 agent 的哪些产出——代价法);③ **未来就是天然的保留集**,
   L4 建号时写下的 `predicts` 能被真实的未来行为检验——小说项目只能"留待后续卷"。
4. **也有三个结构性风险**:① agent 自己是"外生冲击"的施加者(它的建议塑造用户的选择),
   "用户接受了我的建议"是弱证据;② 问一次就改变了被观察者(反应性),且施问者知道假设就会领读;
   ③ **错判的代价是错误的行动和越界的家长主义**,不只是一篇错的评论。
5. **方法里最该直接变成运行期不变量的几条**:M1(事实不夹带解释)、M3(每条观察可回到原始消息)、
   M4/M5/M12(竞争假设必须配判别性追问;"没找到"不判负)、M6(禁全称量词——对用户说"你总是…"同样是坏 UX)、
   M7(撤回后被解释的现象归谁)、M10(名义多腿≠独立多腿)、M11(用户看到的就是图里的,删除要删数据不是删显示)、
   M14(L4 必须带预注册预测)。
6. **指令时的使用原则(本文建议)**:L3/L4 **只用于消歧、提问和排序,不得覆盖显式指令**;
   向用户解释时**出示 L1 证据,不出示心理诊断**("你上 3 次都把结论挪到了开头"而不是"你有掌控需求")。
7. **实际价值多半来自低层**:可计数的行为规律(L1 聚合,`AGG`)+ 每条指令的情境读法(L2)+ 判别性追问。
   L3/L4 是少量、慢更新、默认对用户隐藏程度可调的那一层。GoT 的结果说明:即使投入 6275 个节点,
   八个人物里也**没有一处判别达到 10 dB**(`<IM>\game_of_thrones\analysis\vol1\SUMMARY.md` §3.3)。
8. **最成熟的参照**:方法以 `<SK>`(skill 成文版,含 14 条铁律、8 个检查器、PITFALLS)为准;
   流水线以 **GoT** 为准(事实抽取层与分析层严格分离、抽取规则由 417 条反馈迭代到 v4、分析→事实层的纠错回流、
   A/B/C/D 四阶段 + 二审);单图纪律以 **红楼梦** 为最干净的范例。

## 2. 方法端到端(问题 1)

### 2.1 数据骨架:reasoning-graph 的 DAG

方法本身声明"**这是方法,不是又一种图谱**"(`<SK>\SKILL.md` 开头),数据全部是 `<RG>` 的推理图:

- **四种 kind**:`fact`(F-)、`inference`(J-)、`decision`(D-)、`question`(Q-)。kind 建号后永不可变
  (`<RG>\docs\LIFECYCLE.md` §0)。
- **一个节点只放一个断言;推理住在 `deps` 边里**,statement 里出现"所以/因此/→"就要拆(`<RG>\SKILL.md`)。
- **status 状态机**(`<RG>\docs\LIFECYCLE.md` §1/§3):
  - claim:`unverified ⇄ verified`,任一 → `retracted`;被打它的证据自身被推翻时**复活**回 `unverified`
    (reinstatement);区分 **rebut**(证据说结论假 → retracted)与 **undercut**(推理链不成立 → 降回 unverified)。
  - question:`open ⇄ answered(必带 answered_by)⇄ dropped`;答案被撤回则问题**重开**。
  - decision:`active ⇄ inactive`,带 `by: human | agent`。
- `conditional`:推理本身站得住、但压着一条软前提;**软前提必须是图里的一个节点,不能是自由文本 `assumptions`**
  ——这是整套机器约束里唯一在心理分析中真会触发的一条(`<SK>\assets\rules.yaml` `fires: true`)。
- `scope:` 块(question/in/out/boundary)是开工门禁:没有范围的图"什么都往里装"(`<RG>\SKILL.md`「开工门禁」)。
- 工具:`rg_validate.py`(结构硬校验)、`rg_audit.py`(软检查)、`rg_query.py --dependents-of`(改节点前查下游)。

intent-mining 在其上只加"方言字段"(`<SK>\SKILL.md`「方言字段」):`layer`、`provenance`、`probe`、
`probe_kind: negative-universal`、`no_explanation`、`explains`、`contrast_pair`、`predicts`、
`supports_incidentally`、`discriminates`、`probes[]`(含 `where/if_yes/if_no/if_absent/queries_run/woe_db`)。

### 2.2 四层与置信天花板

| 层 | 内容 | 一句话判据 | kind | status 天花板 |
|---|---|---|---|---|
| L0 方法层 | 纪律本身记成节点(便于在结论里引用) | — | fact/decision | — |
| **L1 表象** | 可核对的言辞、行为、**回避**、他人叙述、情境 | 不认识这个人的旁观者也会同意 | fact | `verified` + `basis: stated` |
| **L2 动机·情境** | **这一次**为什么这么选 | 换个情境就不成立 | inference | `unverified` |
| **L3 真实需求** | **跨情境不变**的那个(被理解/安全感/掌控/名分…) | 换情境仍成立 | inference | `conditional` |
| **L4 内核** | 经历/长期记忆、价值观、风险偏好、关系模式 | 解释"为什么是这个需求" | inference | `conditional` |

出处:`<SK>\SKILL.md`「四层」、`<SK>\docs\LAYERS.md`。要点:

- **层是标签,不是边**:L3 可以直接压在四条 L1 上;层回答"这句话是什么性质的断言",边回答"我凭什么这么说"。
- **90% 的粗糙分析栽在把 L2 当 L3 用**:看见一次行为就宣布核心需求。
- **L3 的立身之本是被多个互相遥远的场景压住**;一条只被一个场景支撑的 L3 是伪装的 L2。检验不是
  "拿掉一条会不会倒",而是 M10:把每条 dep 递归展开到 L1 根做两两包含检验,报"名义腿数 / 独立 L1 根数 /
  **最大不相交腿数**"。实盘:45 条名义多腿的 L3/L4 里约一半中招(`LAYERS.md` 记 23 条、`PITFALLS.md` §3.4 记 22 条——
  skill 自己的文档在这个数上也有轻微漂移),若干条最大不相交腿数 = 1。
- **L3 压着软前提"这个人在这些场景里是同一个人";L4 再多压一条"这段经历是原因,而不只是先发生"**。
  红楼梦把这几条软前提显式建成方法层节点 `J-mth-01`(需求跨情境稳定)、`J-mth-03`(经历是原因)、
  `J-mth-04`(对照对的关键差异确实是申报的那个)、`J-mth-02`(前八十回人格模型一致)
  (`<IM>\dream_of_the_red_chamber\parts\01-method.yaml`)。GoT 则每人一组:`J-TYR-L3-90`
  "1-06 到 1-70 他没有改变需求的转折"、`J-TYR-L4-90`"他自述的往事基本属实且确是原因"等。
- **天花板的例外与出路**:若能拿到与行为**正交**的证据源,L2 才有可能升级——无动机粉饰场合的自陈
  (私下笔记、事后很久的回忆、对无利害第三方说的话)、行为/资源痕迹(实际花的时间、钱)、反事实场景里的选择。
  小说里几乎拿不到,"所以文学心理重建的天花板是结构性的"(`LAYERS.md`)。**真人场景这一条是打开的**——见 §7。

### 2.3 开工门禁三问(`<SK>\SKILL.md`「开工门禁」)

1. **材料能不能被重复检索?** 不能就别开工。血泪:西游记在原著入库前凭记忆建了 80 条表象,入库后
   **12 条要改、3 条撤回**(15%),"把落泪的人记成了另一个角色"。"凭记忆做的 L1 不是弱证据,是**伪证据**"。
2. **对象是真人还是虚构?** 决定追问投向 `text` 还是 `subject`,以及"真人的回答本身是新的表象"这条额外纪律。
3. **要理解还是预测?** 要预测就必须留保留集;只要理解就**不得声称有预测力**。红楼梦 scope 里写死了
   `purpose: 理解,不是预测`(`parts\00-header.yaml`);GoT 以理解为主,但 L4 预测另留第二至五卷作保留集
   (`analysis\ANALYSIS_GUIDE.md` §0)。

### 2.4 原始材料 → 事实(L1)

#### 2.4.1 记什么、怎么记(M1:表象里不许夹带解释)

`<SK>\docs\EVIDENCE.md` 给出写完每条 L1 必过的**四个测试**:

1. **旁观者测试**:不认识这个人、只看同一份材料的人会同意吗?
2. **心理词测试**:情绪档(接受/拒绝/愿意/害怕/想要/故意…)和**更隐蔽的认知档**(得知/发现/明白/意识到/认定/以为…)。
   实例:`F-wk-03`"悟空**在得知**蟠桃会未邀他之后搅乱蟠桃会"通过了全部校验和三轮复核,原文是仙女答
   "不曾听得说"——"得知"是 factive 动词,同时断言"那件事为真"和"他知道了",两条都超出材料。
3. **连接词测试**:后即/之后/因…而/于是/所以/导致/才/反而——"这个连接是材料写的,还是我排的?"没写就拆成两条 L1 + 一条 L2。
4. **省略测试**:有没有省略掉一旦补上就会改变读法的情境?
   全项目最贵的单条:"悟空**接受**了唐僧递来的花帽"——一个动词吞掉了"如来→观音→唐僧"三级合谋的骗局,
   下游读出"他自愿接受约束",连累三个节点(`<IM>\journey_to_the_west\ledger\probe-run-2026-09-04.md`「紧箍更正」)。
   **是用户一句质疑掀翻的**:"他是主动戴上的吗?那不是被骗的吗?"

修法原则:**拆分优于修饰**(把一件事拆成三条各自过旁观者测试的 L1,"是否自愿"变成 L2 推论去接受质疑)。

**provenance(来源)词表**(`LAYERS.md`):`speech`(说过≠属实)、`action`(最硬,但会被情境逼迫)、
**`avoidance`**(没做、绕开、不接话茬——"最被低估的一档",记成"被问及 X 时改谈 Y",不记"从不谈 X")、
`narration`(第三方叙述;真人材料里第三方评价基本是**那个第三方的** L1)、**`setting`**(情境事实;
"归因的头号错误是把情境的作用记到人身上",没有它"他别无选择"这条竞争解释根本进不了图)、`meta`(关于材料本身)。
GoT 扩展为 `speech/action/avoidance/narration/thought/memory/dream/setting/meta`。

#### 2.4.2 可重复定位(M3)与回原文核对

每条 L1 带 `evidence`(人读定位:第几回/哪份转录哪个时间戳)和 `probe`(机器检索式:**材料原字**的关键词列表,
**全部命中同一单元**才算命中)。`<IM>\journey_to_the_west\scripts\check_l1.py`(后泛化为 `<SK>\scripts\check_evidence.py`)
逐条回原文跑,判定:

| 判定 | 含义 |
|---|---|
| `PASS` | 命中单元与声明相符 |
| `MOVE` | 命中在别的单元(声明写错) |
| `MISS` | 全库无命中(措辞或情节记错,或检索式错) |
| `OPEN` | 通例,只报命中了哪些单元 |
| `AGG` | 通例聚合型,无单点检索式 |
| `NEG` | 全书性否定命题(证不了,记 `unverified` + `probe_kind: negative-universal`) |
| `DROP` | 已撤回 |

西游记台账实例(`ledger\l1-check-2026-09-04.txt`):91 条 L1 → PASS 77 / OPEN 3 / AGG 4 / NEG 4 / DROP 3。
红楼梦最终 132 PASS / 0 MISS / 0 MOVE / 2 NEG(`REPORT.md` §4)。GoT 八张图合计 3866 条 L1 全部 PASS。

**检索假阴性三坑**(`EVIDENCE.md`,西游记连栽三次):用字变体(觔斗云/筋斗云)、加载器没去换行、全半角标点。
修法:`normalize()`(去空白+去标点)**同时作用于正文和检索式**。教训 = **M8:"我搜不到"≠"不存在";
"材料稀缺"是可检验的命题**(西游记曾断言"沙僧材料结构性稀缺",而最长的一段沙僧内心直述就在第三十回,从没检索过)。

**否定性全称命题**("他从不…")证不了,但**有义务去试着证伪**:用尽可能宽的检索式扫,扫过的式子记进 evidence。
`F-ts-11`"唐僧从不用咒差遣"就是在对抗复核时被第三十九、九十六回证伪的。

**`PASS` 只证明关键词共现,证不了命题**,尤其证不了连接词(`PITFALLS.md` §1.6)。

#### 2.4.3 工业化抽取:GoT 的事实层

GoT 把 L1 做成**独立的一层流水线**(`<IM>\game_of_thrones\PLAN.md`):"**先抽事实,后做分析,两层严格分开**"。

- **按章派活**:每章一个上下文干净的子代理,只抽事实不分析,输出 `facts/raw/<卷-章>.json`。
- **schema v4**(`extraction\SCHEMA.md`):每条事实有 `fid`、`type`(speech/action/avoidance/thought/memory/narration/dream)、
  `actor`(做这件事的人)、`actor_raw`(原文写法)、`targets`、**`source`(这条信息经谁的口/眼得来)**、
  `origin`(套娃转述的最初讲述者)、`summary`(中性摘要)、`quote`(≤30 字)、**`when`(当下/回忆/转述/概括)**、
  `confidence`(人物识别把握)、`candidates`(新人物/别名/事件提议)、`unresolved`(认不出的、身份争议)。
- **抽取规则**(`extraction\INSTRUCTIONS.md` v4,本项目最精细的一份文档):
  - §1.1 **原文明写的意图、情绪、判断单独成一条 thought/narration,不许括注进行为条目**——
    "原因:下游要分别统计'他做了什么'和'他自己怎么说自己的动机',两者经常不一致,那恰恰是分析的入口。"
  - §1.1.1 修饰词三档:看得见的样子(留)、情绪方式词(留)、**断言目的/伪装/隐藏意图(故意、假装、为了…)必须拆出**。
  - §1.2 有限第三人称:**POV 章节里的叙述一律视为 POV 的感知**,不是客观真相;POV 对他人内心的判断记 narration(actor=被判断者,source=POV)。
  - §2.1 **回避**须同时满足"有指向他的刺激"+"原文写出了他不回应";奉命离开是服从(action)不是回避;
    "原文只是没写他的反应"不记。
  - §2.2 往事:谁经历的、谁讲出来的分开记(讲自己亲历的往事记两条:当下的 speech + 往事条目)。
  - §2 "**原文明确是谎言才写'撒谎',否则写'说'**"。
  - §3 身份识别可以用常识,**事实内容不可以**;不许用后续剧情认人;尸鬼用 `<原ID>_wight`——"尸鬼的行为不是这个人的意图"。
- **归一化**(`PLAN.md` §2、`scripts\normalize.py`):**判断靠大模型,脚本只负责套用和挑问题**。名称表
  `registry\characters.yaml`(ID、别名、OCR 错字、`ambiguous_aliases`、`merges`)。脚本只报分歧不改 ID——
  v1 曾用别名表覆盖子代理的新 ID,把正确识别的伊里斯一世改成了伊里斯二世(`facts\review\PILOT_REPORT.md`)。
  **原文写法永远保留**,纠偏只改名称表 + 重跑归一化,不重跑子代理。
- **事件关联延后统一做**(`extraction\EVENT_LINKING.md`):事件表定稿后专门一轮挂 `event`(发生)/`event_refs`(提及);
  "**拿不准时不挂**——漏挂的仍可按人物查到,挂错的会把无关言行算进某个事件的分析里。"
- **规则迭代闭环**:试点 10 章 → v2/v3;第一卷 73 章跑完后,子代理回报的 417 条"模棱两可"被聚成 42 类
  (A 规则漏洞 26 / B 没读到 10 / C 正常判断空间不立规 6),产出 v4(`facts\review\rules_v4_proposal.md`)。
- **档案(dossier)是代理,原文是被代理者**(`analysis\ANALYSIS_GUIDE.md` §1):`scripts\build_dossiers.py`
  把某人相关事实按章汇总(★本人是行为人 / ·本人是对象),分析子代理拿它当索引,但**每条进图的 L1 必须回原文核对**,
  不符时以原文为准并回报纠错。
- **分析 → 事实层的纠错回流**:分析阶段共报 277 条事实库错误,逐条回原文裁定 88 个 fid 确认(91 处改动)、
  162 条驳回、29 条不明(`facts\review\fact_errors_adjudicated.yaml`);确认的写进 `registry\corrections.yaml`
  的 `fact_corrections`,**只改归一化结果,不改 raw**。典型错误恰恰都是 M1 类:"摘要删去限定语""'佯装'被删"
  "'只得'是外部情境,省略也是夹带"。

### 2.5 事实 → 动机(L2)→ 需求(L3)→ 内核(L4):五种推理动作

`<SK>\docs\MOVES.md` 是"本 skill 的核心智力内容"。按性价比:

| | 动作 | 一句话 | 强度 |
|---|---|---|---|
| 1 | **最小对照对** | 同一个人,两个只差**一个**变量的情境,行为反了 | 最强,可单条定胜负 |
| 2 | **代价法**(显示性偏好) | 他肯为什么付代价、绝不肯让什么 | 强;**真人分析里尤其值钱** |
| 3 | **对照组** | 同类不同人,排除"他是个 X,X 都这样" | 强(排除性) |
| 4 | **矛盾入口** | 前后不一致处信息量最大 | 强(产出新假设) |
| 5 | **时序** | 某需求被满足后,归给它的行为停了吗 | 中,善于**证伪** |

- **Move 1 与 M9**:对照表里**只许翻转一个变量**。旗舰反例:弼马温 vs 齐天大圣——"实职"和"名分"两行都翻了,
  似然比恰好 = 1。真正的对照对一直在图里:第五回"齐天大圣 + 代管蟠桃园"(有实职有名分,他问"有何升赏"欢喜谢恩)。
  这张错表**通过了结构校验、八个检查器和三轮对抗复核**,是一次独立方法论审查抓出来的(`PITFALLS.md` §3.1)。
  对照对要结构化成 `contrast_pair: {a, b, variables, flipped, known_other_differences, exogenous_shock}`,
  让 `check_contrast.py` 去数。判据最终定为:"**混淆本身不是错误,宣称自己没混淆才是**"(statement 里排除了某变量而它在翻转 → ERROR)。
  找不到单变量对照时去找**外生冲击**(变量因与本人心理无关的原因单独变动);真分不开就是"非辨识",
  降成"联合作用"+ 开 `open` 岔口。
- **Move 2**:"说什么不算数,肯付什么代价才算数"。悟空肯低三下四求人,却不肯让称谓——"求人的代价他付得起,称谓的代价他付不起"。
  失效条件:他可能不知道代价;代价可能是情境强加的(→ 补 setting);不作为不总是选择。
- **Move 3**:每提一条 L3/L4 先问"同类人是不是都这样"。红楼梦把对照组单列 domain `control`
  (`parts\09-control.yaml`):晴雯排除"大丫头都谋姨娘"、李纨排除"当家媳妇都揽权"、探春排除"出身受限都守拙"。
  GoT 的教训相反方向:"**一旦有别人做对照,不少看起来像个人特点的东西就站不稳了**"(`SUMMARY.md` §2.8)。
  "这个动作在真人分析里更重要"——"他是产品经理/他是山东人"这类类属解释在日常语言里畅通无阻。
- **Move 4 处理顺序**(西游记 `D-mth-03`、红楼梦 `D-mth-02`):① 需求未变、策略随情境变(首选,产出可检验假设)
  → ② 需求真的变了(须指出有 L1 支撑的转折点)→ ③ 两条并存的需求在此冲突 → ④ 材料有问题("作者写岔了",最后手段,
  "它解释一切,因而什么也不解释")。
- **新假设的硬判据**:"**它能不能顺带解释一个原本挂在别处、跟这个矛盾完全无关的现象?**"——全套方法里最有区分度的单条判据。
  但回溯版有漏洞(那个"别处的现象"你已经读过了,可能是从记忆里挑的),所以加三条界线(M13):
  **时间戳**(被顺带解释的现象措辞定稿早于假设建号,git 可查,即预注册)、**距离**(沿 deps ≥2 且材料区间不同)、
  **前瞻**(M14:L4 建号时写下一条尚未入图的预测再去找,`predicts: [{claim, queries_run, outcome}]`,outcome 填之前不许改)。
  红楼梦 changelog 记录了执行留痕:`J-by-40` 的 predicts 先写、`queries_run` 留空,之后检索命中的第 44、61 回
  记为 `found_in` 而不是 `supports_incidentally`。
- **Move 5**:悟空"求长生"在第三回已到手(强销死籍),第三至五回仍求名分 → 长生轴出局。
  **真人变体**:"**他抱怨的那件事被解决之后,他满意了吗?没有 → 他抱怨的不是他真正要的。**这几乎是需求挖掘里最可靠的一个信号。"
- **伪动作**:单点跳内核、贴标签("他控制欲强"——**预测不出任何新观察**)、叙事顺滑(一致性是你加的,"人本来就不一致")。
  L2 的反标签自测:"如果这个读法对,我在别处应该看到 ___"——补不出来就是标签(红楼梦大量 L2 statement 直接写了这句补全)。

### 2.6 竞争假设与判别性追问(probes)

注意 **"probe" 在这个项目里有两个意思**:L1 节点上的 `probe` 是**回原文的检索式**(§2.4.2);
question 节点上的 `probes` 是**为分辨竞争假设而设计的观察/提问**。后者是"本 skill 相对图谱的核心增量"
(`<SK>\docs\PROBES.md`,`<IM>\journey_to_the_west\README.md`「追问机制」)。

```yaml
- id: Q-wk-01
  kind: question
  discriminates: [J-wk-50, J-wk-59]     # 要分开哪两条竞争假设
  probes:
    - ask: '长生诉求在第三回已到手,此后的行动是否仍能被它解释'
      where: text                      # text 回材料 | subject 问当事人 | user 要使用者定夺
      if_yes: J-wk-59
      if_no: J-wk-50
    - ask: '有没有他明确拒绝一个唾手可得的名分的场合'
      where: text
      if_yes: J-wk-59
      if_absent: inconclusive          # M12:没找到 ≠ 对手赢
      queries_run: ['不受封','不愿做','辞了','不肯受','让与','推辞']
```

(摘自 `<IM>\journey_to_the_west\rg-journey-west-psyche.yaml` 第 663 行起)

- **M4**:每条在用的竞争假设必须被某个 question 的 `discriminates` 认领;**M5**:每个 `open` question 必须带 probes;
  `if_yes/if_no` 必须指向正在分辨的那两条之一——"写不出这个观察出现时算谁赢,说明它没有判别力"。
  西游记首轮就发现两对竞争假设此前根本没有问题去分。
- **预期分离测试**:先分别写下两条假设各自的预期,**一样就是零判别力**。"他重视承诺吗?"两条都预测"是";
  有判别力的是"守信**与**私利冲突**且无人知晓**时他选哪边"。"夹缝往往很窄,而且很少见。"
- **M12 `if_absent` 默认 `inconclusive`**:`if_no` 混了"找到相反形态的正面证据"(合法判负)和"宽泛搜索后无命中"(不得判负)。
  要写 `weakens` 必须附 `queries_run`——**两侧都留痕**,也记为对手预期跑过的检索式。
- **证据权重四档 `woe_db`**:0(两边预期相同,应删)/ 3(约 2:1,旁证)/ 6(约 4:1,"教科书里冒烟的枪"量级,
  "文献说还不够决定性")/ 10(必须写明为什么对手几乎不可能产生这个观察),**不设 >10**。好处:可加、可表示抵消
  (两边都空 = 0 dB"还没研究" vs +7 与 −6 = 净 +1"研究过,真是势均力敌")、给嵌套腿定价。
  自检:"采用之后应当观察到 `answered` 变少、带净 dB 的 `open` 变多;如果一切照样干净收口,说明这个刻度没在干活。"
  实盘:旧词表 strong/medium/weak 里 81–83% 都是 strong(`causal-view.yaml` changelog、`PITFALLS.md` §6.1)。
- **`where` 是唯一可移植点**:虚构 → `text`;真人 → `subject`;材料答不了、要使用者定夺(多牵动 scope)→ `user`
  (查看器里标红置顶;不判胜负,豁免 if_yes/if_no,改为强制写 `note`:"使用者怎么答,会牵动什么",且要对称写两个答案的后果)。
- **`subject` 档必须换一套字段**(`PROBES.md`,**设计了但从未在活人身上跑过**):
  `elicit`(只做情境重建 + 报告一切,不含任何类别词)、`blind: true`(施测者不得预先看 if_yes/if_no)、
  `score_from: transcript`、`scored_by: second-party`(**施测者与判分者分离**)。理由:知道自己在找什么的施测者
  会从副语言通道漏出选择性强化(引 Zaragoza 等 2001 选择性确认反馈造成虚假记忆;Memon 等 2010 认知访谈元分析)。
  **领读检测**:问句词元与竞争假设标题词元有交集即报——`subject` 档 ERROR、`text` 档 WARN
  (`<SK>\scripts\check_probes.py` 第 132 行起)。还有三条纪律:**答案是新的 L1,不是结论**;
  **判别力最强的观察要在问之前做完**(问过之后他会留意,后续行为不再自然);**问具体事件,不要问动机**
  ("动机是你要推的,不是你要问的")。
- **收口**:`answered` + `answered_by`;败方改 `retracted` 并**立刻执行 M7**;过程写进台账(问什么→在哪找→找到什么→判给谁→图上改了什么)。
  **"分不了"是合格产出**:记 `open` 并写明"已用 X 检索式找过,无判别性材料"。

### 2.7 对抗复核与"声明核验"

协议见 `<SK>\docs\ADVERSARY.md`;实录见 `<IM>\journey_to_the_west\ledger\probe-run-2026-09-04.md#对抗复核`、
`<IM>\dream_of_the_red_chamber\REPORT.md` §3、GoT 各人物 `adversary.md`。

- **有效批评只有两种**:① 原材料某处直接反证(给定位);② 依据撑不起这个措辞强度。
  "**这条没被证实**"不算(L2 以上本来就不 verified);用作者意图/教义/改编/当代价值判断挑战越界;
  但"论证某条结论**只有靠作者意图才立得住**"有效且很强。
- **必答项"我攻过但攻不动的"**,写明攻法与检索式——"共识就在这一节里"。
- **两阶段独立性**:复核员先独立读原文形成判断,再看结论;只给结论不给推理链(推理链会锚定它)。
  红楼梦的 `review-claims.md` 就是这份"只给结论、不给推理链"的清单。
- **三轮往返后收口**,每条挑战落到三态之一:接受(改图+changelog)/ 驳回(给定位,对方认可)/
  **分不了(转成带 discriminates 和 probes 的 `open` question)**。"项目结束时留着 8 个带收敛条件的开放岔口,
  比留着 8 条硬判的结论可信得多。"
- **复核员也会错,而且它"最重的一击"可能是错的**;"一条挑战可以'机制错了但设计缺口成立'"——整条接受或整条驳回都是偷懒。
- **"根据复核意见修改"这个动作本身要被检查**:实施意见时又犯三次新错。
- **最值钱的产出是系统性错误模式**,每类应产出一个检查器或一条铁律:西游记三轮(16 条挑战 15 条成立)
  暴露"检索假阴性×3、标题漂移×6、全称量词";红楼梦一轮(16 条挑战,23 个定位 22 个命中,撤 4 改 9 翻 2 岔口)
  暴露"把查无实据的中间事件当时间锚点""三腿论证里一腿方向是反的""量词膨胀""**把角色写成他自己价值观的执行者**
  (只取自陈不取行为记录)""命中第 N 回≠第 N 回的正文"。
- **GoT 把复核制度化为阶段 C/D + 二审**(`analysis\ANALYSIS_GUIDE.md` §3):C 独立子代理"只攻不修"(查后续剧情污染、
  L1 能否核到、循环论证、对照对、覆盖);D 逐条处理并写 `revision_log.md`(表格:意见 / 裁决 / 改了哪些节点);
  再由第三方 `review2.md`"只审不改"(必改 + 建议)。八人合计 162 条复核意见整条驳回 0 条,二审必改 40 条全修
  (`SUMMARY.md` §3.4、§5)。二审抓到的"同一条 L1 在两处被读成相反意思"(R-02/C-07)、"POV 自评当客观证据"(R-03)
  是检查器看不见的。

| `validate_chapter.py`(GoT) | — | 单章 JSON 结构 | — |

**"seams"与"drift"在本项目里的确切含义**:seams 是**语料单元切分的接缝**(合并章、错位文本),属于证据层完整性,
不是人物心理的"裂缝";drift 是**图节点标题与正文不一致 + 全称量词**,属于措辞层。

每个检查器文件头都有一行**谓词自陈**:"本脚本用 ___ 代理 ___,代理在 ___ 情形下失效"
(`<SK>\docs\PITFALLS.md` §8.2)——"它让读结果的人知道'全部通过'到底通过了什么"。

**元铁律**(`<SK>\SKILL.md`):"**不许用上游代理替代下游观察**"——记得的文本 vs 文本本身(M3)、配置 vs 渲染产物(M11)、
读过的印象 vs 重新检索(M14)、判据的转述 vs 判据本身、脚本自己打印的报告 vs 产物里实际有什么。
"这一族错误的定义性特征是**代理与被代理者在文本上无法区分**"——它读起来跟真的一样。

### 2.9 证据链与置信度怎么保存

- **证据链** = `deps` 边。任何 L3/L4 都能沿边追到 L1,再沿 `evidence`/`probe` 回到原文单元(回/章/fid)。
  GoT 的 L1 `evidence: '1-10 / 1-10-045'` 同时指向章节和事实库 fid。
- **`explains` vs 前提**:`explains` 列出推论真正在解释的 L1,其余 deps 当前提;缺省规则:`setting/meta`
  或视图配置里列为 `biographical/context` 的事实是前提(`<SK>\docs\CHECKS.md` ④)。
- **置信度**不是概率:① 层级天花板(status);② `conditional` 的软前提节点;③ probe 级 `woe_db` 与问题级净 dB;
  ④ 因果视图里的边权(也是 dB 四档);⑤ GoT L1 的人物识别 `confidence: high/medium/low` + `id_basis`;
  ⑥ 污染折扣 note("可能受后续剧情记忆影响");⑦ 预测检验结果(found/not-found/inconclusive/pending)。
- **台账与留痕**:图级 `changelog`(每次改动的原因与连带改动)、`ledger\probe-run-*.md`(追问求证)、
  `ledger\l1-check-*.txt`(机器台账)、`revision_log.md`(逐条复核意见裁决表)、`review2.md`、
  墓碑节点(`status: retracted` + `retracted_by` + evidence 写明如何倒的,正文保留"撤回前的原论证")、
  `.bak-before-review2` / `.bak-before-stageD` 备份。
- **墓碑是资产,不是违规**:被推翻的结论留在图上,让下一轮能看见它为什么倒(`REPORT.md` §8)。

### 2.10 两张图:推理图 vs 因果之树(causal-view / persona-causal)

`<IM>\journey_to_the_west\README.md`、`<SK>\docs\VIEW.md`:

| | 问什么 | 边的方向 | 文件 |
|---|---|---|---|
| **推理图** | 我凭什么这么认为 | 表象 → 内核(求证) | `rg-*.yaml`(单一真源) |
| **因果之树** | 他为什么会这样 | 经历 → 三观 → 需求 → 动因 → 表象(生成) | 视图配置 `causal-view.yaml`(只声明因果侧独有的东西) |

视图配置只声明:`bands`(B1 表象 / B2 因果要素 / B3 真实需求 / B4 经历·长期记忆·三观)、`subjects[].core_node`、
`biographical`/`context`(**唯一需要反向的一类边**:推理图里"内核依据经历",因果上是"经历造就内核";不列出来
"树看起来还是一棵树,但因果方向是错的")、`weights`(dB 四档)、`extra_edges`(推理图没有、只在因果上成立的边,
**必须带 `derived_from`** 指向一条推论,"它倒,边就倒";"只买到可追溯、可撤回,没买到已论证")、`suppress`
(推理图有、因果上不成立的边,通常是跨对象对照)、`anonymize`。

**演化(这是一个很好的"交付物无人看管"案例)**:`persona-causal.yaml`(2026-09-04)用裸字符串 `core`
(每个角色一句"内核",**没有 id、没有 status、不进覆盖率、无法被撤回——而它是读者唯一会记住的那句话**)、
`strength: strong/medium/weak`(81% strong)、11 条补边没有出处——其中 5 条是**死配置**(推理图已有同向 dep,
构建时被去重跳过,从未生效),3 条权重引用着已撤回节点。`causal-view.yaml`(2026-09-05)改为 `core_node`、
dB 四档"一律不升到 10"、补边全部带 `derived_from`、删掉死配置(见其 changelog)。红楼梦的 `core_node` 注释
"原为 J-by-40,该节点已被对抗复核撤回";GoT 珊莎"三条 L4 并列,没有一条能单独代表内核——找不到就留空"。

`render_causal.py` 出图前**先校验再出活**(裸字符串 core、core_node 指向已撤回、补边缺 derived_from、
旧强度词、10 dB 占比 >40% 一律 ERROR)。**构建逻辑只有一份**,在 viewer 的 `buildView()`;烘焙脚本只注入不重写
——"两份实现必然漂移,而漂移出来的差异恰好是'图上看到的'与'检查器查到的'不一致"。

### 2.11 覆盖率与停止规则

推理图谱只管"你说的话有没有依据",**从不问"这个现象有没有被解释"**——"一张所有结论都站得住的图,可以同时漏掉一半的材料"。
覆盖率五档:`covered / orphan(最先看:撤回时自己制造的空洞)/ unexplained / by-design / premise`(`CHECKS.md` ④)。

**必须报四个数**:图内覆盖率(分母=已入图表象)+ **材料覆盖率**(分母=全部单元;"几乎总是难看得多,而且它才是真的那个");
coverage 与 consistency 成对报(只报 coverage 会奖励最含糊的解释——"Barnum 效应的形式化");`setting` 占比(<10% WARN;
西游记一度言行 121 : 情境 2 ≈ 60:1,"基本归因错误在台账层面被固化了");`avoidance` 条数(西游记的实现把这一档**整个删掉**,0 条,无人发现)。

**停止规则**(`CHECKS.md` 末节):材料覆盖率多少、没挖的是"没料"还是"没去";新材料还在改变结论吗(连续两批只微调才接近饱和);
orphan 处理完了吗;每个开放岔口写清收敛条件了吗;对抗复核跑过几轮、攻不动的有多少。红楼梦 `REPORT.md` §5 按这五条自评,
结论是"本图**没有**挖到底"。

**承认"这就是没有深层原因"**(`no_explanation`)收得非常紧——四条必须全中:最简解释是情境(换谁都会这么做);
属于材料而非人的属性;**不与任何在用推论抵触**;豁免理由独立于它所拯救的结论。**"只出现一次"反而不得豁免,必须进对抗复核**
(引 Schegloff 1968、Turner 1953 对分析归纳"用重新定义排除反例"的批评)。

## 3. "说的"与"要的"之间的差距(问题 2)

这是与用户论点("人说的话常常绑定情境,不一定准确或真诚")对得最直接的一部分。方法里没有单独一章叫"言意差",
但它散布在每一层的设计里。归纳成九个机制:

### 3.1 言是证据,不是结论(结构性处理)

- **当事人对自己动机的报告是 L1(`provenance: speech`),不是 L2/L3**(`<SK>\docs\LAYERS.md` 末节)。
  "我是因为在乎公平"→ 记"被问及为何退出时他答'我是因为在乎公平'"。理由列得很全:**防御、事后合理化、
  社会赞许性作答、他真的不知道**。
- GoT 抽取层把它做成数据结构:**行为一条、原文写出的意图另起一条 thought/narration**,不许括注进行为
  (`extraction\INSTRUCTIONS.md` §1.1);分析指南:"人物**自称的动机**是 L1(speech/thought),**不是** L2。
  它是证据,不是结论——**自称与行为不一致之处恰恰是分析入口**"(`analysis\ANALYSIS_GUIDE.md` §2)。
- 红楼梦在复核后立规:"**凡'价值观'层节点,证据必须排除人物自陈**"(`REPORT.md` §6 第 4 条)。

### 3.2 自我叙事 vs 行为:"把人写成他自己价值观的执行者"

最好的范例是宝玉(`<IM>\dream_of_the_red_chamber\rg-honglou-intent.yaml` J-by-40/J-by-42):

- 原结论 `J-by-40`(L4 价值观):"他判善恶的轴是'人有没有被当成手段'"——取自他的自我叙述。
- 被四处**行为记录**直接反证:金钏事发他"一溜烟去了"(F-by-29)、留袭人的方案是"多多给你母亲些银子"(F-by-30,
  正是他在别处斥为"倚势仗贵"的做法,拒绝这个方案的是袭人)、事后自陈"四儿是我误了他"(F-by-31)——**他知道**。
- 撤回后的替代结论 `J-by-42` 更窄而不与任何行为抵触:"**他为被兑换掉的人付的是事后的表达性代价,不是当场的干预代价**"
  (祭文、替丫鬟认窃案)。还另起 `J-by-13`:"他动用庇护资源的方式,与他反对的那套用法在形式上是同一种……识别发生在事后。"

这个结构对个人助手极有用:**不是"他虚伪",而是"他的价值观以某种特定形式表达"**。言与行都是真的,区别在于**在哪个时点、
付什么代价**。类似地,唐僧"叙述者先立'一生不会说谎'再当场写他打诳语"→ `J-ts-57`"**干净是分戒条的**"
(淫戒守得住,妄语戒守不住)——价值观是**按领域分的**,不是全局的(`journey\ledger\probe-run-2026-09-04.md` 对抗复核节)。

### 3.3 自陈也可以是反证——不要一概丢弃

凤姐:原结论 `J-xf-40`"说了算本身是标的,不是手段",被**她自己的话**推翻——她对尤氏说怕"指名提我、要休我"(F-xf-16),
叙述者直录她要"保住自己的名誉"(F-xf-17)(`parts\11-review.yaml`)。所以自陈不是被降权的垃圾,而是一种**有特定偏差的证据**:
对己不利的自陈、私下的自陈、事后很久的自陈,价值更高(`LAYERS.md` 正交证据清单)。

### 3.4 情境性言辞:受众与"有没有人在看"

- 悟空 `J-wk-47`"**不动摇是对下的表演,对上位者他示弱**":第七十七回同一回内,在师弟面前"微微笑"说"兄弟莫哭",
  转头在如来面前"泪如泉涌"(`rg-journey-west-psyche.yaml` 第 2382 行)。
- 宝钗的最小对照对:出错代价同样高的两个场合,**只翻转"当场有无上位者在看"**——无人看见时(滴翠亭)把判断引向他人,
  有人看见时(金钏之死)自掏新衣替上位者出说法(`REPORT.md` §1)。
- 方法上的支撑:`setting` 独立成档 + 占比阈值;矛盾先假设"需求未变、策略随情境变"(D-mth-03)。
- 对 ergou 的含义:**受众(私聊/群聊/抄送了谁)、时间压力、渠道是一等的情境变量**,每条指令都要记。

### 3.5 欺骗:不由分析者判定"他在撒谎"

- 抽取规则:"**原文明确是谎言才写'撒谎',否则写'说'**"(`INSTRUCTIONS.md` §2)。叙述者明说的欺骗作为 narration L1 入图:
  袭人"**故先用骗词**"(F-xr-16,赎身之说是骗词,她家早已"再无赎念")、唐僧"**顺口儿答应**"(骗悟空戴帽)、
  琼恩"**琼恩撒了谎**"(1-61 对熊老说很好)。
- **被骗的一方**同样要处理:悟空戴金箍是在受骗情境下的行为,"省略也是夹带"——不补上情境,下游会把它读成"自愿"。
- "真诚与否"的判断本身是 L2 推断:GoT 把"POV 对他人当下心思、真诚与否的判断"记成 narration(source=POV),
  "**两者都不是客观真相,只是 POV 眼中的世界**"(`INSTRUCTIONS.md` §1.2)。
- 袭人那条还展示了**欺骗如何推翻代价法读法**:原说赎身是她当场押上的筹码;原文显示"赎身选项在那场对话开始之前就已经不存在,而她知道"
  → 风险偏好整条撤回,替代为 `J-xr-42`"**她只在代价已被自己事先消掉之后才行动**",并写明证伪条件。

### 3.6 自我欺骗/不自知与"嘴上要真相,心里不想知道"

- 琼恩 Q-JON-04"藏起痛苦是护自己的形象,还是替对方减负?":找的夹缝是"**隐瞒对任何人都无益**"的场合——1-61 他谎称很好,
  哀嚎只有白灵知道并暗谢诸神,+6 dB 偏"护形象",按规则仍不收口(`rg-jon_snow.yaml` 第 12367 行)。
- 提利昂 `J-TYR-p06-011`:与雪伊关系里"嘴上要真相、心里不想知道",**二审要求不外推**——他对父亲恰恰是主动追问的
  (`tyrion_lannister\REPORT.md` §4)。原本外推成 L3 的 `J-TYR-L3-07` 已撤回,且被指出可能受后续剧情记忆污染。
- 提利昂"向来说话算话"是 POV 自评,**不能当客观证据**(二审 R-03)。

### 3.7 回避(avoidance):没说的比说的更有信息

- 贾母:迎春婚事"心中却不十分称意……只说知道了三字"(F-jm-15,`avoidance`)。
- 袭人 `F-xr-11`:进言全程**没有**动用自己手里最有说服力的那张牌。
- GoT 对回避有严格判据(刺激 + 原文写出不回应),并区分拒绝/谢绝/含糊/离场/做不到/忘了。
- "真人分析里 avoidance 是最贵的一档"(`CHECKS.md`),而它又是**最容易被整档漏掉**的(西游记 0 条)。

### 3.8 代价法与时序法:绕开言辞的两条硬路

- 代价法:"人可以说自己重视什么,但**资源分配不会说谎**";真人场景里是少数与言辞正交的证据源(`MOVES.md` Move 2)。
  凤姐对照对:庙外求告给不了她"事情经过她"的位置,她**收**三千两;园内姊妹能给,她**掏**五十两——"钱的方向相反,换到的是同一样东西"。
- 时序法:"他抱怨的那件事被解决之后,他满意了吗?"——对指令场景几乎可以直接照搬(交付后接受/返工/放弃)。

### 3.9 矛盾是入口

前后不一致时**先假设需求未变、策略随情境变**;"作者写岔了/那天他喝多了"是最后手段。新假设必须能"顺带解释一个挂在别处的现象",
否则只是给矛盾起了个名字。

### 3.10 问当事人时的特殊风险

答案是新的 L1;问会改变被问者;问动机拿到的是合理化;施测者知道假设就会领读(`PROBES.md`)。
**这一整套是为真人准备的,但三部小说都没有用上**(`journey\README.md`:"subject 问当事人——分析真人时的主力;
虚构角色无从问起,故本图不用")。也就是说,**对 ergou 最关键的那部分机制,在参考项目里是未经实盘检验的设计**。

## 4. 不确定性、竞争假设与修订(问题 3)

### 4.1 不确定性的表示

1. **层级天花板**(L2 unverified、L3/L4 conditional),且守住它的是**人的纪律而非校验器**——"verified 不许依赖 unverified"
   这条机器规则在心理层**一次都不会触发**(实测 L2 以上 verified 节点 = 0),`rules.yaml` 把它登记为 `fires: false`,
   专门防止再被写成"最承重"(`PITFALLS.md` §5.4)。
2. **软前提即节点**:conditional 必须指名压在哪个 unverified 节点上;变成节点后"它可以被攻、被撤回、被覆盖率统计;自由文本不行"。
3. **竞争假设并列**:title 以"竞争假设:"开头的兄弟节点(西游记约定,check_probes 据此识别),由 question 统领。
4. **证据权重 dB + 净 dB**;"分不了"的两种形态(未研究 vs 研究过但势均力敌)。
5. **预测与结果**:`predicts[].outcome ∈ {found, not-found, inconclusive}`,GoT 增加 `pending`(留待保留集);
   **"在已入图材料上检验的不算前瞻"**(提利昂 C-09:found 改 inconclusive)。
6. **污染标注**(GoT):凡只有知道后续剧情才会注意到的表象/读法,节点 note 标注并对上层打折。
7. **类属解释的显式化**:对照组 domain 与"类属对手"(如 J-CAT-L4-06"贵族女性通例")。
8. **材料缺口声明**:红楼梦后四十回 out of scope 的代价写明;GoT 1-56 原文缺失写入局限。

**一个需要吸取的教训**:GoT 八份报告对"压在前提上但没赢过对手"的结论**标法不一**(四份标 unverified、四份保留 conditional
另注"与对手并列";"候选"一词在不同报告里含义相反),汇总时只好改写成三档白话"有条件成立 / 与对手并列 / 未立住"
(`SUMMARY.md` §3.3)。**ergou 必须从第一天就有统一的状态词表**。

### 4.2 修订:谁触发、怎么传播

- **反向审查是第一纪律**:新证据推翻旧节点时,当场改旧节点 status 并顺 `deps` 复审下游,不许"在新节点里顺嘴提一句旧的错了"。
  完整链条示例:撤回 J-wk-36 → 反查发现 J-wk-54 失去唯一支撑 → 一并撤回 → Q-wk-02 前提为假作废(dropped),重问为 Q-wk-03
  (`PITFALLS.md` §4.3)。
- **复活**:J-wk-54 被"第四十二回关系完好仍求摘箍"撤回,复核发现那是观音先索押品逼出的抵赖,读错语境 → 复活
  (rg 第 712 行:"本条曾被撤回又复活")。J-wk-37 因"把落泪的人记成了悟空"被撤,后来在第七十七回找到正确依据复活。
  **教训:二值判决里没有"中等强度"的格子,一条 6 dB 的证据被当成无穷大用,沿边推倒一片又推回来**——这是引入 woe_db 的直接原因。
- **问题重开**:Q-wk-01 第一轮判 answered,对抗复核指出"第三条候选此前根本不在场",退回 open;三条候选都在场后重新收敛。

### 5.2 演化路径

1. **西游记 = 试错期**(`journey_to_the_west` git log):建双图 → 加追问机制(discriminates/probes)→ 9 条追问回原文求证

   接上通用检查器 → **方法论层面的对抗复核**(git 里是两次收口提交,skill 的 `PITFALLS.md` §9.8 记为三轮;
   产出 M9–M14、新检查器、对照对判据替换、元铁律与 `check_docs.py`)→ 接上 skill 展示层。
   这里长出的每一条规矩都写进了 `<SK>\docs\PITFALLS.md`,"**没有哪条铁律是想出来的**"。
2. **skill 成文**(`<SK>` git log 2026-09-05):首次提交 → 展示层(因果之树、拖拽 viewer、烘焙)→ 发布口径三开关
   (`--prune/--strip/--full`)+ 覆盖率区分"前提/被解释" + "第五件外衣"(看着自己打印的报告宣布成功)。
   方法论复核的人员设计值得注意:**复核员先在不看方案的前提下做跨学科调研**(临床概念化、归因理论、情报分析 ACH、
   定性方法 QCA、自我报告效度、认知访谈、JTBD…),再拿方案打三轮;14 条铁律里 6 条、8 个检查器里 4 个出自这三轮。
3. **红楼梦 = 第一个规范样本**:门禁三问显式过、scope 写死 purpose、L0 软前提全部节点化、对照组单列、预测先写后搜、
   检索先跑后落笔、按材料覆盖率开 pass2、复核用"只给结论"清单。复核又打出新的系统性错误(语料污染、价值观执行者),
   并新建 `check_corpus.py`。
4. **GoT = 规模化**:把 L1 从分析里拆出去成为独立的、有 schema、有版本、有规则迭代、有归一化与纠错回流的**事实层**;
   分析按 A(分段初读,只做 L1/L2,记录 contradictions/invariant_candidates/fact_errors/contamination_flags)→
   B(综合建 L3/L4 + 追问 + 预测)→ C(对抗)→ D(修订 + 报告)+ 二审 流水线化。报告模板固定六节(一句话结论带天花板 /
   内核 / 需求 / 情境动机与竞争假设 / 未解释表象+墓碑+污染声明 / 事实库纠错清单)。
5. **站点**:三部合一,`site\build.py` 只切数据不做因果规则,viewer 直接指向 skill 目录不复制。

### 5.3 哪个最成熟

- **方法**:以 `<SK>` 为准(最后成文,吸收了三部的教训;红楼梦与 GoT 都在用它)。
- **流水线**:**GoT 最成熟**——它是唯一一个把"材料 → 事实"做成独立、可审、可迭代、可回流纠错的层,

### 6.1 现有呈现

**统一站点**(`<IM>\site\`):

- `build.py`:把每部的推理图按人物切成 `data\<系列>\<人物>.json`(`{graph, view}`),只保留 viewer 用到的字段(KEEP 列表);

- `serve.mjs`:**白名单**静态服务,默认拒绝;注释明确"data/*.json 装的比页面上显示的多(含已撤回结论、内部备注),
  换成真人分析时要先收紧"。
- `embed-bridge.js`:被 iframe 嵌入(如 livedeck 演示)时转发 Ctrl+滚轮、加返回按钮。

**因果之树 viewer**(`<SK>\assets\causal-viewer.html`,自带 js-yaml,离线可用;西游记旧版是 `scripts\persona_template.html`):

- 两种模式:**层级一览**(默认;同层平铺成网格;三观与真实需求在最上面、显示正文;动因按所服务的需求分组;超过 60 条的层收起,
  **选中任一节点时收起的层只列出与它相连的那几条**)/ **因果树**(经历在根、表象在梢,光自下而上流;可关掉表象层以扛住上千节点)。
- 交互:单击锁定整条链;双击"独看此链";**「链路」**列出穿过选中节点的全部根→梢路径;**「追问」**抽屉列出该对象所有未决岔口与设计好的问题,
  按"要你定夺(where: user)> 未决 > 已收口"排序,每条显示"A 还是 B"、去哪问(回原文找/问当事人/要问你)、是→/否→;
  "竞争假设"开关;"只看未被解释的表象"(孤儿高亮,"没有任何因果边的节点是因果模型的空洞,标出来不藏起来");
  "弱因果"开关;搜索;顶部 core 行,core_node 已撤回时显示"⚠ 该内核所指节点已撤回"。
- 性能纪律:扛住单人 1300 节点 / 1400 边,禁用 backdrop-filter、SVG 滤镜、逐边渐变等(`VIEW.md`)。
- 推理图(求证方向)用 `<RG>\assets\rg-viewer.html`,按 domain/kind/status 过滤;"取消 stated 这类证据,整张图当场塌成 unverified"
  这种"如果我不认这类证据,还剩什么"的切换很有启发(`<RG>\docs\EXAMPLE-INTERVIEW.md`)。

**报告**:Markdown,固定结构,先写"本报告不回答什么",每条结论带节点号,墓碑表,覆盖率四个数,停止规则自评,已知缺陷"不是免责声明,是账"。

**发布纪律**(`VIEW.md`「真人分析:发布指的是什么」):发布 = 文件离开本机;烘焙产物自包含、`view-source` 能读到墓碑原话与内部备注;
"**被推翻的推测往往比留下的结论更难听**,而 changelog 会原样记着你为什么撤它";`--prune`(已撤回的连标题都不留)、`--strip`;
`subject_kind: person` 时默认收紧;`anonymize` 改写 payload 里的名字但**做不到正文脱敏**;"对象本人有没有同意被这样分析,是范围问题,
写进 scope,别写进代码"。还有一个实测坑:字段计数全绿,但**全文检索仍能搜到被推翻的结论原话**(存根保留了标题)——
"字段级检查回答'这个字段还在不在';**全文检索回答'读者能不能看到那句话'**,后者才是隐私要问的问题"(`PITFALLS.md` §8.3)。

### 6.2 对"我对你的理解"UI 的建议

读者从"研究者看虚构人物"换成"**被分析的人本人看自己**",信息架构要改。建议:

1. **分三栏,由硬到软**:
   - **"我观察到的"(L1 聚合规律)**:可计数、带分母与时间窗,如"近 30 天 10 份报告草稿里,你有 8 份把结论挪到了开头"。
     每条可展开到原始消息/操作(M3 的用户版)。这是最不冒犯、最可纠正、对指令解释最有用的一层,默认展示。
   - **"我猜你在意的"(L3)**:每张卡片 = 一句需求 + "有条件"标记 + 白话强度("略偏/明显偏/分不开",不用 dB)+
     **并排的竞争解释**("或者也可能是…")+ 证据链(点开到 L1)+ 反证 + **预测记录**("我预测过 X,后来 4 次里应验 3 次")。
   - **"更深的猜测"(L4)**:默认折叠,需用户主动开启;明确标注"这是推测,压在'这段经历是原因'这一未经证实的前提上"。
2. **每张卡片的操作**:`对` / `不对` / `部分对(编辑措辞)` / `这只是当时的情境` / `别分析这个领域`(写入 scope.out)/ `删除`。
   区分"**这是证据**"(你的反馈作为新 L1 参与推理)与"**这是授权**"(scope 决定,立即生效、硬约束)。
3. **"我想问你的"面板** = 追问抽屉的用户版:只放 `where: subject` 的中性情境问题("上次你改那份方案前,最后一件让你不顺的事是什么?"),
   以及 `where: user` 的授权问题("要不要我记录你在群聊里的说话方式?")——**授权类置顶**,与 viewer 现有排序一致。
   用户可答、可跳过、可"别再问"。
4. **"我搞错过的"**(墓碑):被推翻的猜测与推翻它的事实,建立信任;但**提供一键彻底删除**(不是只隐藏)——
   这是 M11 在隐私上的形态:**删数据,不是删显示**。
5. **"我还没看过的 / 解释不了的"**:材料覆盖率(哪些时间段/话题从没处理)与孤儿观察("这几件事我还说不清原因,你愿意补充背景吗?")。
6. **"这些理解被用在了哪里"**:指令时使用日志——"你说'随便写写',我参考了 [规律 R-12] 写得偏正式;结果:你接受了 / 你改回了随意"。
   这是让用户审计"agent 有没有拿对我的理解来擅作主张"的唯一办法。
7. **语言纪律**:禁止全称量词("你总是/从不")、禁止人格标签("控制欲强")、禁止"你在撒谎/你其实不想"这类判词;
   用"我注意到…/我猜…/也可能…"。这正是 M6、L2 反标签测试、§3.5 欺骗处理在 UI 文案上的落地。
8. 保留 viewer 的两个好设计:**层级一览**(一屏看全需求与价值观)与**链路**(点任意一条结论看它的全部来路)。
   因果树形态对用户本人可能过于"被解剖感",建议作为高级视图。

## 7. 适配分析:从小说到活人(问题 6)

### 7.1 根本差异

| 维度 | 小说 | ergou 的用户 | 对设计的含义 |
|---|---|---|---|
| 材料 | 封闭、完整、可整本检索 | **增量、碎片、永远不完整**;多渠道(聊天/指令/文件编辑/日历/工具日志) | 无"读完"一说;覆盖率按时间窗与话题算;停止规则变成"预算 + 触发条件" |
| 对象能否被问 | 不能(`text` 为主) | **能**(`subject` 为主) | 追问机制成为主力,但带反应性、领读、合理化风险 |
| 正交证据 | 几乎没有(天花板是结构性的) | **有**:时间/金钱/注意力花费、对 agent 产出的接受/编辑/返工/放弃、长期行为日志 | 代价法与时序法成为最强工具;但自陈仍只是 L1 |
| 预测检验 | 只能"留待后续卷" | **未来行为就是保留集** | M14 预测可被真实检验并统计命中率——从"理解"走向有校准的"预测" |
| 外生冲击 | 作者施加 | **agent 自己施加**(它的建议、默认值、提醒塑造用户行为);外部生活事件 | 必须把 agent 自身动作记为 `setting`;"接受了建议"是弱证据(默认/顺从偏差) |
| 污染源 | 分析者读过全书 | agent 的先验(训练数据里的刻板印象、早期 L3 的锚定)、选择性记录("因为想到解释才记下") | 抽取与分析分离;L1 抽取按规则穷举而非按假设挑选;类属解释显式化 |
| 对象会变 | 人物在文本内可视为稳定 | **人真的会变**(换工作、搬家、有孩子、心情周期) | 需求要有有效期与转折点节点;"需求跨期稳定"软前提必须按时间窗建 |
| 错判代价 | 一篇错的分析 | **错误行动、家长主义、被冒犯、被操纵感、信任崩塌** | 推断的使用权限要远低于推断的存储权限 |
| 发布 | 公网站点,虚构人物"无所谓" | 关于用户本人,本人有知情、查看、纠正、删除权 | 本地优先;展示即数据;删除即删除 |
| 授权者 | 使用者 ≠ 对象 | **使用者 = 对象** | `where: user`(授权/范围)与 `where: subject`(取证)问的是同一个人,但性质完全不同,不能混 |
| 成本 | 一次性大投入可接受 | 持续运行,每轮都要花钱 | GoT 级别(每人上千节点、每章 10 万 token、每轮三审)不可持续,要分层降本 |

### 7.2 搬什么、改什么、丢什么

**原样搬**(方法层):四层 + 天花板(M2);M1 四测试与"拆分优于修饰";M3 可重复定位;provenance 词表(含 avoidance 与 setting 及其分布告警);
M4/M5/M12 追问纪律与预期分离测试;woe_db 四档;M6 全称量词;M7 orphan;M9 对照对结构化;M10 独立腿;M11 交付物即数据;
M13/M14 预注册预测;Move 1–5;矛盾处理顺序;`no_explanation` 的四条严格判据;墓碑与复活;对抗复核两条有效批评标准与"攻不动的"必答项;
元铁律(代理 vs 下游观察)与每个检查器的谓词自陈。

**改造后搬**(流水线层):GoT 的"事实层与分析层分离"→ ergou 的"观察抽取进程"与"理解合成进程"分离;GoT 抽取规则 → 观察抽取规范(见 §7.3);
registry/归一化 → 用户世界的实体表(人、项目、地点、别名);分析→事实纠错回流 → 理解层发现观察记错时的裁定队列;
A/B/C/D 四阶段 → 实时/指令时/会话后/周期四个节奏(§7.4);报告 → "我对你的理解"页面(§6.2)。

**丢弃或大幅降级**:按章的全量抽取(改为按会话增量);每次三轮对抗复核(改为只对变更的 L3/L4 做 dirty 复核,低频);
单人上千节点的 L2 全量建图(L2 只在指令时为需要的指令生成);因果树作为主视图;版权 30 字引文限制(换成"存指针不存副本"的隐私限制)。

### 7.4 更新节奏(对应 GoT 的 A/B/C/D)

| 节奏 | 做什么 | 参考来源 | 成本控制 |
|---|---|---|---|
| **实时(每条消息/操作)** | 原始材料落盘 + 定位;轻量标注 instruction / setting(时间、渠道、受众、agent 上一步做了什么) | 门禁①、M3 | 不做任何解释 |

### 7.5 指令时如何用这些理解去解释意图

这是 ergou 相对参考项目最大的新增部分。参考项目只做"理解",从不需要据此**行动**。建议流程:

1. **记录**:把指令记为 L1(said)+ 当时的 setting(受众、截止时间、渠道、agent 上一步)。
2. **检索**:相关的 L1 规律(最有用)、在用的 L3(只取 user_verdict 非 rejected/forbidden 的)、open Q 中可在本指令触发的 probes、L0 禁区。
3. **生成并列读法**(L2,竞争假设并列,不只挑一条):字面读法、情境读法(约束驱动:"赶时间所以说随便")、需求读法(来自 L3)、
   类属读法(必须标 class_prior)。**矛盾时先假设"需求未变、策略随情境变"**。
4. **预期分离测试的行动版**:这些读法**会导致不同的行动吗**?不会 → 直接按字面做,不必消歧。会 → 进入 5。
5. **按错判代价分级**:
   - 低代价且可逆 → 按最可能的读法做,用一句话出示 **L1 证据**而非诊断("你上 3 次给王总的邮件都改正式了,这次我写得偏正式;要更随意说一声")。
   - 高代价或不可逆 → **问**,而且是 `subject` 档的问法:具体、中性、不含假设措辞(领读检测同样适用于 agent 的澄清问句)。
     这是最自然、最不冒犯的追问时机——问题与手头任务直接相关,不像无端的心理访谈。
   - **任何情况下,L3/L4 不得覆盖显式指令**;最多附注、提问或提供备选。
6. **事后**:回填 outcome(接受/编辑/返工/放弃)——这就是 Move 5 时序法的数据:"他要的那件事交付了,他满意了吗?"
   同时给相关 L2 读法与 L3 的 predicts 记分。
7. **透明**:写一条"使用日志",让用户在 UI 里看得到这次用了哪条理解、结果如何。

**一个走查示例**(体现用户论点"话绑定情境"):

> 用户:"给王总回个邮件,随便写写就行,别太正式。"
> - L1:said(原话);setting(受众=上级、渠道=邮件、距会议 20 分钟)。
> - 规律 R-012:近 30 天发给上级的 5 封草稿,用户 4 封改得更正式。
> - 并列 L2:(a) 字面:要随意语气;(b) 情境:赶时间,"随便"指"快",语气仍需正式;(c) 需求(J3-005,conditional):对上沟通求不出错。
> - 行动分歧:有(语气不同)。代价:中(对上、可在发出前修改)→ 按 (b) 写偏正式的短邮件,附一句 L1 证据与一键切换。
> - 结果:用户直接发出 → +3 dB 给 (b)/J3-005,并给 R-012 增加一个分子;用户改随意 → 记为 (a) 的证据,且触发"需求是否已变"的复审,
>   **不**因为一次就推翻 L3(那会重演"二值判决里没有中等强度格子"的事故)。

第二个示例(需求挖掘,对应 Move 5 与"可控变体"):用户多次要求"更详细的计划",但交付的长计划很少被打开或执行
(did/avoided 观察)。时序法:请求被满足而行为未变 → 说出来的请求可能不是真需求。竞争假设:要确定感/安全感 vs 要可执行的下一步。
`observe` probe:下次给"一页结论 + 前三步 + 折叠的详细附录",看他用的是哪部分;**而不是**问"你为什么想要详细计划"(那只会拿到合理化)。
注意:这种"agent 主动做小变体来判别假设"是小说分析不可能有的能力,但它是对用户的轻量实验,需要用户事先同意(见开放问题)。

### 7.6 主动追问:把 `subject` 档落地

- **两类问题不能混**:`where: user`(授权/范围:"要不要我记录 X?"——答案是 L0 decision,立即生效)与
  `where: subject`(取证:"上次…发生了什么?"——答案是 L1,参与推理)。参考项目里这两类问的是不同的人,ergou 里是同一个人,混了就会出现
  "用户说'别分析这个',agent 却把这句话当成一条'他在回避'的证据"这种严重越界。
- **先观察,后提问**:判别力最强的观察先做完;问过之后他会留意,后续行为不再自然(`LAYERS.md` 末节)。
- **问事件,不问动机**;`elicit` 只做情境重建 + 报告一切。
- **领读检测**:澄清问句与竞争假设标题求词元交集,有交集就改写(参考 `check_probes.py` 的实现)。
- **施测与判分分离**:对话层只拿到中性问句(不知道 if_yes/if_no),后台分析进程从转录判分。这在 agent 架构里天然可实现(两个进程/两个提示)。
- **追问预算**:只在相关指令出现时触发(`trigger`),设每日/每周上限;用户可"别再问这类"。
- **答案的效力**:用户的回答作为 L1,权重按正交程度定(对己不利的、事后很久的、私下的更高);**不得直接兑现为 L3**。

### 7.7 冷启动

- **门禁①在 ergou 的形态**:保存原始材料并可检索(经同意)。**不要用 LLM 摘要当记忆的 L1**——那正是"凭记忆建 L1"(15% 错误率、"读起来跟真的一样")
  与"档案是代理"的教训;摘要只能当索引,结论必须能回到原始消息。
- 初期只有 L1、L1 规律、指令时 L2;**L3 至少要两条来自不同情境的不相交腿才建号**,L4 要等 L3 + 本人讲述的经历(作为 L1 speech)+ 预注册预测。
- 可以有一次**轻量的、以授权为主的引导**(where: user:哪些领域可分析、哪些渠道可读、展示到哪一层),外加显式偏好收集(作为 L1 said)。
  **不要**在冷启动时做动机访谈(反应性 + 合理化,且没有可对照的行为)。
- 类属先验("程序员通常…")可以作为默认 L2 读法,但必须标 `class_prior`,并在有个人证据后让位(Move 3)。

### 7.8 隐私与用户的知情、查看、纠正、删除权

- **本地优先**;理解模型永不发给第三方,永不用于广告/说服式设计;写成 L0 decision。
- **展示即数据**:用户看到的就是存的;反之,用户删除的必须从数据层删除(含墓碑、changelog 里的原话、全文索引)——参考 `--prune` 的
  "已撤回的连标题都不留"与"全文检索才是隐私要问的问题"。
- **敏感领域默认 scope.out**(健康、性、宗教、政治、财务细节、亲密关系),需用户 opt-in。
- **第三方**:用户谈到的其他人,用户的话是**用户的** L1(narration,source=user),不为第三方建心理模型(参考 GoT"梦中人物不进 targets"、
  "讲传说不为故事人物建 ID"那种克制)。
- **"对象本人是否同意"写进 scope**(`VIEW.md` 最后一条)——在 ergou 里这是首次运行时就要问的问题。
- `anonymize` 解决不了正文可识别性——导出/分享理解模型时只能导出结构或重写。

### 7.9 错判代价与过度解读的防线

| 风险 | 参考项目里的对应防线 | ergou 里的形态 |
|---|---|---|
| 一次行为→宣布核心需求 | L2/L3 判据;M10 独立腿 | L3 建号门槛(≥2 条不相交、跨情境腿) |
| 贴标签 | L2 反标签测试("别处应该看到___") | 每条 L2/L3 必须写 expects_elsewhere / predicts |
| 叙事顺滑、硬编一致的人 | MOVES 伪动作第三条;主动找 negative case | 合成时为每条 L3 主动找一条它解释不了的观察 |
| 基本归因错误(情境记到人身上) | setting 档 + 占比告警 | 每条指令强制记 setting;setting 占比监控 |
| 把"没找到"当"没有" | M8/M12 | "他从不…"类结论禁用;`if_absent: inconclusive` |
| 全称量词 | M6 + check_drift | 存储与 UI 文案都禁"总是/从不/一切" |
| 中等证据当决定性 | woe_db 四档,不设 >10 | 一次反例不推翻 L3,一次命中不确认 L3 |
| 硬给行为配深层动机 | `no_explanation` 四条判据 | 允许用户/系统标"情境性/心情/随手",但"只出现一次且与 L3 抵触"的反例不得豁免(Turner 陷阱) |
| 分析者先验污染 | GoT 污染标注 + 二审差集扫描 | 抽取与合成分离;记录"这条理解最初来自类属先验还是个人证据" |
| agent 自己制造了它观察到的行为 | (小说里是作者的外生冲击) | agent 动作记为 setting;"接受建议"默认低 woe |
| 推断被用来擅作主张 | (小说无此问题) | L3/L4 不覆盖显式指令;出示证据不出示诊断;使用日志 |
| 用户被冒犯/被看穿感 | VIEW.md 发布纪律 | 分层展示、L4 opt-in、禁判词、彻底删除 |

### 7.10 检查器 → 运行期不变量

| 参考检查器 | ergou 中的运行期检查 |
|---|---|

## 8. 开放设计问题

1. **用户纠正的效力**:用户说"不对"时,是硬删除/硬抑制,还是作为一条 L1 证据参与推理?方法论说"自陈是 L1 不是结论",
   但用户对自己的模型有自主权,且权力不对称。建议"**行为上硬服从、证据上可保留(经同意)**",需要定。
2. **展示深度**:L4、竞争假设、墓碑默认对用户展示到哪一层?是否允许用户关闭 L4 合成本身?
3. **主动变体实验**:是否允许 agent 在可接受范围内对输出做小变体来判别假设(活人版最小对照对/外生冲击)?同意与告知机制?
4. **追问预算与时机**:只在相关指令出现时问,还是允许空闲时问?每周上限?如何避免"被审讯感"?
5. **原始材料留存**:门禁①要求可重复检索,与隐私、存储成本、删除权冲突;保留期多长?哪些渠道默认不留原文只留指针?
6. **抽取进程**:L1 抽取由对话模型顺手做,还是独立后台进程(GoT 证明分离的价值)?用什么模型?每会话 token 上限?
   抽取规则文档是否也按"反馈聚类 → v2/v3/v4"迭代?
7. **时间模型**:需求变化用"有效期 + 转折点节点"(方法原生),还是引入时间衰减(方法里没有)?二者如何共存?
8. **预测的形式化**:`predicts.claim` 能否写成可自动匹配的条件(领域 + 情境 + 预期行为),从而自动记分?自动化到什么程度仍需人/复核员判?
9. **L3/L4 的行动权限边界**:只用于消歧与提问,还是可用于主动建议(proactive)?主动建议是否必须附证据并可一键关闭?
10. **agent 作为冲击源**:"用户接受了 agent 建议"计多少 woe?是否需要专门记录"agent 推荐 vs 用户自发"的区分?
11. **复核的运行形态**:后台周期性独立复核员 subagent?触发条件(L3 将首次被用于指令时 / 将展示给用户时)?成本上限?
12. **统一状态词表**:吸取 GoT 八份报告口径不一的教训,先定 "有条件成立 / 与对手并列 / 未立住 / 已撤回 / 用户否认 / 禁止分析" 等词表及其 UI 白话。
13. **存储形态**:直接复用 reasoning-graph 的 YAML DAG + 检查器 + viewer(零成本起步,但 YAML 不适合高频增量与并发),
    还是 SQLite/图存储 + 自写检查器(需重写,但可查询)?viewer 是否复用 `causal-viewer.html` 的 `buildView()`?
14. **实体归一**:联系人、项目、地点的别名表(GoT registry 的对应物)是否属于记忆系统的一部分?谁来裁定歧义?
15. **用户可标"情境性"**:允许用户把某次行为标为"那天心情不好/只是随手",等于用户发起的 `no_explanation`;
    如何防止它被用来(或被 agent 用来)排除恰恰会推翻某条 L3 的反例?
16. **保留集**:是否留出一部分观察只用于检验、不用于建模,以获得诚实的预测命中率?
17. **解释语言**:如何把 L3 表述为用户能接受、不冒犯、不标签化的话?是否所有对用户的解释都只出示 L1 证据?
18. **多渠道人格一致性**:工作与私人场合的行为算不算"同一个人的表象"?这正是 PROBES.md 举的 `where: user` 典型问题,需要用户在 scope 里定。
19. **未经实盘的部分**:参考项目的 `subject` 档字段(elicit/blind/scored_by)从未在活人身上跑过;
    ergou 需要自己的第一份"实盘 PITFALLS",并决定用什么指标判断这套机制在真人上是否奏效(例如预测命中率、用户"对/不对"比例、返工率下降)。
