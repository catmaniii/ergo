## 0. 一页结论

1. **AgentSense 的缩放**
   - 只有会话历史能捏合，每个会话都能（它没有普通聊天）。
   - 做法是同一份 DOM 整体 `scale(s)`。每条历史的矩形形状不变，矩形里显示的东西随比例在三层之间交叉淡入淡出。
   - 松手后在对数空间吸附到最近一档：1（对话层）、0.45（要点层）、0.15（全局层）。数组里还留着 0.06，但第四档"计划层"在 2026-10-04 已经去掉，换成了标题栏下的抽屉。
   - 锚点是双指中点下那一点内容。
   - 电脑上是 Ctrl/⌘ + 滚轮，触控板捏合也走这条路；标题栏还有一个 ▤ / 💬 按钮。
   - 没有档位指示。缩小后输入框淡出，换成一条图例。
   - `zoom.ts` 和 `usePinch.ts` 共 243 行，和业务无关，能原样搬。`ZoomHistory.tsx` 1116 行，约四分之一是通用骨架，其余要按二狗的数据改写或不要。
2. **AgentSense 的详情页**
   - 任何一条历史都能打开：用户气泡点整条；回复、思考点"详情 ›"；工具行点整行，行尾有 ›；横条点右边的 ›；计划卡点"详情 ›"。
   - 宽屏（≥600）在右栏，可拖宽，但显示宽度封顶在窗宽的 32%。窄屏是三页滑动里的第三页，整页。
   - 详情之间能一层层钻进去，返回一层层退。有"在对话中定位"。
   - 参数和返回用 `ValueView` 按字段画（中文字段名、单位、表格），不甩 JSON；原始参数收进"给开发者看"的折叠区。
3. **AgentSense 的聊天区**
   - **没有**"调用了 N 个工具 ›"这种汇总行。它是一个工具一行：说人话的一句、缩略图、小签、行尾 ›。连续 3 次以上同名、都顺利执行的调用，折成"还有 N 次同样的操作，都在授权内 ▾"。
   - 思考默认一行："💭 Agent 的想法（点开看）"。
   - 回复只显示第一段，后面有内容时给"展开细节 ▾ / 详情 ›"。
   - 拦下、拉回、退回是一行横条：点开看要点，点 › 进详情。
   - 用户要的汇总行是在 AgentSense 之上加的。二狗的工具是 bash、read、edit 这类细粒度工具，一轮动辄十几次，确实需要汇总。
4. **AgentSense 的两种任务**
   - "固定计划"和"里程碑计划"的内容都由模型现场写。**整个仓库没有 workflow 模板**。
   - 新建会话时二选一，默认里程碑，之后不能换。没有普通聊天模式，也没有命令或口令能触发某种模式。
   - 固定计划是一串"工具 + 参数"的步骤：审查修补后一次授权；执行时偏了就自动引回或改回；没有逐步验收，步骤做没做完靠模型自报。
   - 里程碑计划是一张里程碑的依赖图。每个里程碑有交付件、验收脚本、授权项、规则集，流程是认领 → 动手 → 提交 → 验收，能调整计划，能按依赖重开。里程碑本身又分"定步"和"自主"。
5. **二狗现在的样子**
   - 缩放：25 号票用三个分段按钮，切换的是三套**不同的**渲染。要点层是过滤后的要点列表加"收起了 N 条"，全局层是按阶段、工单段或天聚出的色块列表。没有手势代码，页面也没禁掉浏览器自带的缩放。
   - 详情：只有工具调用有详情，宽屏在右栏，竖屏是底部弹层，内容只是一行参数摘要和一行结果摘要。点消息本身没有反应。
   - 数据：工具调用 part 只带参数摘要（≤160 字）和结果摘要（≤200 字），完整的参数和返回只在 pi 的会话文件里。**详情页得先补这条数据通路。**
   - 聊天区：每次工具调用单独一条消息、单独一个按钮，参数摘要、类别、判定、结果全摊开。
   - 任务：二狗的"任务"就是 AgentSense 的里程碑计划（阶段就是里程碑；有定步和开放；验收方式有脚本、评审、用户；有计划变更；能按依赖返工）。issue 12 已经定了"统一成一种计划"。术语表明确不用"里程碑"和"长程任务"。
   - 没有任何东西能对上 workflow（固定阶段的模板）。定时作业每次只是一句话；立项流程写死在代码里；项目规范（"默认工作流程"）排在第二阶段。
6. **建议**
   - 切成 9 张票，第一张由用户拍板（T0）。
   - 后面三条线并行：会话条目层 → 缩放 → 两侧标注；工具调用的完整数据 → 详情页 → 聊天区精简；两种任务的模型与发起 → 两种任务的界面。
   - 最要紧的三个决定：
     - workflow 的阶段从哪来。推荐：用户维护的流程模板。
     - 秘书"指定的方法"用什么形式。推荐：两个专用工具，加上发起对话框里先选种类；用户没点明就留在对话里，最多给一张建议卡。
     - 术语怎么改。推荐："流程"和"长程任务"；阶段仍叫阶段。

## 1. AgentSense 的捏合缩放

### 1.1 哪些视图能捏合

- **只有会话历史**，组件是 `ZoomHistory`（`W/ui/ZoomHistory.tsx:494`）。整个仓库只有这一处调用 `usePinch`（:668）。
  - 手势挂在整块 `.zh` 上，连底部输入框那一栏也算。注释说这是为了缩到计划层时还能捏回来（:667）。
- **所有会话都能捏合**：AgentSense 的会话都是计划会话，不是固定计划就是里程碑计划（见 §4.3），没有普通聊天。
- **不能捏合的**：
  - 抽屉和横屏左栏里的计划图（`PlanLayer`，`W/ui/milestone.tsx:1934`，由 `W/ui/drawer.tsx:198,258` 使用）；
  - 详情页；
  - 会话列表。

### 1.2 档位：连续的比例怎么落到档上

- **预设**：`PRESETS = [1, 0.45, 0.15, 0.06]`（`W/ui/zoom.ts:10`）。
- **下限**：`MIN_SCALE = PRESETS[2]`（:12），也就是 0.15。所以 0.06 那一档已经到不了。
  - 第四档"计划层"在 2026-10-04 去掉，原话是"捏合去掉了'计划层'那一档，只剩对话、要点、全局三档"（`REF/CHANGELOG.md:236`）。
  - 整个计划的图挪进了标题栏下面拉出的抽屉（`REF/CHANGELOG.md:227-235`；术语见 `REF/CONTEXT.md:167`）。
  - 二狗 25 号票写的"四档吸附"不准确。
- **落到哪一档**：`levelOf(s)` 在对数空间找最近的预设（`W/ui/zoom.ts:28-34`）。分界点是相邻两档的几何平均：

| 档 | 名字 | 预设比例 | 落在这一档的 s | 显示的层 |
|---|---|---|---|---|
| 0 | 对话层 | 1 | s > 0.671（√0.45） | `.zi-l0` |
| 1 | 要点层 | 0.45 | 0.260 < s ≤ 0.671 | `.zi-l1` |
| 2 | 全局层 | 0.15 | 0.15 ≤ s ≤ 0.260 | `.zi-l2` |
| （3） | 计划层 | 0.06 | 到不了 | `--o3`，遗留 |

- **三层的不透明度**由 `layerOpacity(s)` 算（`W/ui/zoom.ts:19-26`），是交叉淡入淡出：
  - `o0`：s ≥ 0.85 时全显，s ≤ 0.6 时消失；
  - `o1`：在 0.35–0.55 之间全显，0.55–0.75 之间和 `o0` 交叉，0.22–0.35 之间和 `o2` 交叉；
  - `o2`：s ≤ 0.2 时全显，s ≥ 0.3 时消失。
- **吸附**：
  - 松手时调 `snap()`，`animateTo(PRESETS[levelOf(s)], …, 260ms)`（`W/ui/zoom.ts:150-152`）。
  - 用 Ctrl + 滚轮时，停 140ms 算松手（`W/ui/usePinch.ts:60-64`）。
  - 中间档也能停住：s 落在 0.26–0.67 之间就吸到 0.45。

### 1.3 每一档显示什么

每条历史是一个 `.zi`，里面同时渲染三层，再加两侧的装饰（`ZItem`，`W/ui/ZoomHistory.tsx:192-306`）。三层叠在同一个矩形里，`.zi-l1`、`.zi-l2` 用绝对定位盖在 `.zi-l0` 上（`W/layout.css:443-488`）。

| 部位 | 对话层 | 要点层 | 全局层 |
|---|---|---|---|
| 每条历史 | 完整内容，即 `ChatItemView`（`W/ui/components.tsx:950`） | 同一矩形填上内容类型的底色（`bg-user/thinking/reply/plan/tool/context`），左上写一行要点 `keyLine`，不换行、放不下用省略号（`W/ui/semantic.ts:136-158`，`W/layout.css:454-468`）；高度 ≥150px 的条改成"对话层内容的缩影 + 浮在顶上的小标题卡"（`W/ui/ZoomHistory.tsx:735-737`，`W/layout.css:933-971`） | 同一矩形只剩纯色块（`W/layout.css:482-488`）；工具调用按只看、动手、删除分深浅，删除加一圈红描边，出错加内描边（`W/layout.css:65-90`） |
| 右侧 | 无 | 风险标注加一根指向原文那一行的箭头；连续几条风险相同时只在第一条标 ×N（`W/ui/semantic.ts:329-346`） | 同要点层，间距更大（`--rgap-px` 从 10 变 34，`W/layout.css:509,514-516`） |
| 左侧 | 无 | 任务卡（只写目标一句）、回退点 ↶、废弃分支 ⑂、里程碑书脊（一轮一段，颜色就是这一轮的结果） | 同要点层 |
| 背景 | 无 | 一个计划从提出到执行完铺一整块浅黄底色，左缘竖排"任务 N · 这件事是什么"（`W/ui/semantic.ts:276-293`，`W/layout.css:385-430`） | 同要点层 |
| 底部 | 输入框 | 输入框淡出，换成图例条 | 同要点层 |
| 固定计划没做的步骤 | 主线底部的虚线框"接下来的计划"，带"已完成 x/y 步" | 同上（标签缩到条外侧） | 同上 |

几点补充：

- **两侧装饰从要点层就出现**，全局层也在：`opacity: var(--od)`，其中 `--od = o1 + o2`（`W/layout.css:507,517-528`）。要点层和全局层的区别只在条里那一层：一行字，还是纯色块。
- **要点那一行写什么**（`keyLine`，`W/ui/semantic.ts:136-158`）：
  - 用户、思考、回复分别写"你：……""思考：……""回复：……"，取首行，最多 80 / 60 字；
  - 工具调用写"说人话的一句"，被拦下、拉回、暂停、拒绝的前面加 ⛔ / ↩ / ⏸ / ✕，读了敏感数据的加 🔒；
  - 里程碑事件写事件文字；
  - 计划写"计划 vN · N 步 · 已授权"。
  - 2026-10-04 起限定只写一行，原因见 `REF/CHANGELOG.md:192-196`。
- **矮的条**：去掉上下留白，字竖着居中（同上）。

### 1.4 输入方式

- **手机，双指捏合**（`W/ui/usePinch.ts:31-45`）：
  - `touchstart` 两指时记下起始距离和中点；
  - `touchmove` 两指时 `preventDefault`，上报 `ratio = 起始距离 / 当前距离`；
  - 比例 `s = s0 / ratio`（`W/ui/ZoomHistory.tsx:674-678`），夹在 [0.15, 1] 之间（`W/ui/zoom.ts:124-127`）；
  - 任何一指抬起（只剩不到两指）就算松手、吸附。
  - 单指上下滑交给浏览器原生滚动：`.zh-viewport { touch-action: pan-y }`（`W/layout.css:346-352`）。
  - 整页禁掉浏览器自己的缩放：`maximum-scale=1.0, user-scalable=no`（`REF/web/index.html:5`）。
- **电脑**（`W/ui/usePinch.ts:46-65`，`REF/CHANGELOG.md:374`）：
  - 普通滚轮照常上下滚动看历史。
  - **Ctrl（Mac 上 ⌘）+ 滚轮才是缩放**：`wheelRatio *= exp(deltaY × 0.0048)`，向下滚缩小，并 `preventDefault` 挡掉浏览器的页面缩放。
  - 触控板双指捏合在浏览器里本来就以带 `ctrlKey` 的 wheel 事件送来，所以不用另写也能用。
- **按钮**（`W/App.tsx:610-618`）：
  - 标题栏右边一个图标按钮。在对话层显示 ▤，点了缩到**全局层**；缩小后显示 💬，点了回到对话层。没有直达要点层的按钮。
  - 里程碑会话只在缩小后才出现这个按钮（`!milestoneMode || level > 0`）。
  - 按钮走 `zoomTo(level)`，以视口中心为焦点（`W/ui/ZoomHistory.tsx:691-695`）。
- **返回手势**：缩小状态下按系统返回，先放大回对话层（`W/App.tsx:416-428`）。
- **提示文案**：`zoomOutHint()` 在触屏上说"双指捏合"，在电脑上说"按住 Ctrl 向下滚动滚轮"（`W/native.ts:48-52`）。只出现在空会话的说明里（`W/App.tsx:685`）。

### 1.5 滚动位置和锚点

- **锚点是"手指中点下的那个内容坐标"，不是某一条消息。**
  - `scaleAround(s, focalY, contentY)` 每次改完比例都设 `scrollTop = contentY × s − focalY`，所以中点下面那一点内容不动（`W/ui/zoom.ts:111-116`）。
  - `contentY` 在 `onStart` 时按双指中点算一次（`contentYAt`，`W/ui/zoom.ts:119-121`）。之后每帧用当前中点的 `focalY`，所以双指边捏边平移时，内容跟着中点走（`W/ui/ZoomHistory.tsx:669-683`）。
  - Ctrl + 滚轮以鼠标位置为锚，按钮以视口中心为锚。
- **在缩小状态下点一条**（`W/ui/ZoomHistory.tsx:709-728`）：
  - 以点击处为焦点，动画放大回 1；同时把这条从点击处滑到不低于视口 40% 的高度；闪一下（1.6s）。
  - 宽屏下，如果这条能打开详情，同时打开它的详情（`W/App.tsx:666`）。
  - 缩小时条里的对话层内容不接收点击（`W/layout.css:489-496`），点击在 capture 阶段统一处理（`W/ui/ZoomHistory.tsx:948`）。
- **"在对话中定位"**（`reveal`，`W/ui/ZoomHistory.tsx:696-706`）：在对话层平滑滚到这条在视口 30% 高度；在缩小状态下边放大边滑过去。
- **跟着最新的走**（`W/ui/ZoomHistory.tsx:501-505, 572-582, 919-945`）：
  - 只有在对话层、停在底部（离底不到 24px）、手指没按着时，新内容才自动滚到底；
  - 往上滚、往上拨滚轮就不跟了。
- **报告正在看哪一条**：取视口 40% 高处的那一条，报给外面（`W/ui/ZoomHistory.tsx:506-527`）。标题里的"第 N 阶段"跟着它变。

### 1.6 动画

- **三层结构**（`W/ui/zoom.ts:1-7, 78-99`；`W/layout.css:346-366`）：
  - viewport 负责滚动；
  - sizer 的高度 = 内容高 × s，撑出滚动范围；
  - content 宽度等于内容列宽，`transform: translateX(w(1−s)/2) scale(s)`，`transform-origin: 0 0`，`will-change: transform`。
- **每帧只写 CSS 变量和 sizer 的高度，不触发 React 渲染**。变量写在 `.zh` 根上（`W/ui/zoom.ts:83-109`）：
  - `--s`、`--o0`…`--o3`、`--colw`、`--vpw`、`--sl`（当前这一档的预设比例，换档时才变）；
  - `data-level`。
- **CSS 怎么配合**：
  - 各层的 `opacity` 直接取这些变量。
  - 要点层的文字和两侧标注按固定比例 `--ds: 0.45` 排一次版，再整体 `scale(--ds / --s)`，所以缩放过程中不重新折行（`W/layout.css:454-462, 500-535`）。
  - 描边、圆点这类用 `calc(2px / var(--s))`，屏幕上看粗细不变。
- **动画**：`animateTo` 用 requestAnimationFrame，ease-out 三次曲线，**在对数空间插值**（缩放的速度感是均匀的），默认 420ms，吸附用 260ms（`W/ui/zoom.ts:133-152`）。
- **两侧标注跟着动**：
  - 每一帧都通过 `onScale` 重算两侧标注和箭头的位置（`W/ui/ZoomHistory.tsx:567, 742-879`）。这是 09-25 修的"缩放过程中标注会飘"（`REF/CHANGELOG.md:469`）。
  - 停稳后 `onSettle` 再触发一次避让排版。
- **竖排任务名和书脊名**：每帧用 rAF 摆到这一段露出部分的中间（`W/ui/ZoomHistory.tsx:603-663`）。
- **减少动态效果**：系统打开时，CSS 的 transition 和 animation 全关（`W/look.css:613-621`）。【推测】缩放是 JS 逐帧驱动的，不受这条影响。

### 2.2 在哪打开

- **断点**：`WIDE_MIN = 600`（`W/App.tsx:27`）。
- **宽屏**是可拖动的分栏：会话列表 | 对话 | 详情（`W/App.tsx:766-786`）。
  - 有详情时才渲染分隔线和 `.pane-detail`。

- **返回栈**：
  - 状态是 `detail` 加 `detailBack[]`（`W/App.tsx:313-315`）。从聊天打开详情会清空栈（:396-403）；`popDetail` 出栈（:406-414）。

- **在对话中定位**：只有 `item` 类型的详情有（`W/ui/DetailPane.tsx:889-893`）。窄屏先切回聊天页，再 `reveal`（`W/App.tsx:740-743`）。

- **没有任何详情时**，宽屏右栏不出现。`DetailPane` 自带一个空状态："点任意一条历史——消息、思考、计划、工具调用，这里显示它的细节"。

### 2.3 每种详情显示什么

- **工具调用详情**分三条路（`ToolDetail`，`W/ui/DetailPane.tsx:576-651`）：
  1. **被挡下的**（拦下、拉回、暂停、你拒绝了）走 `GuardDetail`（:466-527），依次是：
     - 头部，比如"没有执行 · 拦下（底线）"；
     - 逐行的"Agent 想 / 为什么不行（依据）/ 要是没拦 / 结果"（`GuardFull`，`W/ui/components.tsx:803`）；
     - 疑似注入的证据；
     - "怎么判的"：公式、之前的轨迹、这一次、结论；
     - 进规则核对的入口；
     - 系统回给 Agent 的原话；
     - 折叠的"原始参数（给开发者看）"。
  2. **里程碑会话里的普通调用**走 `MilestoneToolDetail`（:533-574）：
     - Agent 想做什么；
     - 系统怎么处理的（比如"✓ 在你的授权内"）；
     - 这一步的规则；
     - 动了什么；
     - 折叠的"原始参数和返回（给开发者看）"。
  3. **固定计划会话里的调用**（:584-651）：
     - 纠偏表，三列"参数 / Agent 写的 / 按计划改为"；
     - 执行时检查 `RuntimeCheckSection`（`W/ui/RuntimeCheck.tsx:114`）：检查器的输入，加上逐项 ✓✕、公式和耗时；
     - 修补经过；
     - 不折叠的"参数"和"返回结果"。
- **文本详情**（`TextDetail`，`W/ui/DetailPane.tsx:707-737`），用户、回复、思考共用：
  - 头部是种类标签和字数，下面写所属任务；
  - "完整内容"一节：回复按 Markdown 渲染，其余按原文显示，敏感片段高亮。
- **横条详情**：
  - 拉回、拦下、拒绝走 `GuardDetail`；
  - 退回、验收走 `AttemptDetail`（:665），每条标准 ✓✕，加表达式和系统直接查到的事实，后面接 `MilestoneDetail`；
  - 把关记录走 `MilestoneLedgerDetail`（:314），有页签"全部 / 动了东西的 / 被挡下的 / 问过你的"，每行带 ›，点进去是那一次调用。
- **详情之间跳转**：两条回调，`onOpen(item)` 和 `onGo(Detail)`，都是先把当前详情压栈再换（`W/App.tsx:752-759`）。

### 2.4 参数和返回怎么展示、怎么折叠

- **`ValueView`**（`W/ui/ValueView.tsx:119`）：
  - 对象画成两列的 `dl`，字段名经 `LABELS` / `BY_TOOL` 换成中文（:10-27）；
  - 数字带单位（¥、MB、GB），状态值显示成中文徽标，布尔值显示"是 / 否"，路径用等宽字体；
  - 对象数组画成表，最多 6 列，多出来的列放在行下面。
- **返回值**：先用 `parseStructured` 试着当 JSON 解析，成功就交给 `ValueView`；解析不了就按正文显示，敏感词高亮（`ResultSection`，`W/ui/DetailPane.tsx:120-136`）。
- **折叠**：
  - 长内容既不截断也不折叠，只有表格能横向滚动、整页能滚动。
  - 唯一的折叠是原始参数那个 `<details>`。
  - 聊天行里**从来不出现**原始参数。

## 3. AgentSense 聊天区里的工具调用、思考、中间步骤

### 3.1 条目怎么切

- **条目种类**（`ChatItem`，`W/agent/sessionView.ts:37-96`）：user、thinking、assistant、tool、correction、ledger、plan、mplan、mevent、context、notice、error。
- **推导时一条一行，不聚合**：一条 assistant 消息拆成三类条目：思考一条、正文一条、每次工具调用各一条（`W/agent/sessionView.ts:399-554`）。
- **内部工具会被改写**：
  - `report_step` 不显示；
  - `propose_plan` 变成计划卡；
  - `claim_milestone` / `submit_milestone` 变成里程碑事件。
- **思考并进工具行**：里程碑会话里，思考不超过 120 字、没有正文、后面紧跟一次工具调用时，这段思考会并进那次调用，显示成工具行下的一行"Agent：“……”"（`W/agent/sessionView.ts:414-418`）。

### 3.2 对话层里各条长什么样

| 条目 | 样子 | 有没有详情、怎么提示 |
|---|---|---|
| 用户 | 蓝色气泡 | 整条可点 |
| 思考 | 默认折成一行："💭 Agent 的想法（点开看）"；流式时显示"💭 Agent 正在想…"，字轻轻明暗（`W/look.css:600-603`）。**点开是在原地展开全文**，12px 灰字，最高 40vh，超出滚动 | 旁边一个"详情 ›" |
| 回复 | 只显示第一段：按 `indexOf("\n\n")` 切出来，用 Markdown 渲染 | 有后文时，气泡下面一行两个文字按钮："展开细节 ▾"（原地切换全文，展开后变"收起 ▴"）和"详情 ›"。只有一段的回复两个都没有 |

## 4. AgentSense 的两种任务

### 4.1 对应关系

- 用户说的"动态阶段、多 milestone 的长程任务"**就是**里程碑计划。
- 用户说的"固定阶段的任务（workflow）"在 AgentSense 里最接近**固定计划**，但有两点不同：
  - 固定计划的"步"是一次工具调用（工具 + 参数），不是阶段；
  - 步骤是模型每次现场写的，**没有模板**。整个仓库没有任何预定义的、固定的阶段模板。仅有的预写计划是演示剧本里喂给假模型的（`W/agent/milestone/demo.ts:102` 一带）。
- **里程碑本身又分两种**（`REF/docs/adr/0002-milestone-plan-alongside-fixed-plan.md:10-13`；`REF/CONTEXT.md:55-56`）：
  - "定步"：里程碑里写明步骤；
  - "自主"：只有目标、交付件和验收标准。
  - 同一份里程碑计划里可以混用。

### 4.2 数据模型

| | 固定计划 | 里程碑计划 |
|---|---|---|
| 计划 | `Plan{version, goal, steps, constraints?}`（`W/agent/plan.ts:25-30`）；审查后是 `AnnotatedPlan`，每步加敏感标注 `marks`，整份带审查结果 `review` | `MilestonePlan{version, goal, milestones, …}`；检查后是 `AnnotatedMilestonePlan`，另带 `policies/selfChecks/loose/stops/problems/adjustment`（`W/agent/milestone/types.ts:147-172`） |
| 单元 | `PlanStep{id, title, tool, args?, after?, inserted?, patches?}`（`W/agent/plan.ts:4-17`） | `Milestone{id, title, deliverable, criteria, mode: "stepped"\|"open", modeReason?, steps?: PlanStep[], approach?, after[], choice?{group, when}, grants, policies, supplementary?, budget?}`（`W/agent/milestone/types.ts:73-96`） |
| 验收 | 无 | `AcceptanceCriterion{id, text, expr?}`：`expr` 是只读世界状态的表达式；没写 `expr` 的就是"由你验收" |
| 授权 | 计划整体一次授权；需要确认的事项逐条勾 | `Grant{id, kind, scope: list\|where\|ref\|any, limit?, text?}`，只在所属里程碑内有效 |
| 状态 | `StepStatus = pending\|in_progress\|done\|failed\|skipped`（`W/agent/plan.ts:41`），靠模型调 `report_step` 自报（`W/agent/runtime.ts:258-272`），视图里再推断（`W/agent/sessionView.ts:328-336, 562-572`） | 7 种 `MilestoneStatus`（`W/agent/milestone/types.ts:174-184`）。全部从会话树上的条目推出来（`deriveMilestoneState`，`W/agent/milestone/state.ts:219-263`）；`applyPlan` 调整计划时保留已验收、未走、已废弃的里程碑（:106-124） |
| 阈值 | 自动修回每步最多 2 次（`MAX_AUTO_FIX`，`W/agent/guard.ts:67-71`） | 默认预算 50 次调用，拉回、催促各 3 次，退回 2 次（`W/agent/milestone/types.ts:225-230`） |

### 4.3 怎么发起

- **界面**：新建会话时先选模式，再选场景（`ScenarioPicker`，`W/App.tsx:100-168`）。
  - 两个页签：
    - "里程碑计划（默认）"，副标题"只定几个里程碑：交什么、怎么验收、允许做什么；中间怎么走交给 Agent"；
    - "固定计划"，副标题"每一步先排好、审查修补，再一次授权"。
  - 里程碑页签下分"演示"和"接真实模型"两组。
- **会话建好后不能换模式**（ADR 0002:8）。术语表写着"以后可由不同的 skill 发起"（`REF/CONTEXT.md:23`）。
- **模式存在哪**：没有单独的模式字段。会话只存 `scenarioId`，模式由场景的 `planMode` 推出来（`W/agent/scenario.ts:111-112`）。
- **运行时怎么切换**：
  - 是里程碑场景才建里程碑控制器（`W/agent/runtime.ts:296-311`）。
  - 系统提示二选一（:325）。
  - 工具集二选一（:326）：
    - 里程碑：`propose_milestones / claim_milestone / submit_milestone / request_adjustment`；
    - 固定计划：`propose_plan / report_step`。
- **对话里没有命令、口令或模板能触发模式**。`scenario.suggestions` 只是空会话里的示例问题，点了只填进输入框（`W/App.tsx:687-691`）。
- **没有普通聊天模式**。两种模式都允许不调工具的纯问答：没授权就调业务工具会被拦；收尾时如果这一轮没干活，也不催。

### 4.4 阶段（步骤、里程碑）从哪来

- **固定计划的步骤**：模型在 `propose_plan` 里现场写（`W/agent/runtime.ts:54-74, 169-193`）。审查可能插入步骤、改写步骤。
- **里程碑**：模型现场拆。提示词里教了"画成一张图，不要串成一条线"（`W/agent/milestone/prompt.ts:41-50`）。
- **场景提供的是环境，不是阶段**（`W/agent/scenario.ts:76-164`）：
  - 工具、示例问题；
  - 固定计划用的规则文档；
  - `goalTemplates`：约束 id → 审查目标，**不是阶段模板**；
  - 里程碑用的权限类型、底线规则集、可选规则集、事实结构等。
- **规则库 `policies/`**：本仓库的人手写，每个规则集配正反用例（ADR 0004）。

### 4.5 执行与验收

- **固定计划**：
  - 每次调用都和计划比对：计划外、超范围、顺序错、重复、禁止（`evaluateCall`，`W/agent/guard.ts:75`）。
  - 能修的不打扰用户，自动修：改回参数（rewrite），或引回前置步骤（redirect）。
  - 一轮要收工时还有没做的步骤，就提醒一次（`W/agent/runtime.ts:401-422`）。
  - **没有逐步验收，也没有阶段验收的概念**。
- **里程碑计划**（`W/agent/milestone/controller.ts`）：
  - **认领** `claim`（:322-391）：前置都验收了才能认领；一次只认领一个。定步里程碑在认领时按当时的真实事实做一次审查（`reviewAtClaim`，:304-320）。
  - **动手** `beforeTool`（:758-1042），关卡按这个顺序：
    - 底线不看进度，任何时候碰了都拦下；
    - 没认领就拉回；
    - 规则集判"确认"或判不了，当场问；
    - **定步里程碑**用了步骤外的非只读工具，拉回。只查"工具在不在步骤里"，不查顺序、参数、次数；
    - 超出授权的范围或次数，问用户；
    - 预算超 1 倍先让 Agent 说明进展，超 2 倍问用户。
  - **提交和验收** `submit`（:419-576）：
    - 用表达式对照真实世界核对，环境里有 `$facts`、`$deliverable`、`$deliverables`、`$task`；
    - 由你验收的标准，弹窗请用户勾；
    - 没通过就退回，最多 2 次；第 3 次还不过，请用户选"调整计划 / 再给一次机会 / 放弃"。
  - **催促** `beforeRunEnd`（:1134-1169）：最多 3 次。
  - **调整计划**：`request_adjustment` 出一版新计划（:239-299）。
  - **按依赖重开**：`reopenPreview` 算范围（:1248-1294），`reopen` 执行（:1297-1348），见 ADR 0003。

### 5.4 任务

- **二狗的任务就是 AgentSense 的里程碑计划**，只是"里程碑"改叫"阶段"：
  - 计划：结构化存储，有阶段、阶段组、工具包、授权项、规则、定时作业定义（`.scratch/ergou-v2/spec.md:380-388`；`P/task-schema.ts:390` 的 `Plan`）。
  - 阶段：交付件、验收标准（每条注明方式：script / review / user）、模式（`steps` 定步 / `open` 开放）、前置阶段、策略（授权项 + 时序规则）、预算、所属阶段组（`PlanStage`，`P/task-schema.ts:267-285`；`AcceptanceCriterion`，:235-252）。
  - 执行：控制器保管当前阶段，前置没验收不能开始，授权只在所属阶段内有效（`.scratch/ergou-v2/spec.md:391`）。维护者用 `start_stage`、`complete_stage`、`propose_plan_change`、`revise_plan` 等工具（`D/tasks/tool-names.ts:3-15`）。
  - 验收：维护者宣布完成后，由控制器跑脚本、派评审子 agent，或交用户验收（`.scratch/ergou-v2/spec.md:393-398`）。
  - 能动态改：不扩大授权的调整（拆阶段、调顺序）由维护者自行调整，记进时间线；扩大授权、改目标或验收走计划变更卡（:402）；返工按依赖重开（:403）。
  - 阶段的状态：未开始、进行中、验收中、等我、已验收（`STAGE_STATES`，`P/tasks.ts:152`）。
- **已定的决定**：issue 12 写着"**统一成一种计划**，阶段就是里程碑。AgentSense 的'固定计划'，就是'每个阶段都定好步骤'的特例"（`.scratch/ergou-v2/issues/12-long-task-generalization.md:83`，2026-10-07 定稿）。
- **术语表的限制**：
  - "任务"不要说"长程任务、长任务"（`CONTEXT.md:43-45`）；
  - "阶段"不要说"里程碑、milestone"（`CONTEXT.md:190-192`）；
  - "对话"是一问一答、不带事前规划和授权（`CONTEXT.md:39-41`），对应用户说的"普通对话"。
- **二狗和 AgentSense 定步的差别**：二狗定步阶段的"步骤"是几行文字（`steps: Texts(...)`），不是"工具 + 参数"，守卫也不按步骤卡工具。比 AgentSense 的定步里程碑还松。
- **秘书怎么发起**：
  - 四个工具：`create_task`、`suggest_task`、`ask_questions`、`write_task_brief`（`D/tasks/secretary-tools.ts:15`）。
  - `create_task` 的参数只有标题、说明、涉及的项目（:17-29），**没有种类或模式参数**。
  - 规格的规定：用户在消息里要秘书去做某件需要任务的事，这就是授权，秘书直接建任务卡；秘书自己发现、用户没要求的，只给"建议发起任务"卡（`.scratch/ergou-v2/spec.md:350-351`）。
  - 页面上还有"＋ 发起任务"按钮（`E/pages/shared.tsx:48-58`）。
  - 任务记了来源（按钮、建议卡、用户要求、项目建设），没有种类（`TASK_ORIGINS`，`P/tasks.ts:84`）。
- **能不能对上 workflow**：没有一样能对上。
  - 定时作业每次运行只是"每次要做的事"一句话（`PlanScheduledJob.each`，`P/task-schema.ts:369-387`）。
  - 立项流程（秘书收口 → 立项问答 → 立项书 → 首个建设任务）是写死在代码里的固定流程，不是可复用的模板（`CONTEXT.md:108-114`，立项和立项书两条）。
  - 项目规范说的是"每个项目默认继承的一套工作流程和文档要求"，并且不要叫"项目模板、SOP、playbook"（`CONTEXT.md:128-130`）；完整的默认工作流程在第二阶段（`.scratch/ergou-v2/spec.md:669`）。
  - skill 只是工具包里的能力，不是流程。
- **界面**：
  - 任务详情里，竖屏有阶段抽屉、宽屏有阶段左栏（`E/pages/TasksPage.tsx:392, 434`）。
  - 标题挂"第 N/M 阶段"，N 是阶段在列表里的位置，不是依赖图的层数（`E/ui/conversation/StageDrawer.tsx:36-40`）。
  - 计划卡在聊天和待我处理里都有（`E/ui/cards/PlanCard.tsx`）。
  - 没有固定计划那样的进度条、计划台账和虚线框。

### 5.6 冲突在哪

1. **术语和已定的决定**：
   - 用户这次说的"长程任务""milestone"正是术语表明确不用的词；
   - issue 12 已经定了"只有一种计划"；
   - 分出两种任务要先改术语表、写 ADR 推翻 issue 12 的第 1 条。
2. **"阶段"的含义不同**：AgentSense 的"阶段"是依赖图的一层，几个并行的里程碑算同一阶段（`REF/CONTEXT.md:36-38`）；二狗的"阶段"就是 AgentSense 的里程碑。照搬界面文案（"第 N 阶段"）时要按二狗的意思写。
3. **要点层的定义**：规格第 19 节和术语表说要点层"只留要点"；AgentSense 是每条都在、只写一行。
4. **分页**：二狗的会话只加载最近 50 条，秘书主线是一条长期会话；AgentSense 整个会话一次进 DOM。
5. **一个会话多个来源**：
   - 项目维护者会话按工单分段，每段是新的 pi 会话（`CONTEXT.md:156-158`）；
   - 子 agent 的调用和结果也进维护者会话，带 `agentId`（20 号票）；
   - 并行阶段的调用会交错。
   - AgentSense 的书脊算法本来就把交错的一轮断成几段，能用。但底色带要改成按工单段或按天。
6. **审批是卡片，不是弹窗**：
   - AgentSense 的授权、验收、超出授权都是模态对话框（`GrantDialog`、`AcceptanceDialog`……）；
   - 二狗的审批、计划确认、验收是卡片，聊天和待我处理里都有，状态只有一份（`CONTEXT.md:100-102`）；
   - 照搬时卡片留着，不改成弹窗。
7. **回退和分支**：AgentSense 有会话树回退、废弃分支、切换动画；二狗没有这个概念，这部分整块不要。
8. **守卫和关注类别 vs AgentSense 的敏感标注和规则核对**：
   - 右侧风险标注的来源换成二狗的要点：关注类别命中、三种样式、通用 bash、范围变更、越界、偏离、审批、验收结果；
   - 横条的种类换成二狗的：硬拒绝、按规则退回（拉回）、问过你、你拒绝了、判定出错；
   - 规则核对详情（公式、轨迹）二狗暂时没有数据，ToolCallDetail 的占位就是它，可以后补。
9. **定时作业、工单、项目**：
   - 定时作业每次运行是一张工单，落在项目维护者或作业维护者的会话里；
   - 秘书发起的东西还包括快速动作、简单提醒、立项；
   - 这些都不是 AgentSense 有的概念，两种任务的划分不应该把它们卷进来（见 §6.2 决定 5）。
10. **视觉风格票**：
    - 39–51 号票（风格底座和 13 套风格）都是 `ready-for-agent`，都要给聊天区换皮，设计稿里画了聊天画面（`.scratch/ergou-v2/impl/39-visual-styles.md`）；
    - 会话区改造会改聊天区的结构和类名；
    - 两批票要排好先后（见 §6.3）。

### 6.2 要用户拍板的决定

按影响排序。每条给推荐。

1. **两种任务叫什么，术语怎么改**。
   - **推荐**："流程"（固定阶段，workflow）和"长程任务"（动态阶段）。"任务"是两者的统称。
   - 两者的工作单元都叫"阶段"，不引入"里程碑"：用户说的 milestone 就是二狗现在的阶段。
   - 术语表删掉"任务"条下"不要说长程任务"这一句；ADR 说明为什么推翻 issue 12。
   - 备选："固定流程 / 开放任务"。
2. **workflow 的阶段从哪来**。
   - **推荐**：从**流程模板**来。模板是用户的个人数据，事先写好阶段列表；发起时套用，执行中阶段不变。
   - 备选甲：照搬 AgentSense 固定计划，由维护者现场把每一步写成"工具 + 参数"。不推荐：二狗的工具是 bash、read、edit，几十步事先写不出来；守卫也没有按步骤比对、引回、改回的机制。
   - 备选乙：维护者现场写阶段，用户确认后锁定。这样和长程任务只差"能不能改"，用户分不清两种有什么不同。
3. **流程模板由谁维护、放哪**。
   - **推荐**：放在数据目录里，一份模板一个文件。内容：名字、一句话用途、要填的输入、阶段列表（标题、交付件、验收标准和方式、定步步骤或开放、前置、建议的授权项、预算）。
   - 维护：用户在"更多 · 流程"里增删改。长程任务做完后可以"存为流程"，由维护者起草、用户确认。框架自带一两个示例。
   - 和"项目规范"（第二阶段）的关系：以后项目规范可以带几份流程。
4. **秘书"指定的方法"用什么形式**。
   - **推荐**：
     - 秘书有两个专用工具：`create_task` 发起长程任务（已有），`start_workflow(模板, 输入)` 发起流程（新加）。
     - 只有用户点明了才调：说了"发起任务 / 长程任务"、点了某个流程的名字，或者在发起对话框里选了种类。
     - 没点明的一律按普通对话处理。秘书觉得该发起时，只给一张建议卡，卡上两个按钮："按某流程做"和"作为长程任务"。
     - 发起对话框先选种类，再填内容（照 AgentSense 的 `ScenarioPicker`）。
   - 这比现在的规格严：现在是"用户要秘书去做某件需要任务的事，这个要求就是授权"（`.scratch/ergou-v2/spec.md:351`）。要用户确认按新的来。
   - 可选：输入框支持 `/流程 名字`、`/任务` 这样的快捷写法，等价于选了种类。
5. **二狗现有的东西归到哪种**。
   - **推荐**：
     - 现有任务全部算长程任务（数据补默认值，不迁移）；
     - 立项后的首个建设任务算长程任务；
     - 定时作业、快速动作、简单提醒、立项本身都不归入这两种，照旧。
   - 以后可以让定时作业"每次跑某个流程"，本批不做。
6. **流程执行中能改什么**。
   - **推荐**：阶段列表、顺序、交付件和验收标准锁定（这就是"固定"）。授权项可以走计划变更扩大。维护者不能用 `revise_plan` 拆阶段、调顺序。其余（验收、阈值、返工）和长程任务一样。
7. **工具调用汇总行的边界**。
   - **推荐**：
     - 一轮里两段话之间连续的工具调用合成一行"调用了 N 个工具 ›"，命中关注类别的加小签（比如"· 1 次做完告诉你"）；
     - 被拦下、问过你、你拒绝了、出错的不并进去，单独成横条；
     - 缩放各档里，一组算一条。
   - 备选：全部并进去，只在汇总行上标"其中 1 次被拦下"。
8. **要点层和档位数**。
   - **推荐**：
     - 照 AgentSense 现在的三档（对话、要点、全局），不要第四档"计划层"。AgentSense 自己去掉了它，二狗也已经有阶段抽屉。
     - 要点层改成"每条都在、一行字"，25 号票的"只留要点、收起 N 条"不要了，要点改成两侧标注。
9. **窄屏详情和页面缩放**。
   - **推荐**：
     - 详情整页滑入，盖住底部导航，返回回到会话（照 AgentSense）；
     - 页面加 `user-scalable=no`，整站不再能用浏览器自己的缩放，换来会话区的捏合不和浏览器抢。
10. **长会话缩小时缩多少**。
    - **推荐**：只缩已经加载的部分。缩小状态下滚到顶，照样取更早的一页，锚点保持不动。秘书主线不一次全量加载。

### 6.3 先后和风险

- **和视觉风格票（39–51）的先后**：
  - 【建议】39（风格底座：token 化，现有的整理成"经典"）不受影响，可以照常做；
  - T2、T5、T6 新加的元素一律用 token；
  - 40–51 各套风格在 T2、T5、T6 合并之后再做聊天画面，或者在各自票里加一条"覆盖新的会话元素"。
  - 不然要么风格票白做，要么会话区改造要跟着 13 套风格各改一遍。
- **捏合和按住说话**：输入框的按住说话是单指手势（`touch-action: none`，`E/styles/voice.css:23`）。`usePinch` 只认两指，不冲突。但手势挂在整块会话上，要验一下双指落在输入框上时的表现。
- **性能**：AgentSense 三层同时渲染，对话层的完整内容一直在 DOM 里。二狗的秘书主线一页 50 条，翻多了会很长。【建议】T2 先量：比如 500 条时捏合的帧率，再决定要不要给远处的条目降级。
- **详情里的完整返回**：可能很大（读文件、bash 输出）。【建议】T4 定一个上限，比如 200KB，超出的截断并注明。
- **工具调用说人话**：AgentSense 的工具行能"切中要害"，靠的是每个场景工具都有 `describe`。二狗的工具是通用工具，汇总行和详情里先用"工具中文名 + 参数摘要"。要再进一步，就得给常用工具（`read`、`edit`、`bash` 拆出来的常见命令、带类型的特殊 bash 工具）写说人话的句子，可以单开一票。
