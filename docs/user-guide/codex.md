# Codex

这台电脑上装了 Codex 的，可以让任务、项目的负责人用它干活。用你自己的 Codex 配置和登录；二狗照样记下它的工具调用，有风险的照样拦下或者问你。少数几样拦不住，下面照实写了。

已经在终端里用着的 Codex 会话，也能交给二狗接着做，做完再交回终端。

只有任务、项目的负责人能用 Codex。秘书不能换。

Codex 这一路是实验性的。能做到什么、做不到什么，集中列在[最后一节](#能做到什么做不到什么)。

## 用之前要准备什么

1. 装 Codex，两种都行：
   - 在 **设置 · 能力 · 组件** 里装「Codex 接入」：从 npm 官方下 Codex 0.166.0（约 170 MB，装好占约 480 MB），装在数据目录的 `components\codex` 里，不放进 PATH。也可以在终端里跑 `ergo components add codex`。
   - 自己装：`npm i -g @openai/codex`。版本要 0.166.0 或更新。

   两份都有时用组件装的那份（它的版本是二狗核对过的）。想用自己装的，在组件页把「Codex 接入」删掉。PATH 上已经有够新的 Codex 时，组件页那一块写「已有」，不用再装。
2. 登录：二狗不替你登录、不看你的登录信息，用的是 Codex 自己的登录（Codex 把它存在自己的配置目录或系统的凭据管理器里）。在终端里登录一次：
   - 自己装的：跑 `codex login`。
   - 组件装的不在 PATH 上，要写完整的命令。**设置 · 能力 · 插件** 的 Codex 那一块下面写着，在 PowerShell 里照抄运行，长这样：`& 'C:\…\node.exe' 'C:\Users\你\.ergo\components\codex\node_modules\@openai\codex\bin\codex.js' login`。

   按提示在浏览器里用 ChatGPT 账号登录。两份 Codex 共用同一个登录，登过一次就行。
3. 打开 **设置 · 能力 · 插件**，找 Codex。写「运行中」就好了。写「没装」时下面一行写着缺什么，装好后点「启用」。

做完以后，发起任务和新建项目的对话框里，「运行时」一排多一项 **Codex**。

**要知道的**

- 没装时，别的功能不受影响。还有别的运行时能选的话，「运行时」里的 Codex 是灰的：组件没装时点一下去设置 · 组件装，装了还没点「启用」时点一下写明怎么办。
- 没登录时，这一轮按出错收尾，写明在 PowerShell 里运行哪条命令登录（组件装的写完整的）。登录后再发一条消息接着做。体检页的「深度体检」也会查登录了没有，没登录时写同一条命令。
- 插件停用后，用 Codex 的负责人不再启动。正在做的任务转成「等我」，启用后接着做。

## 新建一个用 Codex 的任务或项目

和 [Claude Code](claude-code.md#新建一个用-claude-code-的任务) 一样：

1. 点「＋ 发起任务」或「＋ 新建项目」，写清楚要做的事。
2. 「运行时」点 **Codex**。下面多出「从 Codex 会话接管…」和「在哪个文件夹做」。
3. 「在哪个文件夹做」选在默认文件夹下新开，或者用已有的文件夹。默认文件夹在 **设置 · 能力 · Codex** 里定。
4. 点最下面的按钮。卡上标着「Codex」。

## 接管已有的会话

**这是什么：** 你在终端里用 Codex 做到一半，想让二狗接着做。工作目录和之前聊到哪都照原来的。

**在哪里打开：** 发起任务或新建项目的对话框，「运行时」选 Codex 后，点「从 Codex 会话接管…」。

1. 列出这台电脑上的 Codex 会话。每行写标题、工作目录、分支和最近活动。二狗自己开的不列，`codex exec` 跑的也不列（Codex 默认只列终端和 VS Code 里的）。
2. 点选一个会话，看这一行的小签：
   - **占着**：几分钟前还有活动。先去那边关掉，等一会儿再点「刷新」，或者勾「分叉一份接管（原会话不动）」。
   - **可能开着**：列表里看不出来。所以默认勾着分叉；确认那边关了，可以取消勾选直接接。其实还开着的话 Codex 不让接，二狗写明要先去关掉。
   - **在管**：二狗的另一个任务或项目在管。要接只能勾分叉。
3. 接成任务时写「接着让它做什么」；接成项目时可以空着。
4. 点「接管」或「分叉接管」。

会话里先列出前情：Codex 那边最近的一段对话，只给你看，不算新的输入。

**要知道的**

- Codex 不让两个进程同时写一个会话：别的程序开着它时二狗接不了，二狗接着时别的程序也接不了。开着的会话能分叉。Codex 的终端界面是不是也这样还没实测过，接管期间别在终端里打开它。
- 分叉出来的是新会话，原来的不动。

## 交还给终端，再收回来

**在哪里打开：** 任务详情或者项目负责人会话的标题栏，点 ⚙，找「运行时」这一块。

1. 点「交还给 Codex」。这时二狗不写这个会话。
2. 回终端跑 `codex resume`，接着用。
3. 用完了，先在终端里关掉，再回 ⚙ 点「收回到二狗」。

**要知道的**

- 收回前二狗会核对：别的程序还开着这个会话的不收回；交还之后那边动过、几分钟内还有活动的也不收回，写明原因。过一会儿再点。
- 确认终端关了再收回：终端界面开着但一直没说话时能不能看出来，还没实测过。
- 撤回过的话，二狗接着的是分叉出来的新会话，`codex resume` 里要选那一个。

## 选模型、沙箱、思考档位

**在哪里打开：** ⚙ · 运行时。默认都是「跟 Codex 自己的设置」。

- **模型**：列表是 Codex 自己报的。负责人第一次起来之前是空的。换了模型的，旧模型写一份交接摘要，新模型新开一段会话接着。
  - **现在的模型用不了时：** 比如 Codex 配置里写的模型你的账号不支持，第一轮就失败，不花额度，任务转「等我」，写明原因。在 ⚙ 换一个模型，再发一条消息：旧模型写不了交接摘要，二狗新开一段会话，把之前的记录放进上下文。每个任务都要选一次，想省事就改 Codex 自己的配置（`config.toml` 里的 `model`）。
  - **分叉接管、撤回：** 接着用这段会话原来的模型，不会退回 Codex 配置里的。
- **沙箱**：默认只能写工作目录。也能选只读、不用沙箱（只靠守卫）、跟 Codex 自己的设置。跟 Codex 自己的设置时可能是只读（实测遇到了），这时它写文件会被拒，模型会告诉你。
- **思考档位**：低、中、高、很高。

审批策略不是选项：二狗固定用最严的，要过守卫。

## 守卫管到哪

下面是拿真的 Codex 0.166 实测的结果。

命令（`dir`、`git status` 这种只读的也算）、改文件、调 MCP 工具、看图、派子代理、子代理里的这些调用，都先过二狗的守卫。判不放行就不执行，Codex 收到原因。参数和结果都记进二狗。有的模型把工具调用写在一段代码里，里面的每次调用一样先过守卫。

**这几样不过守卫，二狗也记不到：**

- 找工具（`tool_search`）：只看工具说明。
- 那段代码本身和等它的结果（`exec`、`wait`）：它碰不到文件和网络，要碰外面都得经上面那些调用。

**这几样只能事后知道：**

- 联网搜索：Codex 自己的固定关着，工具清单里没有，不能打开。要联网的负责人用二狗的联网搜索，调用之前过守卫；代价是搜索走二狗配的服务，要有联网工具和可用的服务商。万一模型还是搜了，事后记录，判了不放行就打断这一轮。
- 守卫的钩子跑失败、这条命令又是你在 Codex 里设成直接放行的：跑完才知道。只是钩子跑失败的，Codex 还会要审批，二狗在那一步照样能拦。
- 命令在别的目录跑、这条命令又是你在 Codex 里设成直接放行的：已经跑了，判了不放行只能打断这一轮，读到的内容可能已经到了模型那里。
- 生成图片：还没实测过。

**还有这些限制：**

- 模型可以让命令在别的目录跑。二狗按真的目录再判一次，记录里多一条写着那个目录的调用；判了不放行，这条命令不执行，原因写在记录里。目录和负责人的工作目录相同就不多这一条。
- PowerShell 的文件命令守卫认得：删除（`Remove-Item`、`del`）、写入（`Set-Content`、`Add-Content`、`Out-File`、`New-Item`）、移动和复制（`Move-Item`、`Rename-Item`、`Copy-Item`）、读取（`Get-Content`、`Get-ChildItem`、`Test-Path`、`Select-String`）和它们的常用别名，判定和 `rm`、`cat` 一样。只写文件名的（`Remove-Item x.json`）按命令跑的目录解析，所以在二狗的配置、数据库、程序目录里写或删、在密钥区里读，对话审批关着也一律拒绝。
- 看不出动的是哪个文件时：路径里有 `$env:`、变量，或者文件经管道传来（`Get-ChildItem x | Remove-Item`）。写和删一定先问你；读在对话审批开着时先问，关着放行，原文写着密钥区的照样拒绝。
- 守卫拆不开的写法：脚本块（`% { … }`）、`if (…) { … }`、`Invoke-Expression`、圆括号表达式（`Remove-Item (Join-Path a b)`）。算未知的写操作，对话审批开着先问，关着放行（模型常写 `if (Test-Path a.txt) { … }`，所以开着时只读的检查也常出卡）；原文写着二狗的配置、数据库、程序目录或密钥区，或者命令就跑在这些目录里的，照样先问或拒绝。拼出来的路径（字符串相加、脚本块里的变量）守卫认不出。
- 要人敲键盘的交互程序在这里跑不了。往开着的终端里敲字不过守卫，所以二狗启动 Codex 时固定关了这个功能，不能打开。
- 钩子跑失败、在审批那一步被拒时，Codex 只知道被拒了，原因写在二狗的记录里。钩子拦下的说得清原因。
- 有些调用 Codex 不报结果（比如看目标），记录里结果是空的。

## 花的钱

- ChatGPT 账号登录的用订阅额度，消耗页写「用订阅额度、不算钱」。
- API key 登录的按量计费，实际花了钱。消耗页写明没有单价、以服务商账单为准，不算成本不等于免费。
- 交给 Codex 的环境去掉了 `OPENAI_API_KEY`、`CODEX_API_KEY` 这些变量，不会悄悄改计费方式。
- 额度用完时这一轮出错，任务转「等我」，写明额度用完。等额度恢复后再发一条消息接着。
- 一次模型调用大约一万三千多 token（系统提示和工具说明占大头，实测一句「回你好」13651 个）。后面的调用多数走缓存。
- **等你批准时花得很少，但不是零（对话审批开着才会有卡）：** 默认模型把命令放在一段代码里跑，命令等着审批卡时，它可能查几次结果，查一次就是一次模型调用，一次一万多到两万 token，多数走缓存。二狗在系统提示里让它别反复查。实测留一张卡不点：三分钟查 1 到 2 次（没有这句提示时，两分钟查 13 次）。
  - **隔多久点都差不多：** 等满 5 分钟（配置项 `approvals.waitMinutes`），这次调用算挂起，模型再花 2 次调用说明情况，这一轮结束，任务先算做完，之后不再花额度。你什么时候批准都行：任务回到执行中，模型重新跑同一条命令，不出第二张卡，再花 2 次左右。一张卡前后大约 6 次模型调用。拒绝的话模型收到你写的原因。
  - **这不是硬保证：** 靠模型照提示做，实测只有两个样本。它要是不听，每张卡最多多花到 5 分钟那条线，按没提示时的速度大约 30 次。

## 撤回

会话缩小后，条左边的 ↶ 照常能点。Codex 从那条之前分叉出一个新会话接着做，原来的留着，成了一条能切回去的废弃分支。

**只回对话，不恢复文件：** 它改过的文件留着，撤回确认框里也写着。只能回到一条消息之前，回不到阶段、步骤开始前。接管之前的对话撤回不到。

## 要知道的

- 二狗的工具（提交计划、汇报进展、发附件、联网搜索、工具包里的 MCP）它都能调，每次过守卫。
- 工具包里的 skill 复制一份交给它，原件不动。输入框打 `/` 列的是二狗的命令和 skill，Codex 终端里的斜杠命令这里用不了。
- 二狗不读你的 `~/.codex`，也不写它和项目配置。
- 工具包改了不会当场换：这一轮做完，按新的工具包重新起。
- 不能交给 Codex 的官方 App。秘书、子 agent、评审还是 pi。

## 能做到什么、做不到什么

接管和交接的范围集中列在这里。守卫的细节见[守卫管到哪](#守卫管到哪)，额度见[花的钱](#花的钱)。

**能做到的**

- **接管哪些**：这台电脑上终端、VS Code 里的 Codex 会话，最多列 100 个。`codex exec` 跑的、二狗自己开的不列。
- **在哪接着做**：会话原来的工作目录。目录不在了、在二狗的数据目录或程序目录里的，接不了。
- **接成什么**：和 Claude Code 一样，一个普通任务，或者直接建成项目。
- **之前聊到哪**：Codex 接着用这个会话自己的上下文。二狗在会话开头列出最近一段，只给你看，不算新的输入，也不进记忆素材。
- **开着的**：Codex 不让两个程序同时写一个会话，别的程序开着时二狗接不了，二狗接着时别的程序也接不了。开着的也能分叉一份接管，原会话不动。
- **模型**：分叉接管、撤回都接着用这段会话原来的模型，不退回 Codex 配置里的。
- **谁记录**：接管期间只有二狗写这个会话。命令、改文件、调 MCP、看图、派子代理和子代理里的这些调用，都先过守卫，参数和结果记进二狗，用量记进账本。
- **交还和收回**：在 ⚙ 里交还，回终端 `codex resume` 接着用，用完再收回。收回前核对别的程序没开着、交还之后几分钟内没有活动。
- **撤回**：从那条之前分叉出新会话接着做，原来的留着，能切回去。
- **用量算谁的**：ChatGPT 账号登录的用订阅额度；API key 登录的按量计费，消耗页写明。交给它的环境去掉了 `OPENAI_API_KEY`、`CODEX_API_KEY` 这些变量。
- **你的配置**：用 Codex 自己的配置和登录。二狗不读 `~/.codex`，也不写它和项目配置。

**做不到、有局限的**

- **实验性**：二狗接的是 Codex 自己标着实验性的程序接口，按 0.166 核对过。Codex 升级后接口变了，要等二狗跟着改。
- **终端里开着的不一定认得出来**：列表只按最近活动猜，5 分钟内有活动的标「占着」，再早的标「可能开着」，默认勾分叉。先关掉终端，或者分叉一份接管。
- **只有接管来的能交还**：二狗自己开的会话没有「交还给 Codex」。
- **在做一轮时交还不了**：等这一轮做完，或者先停下。
- **换成 pi 就断开**：接管来的负责人在 ⚙ 里换成 pi 以后，不再接着原来的会话，也不能交还了。
- **不过守卫、二狗也记不到的**：找工具（`tool_search`）；模型写的那段代码本身和等它的结果（`exec`、`wait`）。
- **只能事后知道的**：模型硬要联网搜索；你在 Codex 里设成直接放行的命令，又碰上守卫的钩子跑失败，或者换了目录跑。判了不放行只能打断这一轮。
- **守卫拆不开的 PowerShell 写法**：脚本块、`if`、`Invoke-Expression`、圆括号表达式，按未知的写操作判。拼出来的路径认不出。
- **固定关掉的**：Codex 自带的联网搜索，搜索走二狗配的服务；往开着的终端里敲字，要人敲键盘的交互程序跑不了。审批策略也固定用最严的。
- **撤回只回对话**：它改过的文件留着。只能回到一条消息之前，回不到阶段、步骤开始前。接管之前的对话撤回不到。撤回过的，二狗接着的是分叉出来的新会话，交还后 `codex resume` 里要选那一个。
- **换了模型**：接管来的会话在二狗里换了模型的，之后二狗接着的是新开的一段会话，交还给终端的还是原来那个。
- **别的做不了的**：不能交给 Codex 的官方 App；终端里的斜杠命令这里用不了；工具包改了要等这一轮做完重新起。
- **等你批准时还会花一点额度**：它可能查几次结果，靠提示词压着，不是硬保证。
- **还用二狗自己的模型**：范围审视、撤回时的分支摘要。
- **谁能用**：只有任务、项目的负责人。秘书、子 agent、评审还是 pi。

**还没在真终端上验证完的**

- 终端界面开着这个会话时，Codex 拦不拦二狗。`codex exec` 和别的程序开着时，实测是拦的。
- 直接接管（不分叉）一个终端里用过的会话，交还后在终端 `codex resume` 接着说，再收回到二狗，这一整圈。这几步的做法用 `codex exec` 开的会话走通过。
- 生成图片、ChatGPT 账号多出来的工具（应用、插件）过不过守卫。
- 额度用完、登录过期时 Codex 真实报的错。现在按模拟的样子处理：任务转「等我」，写明原因。
