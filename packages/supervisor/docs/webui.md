# WebUI

单页，无构建步骤（原生 ESM + 一条 WebSocket）。绑 `127.0.0.1`，公网经 VPS 隧道。
它是这台机器上权限最高的入口，所以每个设计取舍都偏向「看得清、不误操作、不泄密」。

## 服务卡片

每个服务一张卡，常驻显示：

```
● web-server            linked        8799     运行 3h12m
  ⚠ 正在跑任务：正在合成第 3 段语音              ← busy 自报（接入协议）
  tmp/server.log · 最近 3 行 ...
  [ 停止 ]  [ 重启 ]  [ 日志 ]                   ← 无该能力则灰显 + 悬停说明
```

- **状态灯旁边永远写着探活档位**（`linked` / `health` / `port` / `process`），
  因为一盏绿灯在不同档位下保证的东西完全不同。
- **busy 独立于健康**显示。忙碌时点重启要二次确认，并默认选中「等空闲再停」。
- 灰显的按钮必须给出理由（「该服务未提供停机能力，接入统一层后可用」），
  否则半年后的你会以为是 bug。

## 实时性

- **状态永远实时推**：事件驱动的 WS 推送（状态变更、心跳汇总、探活结果、哨兵发现），不轮询。
- **日志按需流**：卡片上的「日志」在新标签页打开日志页（`/logs.html?id=<服务>`），只读：
  首屏是文件末尾 2 MB，顶上「加载更早的」可以一直往前翻到文件开头；新输出由 SSE 实时推，
  断线自动重连，从断点的字节位置续上（`Last-Event-ID`），不重放、不漏。页面关了流就停。
  一个服务有几份日志（命令行输出 + 项目自己登记的）就有几个标签。
  控制面只在本机（用户 2026-10 定的），所以可以给全量；最早「只给末 N 行」是为公网暴露设的。
- **日志一律过脱敏正则**（`sk-`、`apiKey`、`token`、长 hex 串）。流只按**整行**推进位置——
  密钥被拆在两个块里正则就认不出来了；还没写完的半行只在写入方停顿时、或 `\r` 进度条已写完的那一段才给。
  有的项目配置文件里就明文躺着第三方的 key。
- **编码**：同一个 `.out.log` 里常混着 UTF-8（node 写的）和 GBK（PowerShell 重定向写的），逐行判；
  ANSI 颜色照常渲染，`\r` 按终端的方式覆写当前行。

## 名下的服务

接入的项目经协议登记的服务（link-protocol.md §7）和手写登记的一样占一张卡，元信息那一行多一个青色小标「由 ergo-daemon 登记」
（简略卡片上只写登记方的名字），悬停说明它是独立常驻的、登记方掉线不影响它、撤销用 `lsm owned remove <id>`。
启停、强制停止、开机自启开关都照常能用——它归管理器管，不归登记方管。卡片上没有「撤销」按钮：撤销是删登记，走 CLI。

## 开机自启

每张卡片右上角一个「开机自启」开关，公网栏里隧道有「开机接通」。亮 = 新开机时管理器会把它拉起来；
虚线 = 开机不管它。改的是 `registry/autostart.yaml`，**不会现在就起停任何东西**。
「服务」标题旁汇总当前名单。名单之外的服务开机后一律不拉（哪怕关机前在跑、哪怕开着 autoRestart）。
「开机」按登录会话的建立时间认：开机、注销再登录算，管理器自己重启（看门狗、改代码）不算。

## 操作集

启动 / 停止 / 重启 / 场景切换 / 查看日志 / 裁决孤儿 / 纳管哨兵发现的服务 / 强制停止。
**所有写操作写审计日志**。

**停止和强制停止**（2026-10-13 起）：

- 「停止」碰上正在跑任务的服务，只会排队「等空闲再停」，管理器自己绝不强杀它（link-protocol §停机）。
  长任务一跑几小时，这个按钮就等于停不下来——实测就遇到过。
- 所以只要不是已停 / 孤儿，**每张卡片都有「强制停止」**（详细卡片是按钮，简略卡片是闪电图标），点了要再确认一次：
  - 有停机能力的：不等空闲，按 `now` 让它立刻停，**10 秒**内没停下就 `taskkill /T /F` 杀进程树；排队中的「等空闲再停」被这次覆盖。
  - 没有停机能力的：直接杀进程树（原来的「强制 kill」，规矩不变：不替它伪造停机能力，只是如实地杀）。
- 命令行同样：`lsm stop <id> --force`。审计里记 `stop{force:true}`，真杀了再记一条 `force-kill{reason:"force"}`。
- **停了没有只看进程和端口**（2026-10-18 起）：健康检查不过的服务，原来点了停止当场报「已停止」，进程其实还在听端口。
  现在端口真的空了才报已停，杀了还空不出来就转 FAILED 并写明谁还占着；本来就没在跑的，点停止直接成功。

## 哨兵提示

哨兵发现的东西不弹窗打断，聚在页面顶部一条横幅：
「发现 2 个未纳管服务：8888 (node, C:\dev\xxx) · 计划任务 `my-app-hub`」，
点开可直接进入纳管流程。这是最好的纳管入口——比事后想起来调 skill 有效得多（哨兵只让你看见、邀请你纳管，不阻止你手动启动任何东西）。

横幅默认折叠：一行摘要 + 按「项目 + 进程名」归组的小标签（悬停看端口和命令行）——
一个项目的测试 worker 一次能占十几二十个端口，逐条列出来就是一整屏。「展开明细」才逐条一行列出，命令行截断、悬停看全文。
「重复自启」例外：那是要你动手摘除的，永远整行显示。展开与否记在本浏览器里。

## Tailnet

哨兵横幅下面一条 Tailnet 栏：本机节点在不在线、哪个 tailnet、tailnet 里几台设备在线（悬停看每台最后在线时间）、
`tailscale serve` 把 443 转给了谁、网关（tailnet-gateway）活着没，带它的「开机自启」开关和日志。

卡片的公网栏里有「开通 tailnet」：给服务开一个只在 tailnet 里能打开的 HTTPS 地址
（会去 VPS 签证书、写 headscale 的 DNS 记录，弹窗里写明）。开了之后卡片多一栏 TAILNET：
地址、实测结论（网关 / tailnet DNS / serve 三段）、证书到期日、「撤销」。手机到本机那一跳从本机测不到，栏里如实写着。
简略卡片上是一个 tailnet 小标记，点它直接打开地址。

## VPS 订阅

Tailnet 栏下面一条：每个包年包月订阅「到期日 · 剩几天 · 手动 / 自动续费」（这台 VPS 标成「这台 VPS」），
余额顺带，几分钟前查的；「刷新」立刻去阿里云费用中心查一次（只读），「续费 / 充值」「控制台」直接跳阿里云。
到期前 7 天起整条变黄、3 天内变红，逐条写清楚「几天后到期、是手动续费——去续费 / 充值」；某项查不到时单列原因和补法。
还没放只读 AccessKey 时只显示一行「还没配」和「怎么配」（步骤 + 凭证该放的目录，可复制）。
快到期时还会弹 Windows 系统通知，同一条一天最多一次。

## 详细 / 简略

「服务」标题旁可以切换卡片样式。简略卡片只留：状态灯、id、状态、探活档位、端口（可点开本地地址）、运行时长，
一排图标按钮（启动 / 停止 / 重启 / 强制停止，孤儿时多出认领 / 杀掉）、公网 / 开机自启 / 告警三个小标记（悬停看详情）和日志。
入口、公网链路、依赖、报错全文都在详细模式里。选择记在本浏览器里。

## 外观

顶栏右侧「跟随系统 / 浅色 / 深色」三段开关，主页和日志页共用同一个选择（存在本浏览器的 localStorage，
`lsm.theme`；读不到就按跟随系统）。主题在首帧之前由 `<head>` 里一小段脚本定下来，不会先闪一下深色；
跟随系统时，系统一切换页面就跟着切，另一个标签页改了这边也同步。
颜色全部走 `:root` 上的变量，浅色是 `:root[data-theme="light"]` 整套覆盖——状态色在浅色下换成更深的色阶，
日志页的 ANSI 16 色也有一套浅色版（黑底调的亮黄字放在白底上根本看不见）。
「在跑」和「停着」不只靠颜色区分（浅色下翠绿和石板灰染成淡底色后几乎一样）：在跑的卡片染色、状态标签实心；
停着的卡片几乎不染色、左轨变淡、标签空心。浅色下的绿也换成了不偏蓝的纯绿（#15803d）。
