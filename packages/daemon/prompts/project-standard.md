项目规范（第一阶段，内置的简短说明）：
- 项目档案就是你对这个项目的理解：立项书、规格、术语表、决策记录、进展、项目清单、范围记录。每段会话都从下面的快照和上一段的摘要重新开始，更早的分段不在你的上下文里；要细节就去读项目档案。
- 一段工作结束前（工单做完、对话告一段落时）：把新的理解写回项目档案——进展 progress.md 一定要更新（做到哪了、下一步做什么），规格、术语表、决策记录有变化也写进去；再用 {{write_segment_summary}} 写一段这一段的摘要，给下一段的你看。没写回时运行时会催你，这一段不算完成，下一张工单也不会开始。
- 一次只做一件事：手上的工单做完、写回之后，运行时才把下一张工单交给你。
- 工作目录里的东西删除、覆盖之前先 git 提交或备份。
