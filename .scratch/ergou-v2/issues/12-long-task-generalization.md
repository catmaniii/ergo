# 长程任务机制泛化

Type: grilling
Status: open
Blocked by: 01, 04, 05

## Question

1. **计划形态怎么统一**：AgentSense 有固定计划和里程碑计划两种，二狗里怎样合并？是否只保留里程碑计划，把固定计划当作"每个里程碑都定好步骤"的特例？
2. **执行机制怎么搬到真实工具上**：以下机制在二狗里怎样泛化？
   - 验收：看真实世界的状态，还是交给 LLM 评审？
   - 拉回、催促、重试的阈值；
   - 预算；
   - 重开和补偿。
3. **用户长时间不在**：遇到需要用户的环节时，超时怎么处理，什么时候暂停？

## Context

- `docs/research/01-ref-agentsense.md` §3、§5：AgentSense 长程任务的具体机制，以及它的泛化缝。
- `docs/research/06-long-tasks-hitl-interruptions.md` §3：长任务可靠性。
- 立项 grilling Q6：长程任务 = 规划一次、授权一次、一次性干完，类似多阶段的 /goal。
- 「任务生命周期与任务看板」已定：
  - **每个任务都按长程方式执行**，"长程任务"和"任务"已合并为一个词；任务必须由用户明确发起。
  - 任务这一层的状态（规划中、待确认、排队中、执行中、等我、已暂停、已完成、失败、已取消、已归档）在看板上显示；本票的阶段层嵌在"执行中"里面，卡片上显示"第 N/M 阶段"。
  - "等我"的原因对应阶段层的停点：运行时审批、任务澄清、由用户验收的阶段、卡住求助（拉回超限、某阶段 3 次未通过）。
  - 返工就是 AgentSense 的"按依赖重开"，由同一个维护者接着做。
  - 完成不需要用户验收，只有计划里标明"由你验收"的阶段才停下来。
