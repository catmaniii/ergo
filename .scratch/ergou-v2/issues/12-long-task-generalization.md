## Question

1. **计划形态怎么统一**：AgentSense 有固定计划和里程碑计划两种，二狗里怎样合并？是否只保留里程碑计划，把固定计划当作"每个里程碑都定好步骤"的特例？

   - 拉回、催促、重试的阈值；
   - 预算；
   - 重开和补偿。
3. **用户长时间不在**：遇到需要用户的环节时，超时怎么处理，什么时候暂停？

## Answer

2026-10-07 定稿。

### 1. 计划的形态

- **统一成一种计划**，阶段就是里程碑。AgentSense 的"固定计划"，就是"每个阶段都定好步骤"的特例。
- **每个阶段有这些字段**：
  - 交付件；
  - 验收标准，每条注明验收方式（见第 3 节）；
  - 模式：定步，或开放；
  - 前置阶段；
  - 授权项；
  - 策略，见第 2 节；
  - 预算。
- **并行**：阶段图允许并行，但只有用户确认派子 agent 时才真正并行。

### 2. 策略与时序规则

- 第 1 轮 D1 说"v1 不搬规则引擎"，第 2 轮 Q4 推翻了这一条：**v1 搬 planguard 的引擎核心**（expr + spec + checker，约 570 行），规则格式与它兼容。
- **四种规则形态照搬**：
  - B 之前必须做过 A；
  - B 之前不能做过 A；
  - 这一次调用当下必须满足某个条件；
  - 一律禁止。

  规则只看已经成功执行过的调用；判断不了的就问用户。
- **v1 自带一套针对真实工具的规则模板**：
  - 删除或覆盖之前，必须已经备份或已经 git 提交；
  - push 之前，必须跑过测试；
  - 读过 `.env` 或密钥文件之后，不许对外发送、不许发 HTTP 请求；
  - 同一收件人、同一内容不重复发；
  - 对外内容不许含密钥（用正则查）；
  - force push、在项目外 `rm -rf`，一律禁止。
- **规则怎样认 bash**：规则只认工具名和参数。所以特殊的 bash 操作要么封装成带类型的工具，要么由守卫把命令拆成"伪工具调用"再套规则（「关注类别与打扰策略」第 5 节）。
- **控制器里的硬检查也照搬**：
  - 授权只在所属阶段内有效；
  - 前置阶段必须已经验收；
  - 碰过红线的对象，再做对外动作要先问。
- **策略挂在哪**：策略（规则加授权）可以挂在单个阶段上，也可以定义一次、套给一组阶段（**阶段组**）。在这些阶段执行期间，守卫一直检查。
- 用户在对话里说的限制，要编译成规则，显示在计划卡上，不能只留在对话里。
- **历史记录**：只有执行成功的调用才追加进效果日志。环境事实（文件元数据、git 状态）在检查时现取。

### 3. 阶段验收

- 每条验收标准写明用哪种方式验收：
  1. **系统检查**：文件存在、测试通过、命令结果。验收标准明确、能写成脚本的，必须写成脚本。维护者宣布阶段完成时，由钩子运行，不由维护者自己跑。
  2. **独立评审**：写不成脚本的，派一个评审子 agent。它用只读工具包，在新的上下文里只看交付件和验收标准，不看执行者自己怎么说。卡片上标"评审判定"。
  3. **由你验收**：只有计划里标明的，才停下来等用户。
- 维护者自检不能单独算验收。

### 4. 包含多项目工单的阶段

- 每张工单带自己的验收标准，项目维护者完成后交回执。
- 回执全部到齐后，任务维护者再跑一遍本阶段的验收。收到回执不等于验收通过。
- 任何一张工单被退回或做不了，本阶段就算没通过。任务维护者可以调整方案（算一次退回），或者转为"等我"。
- 按依赖重开某个阶段时，向相关项目重新派工单。

### 5. 阈值、预算与卡住

- **次数阈值**照搬 AgentSense，并且可以配置：
  - 拉回 3 次；
  - 催促 3 次；
  - 退回 2 次，第 3 次还不过就找用户。
- **预算**按 token 加工具调用次数计算。超出 1 倍，让维护者说明进展；超出 2 倍，问用户。
- **无进展检测**：agent 还活着，但很久没有新进展。
- **用户长时间不在**：
  - "等我"的事项永不自动批准，可以一直等；
  - 不依赖它的阶段继续推进；
  - 授权过了有效期要续期。

### 6. 压缩时不丢计划

- 计划、授权、当前阶段，以及用户说过的边界，都存在任务存储和事件日志里，不只在会话里。
- 每次唤起或压缩之后，运行时都固定重新注入一块内容："计划摘要 + 当前阶段 + 授权 + 边界"。
- 会话按工单分段，本来就能避开大部分压缩。阶段太长时，用自定义摘要指令。

### 留给规格

- 阶段的 schema；阈值的具体数值。
- 规则模板的 JSON；伪工具名对照表；参数名统一，并加一道规则校验（参考 AgentSense 的 `policies-check.ts`）。
- 效果日志的字段；总账的字段。
- 退回说明和催促的文案；补偿阶段；"无进展"的判定。
