# 项目规范：默认工作流程与文档模板

Type: grilling
Status: open
Phase: 2（暂缓，第一阶段规格之后再做）
Blocked by: 14

## Question

每个新项目的维护者要遵守一套固定的工作流程和文档规范。项目默认继承这套规范，用户也可以针对单个项目提出修改，让维护者改写。需要定下：

1. **工作流程**：
   - 立项用类似 grill-with-docs 的方式明确项目范围；
   - 每个状态（开发、运营、下线……）要做什么、交出什么；
   - 状态之间转换时的检查清单，比如转入运营时要完成哪些交接。
2. **文档清单**：每个项目都要有、并且位置和格式固定的文档。候选：
   - 范围与规格；
   - 进展跟踪；
   - 项目架构图；
   - 用到的服务和前端；
   - 是否有公网接口、有哪些；
   - 术语表与决策记录（ADR）。
3. **项目类型**：用户 2026-10-07 已明确，项目是"原子的、带运营的功能模块"，日常的综合性事务属于任务，不是项目。所以默认模板可以按功能模块来设计。还需要确认：有没有不含服务、没有公网接口的项目（比如纯文档或纯数据类的模块），模板怎样适配它们。
4. **继承与改写**：
   - 默认模板放在哪里，属于框架还是个人数据；
   - 单个项目怎样改写模板；改写要不要用户确认、怎样留痕；
   - 模板本身升级后，已有项目要不要跟着变。
5. **统一查看的接口**：为了让二狗 Web UI 用同一种方式查看每个项目，项目要对外提供哪些固定的元数据和文档入口（比如一个项目清单文件）。

## Context

- 用户 2026-10-07 提出（在「记忆边界」定稿之后）：
  - 开新项目的维护者要遵守一套固定的流程，参考 grill-with-docs，先把项目范围明确下来；
  - 要形成进展跟踪文档、项目架构图，写明项目需要哪些服务或前端、是否有公网接口，这些都按规范管理；
  - 规范只是默认继承，用户单独给某个项目提修改建议，维护者可以改掉默认的页面或管理方式；
  - 每个项目查看这些东西的方法和接口要类似，好在二狗前端统一查看。
- 现成的样板：二狗 v2 自己的规划就是这么做的——地图 + 决策票 + `CONTEXT.md` + ADR + 规格。可以作为开发类项目默认模板的起点。
- 「项目生命周期、工作空间与维护者」定项目状态机和隔离；本票在那之上定流程和文档。
- 「运营态项目的服务托管与公网入口」定转入运营时服务和公网入口怎么交给 LSM；本票的转运营检查清单引用它。
- 地图 Not yet specified 里的"二狗自举"：二狗将来也会是遵守这套规范的一个项目。
- 主地图 Notes 的"落盘要有章法"同样适用于项目文档。
- 「项目生命周期、工作空间与维护者」已定（2026-10-07）：
  - 项目状态：筹备中 → 建设中 → 运营中 / 已完成；运营中 ⇄ 已停用；已归档只能手动。本票按这套状态定每个状态的流程和交付。
  - 立项两步：秘书收口后项目诞生，维护者在自己的会话里做 grill-with-docs 式立项问答，交出**立项书**（范围、目标、首版要做到什么程度）。本票定立项书和立项问答产出文档的格式。
  - **项目档案**（立项书、规格、术语表、ADR、进展、项目清单、维护者会话）固定在数据目录的 `projects/<项目名>/`，永不放进外部仓库；**工作目录**默认在档案内，开发类项目可绑定外部路径。
  - 维护者的理解靠项目档案：每段工作结束前必须写回档案。本票定要写回哪些文档。
  - 不设"目标"实体，阶段只挂在任务上；"一期、二期"这类长线规划写在规格和进展文档里。
  - 项目要推到 GitHub 时，由维护者单独建仓库，建仓库和推送都要用户确认。本票定这个流程。
  - 要有转运营、停用、重新启用的检查清单。
- **用户 2026-10-07 补充（开发二狗 v2 时提出）**：二狗里起的每个项目，都要用类似 Matt Pocock 那套 skill 的流程来推进：立项问答 → 规格 → 拆成带依赖关系的实现票（tracer bullet，每张票写明验收标准和 Blocked by）→ 按依赖分波实现（一张票一个子 agent、测试通过并评审后合并）。二狗 v2 自己正在用的 `/wayfinder`、`/to-spec`、`/to-tickets`、`/implement`、`/tdd`、`/code-review` 就是样板。本票要把这套流程定为开发类项目的默认工作流，并定好票和规格在项目档案里的格式，让 Web UI 能统一读取。和地图待定项「内置 skill 库」相关：这些 skill 可能作为框架自带的 skill 提供（需先看许可）。
