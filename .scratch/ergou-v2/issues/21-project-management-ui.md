# 项目管理界面

Type: prototype
Status: open
Phase: 2（暂缓，第一阶段规格之后再做）
Blocked by: 19, 20

## Question

二狗 Web UI 里的项目管理界面长什么样？需要回答：

1. **项目列表**：按状态（筹备中、建设中、运营中、已完成、已停用、已归档）分组或筛选，增删改查。
2. **项目详情**：用统一的方式展示每个项目按「项目规范」交出的东西：范围、进展、架构图、用到的服务和前端、公网接口。
3. **运营态项目**：额外显示当前服务的运行情况（来自 LSM）。
4. **改写过模板的项目**：用户让某个项目改掉默认页面后，详情页怎样适配。
5. **和维护者交流**：**每张项目卡片上都有一个按钮，点了直接进入和该项目维护者的聊天会话。**这个会话界面和任务看板里打开维护者会话的是同一个（记忆管理者也复用它）。还要定：项目管理界面和任务看板怎样互相跳转。

做一个粗原型（可以点击的页面骨架）供评审，原型作为附件链接在本票里。

## Context

- 用户 2026-10-07：二狗 Web UI 里要有一套项目管理界面。进去能看到当前有哪些项目、各自处于什么状态；开发态和运营态的项目点进去能看到项目架构图等；运营态的还能看到当前服务的情况。
- 「项目规范：默认工作流程与文档模板」定义每个项目对外提供的统一元数据和文档入口，本界面只消费这些。
- 「运营态项目的服务托管与公网入口」定服务状态从 LSM 怎样读回来。
- 视觉语言继承 AgentSense，见 `docs/research/01-ref-agentsense.md` §5、§7。
- 「Web UI 信息架构」只给本界面留入口。
- 用户 2026-10-07 补充：每张项目卡片上要有一个"和维护者交流"的按钮，点了进入和这个 agent 的聊天会话。
- 「任务生命周期与任务看板」已定：任务和项目多对多。项目详情要列出所有涉及它的任务，并能跳到任务看板上对应的卡。
- 「项目生命周期、工作空间与维护者」已定（2026-10-07）：
  - 项目状态：筹备中、建设中、运营中、已完成、已停用、已归档（替换 Q1 里的旧草案）。
  - 项目页显示背后服务的在线情况（服务层的数据，不是项目状态）和进行中任务数。
  - 项目页要有维护者的**工单流水线**：排队中、进行中、已结束三栏，每张工单显示来源（用户、哪个任务、哪个定时作业）、所属任务和当前阶段，点开跳到任务或会话。
  - 已归档项目的维护者会话只读，取消归档后才能对话；删除只能从已归档发起，要二次确认。
  - 项目列表上用小圆点显示维护者的活动状态（休眠、干活中、等你、排队）。
