# 运营态项目的服务托管与公网入口

Type: grilling
Status: open
Phase: 2（暂缓，第一阶段规格之后再做）
Blocked by: 10, 14

## Question

项目转入运营后，它的后台服务、公网入口和身份鉴权怎样统一管理？需要定下：

1. **服务托管**：项目的后台服务按什么模板注册进 LSM（探活、自启、场景、`exposure` 声明）？由维护者生成注册文件，还是由二狗统一生成？
2. **公网入口**：
   - 本机侧的隧道由 LSM 托管，这已经现成；
   - VPS 上的 nginx 站点由谁来写：用户手动贴，授权二狗代办，还是要求 LSM 扩展能力？
   - 域名和端口怎样分配。
3. **身份鉴权**：各项目的公网入口用统一鉴权，还是各自鉴权？如果统一，放在哪一层（二狗做鉴权网关、VPS nginx、还是要求 LSM 扩展）？
4. **服务状态怎样回到二狗**：项目管理界面要显示运营态项目的服务情况，从 LSM 的接口读取哪些数据？
5. **下线**：项目下线时，服务、隧道、站点和证书怎样回收。

## Context

- 用户 2026-10-07：项目转入运营态时，要让 Local Service Manager 统一管理后台服务、VPS 前端公网入口以及身份鉴权相关功能。
- `docs/research/08-local-infra.md` §3 的现状：
  - **LSM 已经能做**：一服务一 YAML 注册；四档探活；隧道本身是 `role: tunnel` 的托管服务；被暴露的服务在 `exposure` 里声明 `via`、`remotePort`、`publicUrl`；管理器每 60 秒实测一次公网地址。HTTP + WebSocket 接口在 `127.0.0.1:7420`。
  - **LSM 不做**：
    - 从不改 VPS（LSM ADR-0009）。WebUI 的"开通公网入口"只生成隧道 YAML 和一段 nginx 片段，要用户自己贴到 VPS 上；
    - 不给被暴露的服务做鉴权。LSM 自己的鉴权目前也没开，现有做法是每个服务自带鉴权。
  - 所以用户要的"统一管理公网入口和鉴权"，一部分现在就有，另一部分需要二狗自己做，或者需要 LSM 扩展。LSM 那一侧的改动属于外部依赖，不在本地图范围内，本票只定二狗对它的要求。
- 「部署、数据目录与备份」先定二狗自己的守护进程、隧道和 nginx 怎么处理；本票把那套做法推广到所有运营态项目。
- 主地图 Notes：二狗的所有服务都在 LSM 注册并由它启动。
- 「项目生命周期、工作空间与维护者」已定（2026-10-07）：
  - **服务在不在线不是项目状态**：服务的在线、离线、按需拉起由服务层单独监控，项目页只显示。本票定服务层怎样监控。
  - 运营中的项目，服务可以常驻，也可以按需（平时离线，要用时拉起，办完就停）。本票定按需服务由谁拉起、要不要用户确认。
  - **已停用** = 项目不再使用：服务撤出 LSM、公网入口收回；可以重新启用。停用和重新启用都作为任务由维护者执行。本票的"下线"即停用。
  - 运营告警先只进"待我处理"；要不要自动唤起维护者去诊断，由本票定。
  - 定时调度做在二狗守护进程里，不用 Windows 计划任务（LSM ADR-0005）。
