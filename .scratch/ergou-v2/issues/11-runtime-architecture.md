## Answer

2026-10-07 定稿。

### 1. 进程模型

- **每个 agent 一个子进程**：秘书、记忆管理者、每个维护者、每个子 agent，各自跑在自己的子进程里，子进程里是一个 pi `pi-coding-agent` SDK 会话。
  - **有活时常驻**：工单到达、用户说话、定时作业触发时拉起；一段活干完、闲下来就退出，回到"休眠"。秘书常驻。
  - 状态都在磁盘上（pi 会话文件、事件日志、项目档案），进程退出不丢东西，下次拉起从磁盘续上。
- **守护进程只当管家，自己不跑模型**。它负责：
  - 子进程的启停、超时、数量上限和回收；
  - 守卫判定、审批表、事件日志、派单器、调度器；
  - 网关和 Web UI。
- **子进程之间不直接通信**。agent 之间只有工单，全部经守护进程转交（「项目生命周期、工作空间与维护者」已定）。子 agent 的结果一定回到父 agent 的会话里，不能只写进守护进程的记录。
- **好处**：
  - 一个 agent 卡死、内存爆掉或崩溃，不影响秘书和其他 agent；
  - 每个项目的工作目录、环境变量、工具包天然分开；
  - pi 的全局单例在多会话下会不会互相干扰，这个问题不存在了。
- **代价**：要写一层守护进程和子进程之间的通信；agent 被唤起时有一次冷启动。
- **开工后的第一个 spike**：验证 pi 的 RPC 模式（`--mode rpc`）能不能当这层通信；不行就在子进程里用 SDK，自己写一层 IPC。
- **drama_maker 的教训一并落实**：
  - 每次拉起子进程，都显式注入它需要的 key 和环境变量，不继承守护进程的环境；密钥从工具的孙进程环境里剥掉；
  - 每次模型调用和工具调用都有超时；
  - 同时存活的子进程有上限；
  - 守护进程定期回收孤儿进程；
  - 所有子进程和孙进程放进二狗自建、不允许脱离的 Job 对象，守护进程被 LSM 杀掉时一起清掉（「Windows 原生沙箱能力调研」）；
  - 进行中的回合持续写盘；
  - 同一个 agent 的输入串行排队，队列放在事件日志里，不放内存。

### 2. 守护进程的部件

| 部件 | 职责 |
|---|---|
| 网关 | 一个端口提供 HTTP API、WebSocket 和 Web UI 静态文件 |
| agent 管家 | 拉起、监控、回收 agent 子进程；转发会话事件；上报活动状态（休眠、干活中、等你、排队） |
| 守卫与审批 | 每次工具调用的判定（关注类别、授权项、时序规则、路径围栏）都在守护进程里做；子进程里的 pi 扩展只负责把调用送来、按判定执行。审批表、"等我"事项在这里 |
| 派单器 | 工单进事件日志后，送进收件维护者的工单队列；全局最多 3 个任务同时执行（可调），子 agent 不占名额 |
| 调度器 | 简单提醒和定时作业共用；简单提醒到点直接发通知，不拉起 agent |
| 快速动作执行器 | 用户确认后由运行时直接执行，不拉起 agent |
| 事件日志与派生视图 | 唯一真相；看板、待我处理、工单流水线都由它推导 |
| 素材采集 | 七类素材事件由运行时确定性地产生，写入素材库 |
| 记忆检索 | 每轮简报和深查都是运行时的检索，不调用记忆管理者 |
| 通知 | 推送到前端；推送通道见「推送与远程审批通道」 |
| token 账本 | 从 pi 每次调用的用量里记任务、agent、会话、模型、输入（缓存命中 / 未命中）、输出 |

### 3. pi 封装层

- pi 只跑在 agent 子进程里。守护进程不跑 agent 循环。
- **每个 agent 的会话按它的工具包装配**：
  - 工作目录、追加的系统提示（工具包说明、项目规范、项目档案快照、上一段摘要、这次的工单）；
  - 只加载工具包里列出的 skill，不自动发现 `~/.pi`、`~/.claude/skills` 和 CLI 的认证；
  - 工具白名单按工具包来，必须包含 `read`；
  - 挂上二狗的扩展：守卫、范围审视、素材事件上报。
- **一个会话一个模型**。换模型就新开会话，附一份交接摘要。
- **业务状态不进 pi 会话**：计划、授权、阶段、工单、审批都存在二狗自己的存储里，每次唤起和每次压缩之后重新注入（「长程任务机制泛化」）。
- **pi 版本**：二狗在自己的工作区里装一个固定版本，开工时取最新稳定版，不用本机全局那份 0.84.1。用 faux provider 的契约测试把关以后的升级。

### 4. 持久化

- **`ergou.db`**（SQLite，WAL 模式）：事件日志，以及由它派生的看板、审批表、工单、提醒、token 账本。
- **`memory.db`**：素材和记忆，只由记忆模块写。
- **pi 会话文件**：每个 agent 一组 JSONL，放在数据目录的 `sessions/` 下。
- **文件**：项目档案、素材原文、媒体（按内容哈希存）。
- 有副作用的请求带幂等键；审批记录先写库、再推送。

### 5. 被杀后的恢复

LSM 每次重启都会连带杀掉守护进程，Job 对象会把所有 agent 子进程一起清掉。重启后：

- **待审批的事项**：从审批表恢复，不重复推送。
- **只读或幂等的工具**：告诉模型"这次调用被中断了"，由它决定要不要重做。
- **有副作用、又说不清做没做完的**：任务转为"等我"，写明"中断：不确定 X 是否已执行"。这是「关注类别与打扰策略」里"等我"的一种新原因。
- **输出到一半的回复**：丢掉中间片段，从会话文件里最后一个完整的回合续上。
- **错过的定时触发**：提醒晚了 60 分钟以内照发，标明晚了多久；更晚的改进"待我处理"；定时作业只补跑一次。
- 重启后没人登录时，二狗一直不在线，等用户登录后再补（「部署、数据目录与备份」）。

### 6. skill 和外部工具（MCP）

- **二狗自己的 skill 库**：框架自带一批，数据目录里放用户自己加的。不自动读取 `~/.claude/skills`；intent-mining、reasoning-graph 这类现成的 skill，要用就显式导入一份。
- **MCP** 先在二狗里登记，再授权给项目或任务。
- **授权按项目或任务**，写在工具包里，不按角色（v1 不设角色，见「角色模型」）。

### 7. 工程栈

- TypeScript + Node（≥22.19）。固定一个专用的 Node 22 LTS，LSM 里写绝对路径。
- npm workspaces，三个包：守护进程、Web、共享协议。
- Web UI：React 19 + Vite，手写 CSS，不用组件库和状态管理库；从 AgentSense 复制前端代码，之后各自演进。
- 测试 vitest，lint 用 oxlint。

### 留给规格

- 守护进程和子进程之间的协议：消息类型、守卫判定的往返、流式事件的转发、心跳。
- 子进程的超时、上限、闲置多久退出、回收周期等数值。
- **范围审视扩展**：在 `session_before_compact` 里，把即将被压缩的那段对话交给另一个便宜模型，对照项目范围和用户给过的授权，找出范围外的事；结果用 `appendEntry` 写进会话，同时写进项目档案；在 `before_agent_start` 里把最新的范围记录拼到系统提示末尾。工单结束时也跑一次。具体规则见「角色模型」。
- **按项目装配会话**：每个项目一个 `DefaultResourceLoader({cwd, noSkills: true, additionalSkillPaths, appendSystemPrompt, extensionFactories})`，再用 `createAgentSession({tools, customTools})`。工具白名单必须含 `read`，否则 skill 不注入。
- **硬限制一律在 `tool_call` 里用拦截实现**，不用原地改参数（改完不会重新校验）。drama_maker 的 `pi-extensions/drama-path-guard` 可以当路径围栏的样板。
- 文件工具在守护进程这一侧做路径围栏（只允许项目档案和工作目录）。
- 事件的 seq 和活动状态的格式，与「消息协议与多前端」对齐；素材事件的信封，与「素材管理」对齐。
- `node:sqlite` 在 Node 22.23 上会打 ExperimentalWarning，规格里决定是否接受。
- 秘书主线会话的专用压缩指令（「记忆边界」已定内容）。
- 测试 DeepSeek 上 `supportsMidConvoSystemMessages` 对前缀缓存的影响。
- 记忆管理者的做梦阶段放在夜间。
- LSM 的 link 协议：有任务在跑时报 busy。
