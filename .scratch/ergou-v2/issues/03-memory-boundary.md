# 记忆边界：秘书、任务与记忆管理者之间的接口

Type: grilling
Status: resolved

## Question

秘书、任务执行者、项目、记忆管理者之间的接口是什么？要回答以下五点：

- **(a) 秘书读到什么**：秘书读到的记忆是什么形态，怎样注入上下文？
- **(b) 哪些事件算素材**：系统里哪些事件作为素材交给记忆管理者？候选：
  - 对话；
  - 用户对产出的反应；
  - 审批决定；
  - 澄清问题的回答；
  - 用户主动投喂的材料。

  每类事件的格式是什么？
- **(c) 任务和项目能看到多少**：任务或项目被授权看到哪一部分记忆？超出授权时，怎样向用户申请？
- **(d) 问题怎么流转**：记忆管理者生成的澄清问题，怎样流到秘书和"了解你"问题箱？
- **(e) 记忆管理者本身怎么托管**：它作为一个运营中的内部项目，怎样被托管？用户怎样直接找它调整规则？

记忆的内部设计不在本票，归子地图 [二狗记忆系统](../../ergou-memory/map.md)。

## 讨论稿 v0（2026-10-07，供讨论用，尚未定案）

### 参与方与权限

| 参与方 | 对记忆的权限 |
|---|---|
| 记忆管理者 | 用户模型的**唯一写者**；能读全部素材；产出用户卡、记忆简报和"了解你"问题 |
| 秘书 | 通过用户卡、简报和深查工具读全部记忆；**不直接写**，"记住 / 忘掉"这类显式命令交给记忆管理者执行 |
| 维护者 / 子 agent | 只读本任务的记忆包；不写；需要更多时提出申请 |
| 运行时（网关） | 自动、确定性地产生素材事件 |
| 用户 | 通过"了解你"页面和记忆管理者的会话查看、纠正、删除 |

### (a) 出口：秘书读到的三层

1. **用户卡**：放在 system 段里，常驻上下文，约 1000 token 以内。
   - 内容：硬约束和显式指令、已确认的偏好、由动机层编译出来的交互策略。**不放动机假设的原文。**
   - 刷新：做梦阶段结束后每天最多一次。原因是在 deepseek-flash 上，每改一次 system 段，前缀缓存就全部失效。
2. **记忆简报**：每条用户消息进来时，运行时自动做一次不调用模型的检索（关键词 + 向量）。
   - 把 5 条以内的相关条目，作为一条**持久化的上下文消息追加在对话尾部**。不改 system 段，所以不会打穿缓存。
   - 每个条目带 id、所属层、状态（已确认 / 假设）、置信度和一句证据摘要。
   - 可以附带 1 个和当前话题相关的待问问题。
3. **深查工具**：`memory.search` 和 `memory.explain(id)`，用来查看证据链。

### (b) 入口：素材事件

素材事件由运行时自动产生，agent 不能挑选。共七类：

1. 用户发言：任何会话里的都算，包括语音转写和附件引用。
2. 用户对产出的反应：采纳、修改（附 diff）、要求返工、放弃。
3. 审批决定：批准、拒绝、收窄授权。
4. 澄清问题的回答。
5. 用户主动投喂的材料。
6. 显式记忆命令："记住 / 忘掉 / 别推断 X"。走热路径，确定性地立即生效。
7. 任务结局：完成、失败、取消，以及用户对项目目标"已完成"的判定。

**统一信封**：`{id, 类型, 时间, 来源会话, 任务或项目, 来源等级（本人 / agent / 外部不可信 / 系统）, 指向原始记录的引用, 情境标签}`。只存引用，不复制原文。

**硬规则**：
- 只有来源等级为"本人"的素材，才能生成关于用户的判断。
- agent 的产出、邮件和网页等外部内容，都不进入用户模型。
- 从记忆里召回的内容，不能再当作新素材。
- agent 之间的内部往来不算素材。

### (c) 任务能看到多少：记忆包

- **组包**：派遣任务时，秘书为它组一个记忆包。
  - 只装与该任务相关的事实、偏好和交互策略。
  - 不含动机假设（L3 / L4）。
  - 默认排除敏感类别。
- **确认**：记忆包随计划一起交给用户确认，在计划卡里折叠显示为"这个任务会知道你的这些信息"。
- **项目**：立项时设定"项目记忆授权"，即允许的领域。维护者每次被唤起时，都在授权范围内重新取包。
- **申请更多**：维护者调用 `request_memory(问题, 理由)`。
  - 在授权范围内：由秘书直接回答。
  - 超出授权：作为一个关注类别（"访问授权外的个人记忆"）走审批。
- **子 agent**：只拿到维护者记忆包的子集。

### (d) 问题怎么流转

问题分两种：

- **任务澄清**：任务卡住、需要用户做决定的问题。来自秘书或维护者，属于阻塞类，走审批和推送通道。
- **了解你问题**：记忆管理者为验证某个假设而提出的问题，不阻塞任何任务。
  - 进入"了解你"问题箱。
  - 秘书在简报里拿到与当前话题相关的问题时，可以在对话中顺口问。每天顺口问的次数有上限，可调，默认 3 次。
  - **这类问题永远不推送到手机。**

用户的回答作为"澄清回答"素材事件交回记忆管理者。

### (e) 记忆管理者怎么托管

- 系统内置一个项目"记忆管理"，常驻在运营状态，不能归档。记忆管理者就是它的维护者，和其他维护者用同一套机制：在任务看板上能看到，能直接打开它的会话和它对话。
- 工具：
  - 记忆库读写，全系统只有它能写；
  - 读取素材；
  - **没有任何对外有副作用的工具，也不能派任务。**
- 做梦阶段作为这个项目的定时作业运行，细节在记忆子地图里设计。
- 用户关于记忆的规则（如"别推断我的健康""别记这件事"）是权威指令，存为这个项目的规则。

## Answer

2026-10-07 定稿。

### 1. 参与方与权限

| 参与方 | 对记忆的权限 |
|---|---|
| 记忆管理者 | 用户模型的**唯一写者**；读全部素材；产出用户卡、记忆条目和"了解你"问题 |
| 秘书 | 读全部记忆，**包括动机假设**；不直接写，"记住 / 忘掉"这类命令交给记忆管理者执行 |
| 维护者 / 子 agent | 只能读用户授权的记忆范围；**看不到动机假设**；不写 |
| 运行时（网关） | 自动、确定性地产生素材事件 |
| 用户 | 在记忆 Web UI 里查看、纠正、删除；在记忆管理者的会话里调整规则 |

### 2. 短期记忆与长期记忆

- **短期记忆**：所有会话（包括维护者会话）近期产生的素材及其临时提炼。
  - 检索时按**时效权重**衰减。衰减的是"现在还适不适用"，不是"是真是假"。所以展示为"这是 N 天前的临时记忆"，不显示成低置信度。
  - 半衰期默认 **1 个月**。每轮自动检索只看最近 **3 个月**，更早的只能深查。两个数字都可以在设置里调。
  - **永不自动删除**，只有用户能删。被提炼进长期记忆之后也保留，作为证据。
- **长期记忆**：记忆管理者（主要在做梦阶段）从短期记忆里提炼出的事实、偏好和对用户的认知（包括动机假设）。
  - 每条都带证据链接，指回它依据的短期记忆。
  - **不随时间衰减，只会被新证据取代**。被取代的旧版本标为"已被取代"，历史保留。
  - 动机假设如果连续预测落空，就降级。
- **按类型设置不同的衰减速度**（比如情绪几天就失效、偏好可以维持几个月），v1 不做，跑起来遇到问题再说。
- 短期、长期和 L1–L4 分层的对应关系，归记忆子地图「用户模型的分层与证据」。

### 3. 出口：秘书读到的三层

1. **用户卡**：放在 system 段，常驻上下文，约 1000 token 以内。
   - 内容：硬约束和显式指令、已确认的偏好、由动机层编译出的交互策略。**不放动机假设的原文。**
   - 刷新：做梦阶段结束后，每天最多一次，以免打穿 deepseek-flash 的前缀缓存。
2. **记忆简报**：每条用户消息进来时，运行时自动检索一次，不调用模型（关键词 + 向量，并计入时效权重）。
   - 5 条以内的相关条目，作为一条**持久化的上下文消息追加在对话尾部**。不改 system 段。
   - 每个条目带 id、短期还是长期、状态（已确认 / 假设）、证据摘要；短期条目注明是几天前的。
   - 可以附带 1 个和当前话题相关的待问问题。
3. **深查工具**：`memory.search` 和 `memory.explain(id)`，后者用来查看证据链，也是查 3 个月以前短期记忆的唯一途径。

### 4. 入口：素材事件

素材事件由运行时自动产生，agent 不能挑选。**全部进入短期记忆**，由记忆管理者决定是否用于动机推导或提炼进长期记忆。共七类：

1. 用户发言：任何会话里的都算，包括维护者会话、语音转写和附件引用。
2. 用户对产出的反应：采纳、修改（附 diff）、要求返工、放弃。
3. 审批决定：批准、拒绝、收窄授权。
4. 澄清问题的回答。
5. 用户主动投喂的材料。
6. 显式记忆命令："记住 / 忘掉 / 别推断 X"，以及在记忆 Web UI 里的纠正和删除。走热路径，确定性地立即生效。
7. 任务结局：完成、失败、取消，以及用户对项目目标"已完成"的判定。

**统一信封**：`{id, 类型, 时间, 来源会话, 任务或项目, 来源等级（本人 / agent / 外部不可信 / 系统）, 指向原始记录的引用, 情境标签}`。只存引用，不复制原文。

> **2026-10-07「素材管理」修订**：
> - 来源等级为"本人"的素材，素材库**保存一份原文副本**：不可修改、只追加、只有用户能删。agent 的产出、附件和外部内容仍然只存引用加内容哈希（媒体本来就按哈希存）。（改本节"只存引用，不复制原文"）
> - 原因：「项目生命周期、工作空间与维护者」定了删除项目时维护者会话一起删、素材不删。如果只存引用，项目一删，维护者会话里用户说过的话就断了引用。

**硬规则**：
- 只有来源等级为"本人"的素材，才能生成关于用户的判断。
- agent 的产出、邮件和网页等外部内容，都不进入用户模型。
- 从记忆里召回的内容，不能再当作新素材。
- agent 之间的内部往来不算素材。

### 5. 记忆在计划和执行中的使用

- **动机假设只有秘书能看到。**派出去的活已经是具体的事，任务只带具体信息，不会泄露用户的动机。
- **计划里标出两件事**：
  1. 这份计划**引用了哪些记忆**，可以点开看证据；
  2. 执行中**可能调用记忆的范围**，即记忆范围，按领域或类别描述。敏感类别默认不在范围内。
- **用户确认计划，就是授权了这个记忆范围。**派遣时，任务带上计划中引用的那些记忆。
- **执行中取用**：维护者调用 `request_memory(问题, 理由)`。
  - 在范围内：直接返回。
  - 超出范围：提醒用户临时授权。这作为一个关注类别（"访问授权外的个人记忆"）走审批。
- **项目**：立项时授予项目级的记忆范围，维护者每次被唤起时都在这个范围内取用。
- **子 agent**：只能拿到其维护者范围的子集。

### 6. 两种问题

- **任务澄清**：任务卡住、需要用户做决定。来自秘书或维护者，属于阻塞类，走审批和推送通道。
- **了解你问题**：记忆管理者为验证假设而提出，不阻塞任何任务。
  - 进入"了解你"问题箱。
  - 秘书在简报里拿到与当前话题相关的问题时，可以在对话中顺口问。每天的次数有上限，可调，默认 3 次。
  - **永远不推送到手机。**
- 用户的回答作为"澄清回答"素材事件交回记忆管理者。

### 7. 记忆管理者的托管与两个用户入口

- **托管**：系统内置项目"记忆管理"，常驻运营状态，不能归档。记忆管理者就是它的维护者。和其他项目一样列在「项目管理界面」里（2026-10-07「任务生命周期与任务看板」第 1 轮确定项目和任务分开管理后修订）。
  - 工具：记忆库读写（全系统只有它能写）、读取素材。**没有任何对外有副作用的工具，也不能派任务。**
  - 做梦阶段是这个项目的定时作业，细节归记忆子地图。
  - 用户关于记忆的规则（如"别推断我的健康""别记这件事"）是权威指令，存为这个项目的规则。
- **入口一：和记忆管理者对话**。和找其他维护者完全一样：在项目管理界面点它的"和维护者交流"按钮，直接说。不需要专门的界面。用户默认仍然找秘书。
- **入口二：记忆 Web UI**。二狗系统里一个独立的子模块，不是对话。
  - 它调用记忆模块提供的查看、纠正、删除接口。
  - 纠正和删除按"显式记忆命令"处理：确定性地立即生效，受影响的派生内容由记忆管理者随后修订。
  - 界面怎么做，归记忆子地图，逐步迭代。

### 8. 秘书会话：一条主线，重要的东西都落盘

秘书只有一条长期主线会话，靠自动压缩控制长度。为了让压缩不丢东西，定三条硬原则：

1. **要记住的东西不能只活在对话里。**每样东西都有固定的归宿：

   | 东西 | 归宿 | 压缩时 |
   |---|---|---|
   | 任务、项目、提醒 | 任务看板 | 可丢，看板是权威 |
   | 用户的偏好、事实、说过的话 | 短期记忆（素材事件实时写入） | 可丢 |
   | 项目的规格和决策 | 项目自己的文档 | 可丢 |
   | 进行中的话题、未回答的问题 | 只在对话里 | **必须保留**，写进压缩摘要 |

2. **承诺即任务。**秘书答应"以后、到点做某事"时，必须当场在任务看板上建任务或提醒，不能只靠对话记着。
3. **落盘要有章法**（用户补充）。要记下来的每类东西都有固定的、统一管理的归宿（任务看板、记忆库、项目文档、配置），任何 agent 都不能随手新建文件来存。临时文件只能放进专门的临时区，定期清理。

具体做法：
- **秘书掌握任务靠查看板，不靠回忆。**它有只读的看板查询工具。看板自上次以来有变化时，运行时在下一条用户消息后追加一条"看板变化"上下文消息，做法和记忆简报一样，不改 system 段。
- **秘书专用的压缩指令**：
  - 丢掉任务的执行细节和已解决的问答，涉及的任务只留 ID 和一句话；
  - 保留进行中的话题、未回答的问题，以及刚说的、还没被记忆管理者处理的指示。

### 9. 定时类任务

- **简单提醒**（如"明早 9 点提醒我交报告"）：**没有 agent**。调度器到点直接发通知，秘书负责建、改、取消。在看板上显示为"运营中 · 待触发"。这是"每个任务都有维护者"的例外（「任务生命周期与任务看板」又定了快速动作，同样不配 agent）。
- **定时作业**（如"每天早上 8 点出一份 AI 安全简报"）：每次都要 agent 干活。处于运营状态，有自己的维护者，积累经验。做梦阶段就是一个定时作业。
- **任务形态**一共四种，移交「任务生命周期与任务看板」细化：
  - 一次性任务：做完归档；
  - 项目：目标完成后归档或转入运营；
  - 简单提醒；
  - 定时作业。
