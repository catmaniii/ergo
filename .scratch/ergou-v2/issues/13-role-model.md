## Question

   - 目的；
   - 非目标；
   - 工具清单；
   - 能看到的记忆范围；
   - 预算；
   - 交接方式。
2. **怎样在代码里强制"只做本领域的事"**：工具白名单；越界时拒绝并上报。
3. **角色经验怎样沉淀**：
   - 运行中只写项目笔记；
   - 结项时做增量合并；
   - 经验先进候选，经审批后转正；
   - 每条经验标注来源；
   - 防止跨项目污染。
4. **角色怎样增删改查**：包括出现新需求时，由秘书提议新增角色。

## Answer

2026-10-07 定稿。

### 1. 取消"角色"

- 二狗 v1 **不设角色**：没有角色卡、角色库、角色管理页，也没有"角色经验"。
- 立项需求 3 里"每个专业子 agent 只能做本领域的事"，改由两样东西承担：
  - 维护者绑定的**项目或任务**，本身就界定了它该做什么：立项书写了范围，任务有计划；
  - 维护者的**工具包**，决定了它能做什么。
- 维护者是项目或任务的"座位"，不分工种。子 agent 做什么，仍由维护者决定（「项目生命周期、工作空间与维护者」已定）。
- 「v1 起步角色目录」随之失去前提，应关闭为超出范围。框架自带哪些 skill，改作第二阶段的待定项「内置 skill 库」。

### 2. 工具包

- **工具包**是一个维护者能用的东西的集合，按项目或任务配置，包括：
  - 哪些 skill；
  - 哪些外部工具（MCP）；
  - 能不能用 bash；
  - 能不能联网。

  文件工具的范围固定为项目档案和工作目录两处（「项目生命周期、工作空间与维护者」已定），不在工具包里另配。
- **谁定**：立项时写在立项书里，发起任务时写在计划卡上。由维护者提议，用户确认。开发类项目默认带 bash。
- **运行中怎么改**：
  - **skill 的增减**，维护者可以自己做，记进时间线。skill 只是说明书，不增加权限。
  - **能力的增加**，比如开 bash、加 MCP、开联网，算扩大授权，要走"计划变更"问用户。
  - **减少能力**随时可以。
- **两个固定的工具包**：
  - **跨项目任务的维护者**：只有读项目档案、派工单、汇总回执三样，改不了任何项目。v1 不设"只管不干"的独立 PM，其他维护者照常既管又干。
  - **评审子 agent**（阶段验收用，见「长程任务机制泛化」）：只读。
- skill 和 MCP 来自二狗自己的 skill 库，按项目或任务授权，不按角色（见「运行时架构」）。

### 3. 范围软卡

- **立场**：维护者的"做事范围"**不硬卡**。用户有时会在授权的基础上，让维护者先做点别的事，范围要能被突破。
- **硬闸仍然是守卫**：越出项目目录、对外发送、删除等关注类别，照常拦或问（「关注类别与打扰策略」）。软卡只管"做的事是不是这个项目该做的"。
- **什么时候审视**：两个时点都审视：
  - 维护者会话压缩时。会话按工单分段，压缩其实不常发生。
  - 每张工单结束时。
- **怎么审视**：另开一次便宜模型的调用，对照项目范围（立项书、任务计划）和用户给过的授权（包括用户在会话里直接说的话），找出这段工作做了哪些范围外的事，分成两类：
  - **范围变更**：用户授权过的。写进项目档案，项目页上看得到。
  - **越界**：没授权的。
- **结果去哪**：
  - 审视结果存进会话，从下一轮起拼到维护者系统提示的末尾，标题是"近期范围记录"。
  - 发现越界时，另在"待我处理"里放一条**不推送**的通知。
  - 不暂停维护者。
- **技术接法**（pi）：给维护者会话挂一个扩展。
  1. 在 `session_before_compact` 里把待压缩的消息转成文本，交给另一个模型审视。
  2. 用 `appendEntry` 把审视结果存进会话，然后放行，让默认压缩照常进行。
  3. 在 `before_agent_start` 里读最近一条审视结果，拼到系统提示末尾。

  工单结束时，运行时直接调用同一个审视函数。压缩和工单结束都不频繁，所以改系统提示不会经常打穿前缀缓存。

### 4. 经验

- **按项目沉淀**，就放在项目档案里。维护者每段结束前要把新的理解写回档案（「项目生命周期、工作空间与维护者」已定）。
- **不自动提炼**，没有候选经验、转正、审批这一套。
- 用户要求时，维护者用 `reasoning-graph`（推理图谱）skill 把项目里的领域知识沉淀成图谱，存进项目档案。
- 用户的偏好不进项目经验，统一来自记忆。

### 留给规格

- 工具包的数据结构（skill 名单、MCP 名单、bash、联网），以及它在立项书和计划卡上怎样显示。
- 维护者唤起时的固定上下文：工具包说明、项目规范、项目档案快照、上一段摘要、这次的工单。
- 范围审视的提示词、用哪个便宜模型、"近期范围记录"保留几条。
- 计划变更里"能力增加"的卡片样式。
