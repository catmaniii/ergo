# Web UI 信息架构

Type: prototype
Status: open
Blocked by: 05, 06, 13, 14

## Question

在继承 AgentSense 视觉语言的前提下，二狗 Web UI 的信息架构是什么？

1. **要组织的页面**：
   - 聊天：类似 WhatsApp / Telegram 的多媒体会话；
   - 任务看板；
   - 项目管理（页面本身见「项目管理界面」，本票只留入口）；
   - 角色管理；
   - 记忆 Web UI 的入口（子模块本身由记忆子地图设计）；
   - 设置：关注类别、音色、通知。
2. **缩放视图**：AgentSense 的全局层和要点层缩放视图放在哪里。

做一个粗原型（可以点击的页面骨架）供评审，原型作为附件链接在本票里。

## Context

- `docs/research/01-ref-agentsense.md` §5、§7：UI、设计 token、视觉规矩。
- `docs/research/09-chat-multimedia.md`：消息模型和多媒体交互。
- 「多 agent 架构与 token 成本」已定，原型需要体现：
  - 任务列表及各任务的状态；
  - 打开某个任务维护者的会话历史，展示方式参考 AgentSense；
  - 在维护者的会话里直接给它发指令，不经过秘书。
- 「记忆边界」已定：
  - **记忆 Web UI 是独立的系统子模块**，由记忆子地图设计。本票的信息架构只给它留入口。原先列的"了解你"页面并入记忆 Web UI。
  - 和记忆管理者对话不需要专门的界面，复用维护者的会话视图。
- 「任务生命周期与任务看板」已定：
  - 主界面用若干 tab，其中"待我处理"在有未读时亮小红点，竖屏时点进去是单独的页面，事项可以标已读、归档、删除；
  - 任务看板按"等我 → 进行中 → 运营中 → 最近结束 → 已归档"分组；
  - 全局"消耗"页；
  - "发起任务"按钮。
