## Question

在继承 AgentSense 视觉语言的前提下，二狗 Web UI 的信息架构是什么？

1. **要组织的页面**：
   - 聊天：类似 WhatsApp / Telegram 的多媒体会话；
   - 任务看板；
   - 项目管理（页面本身见「项目管理界面」，本票只留入口）；
   - 角色管理；
   - 记忆 Web UI 的入口（子模块本身由记忆子地图设计）；
   - 设置：关注类别、音色、通知。
2. **缩放视图**：AgentSense 的全局层和要点层缩放视图放在哪里。

做一个粗原型（可以点击的页面骨架）供评审，原型作为附件链接在本票里。

## Answer

2026-10-07 定稿。信息架构已定；可点击原型放到实现阶段做，不单独阻塞规格（见第 6 节）。

### 1. 主框架

- **竖屏**：底部 5 个 tab：
  - 秘书；
  - 任务；
  - 项目；
  - 待我处理（有未读时亮小红点）；
  - 更多：消耗、记忆（入口，子模块由记忆子地图设计）、设置；第二阶段在这里加全景入口。
- **宽屏**：tab 变成左侧竖栏，内容区按 AgentSense 的做法分栏（窄屏三页堆叠，宽屏分栏）。
- **没有角色管理**。维护者的工具包在项目页和任务详情里看和改。
- **"发起任务"按钮**放在秘书页和任务页。

### 2. 竖屏优先

- 先按手机竖屏设计；宽屏复用同一套组件，只改布局。
- 手机外壳只是 WebView，加载守护进程提供的同一套页面。

### 3. 会话组件

- **秘书聊天和维护者会话用同一个组件。** 维护者会话多三样：
  - 工单分隔线（会话按工单分段）；
  - 阶段抽屉；
  - 直接给维护者下指令的输入框（不经过秘书）。
- **全局层和要点层缩放**（来自 AgentSense）在所有会话里都能用。秘书主线缩放到全局层时，按天显示色块。
- **要点层和全局层要标出**：
  - 命中关注类别的操作（沿用 AgentSense 的标注）；
  - **通用 bash 调用**：没有事先规定类型的 bash，单独标记，让你一眼看到"这里调了一个通用 bash"；
  - 范围变更和越界记录。

### 4. 第一阶段的页面

| 页面 | 内容 |
|---|---|
| 秘书聊天 | 多媒体会话，带各种卡片 |
| 待我处理 | 所有要你注意的事；三档紧急度；可标已读、归档、删除；越界通知、计划变更、"错过的提醒"都在这里 |
| 任务看板 | 按"等我 → 进行中 → 运营中 → 最近结束 → 已归档"分组；每张卡上有活动状态小圆点 |
| 任务详情 | 维护者会话、阶段抽屉、工单列表、计划卡、工具包 |
| 项目列表 | 项目状态、活动状态小圆点、进行中任务数 |
| 简版项目页 | 状态、"和维护者交流"、工单流水线（每张工单是哪个任务派的还是你派的）、工具包、范围记录 |
| 消耗页 | 全局 token 消耗 |
| 设置 | 关注类别、已配对设备 |
| 配对 | 新设备的配对等待页；批准页（设备名、短指纹） |

**第二阶段**：记忆 Web UI、全景、完整的项目管理界面（含背后服务的在线情况）。

### 5. 技术栈

- React 19 + Vite + TypeScript，手写 CSS，不用组件库和状态管理库。
- AgentSense 的 `web/src` 复制过来，之后各自演进；视觉 token 沿用它的 `look.css`。
- UI 由守护进程提供：PC 上走本机端口，其他设备经 VPS HTTPS 域名到外网端口。

### 6. 原型

- 本票原定先做可点击原型再定稿。框架大轮里信息架构已经逐项定下，原型改到实现阶段：复制 AgentSense `web/src` 之后的第一个 UI 切片，就是一个用假数据、可点击的页面骨架，供你评审。
- 评审后的修改按普通需求变更处理，不回头阻塞规格。
