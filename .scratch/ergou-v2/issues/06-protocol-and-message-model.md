## Question

1. **前端协议**：守护进程用什么协议对外服务各个前端？可参考 OpenClaw Gateway 的做法：WebSocket 上分请求帧和事件帧，带幂等键，用 schema 生成各端的数据模型。
2. **消息数据模型**：一条消息由信封加若干 part 组成。part 的种类包括：
   - 文本、图片、文件；
   - 语音及其转写、TTS 音频；
   - 视频（先预留）；
   - 计划、审批、进度、提问四种卡片。
3. **媒体的存储与传输**：是否用内容寻址？是否支持 Range 请求和断点续传？
4. **远程访问认证**：设备怎样配对？
5. **HTTPS**：麦克风要求安全上下文。

第 2 轮前查到的事实（OpenClaw 仓库 `openclaw/openclaw@eb1b48c`，2026-10-06）：
- **OpenClaw 的配对流程**：
  - 新浏览器先过网关共享 token，然后显示一个配对请求编号（没有配对码）；
  - 批准方式：在网关主机上执行 `openclaw devices approve <编号>`，或在已授权浏览器的 Devices 页点批准；
  - 待批请求 5 分钟过期。
- **OpenClaw 的密钥**：
  - 设备密钥是 Ed25519，用纯 JS 库签名，**私钥明文存在 localStorage**，页面一旦被注入脚本就能读走；
  - 每次连接都对服务器下发的随机数签名；
  - 令牌是 32 字节随机串，服务端明文存在 SQLite。
- **OpenClaw 的本机判定**：来源是本机地址，并且没有 Forwarded、X-Forwarded-*、X-Real-IP 这几类头，才算本机。即使是本机，自动批准前也还要先过共享 token。
- **成熟度**：
  - 设备鉴权和配对在 2026-01-19 统一，约 8.5 个月；
  - 2026-01-26 出过公开事故：反向代理让外网流量看起来来自 127.0.0.1，900 多个实例因此暴露；
  - 仓库 722 条安全公告里，和配对、本机判定、可信代理相关的约 45 条，最近一条在 6 月。直接相关的：
    - GHSA-844j-xrrq-wgh4：伪造 X-Forwarded-For 冒充本机；
    - GHSA-chr9-m4q2-76hw：伪造本机身份换到长期管理员令牌；
    - GHSA-rggc-m335-3wvj：同机进程伪造代理身份头。
- **对二狗的含义**：经 VPS 隧道进来的连接，在 PC 上看也是 127.0.0.1。所以"本机自动信任"不能按来源 IP 判断。
- **外壳和浏览器**：
  - 安卓 WebView 的 `setDomStorageEnabled`、鸿蒙 ArkWeb 的 `domStorageAccess` 默认都是关的；
  - WebCrypto 的 Ed25519 要 Chrome 137 起才有，鸿蒙 6.x 的 ArkWeb 内核是 M132，大概率不支持。
- **nginx 的坑**：某一级只要写了任何一条 `proxy_set_header`，就不再继承上一级的设置，WebSocket 的 location 最容易漏掉转发头。

## Answer

2026-10-07 定稿。

### 1. 传输

- **每个前端只开一条 WebSocket**，上行动作和下行事件都走它。帧分三种：请求、响应、事件。
- **按频道订阅**：秘书会话、正在看的维护者会话、任务看板、待我处理、活动状态。
- **幂等**：有副作用的请求都带幂等键，重发不会做两次。
- **HTTP 负责两类东西**：
  - 历史分页；
  - 媒体：按内容哈希（sha256）存在数据目录，支持 Range 请求，上传可以分片续传。
- SSE 不做主通道。
- **协议 schema 用 TypeBox 定义**（pi 也用它），由它生成守护进程、Web 和外壳各端的类型，放在共享协议包里。

### 2. 消息模型

- **一条消息 = 信封 + 若干 part**。part 的形状对齐 AI SDK 的 UIMessage parts，但类型自己定义，不依赖 `ai` 包。
  - 基本 part：文本、图片、文件、语音（附转写）、TTS 音频、视频（先预留）。
  - 二狗自有的 part 用自定义类型，比如卡片引用。
- **存储和发给模型是两回事**：
  - 界面视图照原样存；
  - 发给模型之前，用带版本号的转换函数投影：语音换成转写文字，卡片换成一行摘要；
  - 投影规则固定，提示词前缀才稳定，缓存不被打穿。

### 3. 卡片

- **卡片是独立实体**，有 id、类型、状态和版本；消息里只放对它的引用。
- **同一张卡可以同时出现在多处**：聊天、待我处理、任务时间线。状态只存一份，在哪里处理都同步。
- **按钮闭环**：前端发上行动作 → 服务端按条件更新（先到先得）→ 回 ack → 推送卡片更新事件。后到的按钮请求得到"已被处理"。
- **卡片类型注册表**：每种卡登记类型、schema、版本，以及一个纯文本降级版本。不认识这种卡的前端，显示文字加一个"去 Web 处理"的链接。
- **第一阶段的卡片和事项**（来自各票的结论）：
  - 计划确认卡（计划和授权一次确认，可逐行勾掉或收窄、附意见打回）；
  - 审批卡（先问我）、提问卡（意图澄清的成批问题，每题带推荐、可一键全按推荐）、进度卡；
  - 快速动作卡（含"已执行"状态）、"建议发起任务"卡、"建议立项"卡、简单提醒；
  - 立项书卡（"确认并开工" / "只确认，稍后开工"）；
  - 工单卡（任务时间线里）；
  - 计划变更卡（扩大授权、加项目、改目标或验收时进待我处理）；
  - 待我处理事项卡：包括"错过的提醒"、"中断：不确定 X 是否已执行"、越界通知（不推送）、备份失败等。
- **待我处理事项带紧急度字段**，分三档：卡住任务且有时限、卡住任务、不卡任务。推送与否由推送票按这个字段决定。

### 4. 多前端同步与断线重连

- **事件日志是唯一真相**。每个频道有单调递增的序号；前端重连时带上最后收到的序号，服务端补发缺失的事件。
- **历史从日志重建**。前端乐观显示的尾巴，收到权威事件后被替换。
- **流式输出**：中间增量只推送、不落盘，只存最终的 part（AgentSense 在这里踩过坑）。
- **已读、已处理是服务端状态**，所有前端同步。
- **活动状态**（休眠、干活中、等你、排队）作为独立频道的事件推送。

### 5. 远程访问与身份确认

- **访问路径**：PC 本机走 localhost；其他设备一律走 VPS 上的 HTTPS 域名，在家也一样（见「部署、数据目录与备份」）。
- **两个监听端口**：
  - **本机端口**：只监听 127.0.0.1，给 PC 上的浏览器用，自动信任。校验 Origin 和 Host，防 DNS 重绑定和跨站 WebSocket。
  - **外网端口**：隧道只连这个端口。它永远不享受本机信任，每个请求都要带有效的设备凭证。
  - 本机信任只看"从哪个端口进来"，不看来源 IP。
- **配对流程**：
  1. 新设备打开二狗，页面显示一个配对请求：设备名、短码和短指纹。
  2. 在已信任的设备上或 PC 本机页面上批准。批准页显示同样的设备名和短指纹，供你核对。
  3. 批准后，服务端发一个 HttpOnly、Secure、SameSite=Strict 的 cookie：256 位随机值，服务端只存哈希，长期有效。
  4. 在"设置 → 已配对设备"里可以随时吊销。
- **待批请求 5 分钟过期，并限制请求频率。**
- **网页脚本里不放私钥，也不放令牌。** 不照搬 OpenClaw 把私钥存在 localStorage 的做法：它在防脚本注入上并不比 HttpOnly cookie 强。
- **高危审批的签名**（需要你在手机上亲手确认、防伪造的审批）留给「推送与远程审批通道」，用安卓 Keystore / 鸿蒙 HUKS 的原生密钥做。
- **外壳要求**：安卓 WebView 和鸿蒙 ArkWeb 都要打开网页存储，并保证 cookie 持久化。
- **nginx 要求**：每个 location（包括 WebSocket 的）都用覆盖写的方式设置 `X-Forwarded-For` 和 `X-Real-IP`，加 HSTS。VPS 上的隧道端口只绑本机地址。

### 6. 留给规格（默认做法）

- 帧字段、频道命名、卡片字段、幂等键格式；
- 上传分片协议（tus 或自定义）与大小上限；图片 EXIF 剥离；派生物（缩略图、转码）的生成规则；
- 进度事件节流；反应、编辑、撤回、"正在输入"；
- 设备 cookie 的有效期与轮换；配对短码长度；限流数值；本机端口的 Origin 白名单；
- 被素材引用的媒体不回收。
