## Notes

- **领域**：单用户个人助理 agent。框架将来可分享给他人；个人数据永不进仓库。全程中文交流。
- **每个 grilling 票**都调用 `/grilling` 和 `/domain-modeling`：术语即时写进 `CONTEXT.md`；难以逆转、出人意料且有真实取舍的决定写 ADR 到 `docs/adr/`。
- **先查调研**：`docs/research/`（索引见 `README.md`，01–12 已完成）。开新调研前先看是否已有答案。
- **参考项目**：
  - AgentSense（`D:\code\claudecode\user_agent_sense_of_security`）：UI 视觉语言、长程任务、少打扰的继承来源。
  - intent-mining（`D:\code\claudecode\intent-mining`，skill 在 `~/.claude/skills/intent-mining`）：动机挖掘方法。
- **已定的大方向**（立项 grilling 第一至第三轮，2026-10-06/07）：
  - 本地图只产出规格，不写实现代码。
  - 部署：单用户；常驻 Node 守护进程跑在用户的 Windows PC 上；外网访问走 ssh 反向隧道 → VPS nginx → HTTPS。
  - 底座：基于 pi 从零搭建，OpenClaw 只作设计参考。用 `pi-coding-agent` 的 SDK，外面包一层二狗自己的薄封装，并锁定版本（ADR-0001）。
  - 进程：每个 agent（含秘书）一个子进程，有活时常驻、闲了退出；守护进程只当管家，自己不跑模型（ADR-0002）。
  - 不设角色：维护者的能力按项目或任务配一个工具包（skill、外部工具、bash 和联网开关）（ADR-0003）。
  - 前端：先做 Web UI。再把同一套 Web 套成鸿蒙单框架 App（以及 Android App），用来拿到系统级推送。将来可能接 Telegram。不用飞书。
  - 场景：所有日常事务。将来可能操作电脑或手机。
  - 秘书：信息权限最高，可读全部记忆、知晓全部任务；行动权限最低，只有只读工具和派遣。有副作用的操作，要么是用户确认后由运行时执行的快速动作，要么成为任务。
  - 工作形态有三种：对话、任务、项目（「任务生命周期与任务看板」定稿后的用法）。
    - 任务由用户明确发起，按长程方式执行；执行任务的 agent 只看到与该任务相关的信息。
    - 项目是原子的、可运营的功能模块，有自己的项目档案和工作目录，只能访问被授权的那部分记忆。v1 不做系统级沙箱，靠路径白名单和 AgentSense 式 hook 守卫。
  - 意图澄清 = 带状态、带记忆的 grill-with-docs，目标是大幅减少提问次数。
  - 实现顺序：秘书、派遣、项目这副骨架先行；长程任务和少打扰随骨架一起继承过来；记忆从第一天起就积累素材。
  - 模型：先全部用 DeepSeek V4.1 Flash（`deepseek-flash`）。不设预算上限，但要能看到消耗。以后可能换用 Pro，或者让 pi 指挥 Claude Code。
  - 多媒体：v1 双向支持文本、图片、文档、语音；视频只预留接口。
    - 语音转文字用本地 faster-whisper 服务。
    - 文字转语音用 audio.cpp，音色可配置。
  - 运维：
    - 二狗的所有服务都在 Local Service Manager 注册并由它启动，二狗不自行启动任何服务。
    - 个人数据放在仓库外的数据目录，可以用数据库，定期备份到华为家庭存储。
  - 二狗 v1（套用 OpenClaw 的版本）已丢失，无数据需要迁移。
- **阶段划分**（用户 2026-10-07）：每张未解决的票都有 `Phase:` 行。**选票时只从 `Phase: 1` 的票里挑**，`Phase: 2` 的票暂缓。

## Decisions so far

<!-- 每个已关闭的票一行：[票名](issues/NN-slug.md) — 一句话结论 -->

- [pi 1.0 各层能力映射](issues/01-pi-layer-mapping.md) — 三层能力已摸清；用户排除实验性的 pi-durable，底座在 agent-core `Agent`（全自建）与 coding-agent SDK 之间选，移交运行时架构；deepseek-flash 上分段改 system prompt 会打穿缓存；只记 token 用量，不做按时段计价
- [多 agent 架构与 token 成本](issues/02-multi-agent-and-token-cost.md) — 每个任务/项目绑定一个常驻维护者，默认串行；可并行时由维护者提议、用户确认才派多个 agent；用户可绕过秘书直接查看维护者会话并给它下指令
- [记忆边界：秘书、任务与记忆管理者之间的接口](issues/03-memory-boundary.md) — 记忆管理者是唯一写者；秘书读用户卡（每天最多刷新一次）+ 每轮自动简报（追加在尾部）+ 深查；短期记忆按时效衰减（半衰期 1 个月，自动检索 3 个月），长期记忆只被取代；动机假设只给秘书看，任务在计划授权的记忆范围内取用；秘书一条主线会话，要记住的都落到固定归宿，承诺即任务；简单提醒无 agent，定时作业有维护者；记忆 Web UI 是独立子模块
- [任务生命周期与任务看板](issues/05-task-lifecycle-and-board.md) — 对话 / 任务 / 项目三分：任务由用户明确发起、按长程方式执行，看板只放任务、简单提醒、定时作业，项目单独管理；只有项目维护者能改项目；完成自动、归档只能手动；全局 3 个任务并发；快速动作不配 agent；"待我处理" tab 汇集一切要用户注意的事、未读亮小红点，秘书不主动转述；token 从 pi 用量逐次记账
- [项目生命周期、工作空间与维护者](issues/14-project-lifecycle-and-maintainer.md) — 项目状态：筹备中 → 建设中 → 运营中 / 已完成，运营中 ⇄ 已停用，归档只能手动；服务在不在线归服务层，不算项目状态；立项两步：秘书收口，维护者做立项问答、交立项书；项目档案固定在数据目录；维护者的理解靠项目档案、按工单分段；维护者的所有工作都是工单，由派单器送进队列，一次只做一件，项目页能看工单流水线；agent 间只有工单通信；跨项目改动随计划一次授权；定时调度做在守护进程里；v1 不做沙箱；agent 活动状态四种，拟人化全景放第二阶段
- [Windows 原生沙箱能力调研](issues/22-windows-native-sandbox.md) — 原生可行，最贴合的是每项目一个 AppContainer，但 MXC 要每次开机管理员重置、和 LSM 规则冲突；不管做不做沙箱，都要在守护进程里加路径围栏、把子进程放进不允许脱离的 Job 对象；v1 不做沙箱
- [角色模型：角色卡、领域边界与经验沉淀](issues/13-role-model.md) — 取消角色（ADR-0003），维护者按项目或任务配工具包，维护者提议、用户确认，skill 自主增减、加能力走计划变更；"只做本领域"改为范围审视（压缩时和工单结束时，越界记录、写进提示、不推送地通知）；经验按项目存档案，按需用推理图谱沉淀
- [关注类别与打扰策略](issues/04-watch-categories-and-interruption.md) — 类别是给工具调用分的类，按工具标签、参数、拆开的 bash 确定性判断，自定义也只写规则；六档处置加两条底线；授权项照搬 AgentSense 并加有效期和记忆范围；常用 bash 操作封装成工具，通用 bash 照常检查并在要点层和全局层标出
- [长程任务机制泛化](issues/12-long-task-generalization.md) — 统一一种计划；搬 planguard 引擎核心并配真实工具规则模板，策略挂阶段或阶段组、守卫持续检查；验收分脚本（钩子跑）、评审子 agent、用户三种；阈值照搬，预算按 token 加调用次数；计划和授权由运行时保管、压缩后重新注入
- [意图澄清与规划交互](issues/15-clarification-and-planning-flow.md) — 秘书同一轮结构化分成五种形态；不设提问上限，少问是长期探索目标；秘书写任务书、执行的维护者起草计划；一张卡确认计划、工具包和授权；扩大授权才走计划变更，只停受影响阶段
- [消息协议与多前端](issues/06-protocol-and-message-model.md) — 每前端一条 WebSocket 按频道订阅，事件日志为唯一真相、按序号补发；消息形状对齐 AI SDK parts；卡片是独立实体；双端口（隧道只连外网端口）；配对后发 HttpOnly cookie，高危签名移交推送票
- [运行时架构](issues/11-runtime-architecture.md) — 每个 agent 一个子进程（ADR-0002），守护进程只当管家、集中做守卫判定；首个 spike 验证 pi RPC 模式；被杀后混合恢复；二狗自有 skill 库按项目或任务授权；pi 装工作区固定的最新稳定版；TypeScript + React 19 + Vite，npm workspaces
- [部署、数据目录与备份](issues/10-deployment-data-backup.md) — 数据目录 `C:\Users\catmaniii\.ergou\`；LSM 只登记守护进程和隧道，agent 子进程放进 Job 对象；所有设备走公网域名，PC 走本机端口；每晚快照复制到华为家庭存储同步目录，不加密，密钥不进备份；登录前停机、登录后补发
- [Web UI 信息架构](issues/17-web-ui-information-architecture.md) — 竖屏底部 5 个 tab，宽屏变左侧竖栏；不设角色管理，工具包在项目页和任务详情里管；秘书和维护者共用一个会话组件；可点击原型放到实现阶段的第一个 UI 切片

## Not yet specified

- **不可信内容与提示注入防护**：邮件、网页、文档进入上下文时如何隔离和标记。运行时架构和关注类别定下来之后再细化。

- **操作电脑或手机**：computer use 和手机 GUI agent 将来以什么方式接入。
- **内置 skill 库**（第二阶段）：框架自带哪些 skill，覆盖哪些日常场景；从「起步角色目录」转来（角色已取消）。
- **二狗自举**：二狗用自己的项目机制开发和维护自己的代码。等多 agent 架构和沙箱定下来再看。
- **更多前端**：Telegram 等。
- **项目沙箱**：v1 不做，只靠路径白名单和 hook 守卫（「项目生命周期、工作空间与维护者」）。将来要加固时，以「Windows 原生沙箱能力调研」为参考再开票。
- **模型路由与预算**：什么时候、给哪些维护者或子 agent 换更强的模型；拿到真实消耗数据后，定什么样的预算策略。
