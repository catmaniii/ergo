# 19 — 定时作业与错过补发

Status: done
Blocked by: 16（工单与派单：单项目任务）
Spec: [第一阶段规格](../spec.md) 第 13 节（调度）、第 8 节（任务、计划与阶段）、第 11 节（项目与维护者）、第 12 节（工单与派单）、第 17 节（被杀后的恢复）、第 21 节（实现细节补充）

## What to build

任务看板上出现定时作业：按时间表反复执行、每次都要 agent 真正干活。定时作业通过任务建：用户发起一个任务（比如"每天早上出一份简报"），维护者起草的计划里带上定时作业定义（时间表、每次要做的事、属于哪个项目；时间表可选每天、每周几、每月几号加上时刻，29 号票完成后还能选"按我的工作日"）；用户确认计划后，作业登记生效，出现在看板的"运营中"分组。属于项目的作业，就是对那个项目发起的任务；秘书没有直接建定时作业的工具。到点时，属于项目的作业作为一张工单交给该项目的维护者，不属于项目的交给作业自己的维护者；每次运行占一个全局并发名额，名额满时排队；每次运行都在作业上留一条运行记录。某次运行失败，作业卡标"最近一次失败"；连续失败 3 次自动暂停，并在待我处理里放一条"定时作业被自动暂停"的事项。用户可以在任务看板上把作业暂停、恢复。简版项目页列出这个项目有哪些定时作业、各自什么状态。项目停用时，它的定时作业全部暂停，重新启用时恢复；作业的登记、暂停、取消都不改变项目状态。

守护进程每次启动时补上停机期间错过的触发：简单提醒晚了 60 分钟以内照发，并标明晚了多久；更晚的不再发通知，改放一条"错过的提醒"进待我处理；重复的简单提醒错过了好几次，只按最近一次处理；定时作业不管错过几次只补跑一次；错过的内部作业（比如当晚的备份）开机后补做一次。调度器还有一个每周的内部作业：把结束（已完成、失败、已取消）超过 7 天、还没归档的任务汇总成一条归档清单放进待我处理，每项可选归档、继续改、先留着。

演示：faux provider 剧本走一遍"发起'每天早上出简报'的任务 → 计划卡上带着作业的时间表 → 确认"，看板运营中分组出现作业卡；用可注入的时钟拨到触发点，项目页的工单流水线出现一张来自定时作业的工单、作业卡多一条运行记录，项目页的定时作业列表里能看到这个作业和它的状态；停掉守护进程，把时钟拨过一个提醒和几次作业触发点再启动，看提醒标着晚了多久照发、作业只补跑一次。

## Acceptance criteria

- [x] 主切面（faux provider）：计划里带定时作业定义的任务，用户确认计划后作业登记，任务看板频道推送一张在"运营中"分组、状态为运营中的作业卡；作业记着时间表（每天、每周几、每月几号，加上时刻；"按我的工作日"在 29 号票完成后可选）、每次要做的事和所属项目（可为空）。秘书的工具里没有建定时作业的工具。
- [x] 主切面（可注入时钟）：属于项目的作业到点后，派单器给该项目维护者开一张来源为"定时作业"的工单，维护者被唤起执行；不属于项目的作业到点后，由作业自己的维护者执行。两种情况都在作业上留一条运行记录（触发时间、结局），看板频道推送作业卡的更新。每次运行占一个全局并发名额：已有 3 个（默认）在执行中时，到点的运行排队，名额空出后才开始。
- [x] 主切面：一次运行失败时记一条失败的运行记录，作业卡标"最近一次失败"；连续失败 3 次后作业自动转为已暂停，待我处理出现"定时作业被自动暂停"事项；已暂停的作业到点不再触发；中间有一次成功则连续失败重新计数。
- [x] 主切面：用户在任务看板上能把定时作业在运营中和已暂停之间切换，状态变化是事件，同时打开的多个前端都看到更新。
- [x] 主切面：项目转为已停用时，它运营中的作业全部转为已暂停；重新启用（回到使用中）后，因停用而暂停的作业恢复为运营中，停用前就已暂停的保持已暂停。给项目登记、暂停、取消作业都不改变项目状态。简版项目页列出该项目的全部定时作业及各自状态（运营中 / 已暂停、"最近一次失败"），随作业的状态事件实时更新。
- [x] 主切面（停掉守护进程、拨动时钟后再启动）：晚了 60 分钟以内的简单提醒照发，通知里标明晚了多久；晚了超过 60 分钟的不发通知，改为待我处理里的"错过的提醒"事项；同一个重复提醒错过多次，只按最近一次照发或放一条事项；停机期间错过多次的定时作业只补跑一次；错过的内部作业（测试里用当晚的备份）启动后补做一次。
- [x] 主切面：补发是幂等的——补发完成后再重启一次，不会再补发同一个提醒，也不会再补跑同一个作业或内部作业。
- [x] 主切面（可注入时钟）：每周的归档清单把结束（已完成、失败、已取消）超过 7 天、还没归档的任务汇总成一条待我处理事项。选"归档"后任务变为已归档、移到看板的已归档分组；选"继续改"时，已完成的任务走 13 号票的返工、失败的任务走重试，任务回到执行中；已取消的任务在状态机里回不到执行中，清单上只给"归档"和"先留着"；选"先留着"任务不变。"继续改"照常产生 13 号票对应的素材事件（返工为"要求返工"，由 08 号票采集）。
- [x] 前端状态层回放：用主切面录下的事件流回放，看板运营中分组里作业卡的状态（运营中 / 已暂停、"最近一次失败"标记）、项目页的定时作业列表和待我处理里的"定时作业被自动暂停""错过的提醒""归档清单"三种事项都能正确显示。
- [x] 所有测试通过（vitest），lint（oxlint）无报错。

## Comments

- 2026-10-08（实现，19 号票的 agent）：规格没写清、又必须定的地方，按最保守、最贴近规格的做法定了（ADR-0017 记了一次运行的形态那部分）：
  - **作业自己的维护者**：不属于项目的作业每个一个维护者 `jm-N`（`j-N` 的），会话频道 `maintainer:jm-N`，接着同一个 pi 会话，工作目录是建它的任务的产出目录 `outputs/<任务>`。不复用建它的任务的维护者。一次运行是一条带作业身份（`scheduledJobId`）的通知。
  - **属于项目的作业**：一次运行是一张工单，来源"定时作业"、种类 `run`（"定时作业"），**没有所属任务**（`taskId` 空着，带 `scheduledJobId`、`runId`）。工单的派发、排队、开段、写回检查、已归档退回全照 16 号票。运行的段里没有 `ask_clarification`（做不了就报失败），工具包取建它的计划里的那一份和项目的交集，加 `fail_job_run`。项目的任务里的作业都属于这个项目（计划里没写就补上，写了别的项目的被拒）；不属于项目的任务里的作业不能写属于哪个项目。
  - **结局**：这一轮正常结束算成功；维护者用 `fail_job_run` 报了原因、或者这一轮出错、被中止、被打断算失败。属于项目的在工单结束时结束（完成是成功，退回、做不了是失败）。没有"验收"。
  - **授权**：一次运行没有任务和计划的授权项，守卫按聊天的处置判。
  - **名额**：每次运行从开始到结束占一个全局执行名额（和执行中的任务共用 `tasks.maxRunning`）；属于项目的从派单起就占着，哪怕还在项目的队列里等。同一个作业上一次还没跑完（排着或在跑）的，这一次跳过，只把下一次往后算（事件 `rescheduled`）。
  - **暂停、恢复、取消**：看板上的 `scheduled_job_action`（带幂等键）。恢复后下一次从现在往后算，连续失败清零（"最近一次失败"的标记留到下一次运行有了结局）；项目已停用或已归档时恢复被拒。取消时排着的运行丢掉（不算失败次数），正在跑的照常做完；取消的不上看板。已暂停的作业排着的运行照常做（到点时已经进队列了）。看板上取消要再确认一次。
  - **项目**：停用时运营中的作业暂停（`project_retired`），重新启用时只恢复这些；**归档不暂停作业**（规格只说停用），运行的工单派出时就退回，记失败；删除项目时它的作业取消。作业的任何变化都不改项目状态。
  - **自动暂停的事项**：`scheduled_job_auto_paused` 通知，动作"恢复""保持暂停"，不卡任务（`non_blocking`）。点"恢复"和看板上恢复一样（项目停用时恢复不了，事项照样算处理了、日志里记一笔）。
  - **错过的触发**：启动时在 23 号票的恢复之后补；停机时正在跑的那次记为失败（"被打断了"），不重做、不补跑；过了点的运营中作业只补跑一次（运行记录写明是开机补跑、错过了几次）。补发的幂等靠"下一次的时间和这次补跑同一事务落盘"。提醒和内部作业的补发沿用 06、11 的实现，没改。
  - **一个任务只登记一回**：14 号票的计划变更、自行调整出的新一版计划沿用原来的定时作业（`mergeDraft`），不再登记（评审中发现重启后会按新一版计划重复登记，已修、有用例）。
  - **归档清单**：做成一张卡片（卡片类型 `archive_list`，版本 1，不卡任务），每项单独选（动作 `decide`），每项都选了卡片算处理完；没用协议里预留的 `archive_list` 通知类型（通知只能整条选一个动作）。新一周的清单出来时上一张没处理完的过期。"继续改"：已完成的返工最后一个阶段（照常产生"要求返工"的素材事件）、失败的重试；已取消的和转为项目结束的只给"归档""先留着"。任务的变化 `archived`（已完成、失败、已取消 → 已归档）由清单上的"归档"产生。
  - **阈值**：晚了多少分钟照发（60）、连续失败几次自动暂停（3）、结束超过几天进清单（7）照 14 号票的规矩放进配置 `schedule`，默认值只在 `scheduled-jobs/thresholds.ts`。
  - **LSM 忙闲**：正在运行的作业也算忙（等空闲再停会等它做完）。秘书的"查看板"加了定时作业一行。
