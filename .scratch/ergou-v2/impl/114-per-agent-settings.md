# 114 — 每个 agent 的会话里一个 ⚙：单独的提示词、清空当前对话、上下文用量和"现在压缩"

Status: ready-for-agent
Blocked by: 无
Spec: [第一阶段规格](../spec.md) 第 19 节（Web UI）、系统提示一节（71 号票：通用模板在设置·系统提示里）；16 号票（重置维护者、会话分段）、22 / 24 号票（秘书的压缩、按上下文用量压缩）、83 号票（换模型新开会话附交接摘要）

## What to build

用户 2026-10-13 原话："每一个 agent 的聊天窗口需要有一个设置按钮，点进去之后可以单独设置它的系统提示词，也就是说你在系统的设置里面设的是一个通用的系统提示词模板，但是每个单独的 agent 还可以单独设置提示词以及清空当前的对话。"用户随后定了两处（见下）。

**哪些会话有**：秘书会话、任务整页（负责它的维护者）、项目整页（项目维护者）。标题栏加一个 ⚙（各套风格的标题栏照现有按钮的样子），点开一个面板（宽屏侧栏或弹层、手机底部弹层，照仓库现有的做法挑）。子 agent、评审没有自己的会话窗口，不做。

### 1. 这个 agent 单独的提示词（用户定：默认追加，也能整份替换）

- **追加**（默认）：在通用模板（设置·系统提示里这个角色的那份）后面追加一段这个 agent 自己的话。通用模板以后改了，这个 agent 跟着变，追加的照旧接在后面。
- **整份自己写**：从通用模板复制一份来改；占位符照设置页的规矩检查（`packages/protocol/src/system-prompts.ts`，设置页共用的那套）；可以"恢复用通用模板"。通用模板之后再改，整份替换的不跟着变（面板上写明"这个 agent 用的是自己的一整份，通用模板改了不影响它"）。
- 存在守护进程（数据目录配置区，照 71 号票用户改的提示词的放法，按 agent 分；不进仓库）；改完从这个 agent 的**下一轮**起生效（照改名时秘书 `refresh()` 的做法：手头这一条处理完再按新提示重新拉起，接着同一个会话）。
- 任务的维护者：任务结束（归档）后面板只读；项目维护者重置后照旧用这个项目的设置（设置跟着项目走，不跟着某一段会话）。
- 面板上能看到"现在实际用的系统提示"（模板 + 追加，或整份）的全文，只读。

### 2. 清空当前对话

- 新开一段会话：模型不再带着之前的聊天内容。旧的不删——界面上收进"更早的对话"（一条分隔线"以下是新对话 · 10-13 14:02 清空"，往上翻照样能看），素材、记录、时间线都留着。
- **不能把正在做的事忘掉**：任务的计划、当前阶段、进展，项目的项目档案，照常作为固定上下文给到新会话（现有的上下文块 / 固定上下文机制）；秘书新会话照常有看板感知。
- 项目维护者的"清空"就是现有的"重置维护者"（16 号票：新开一段、只凭项目档案重建理解），并到 ⚙ 里，原来项目档案栏里的入口可以留着或改成指向 ⚙（挑一处，别两套）。
- 先确认一下再清（"清空后它不记得之前聊过什么，记录照样能看"）；agent 正在处理一条时，等这一条处理完再清（或者提示"等它说完"）。

### 3. 上下文用量和"现在压缩"（用户定：要）

- 面板上显示：上下文现在用了多少 / 这个模型的窗口多大（比如"8.2 万 / 12.8 万 token"，加一条进度条）、上次压缩是什么时候、离自动压缩还有多少（pi 的规矩：用量超过窗口减 16384 时自动压缩，最近约 2 万 token 原样保留）。数从子进程每次模型调用报的 `usage` 来（现有的账本 / `AgentUsage`，别另数一套）；agent 没在跑时显示上一次的。
- "现在压缩"按钮：经宿主协议现有的 `compact` 命令手动压缩（秘书照旧用它专用的压缩说明，维护者照旧在压缩时做范围审视、压缩后重注入固定上下文）；agent 没在跑时先拉起再压；正在处理一条时等这一条处理完。压缩那次的用量照常记账（用途"压缩"）。
- 会话里压缩过的地方，时间线上有一条小记录"这里压缩过一次"（如果现在还没有的话）。

## Acceptance criteria

- [ ] 秘书、任务、项目三种会话都有 ⚙ 和面板；追加 / 整份替换 / 恢复通用模板都能用，占位符检查和设置页一致，下一轮生效；有测试（守护进程主切面：存、读回、拼出实际提示、下一轮按新的；协议 / Web 状态层：两种模式、占位符检查）。
- [ ] 清空对话：新开一段会话、旧的收进"更早的对话"不删、固定上下文照常给到；项目的重置并到这里；有主切面测试（清空后模型看到的上下文里没有旧聊天、有计划 / 项目档案）。
- [ ] 上下文用量和"现在压缩"：数对得上 `usage`、按钮真的压缩（契约测试里 faux 的 `compact` 那套）；有测试。

- [ ] 规格（系统提示一节、Web UI）、`docs/dev.md` 跟着改；动了守护进程和协议：全量测试一次，typecheck、oxlint 通过。
