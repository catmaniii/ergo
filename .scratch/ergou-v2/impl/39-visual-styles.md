## What to build

用户 2026-10-09 看了 Fable 画的四套视觉方案（暖纸手帐、净白格栅、夜航仪表、软糖圆角），说全都要，现有的风格也保留，在设置里选。之后还会再来 4–5 套（另行设计、另开票）。

本票搭风格的底座，并做第一套新风格"净白格栅"打通全程。另外三套各开一票（40–42），在本票之后并行做。

设计稿在 `docs/design/styles/`，本票用 `b-*.dc.html`，说明见那里的 README。设计稿只画了聊天、任务看板、待我处理、宽屏这几个画面；其余页面（项目、日历、消耗、记忆、设置……）按同一套 token 和规则推出来。

## Acceptance criteria

- [x] **设置**：设置 · 外观里，在"浅色 / 深色 / 跟随系统"之外加"风格"。
  - 列出各套风格，每套显示名字和一个小预览（色块、字样之类）；选了立即生效。
  - （用户 2026-10-09 加）每个风格选项带浅色、深色两张预览图：用这套风格自己的 token 和规则生成（不是手画的，风格改了预览自动跟着变），固定一小段场景（一条对方气泡、一条自己的气泡、一张带按钮的小卡片、一排导航图标），浅深并排；以后加风格的票零额外工作。预览显示这套风格的字体，但不为此下整套字体，只下预览里那几个字的切片。紧凑到 11 套风格在手机上也放得下。测试保证每套风格都有浅深两张预览，新加的风格自动纳入。
  - 按设备记住（照 34 号票的 `app/device-storage.ts`）。打开页面时直接按记住的风格画，不闪。记住的风格已经不存在时，按"经典"。
  - 每套风格都有浅色、深色两种，和"浅色 / 深色 / 跟随系统"正交。
- [x] **风格就是换皮**：
  - 每套风格由两部分组成：一组 token（颜色、字体、字号阶、圆角、阴影、间距密度、边框），加上必要的、限定在这套风格下的规则（比如 `[data-style="grid"] …`）。
  - 每套风格放在自己的文件里。新加一套风格只加文件、在风格清单里登记一行，不改页面组件。
  - 页面结构和功能不因风格而变：设计稿里出现了产品没有的信息或控件，不加，写进 Comments。为了好下样式，可以给现有元素补 class 或 data 属性。
- [x] **经典**：现有风格整理成"经典"。只是 token 化，浅色、深色下看起来都和现在一样。
- [x] **净白格栅**：
  - 按设计稿还原四个画面：聊天（文字气泡、语音气泡、审批卡、输入栏）、任务看板、待我处理、宽屏（左侧竖栏 + 聊天 + 右侧面板）。
  - 浅色、深色都要。其余页面按同一套推。
- [x] **字体**：
  - 风格要用的字体由二狗自己提供：打包进来，由守护进程提供文件，按 unicode-range 切片，只下页面用到的那部分。
  - 只在选了这套风格时才加载。
  - 运行时不请求外部 CDN：手机经 tailnet 访问时也要能用，也不把使用情况透露给第三方。
  - 外网端口上的字体文件和页面一样，要设备凭证才能取。
  - 字体的许可证要允许这样分发（OFL 等），写进 Comments。
  - 字体还没下好时用系统字体顶着，不出现空白文字。
- [x] **对比度**：正文 4.5:1，大字 3:1，浅色深色都要达到。要有测试，比如风格清单里每一套在浅色、深色下正文与底色的对比度表格测试；以后加风格自动纳入。
- [x] **状态层测试**：风格的选择、记住、找不到时退回经典，前端状态层都有表格测试。
- [x] 所有测试通过（vitest），lint（oxlint）无报错。
