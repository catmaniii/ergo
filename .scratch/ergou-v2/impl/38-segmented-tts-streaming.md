# 38 — 语音回复分段合成、边合成边推送、前端无缝播放

Status: ready-for-agent
Blocked by: 32（agent 用语音回复）, 36（语音气泡自动播放、文字同框）
Spec: [第一阶段规格](../spec.md) 第 22 节（语音消息）

## What to build

用户真机实测：一段 309 字的口语总结合成出 56 秒的语音，用了 51 秒，要等它整段合成完才听得到。用户要求（2026-10-08）：长的语音分段合成，由系统无缝拼接、边合成边推送。

audio.cpp 的原生流式输出只对标了 streaming 的模型可用（比如 VoxCPM2），我们用的 Fish-Audio S2 Pro 不在其列，所以由守护进程分段：把送进 TTS 的稿子按句子切成若干段，依次合成，每合成好一段就推给前端；前端把各段在时间上首尾相接地排好播放，听起来是连着的一段。全部合成完后拼成一条完整的音频存进语音对象，之后重播、下载都用这一条。合成大约比实时快一点（1 秒语音约 0.85 秒），所以第一段出来以后，后面的段一般赶在前一段播完之前就好。

## Acceptance criteria

- [ ] 主切面：送进 TTS 的稿子按句切段（句号、问号、叹号、分号、换行等），太短的并到相邻句、太长的再按逗号切，第一段尽量短以缩短第一声的等待；依次合成，每段合成好就经频道推一次 agent 语音的更新（这一段的音频、时长、在整段里的位置）。全部完成后拼成一条完整音频（同样的采样率和格式，段间留一个自然的短停顿），语音对象记完整音频、总时长，状态"完成"；中间段的音频不留成没人引用的孤儿文件，彻底删除时连同处理（沿用 21、32 号票的口径）。测试里 TTS 用假的（按段返回）。
- [ ] 合成到一半失败或超时：已经推出去的段照常可以播；语音对象记"只合成了一部分"，会话里一条说明，回复的文字照常显示出来（短回复原本只出语音的，这时把文字补出来）。服务忙（503）时同样处理。合成到一半守护进程被杀，重启后按 32 号票的做法重做整条。
- [ ] 前端：第一段到了就出现 agent 的语音气泡（时长随已到的段增长、标"合成中"），开着自动播放时（36 号票）立刻开始播，后面的段到了接着排，段与段之间不出现明显的空白或爆音（用 Web Audio 按时间排程，或同等效果的做法）；全部完成后气泡显示总时长，点一下重播用完整音频。用户中途点暂停、点别的语音时停掉整条。前端状态层用主切面录下的事件流回放（含"合成到一半失败"的流程）。
- [ ] 计时记录：语音对象记"第一段出来用了多久"和"整条合成用了多久"，本机接口取得到，方便真机上看。
- [ ] 所有测试通过（vitest），lint（oxlint）无报错。

## Notes

- 合成和语音对象在 `packages/daemon/src/voice/`（`speech.ts`、`voice-reply.ts`、`agent-voice-views.ts`、`wav.ts`）；前端的 agent 语音气泡和自动播放在 36 号票之后的版本里。
- 段的大小影响音色连贯和等待：句子太碎，段间语气容易不连；第一段太长，等待又变长。按句切、首段短，是平衡点，具体数字写进 Comments。
- 真机冒烟：用户发一条语音、让秘书回一段长的，记录第一声的等待和整条耗时，写进 Comments。
