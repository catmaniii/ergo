# 83 — 换模型时新开会话，附一份交接摘要

Status: done
Blocked by: 73（设置里的"模型"页）
Spec: [第一阶段规格](../spec.md) Implementation Decisions"模型"一条："一个会话固定一个模型；换模型就新开会话，附一份交接摘要"

## What to build

73 号票做了按角色选模型，但"一个会话固定一个模型"，接着原会话时照它开始时记下的模型。秘书只有一条长期主线会话，所以**改了秘书的模型永远不生效**；维护者的长会话（项目维护者、定时作业的维护者）也一样。

照规格补上"换模型就新开会话，附一份交接摘要"：

- 某个角色的模型或思考档位在设置里改了以后，这个角色的下一轮（秘书：用户的下一条消息；维护者：下一次唤起）发现会话记下的模型和设置不一致，就**新开一个 pi 会话**：
  - 先用旧会话的模型写一份交接摘要（这段会话在做什么、用户的要求和偏好、做到哪了、还没做完的），参照 pi 的压缩摘要和二狗已有的段摘要做法；
  - 新会话的第一条输入就是这份摘要，之后照常；
  - 聊天界面里记一条系统说明"已换成 X 模型，接着之前的对话"，用户看到的会话是连着的（同一个会话频道），只是模型侧的上下文换了。
- 任务的维护者在执行中途不换：照规格"一个会话固定一个模型"，任务执行完或下一次新开段时才用新模型；设置页上说明这一点。
- 交接摘要失败（模型出错）时：不换，照旧用旧模型，记一条说明，下一轮再试。

## Acceptance criteria

- [x] 改了秘书的模型，用户下一条消息时新开会话、带交接摘要，之后用新模型；主切面测试（假模型）。
- [x] 项目维护者、定时作业的维护者同样；任务执行中途不换。
- [x] 交接摘要失败时不换，下一轮再试；有测试。
- [x] 所有测试通过（vitest），lint（oxlint）无报错。

## Comments

- **实现**（2026-10-10，worktree-agent-a254156d597c6bd0f，从 main `626ebda1` 开工）：
  - **什么时候换**：`AgentSession` 加了 `modelSwitch { instructions(), allowed(input), wanted() }`，三处配：秘书（用户的消息才换，运行时给它的通知不触发）、项目维护者（对话段里才换；第一段对话段接着以前的长会话、重启后接着这一段都算）、定时作业自己的维护者（一次运行的开头，也就是这次运行的通知之前）。任务的维护者不配（一个任务一个会话，执行中途不换）；项目维护者的工单段（起草计划、执行任务、作业的一次运行）做到一半不换，下一段本来就是新会话。时机：休眠的唤起时就带上 `handoff` 拉起；活着的，在下一条能换的输入之前，子进程就绪时报了 `differs`（接着的会话开始时的模型和装配参数不一样）或者设置在它拉起之后改了（`wanted()` 和拉起时的目录模型不一样），先停掉再带上 `handoff` 拉起。
  - **比对在子进程里做**：模型不一样，或者思考档位按装配参数的模型支持的档换算（pi 的 `clampThinkingLevel`，pi 新开会话时也这样换算后记下）之后不一样，才算不一样——不然 v4-pro 的"低"会被记成"高"，每轮都换。看图能力改了不触发换（票面只说模型和思考档位）。
  - **交接摘要怎么写**：照 pi 的压缩摘要——子进程用原来的会话的模型和思考档位调 pi 导出的 `generateSummaryWithUsage`（同一份结构化摘要提示、同一个把对话转成文字的写法；会话压缩过的，上次的摘要作为 previous summary、用 pi 的"更新摘要"提示），二狗的写法接在后面（"Additional focus"，和秘书的压缩指令同一种接法）。写法在 `packages/daemon/prompts/handoff-summary.md`（设置 · 系统提示里能改），内容照段摘要的要求：在做什么、用户的要求和偏好（照录原话）、做到哪了、还没做完的和下一步；秘书的长期主线另有几句（`{{#秘书}}`：任务只留编号和一句话、看板不用写，同秘书的压缩指令）。写成了就新开一个会话（先建空文件交给 pi 打开，pi 写好会话头、之后每条马上落盘：换过去的那一刻新会话就在盘上），第一条是这份摘要（`HANDOFF_SUMMARY_TYPE` 的自定义消息，开头一句"【交接摘要】这个对话换了模型……"），之后照常。写摘要那次的用量记一笔，用途是新加的"交接摘要"（`purpose: "handoff"`，原来的模型）。
  - **聊天里**：换成了，同一个会话频道里记一条系统说明"已换成 DeepSeek V4 Pro 模型（思考：高），接着之前的对话。"，再把这条输入交给新会话；项目维护者的新会话名字经 `onReady` 记进这一段。
  - **失败**：交接摘要没写成（模型出错、超时，超时按单次模型调用的超时），不换，照旧接着原来的会话、用原来的模型，记一条"没能换成 X 模型：写交接摘要时出错（原因）。这一轮照旧用 Y 模型，下一轮再试。"（原因去掉 key 的内容）；同一条输入只试一次，下一条能换的输入再试。秘书写摘要那段时间 `/healthz` 不算"不在运行"。
  - **彻底删除**：交接摘要是从原来的会话写的，改写会话文件时跨文件看——原来的会话（连同它再往前换过来的，一层层往后推）里有要改的条目，新会话开头的交接摘要整段换成删除说明，覆盖了它的压缩摘要也换掉。
