## What to build

用户 2026-10-11 评审 60 号票时定的：60 先合并，这些接着做。照 AgentSense 做，和它不一样的地方先问用户。

- **执行中也能"从这里重做"**：AgentSense 只要阶段开始过就能重开，执行中也行；二狗现在只对做完的任务能返工。照 AgentSense：维护者正在做就先停掉这一轮（暂停用的那个办法），这一阶段和依赖它的后续阶段回到未开始、交付件和验收结果清掉，原会话末尾追加一条重开记录，旧记录在界面上标已废弃，再让维护者接着做。会话**不分支**（"撤回到这里"那种会话树退回在 85 号票）。"谁能改"表跟着加行。
- **重做对话框列"这几步已经做了的事"**：从效果记录（`guard/effect-log`）按阶段取出这一段成功做了的事，分"本机""对外"两类列出来，同时告诉维护者；**不真撤回**（真撤回在 85 号票），说明里写清楚收不回。
- **阶段详情补上几块（数据基本已有）**：
  - 授权"已用几次"：守卫已经在算（`guard/grants.ts` 的 `usesOf`），传到界面。
  - 按授权分的"问 / 权 / 外"计数："问"计划里已有；"权""外"按授权项是否对外分。"敏"要加字段，在 85 号票。
  - 出过的状况里的"撤回"一类：用返工 / 重开记录；不写 AgentSense 的"本机改动已恢复"。
  - 尝试记录的备注：维护者宣布完成时写的那句存到每次提交上；你验收时写的说明（逐条结果的备注、退回原因）也挂上。
  - 选这种执行方式的理由、初步思路：阶段计划加两个可选字段，系统提示让维护者起草时填。
  - 规则点进详情：复用 60 号票的检测项全览，点开单条规则。
- **顺手修**：手机竖屏把阶段抽屉全开时，输入框被底部导航压住（55 号票抽屉固定 82% 高度）。

## Acceptance criteria

- [ ] 执行中的长程任务能从某个阶段重做：维护者这一轮被停掉，阶段和下游回到未开始，会话里有重开记录，维护者接着做；主切面测试。
- [ ] 重做对话框列出这一段做过的事（本机、对外分开），不撤回；有测试。
- [ ] 阶段详情显示授权已用几次、问 / 权 / 外计数、"撤回"状况、尝试记录的备注（维护者的、你的）、执行方式理由和初步思路、规则详情；有测试。
- [ ] 竖屏抽屉全开时输入框不被压住；截图 390、1280，两种风格。
- [ ] 协议新字段都是可选的，旧记录照常能读；事件日志不改写。
- [ ] 和 AgentSense 不一致的地方先回报，由主会话问用户。
- [ ] 所有测试通过（vitest），lint（oxlint）无报错。
