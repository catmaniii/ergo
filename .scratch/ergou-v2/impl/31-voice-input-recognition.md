# 31 — 语音输入与识别

Status: ready-for-agent
Blocked by: 04（秘书聊天最薄端到端）, 08（素材采集与索引）, 09（多媒体消息）
Spec: [第一阶段规格](../spec.md) 第 22 节（语音消息）、第 5 节（前端协议）、第 15 节（素材）、第 21 节（语音识别的默认运行方式）

## What to build

用户能像微信那样发语音：输入栏右侧的按钮切到语音模式，整个输入框变成"按住 说话"（左边的加号不变）；按住时弹出录音面板，实时显示音量和滚动的最近一小段波形；抬手发送，按住时上划松开就取消。语音在本地录好、抬手后整段上传，上传完成后服务器先用 faster-whisper 识别、再让大模型保守修正，两份文字和音频绑成同一个语音对象保存。聊天里语音显示成带时长的气泡，点一下播放，长按（桌面右键）弹出菜单，能"转文字"、"复制文字"。agent 收到的是修正后的文字，识别完成前这条输入在 agent 的输入队列里等着。

界面参考 vibecraft 的语音输入（只读参考：`D:\code\claudecode\vibecraft\web\src\components\CommandInput.vue`、`web\src\composables\useVoiceInput.ts`、`web\public\pcm-worklet.js`，以及 `docs\voice-input-runbook.md`）。只参考界面：vibecraft 是边说边在服务器识别、客户端实时显示文字，二狗不这样做。

## Acceptance criteria

- [ ] 前端状态层和组件：语音模式切换（加号不变）；按住开始录音、录音面板显示实时音量和滚动波形；抬手发送；按住上划超过阈值显示"松开取消"、抬手不发送；不到 1 秒提示"说话时间太短"不发送；到 60 秒自动发送，最后 10 秒倒计时；没有麦克风权限时给出提示。触屏（pointer 事件）和鼠标都能用。
- [ ] 录音在本地完成，抬手后经 09 号票的可续传上传整段上传（浏览器 MediaRecorder 能录什么格式就收什么格式，比如 webm/opus、mp4/aac），上传完成后发出一条带语音 part 的消息；录音过程中不往服务器发任何音频。
- [ ] 主切面：语音上传后，服务器建出一个语音对象，绑定音频（内容哈希）、时长、格式、波形摘要、faster-whisper 的识别原文（含分段和模型名）、大模型修正后的文本（含模型名）和识别状态；前端经频道收到识别状态的变化。识别引擎和修正模型在测试里用假的（不加载真模型、不联网）。
- [ ] 主切面：agent 收到的是修正后的文字（注明"语音转写"），识别完成前这条输入在输入队列里等着、不先拉起一轮；识别失败时 agent 收到"[语音，识别失败]"，用户可以在气泡菜单里重新识别，成功后按正常流程交给 agent。
- [ ] 主切面：大模型修正只改同音字、错别字、标点和明显口误；修正的提示词把最近几轮对话作为参考；修正失败时文字取识别原文，状态里注明没修正。
- [ ] 识别进程：守护进程按需拉起 Python 识别进程（放进 Job 对象，环境照 agent 子进程的白名单），闲置超过配置的时间自动退出；Python 路径、设备（显卡 / CPU）、模型、计算精度、闲置时间都在配置里，默认值照第 21 节（显卡上 large-v3、int8_float16，闲置 5 分钟退出；显卡不可用或显存不够时退回 CPU small，并在识别结果里记下用的是哪个）；识别进程不可用（没装、加载失败）时，识别状态为失败并在待我处理里放一条说明，守护进程照常运行。
- [ ] 语音气泡：宽度随时长变，显示时长；点一下播放或暂停，同一时间只播一条；长按（桌面右键）弹出菜单，有"转文字"（气泡下方展开修正后的文本，可收起）、"复制文字"，以及消息通用的菜单项；识别中显示"识别中"。前端状态层用主切面录下的事件流回放。
- [ ] 素材：用户的语音算用户发言（本人），素材文字取修正后的文本，信封标"语音转写"；原文副本里同时存识别原文、修正文本和音频的引用。彻底删除这条语音时，音频、两份文字和原文副本一起删（沿用 21 号票的改写口径）。
- [ ] 手动冒烟（经 LSM 起的守护进程、真模型）：在本机浏览器录一段中文语音，记录上传到出文字的耗时，文字准确；结果写进票的 Comments。
- [ ] 所有测试通过（vitest），lint（oxlint）无报错。

- 外网（经 HTTPS 的手机）和本机 `http://127.0.0.1` 都是安全上下文，浏览器允许取麦克风。
