## What to build

用户能像微信那样发语音：输入栏右侧的按钮切到语音模式，整个输入框变成"按住 说话"（左边的加号不变）；按住时弹出录音面板，实时显示音量和滚动的最近一小段波形；抬手发送，按住时上划松开就取消。语音在本地录好、抬手后整段上传，上传完成后服务器用 faster-whisper 识别，识别出的文字和音频绑成同一个对象保存。聊天里语音显示成带时长的气泡，点一下播放，识别出的文字默认直接显示在气泡下方，长按（桌面右键）弹出菜单，能"复制文字"。agent 收到的是"语音转写：<识别出的文字>"，识别完成前这条输入在 agent 的输入队列里等着。（2026-10-08 用户改：去掉大模型修正，识别文字默认直接显示、就算确认，语音转写和打的字一样参与快速动作的点明判定。）

界面参考 vibecraft 的语音输入（只读参考：`D:\code\claudecode\vibecraft\web\src\components\CommandInput.vue`、`web\src\composables\useVoiceInput.ts`、`web\public\pcm-worklet.js`，以及 `docs\voice-input-runbook.md`）。只参考界面：vibecraft 是边说边在服务器识别、客户端实时显示文字，二狗不这样做。

- [x] 前端状态层和组件：语音模式切换（加号不变）；按住开始录音、录音面板显示实时音量和滚动波形；抬手发送；按住上划超过阈值显示"松开取消"、抬手不发送；不到 1 秒提示"说话时间太短"不发送；到 60 秒自动发送，最后 10 秒倒计时；没有麦克风权限时给出提示。触屏（pointer 事件）和鼠标都能用。

- [x] 主切面：语音上传后，服务器建出这条语音的数据对象，绑定音频（内容哈希）、时长、格式、波形摘要、faster-whisper 识别出的文字（含分段、语言和模型名）和识别状态；前端经频道收到识别状态的变化。识别引擎在测试里用假的（不加载真模型、不联网）。（2026-10-08 用户改：不再有大模型修正后的文本）

- [x] 语音气泡：宽度随时长变，显示时长；点一下播放或暂停，同一时间只播一条；用户发的语音，识别出的文字默认直接显示在气泡下方（识别中显示"识别中"，失败显示"识别失败"）；长按（桌面右键）弹出菜单，有"复制文字"，失败的有"重新识别"；气泡组件留好 agent 发的语音（32 号票）的用法：长按"转文字"展开 TTS 原文、再点收起。前端状态层用主切面录下的事件流回放。（2026-10-08 用户改：不再需要"转文字 / 收起文字"）

- [x] 素材：用户的语音算用户发言（本人），素材文字取识别出的文字，信封标"语音转写"；原文副本里同时存识别文字和音频的引用。彻底删除这条语音时，音频、文字和原文副本一起删（沿用 21 号票的改写口径）；设置里按会话、按时间段彻底删除时，没识别出文字（没有素材）的语音也连同消息和音频一起删。

规格没写清、按最保守做法定下的：

- **语音 part 的形状**：`{ type: "voice", voiceId, mediaId, mime, durationMs, waveform }`。04 号票预留的 `transcript` 去掉了：文字要等识别完成，消息事件又不能改，所以文字只在 `VoiceRecord` 里（会话频道上的 `voice` 事件）。前端发送时不带 `voiceId`（服务端填上，前端带了也不算）。时长和波形由前端量（服务端核对范围：不短于 1 秒、不长于 60 秒加 2 秒余量、最多 64 格）；格式按内容认（不认的拒收），识别进程量出的时长另记在 `recognition.audioSeconds`。一条语音消息只有这一段语音，可以带引用的卡片，不能和文字、附件一起发（2026-10-10 改：可以带附件，仍不能和文字、别的语音一起发）。
- **发给模型前的投影就地改了第 1 版**：语音 part 以前只预留、从没有消息带着它交给过模型（`postUserMessage` 一直拒收），所以没有另起第 2 版（理由写进了 dev.md）；写法"语音转写：<识别出的文字>"（不带方括号），识别失败的"[语音，识别失败]"。
- **识别状态**四个：排队、识别中、完成、失败。没识别出内容（静音被过滤掉）算失败。只有失败的能重新识别；重新识别成功、而那条输入已经作为"[语音，识别失败]"交给过 agent 的，另追加一条交给 agent 的系统通知（带识别出的文字）——不能把同一条消息再排一次队。
- **识别完成前不越过它**：队首是没识别完的语音时，后面的输入也等着（保持先后），也不为它唤起 agent；插话同样不越过它。
- **识别进程**：放进它自己的 Job（不放 agent 管家那个，原因同 28 号票）；拉起后先交给它设置（`init`），它读到之前什么都不做，所以不需要 28 号票那样的闸门进程。环境照白名单，另加 `HF_HUB_OFFLINE=1`（只从本机缓存加载模型，不在缓存里就是"加载失败"，不自动下载）、UTF-8。识别参数：`beam_size=5`、`vad_filter=True`（短语音的静音最容易让 Whisper 编出"谢谢观看"）、`condition_on_previous_text=False`、语言 `zh`、提示"以下是普通话的句子。"（都在配置里）。显存不够的判断不另查，靠加载或识别时的报错退回 CPU。
- **待我处理的说明**：识别进程不可用时放一条 `voice_recognizer_unavailable`，开着的只有一条；之后识别成功就收进归档。
- **素材**：识别完成那一刻产生一条"用户发言"（时间是说话的时间），信封的情境标签是 `voice_transcript`。识别失败的不产生素材。
- **彻底删除**：给 `PurgeRewriter` 加了可选的 `related`（改写这条事件时要连带改写的事件），记忆模块的 `purgePlan` 顺着它找，另收调用方给的 `extraTargets`（没有素材的语音）；语音的改写函数连带它的消息、别的 `voice` 事件和重新识别后的那条通知。识别完成时消息已经被删了的，识别结果不再写进去。设置里批量彻底删除只有没素材的语音时，记下的记忆命令是"彻底删除：…… 里的 0 条素材"（素材条数照实写）。
- **历史分页**多了可选的 `voices`（这一页的语音消息引用的 `VoiceRecord`）：第一次订阅只补发最近一页，更早的语音的 `voice` 事件不在里面。
- **下载**：认得的音频按它的类型 `inline` 发（`<audio>` 直接播放），别的照旧一律作为附件。
- **Web**：上划取消的距离 60 像素；面板上滚动的波形是最近约 4 秒（40 格，每 0.1 秒一格）；波形摘要最多 32 格；排队和识别中在气泡下方都显示"识别中…"（用户不必知道排队）。界面我没能在真浏览器里点过（本机这次没有可用的浏览器自动化），手势的规矩由 `voice-gesture.test.ts` 覆盖，页面靠用户评审和下面的冒烟。原型（`file://`）里秘书主线有一条假的语音消息，发语音由假连接推一遍假的识别。
- **宿主协议没变**：这张票没改守护进程和 agent 子进程之间的协议（语音在交给子进程之前已经投影成文字），所以 `HOST_PROTOCOL_VERSION` 保持 main 上的值。
- 之前在本机用 `tiny`、CPU 跑过一次 `recognizer.py`（一段 ffmpeg 生成的 2 秒正弦波，`HF_HUB_OFFLINE=1`）：脚本能加载真的 faster-whisper 1.2.1、协议的行对得上，静音被 VAD 过滤后文字为空（守护进程记成"没有识别出说话的内容"）。没跑 large-v3、没占显卡。

1. 数据目录的 `config/ergou.json` 里写 `voice.recognizer.python`（装了 faster-whisper 的 Python 的绝对路径；不写就用 LSM 环境里 PATH 上的 `python`）。确认 large-v3、small 在 Hugging Face 缓存里（识别进程不联网下载）。其余（`device`、`model`、`computeType`、`fallback`、`idleMinutes`、`timeout`）不写就是默认值。
2. `npm run build:web`，在 LSM 里重启 `ergou-daemon`。
3. 浏览器开 `http://127.0.0.1:8810/`，秘书页输入栏右边点 🎤 切到语音模式：这时不该要麦克风、浏览器的麦克风指示灯不亮。按住"按住 说话"（第一次这时才弹权限请求；拒绝时看提示），面板先显示"准备中"再开始计时，说一段 10–15 秒的中文：音量和波形在动；松开后指示灯熄灭。上划看"松开取消"、松开不发；点一下就松开看"说话时间太短"。
4. 记录：松开到气泡下方出现"识别中…"、到识别出的文字出现的时间；第一次（冷启动）和第二次各一条。`recognition.elapsedMs`、`model`/`device`（应是 large-v3 / cuda）可以在 `ergou.db` 的 `voices` 视图看。
5. 气泡下方的文字准确；长按（桌面右键）气泡 → "复制文字"能贴出来；点气泡能播放、再点暂停，播另一条时前一条停下。秘书的回复是按这段文字理解的。
6. 点明：有个执行中的任务时，用语音说"暂停任务 t-N"，应直接执行（聊天里是"已执行"卡，不进待我处理）；引用它的计划卡再说"把这个继续"也一样。
7. 语音模式下点加号选一张图：~~传好直接作为单独一条消息发出~~（2026-10-10 改：图等在输入框上方，按住说一段话，松开后图和语音作为一条消息发出；不说话就点"直接发送"）。
8. 等 5 分钟（闲置退出）后看识别进程已经退出、显存释放（任务管理器或 `nvidia-smi`）；再发一条，冷启动重新加载。
9. 手机经 HTTPS 外网地址重复第 3、5 步（触屏的按住、上划、长按）。
10. 结果写回这里。
