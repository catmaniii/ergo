## What to build

二狗的守护进程 `ergou-daemon` 从 04 号票起就在 Local Service Manager 里登记、由它启动（固定的 Node 22 LTS 绝对路径，指向主分支的构建产物）。本票在这个条目上补两件事：有任务在跑时经 LSM 的 link 协议心跳上报"忙"；条目开着 autoRestart，被 LSM 重启后按规则恢复。二狗自己不启动任何服务。

LSM 每次重启都会连带杀掉守护进程，Job 对象把所有子进程一起清掉。守护进程重新起来后，正在做的事按规则恢复，不乱、也不悄悄重做有副作用的操作：待审批的事项从审批表恢复，不重复通知；被打断的调用按工具注册表里的"只读或幂等"标记分两种——只读或幂等的告诉模型"这次调用被中断了"，由它决定要不要重做；有副作用、效果日志里又查不到成功记录的，任务里的让任务转为等我，原因写"中断：不确定 X 是否已执行"，秘书会话里的放一条同样写法的待我处理事项；输出到一半的回复丢掉中间片段，从会话文件里最后一个完整的回合续上；每个 agent 排着队的输入都在事件日志里，重启后按原顺序接着处理。

演示：主切面测试里，任务执行到一半时直接杀掉守护进程再起——一个正在等审批的调用重启后审批卡还在、没有多出一张；一个发到一半的"对外发送"调用让任务转为等我，看板上写着"中断：不确定 X 是否已执行"；秘书那条说到一半的回复不见了碎片，会话从上一个完整回合续上。

## Acceptance criteria

- [ ] 手动验证：在本机 LSM 里，`ergou-daemon` 条目开着 autoRestart；直接结束守护进程后由 LSM 拉起，`/healthz` 恢复健康，下面各条恢复规则在真实重启下照样成立；有任务执行中时，LSM 上能看到它报"忙"。
- [ ] 主切面（测试里用替身接收 LSM link 心跳）：有任务处于执行中时，心跳上报"忙"；没有任务在执行时不报"忙"。
- [ ] 主切面：直接杀掉守护进程后，所有 agent 子进程和孙进程随之结束（27 号票完成后，MCP 服务进程同样）；再起守护进程后没有遗留的旧进程。
- [ ] 主切面：子进程正在等审批时守护进程被杀——重启后审批卡从审批表恢复、仍是待处理，不新建卡，也不再推送"新审批"事件，任务处于等我；这次调用不算"说不清做没做完"。用户事后批准后，按调用指纹记一条一次性授权，运行时唤起维护者并附"……已获批准，可以重试"，重试的那次调用直接放行，且只放行一次。
- [ ] 主切面：被杀时正在执行、注册表里标了"只读或幂等"的工具调用，重启后运行时告诉模型"这次调用被中断了"，由模型决定是否重做；任务不转等我。
- [ ] 主切面：任务里被杀时正在执行、有副作用（注册表里没标"只读或幂等"）、效果日志里又查不到成功记录的调用，重启后任务转为等我，原因写"中断：不确定 X 是否已执行"（X 为规范化后的调用摘要），待我处理出现一条"中断不确定"事项，任务看板的任务卡上能看到这个原因；运行时不自动重做这次调用。
- [ ] 主切面：秘书会话里被杀时正在执行的有副作用调用（比如经用户批准、正在跑的草稿区外脚本），重启后待我处理出现一条"中断：不确定 X 是否已执行"事项（紧急度"不卡任务"），运行时不自动重做；秘书会话照常可用。
- [ ] 主切面：被杀时正在流式输出的回复，重启后历史分页和会话文件里都没有半截内容，会话从最后一个完整回合续上；被杀时已经排队、还没处理的输入按原顺序处理，不丢也不重复。
- [ ] pi 契约测试里加上对应用例：从末尾带半行、或带未完成工具调用的会话文件恢复会话，只保留完整回合，并能补上"被中断"的工具结果。
- [ ] 所有测试通过（vitest），lint（oxlint）无报错。

## Notes

- **不在本票**：`ergou-daemon` 条目的登记（固定 Node 22 LTS 绝对路径、指向主分支构建产物、`/healthz`、密钥由 LSM 经 `env.from: file` 注入）和开发期间经 LSM 演示，从 04 号票起就有；本票只补 link 协议的"忙"上报和 autoRestart 重启后的恢复。Job 对象本身归 01 号票；agent 管家的子进程上限、超时、孤儿回收归 12；ergou-tunnel 的 LSM 条目归 10；错过的定时触发和内部作业怎么补归 19（本票只保证重启后调度器照常起来）；审批表、审批卡、5 分钟等待和按调用指纹一次性放行的正常流程归 07，本票只验证它们在被杀重启后照样成立。
- "只读或幂等"标记的字段在 03 号票的工具注册表里就有；内置工具的标记在 03 填，带类型的特殊 bash 工具在 28 填，MCP 工具在 27 登记时填。注册表里没标的工具一律按有副作用处理。
- 自动测试里在临时目录起的守护进程实例是测试的一部分，用完即销毁，不算服务，不进 LSM。
- 重启后没人登录时二狗不在线，等用户登录后由 LSM 拉起再补；二狗不另做开机自启，也不自己拉起任何服务。
