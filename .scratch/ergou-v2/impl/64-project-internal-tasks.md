# 64 — 项目内部任务：项目维护者在自己项目里做流程或长程任务

Status: ready-for-agent
Blocked by: 58（流程：起草、审查、授权）, 59（流程执行）
Spec: [第一阶段规格](../spec.md) 第 8 节"两种任务"、第 11 节（项目与维护者）；ADR 0019

## What to build

用户 2026-10-09 定：除了秘书发起的普通任务，项目维护者也可以在自己项目里用两种任务做代码维护，比如升级依赖、重构、按固定步骤发版。

- 任务的种类照旧是流程或长程任务，由这个项目的维护者自己执行。
- 这类任务只在项目内部可见。

**发起**：规矩和秘书一样（用户定）。

- 用户在这个项目的维护者会话里点明了才发起，比如"按流程做……""发起长程任务……"、`/流程`、`/任务`。
- 维护者自己觉得该做维护时，只给一张建议卡，卡上两个按钮"作为流程""作为长程任务"，用户点了才发起。

**可见范围**（用户定）：

- 不上全局任务看板，只在项目页里列出；执行过程只在项目的维护者会话里看得到。
- 要用户确认或处理的东西照常进待办：计划卡、审批、卡住求助、验收。
- 秘书看不到它的细节。

## Acceptance criteria

- [ ] **种类和执行**：项目内部任务的种类是流程或长程任务，由该项目的维护者执行。计划、审查、计划卡、一次授权、执行时比对（流程）、阶段验收（长程任务）都和普通任务一样。
- [ ] **发起**：
  - 用户在项目维护者会话里点明时发起，点明的判断和秘书共用一份。
  - 维护者没被点明时，最多给一张建议卡，用户点了才发起。
  - 主切面覆盖：点明流程、点明长程任务、没点明只出建议卡、点建议卡。
- [ ] **可见范围**：
  - 内部任务不出现在全局看板上，项目页里有"内部任务"一栏，显示状态和进度。
  - 要用户处理的东西进待办，待办里标明"某项目内部"。
  - 秘书的只读工具（查看板等）看不到内部任务的细节。
  - 主切面断言这三处的可见性。
- [ ] **名额和用量**：执行时照常占全局执行名额（12 号票），token 用量记在这个项目和这个任务名下，消耗页能看到。
- [ ] **工单和多项目**：内部任务只动本项目，不派工单给别的项目；要动别的项目，告诉用户改成普通任务。
- [ ] **被杀后恢复、彻底删除、删除项目**：按现有规则处理。删除项目时，它的内部任务一起删掉。
- [ ] 所有测试通过（vitest），lint（oxlint）无报错。

## Notes

- 普通任务的流程在 58、59 号票。58 号票里"点明要用流程做某个项目的事时，告诉用户暂不支持"那一句，由本票改成按上面的规矩支持。
- 和项目维护者的工单段（16 号票）、范围审视（18 号票）怎么衔接，开工前读这两张票和 ADR 0012、0016，在 Comments 里写清楚。
