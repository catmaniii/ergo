# 25 — 时间线缩放与活动状态

Status: done
Blocked by: 07（秘书草稿区、守卫接入与审批）, 13（任务执行与阶段验收）
Spec: [第一阶段规格](../spec.md) 第 19 节（Web UI）、第 5 节（前端协议）、第 2 节（守护进程的模块）、第 9 节（守卫）、第 21 节（实现细节补充）

## What to build

秘书聊天和维护者会话共用的会话组件，可以从完整视图缩放到要点层和全局层。要点层只留关注类别命中、审批、偏离、验收这类要点；全局层把会话聚成色块：任务的维护者会话按阶段着色，项目维护者会话按工单段着色，秘书主线按天着色。两层都单独标出命中关注类别的操作、通用 bash 调用、范围变更和越界记录；授权内的、做完告诉我的、被拦下或问过的操作用三种不同的样式，扫一眼就知道发生了什么。

活动状态频道实时推送每个 agent 此刻在做什么：休眠、干活中（附带在做什么）、等你、排队。任务看板的任务卡和项目列表的每个项目上用小圆点显示对应维护者的活动状态。活动状态和任务状态、项目状态是三回事，互不影响。

演示：打开一个跑过几个阶段的任务详情，把会话组件拨到要点层，只剩审批、关注类别命中、通用 bash 和验收这些要点，样式各不相同；再拨到全局层，看到按阶段的色块；打开一个项目的维护者会话拨到全局层，看到按工单段的色块；切到秘书页拨到全局层，看到按天的色块。同时看任务看板，维护者被唤起、等审批、闲置退出时，任务卡上的小圆点跟着变。

## Acceptance criteria

- [x] 前端状态层回放（用主切面录下的事件流）：同一段会话投影到要点层时，只剩关注类别命中、审批、偏离、验收、通用 bash、范围变更和越界这些要点，其余条目收起；投影到全局层时，任务的维护者会话按阶段、项目维护者会话按工单段（16 号票的对话段也各成一块）、秘书主线按天聚成色块，色块上仍标出这些要点。
- [x] 前端状态层回放：工具调用的三种情形——授权内放行、做完告诉我、被拦下或问过——在要点层和全局层上得到三种不同的样式标记；每个通用 bash 调用在两层上都带"通用 bash"标记，带类型的特殊 bash 工具（28 号票）不带。
- [x] 主切面：消息里的工具调用 part 带齐第 5 节列出的字段——工具名、参数摘要、命中的关注类别、判定、是否授权内、是否通用 bash——取自守卫判定的结果；其中"是否授权内"由本票加进 part。
- [x] 前端状态层回放：范围变更和越界记录在要点层和全局层上被单独标出；若 18 号票尚未完成，用按共享协议 schema 构造的范围记录事件验证。
- [x] 主切面：活动状态频道在 agent 被唤起、开始干活、等用户（审批或澄清）、排队、闲置退出时各推送状态事件；"排队"包括同时存活的子进程满 8 个时新的唤起在等名额（12 号票）；"干活中"附带在做什么的简短说明，这类更新按进度事件的节流，每 100 毫秒最多一次。
- [x] 主切面：活动状态事件只出现在活动状态频道上，不引起任务状态或项目状态的迁移；任务或项目状态变化也不改写活动状态。
- [x] 界面：秘书页、任务详情和项目页的会话组件上有缩放控件，能在完整、要点层、全局层之间切换；任务看板的任务卡和项目列表的每个项目上有活动状态小圆点，随活动状态频道实时变化，断线重连后按序号补齐。
- [x] 前端状态层回放：快速动作的执行事件（21 号票的"操作记录"）在时间线上可见，要点层和全局层都标出。
- [x] 所有测试通过（vitest），lint（oxlint）无报错。

## Comments

- 2026-10-08 实现（25 号票子 agent；评审后按意见改过，下面写的是改后的样子）：
  - **"是否授权内"**：07 号票已经把守卫判定的 `withinGrant` 写进了工具调用 part，本票没有再加字段；主切面 `timeline.test.ts` 在一个真实执行的任务里逐条断言 part 的工具名、参数摘要、命中的关注类别、判定、是否授权内、是否通用 bash（含授权内的建目录、做完告诉我的提交、问过的读主目录、硬拒绝的写围栏外）。
  - **活动状态的口径**：agent 管家报子进程这一侧——排队；干活中（被唤起、处理一条输入，附带进度）；等你（这一轮里有调用停着等用户批准）；休眠（闲着：按需的说明是"空闲"，常驻的秘书闲着就是休眠；闲置退出的说明是"闲置退出"）。活动状态模块再把待处理的卡片合进来：管家报的是休眠、还有属于这个 agent 的待处理审批卡（挂起、这一轮结束以后）或提问卡时，就是"等你"，说明写原因（审批带工具名、澄清），处理掉以后回到休眠；由卡片视图和审批表推出，守护进程重启后照样对（`activity/card-waits.ts`，新的"等用户"的卡往 `CARD_WAITS` 加一行）。"转为等我"是任务状态，看板任务卡上另有显示，不算活动状态的等你。任务取消时它没处理的审批卡不会过期（13 号票原有的做法），这时维护者仍是等你，直到卡被处理；要改成取消时让卡过期，不在本票。
  - **"闲置退出"小圆点颜色不变、只改说明**（评审确认保留）：闲置退出推的是一条说明从"空闲"变成"闲置退出"的休眠事件；有待处理卡片在等的 agent 闲置退出时仍是等你，不多记。守护进程重启后（子进程都不在了）没有待处理卡片的一律是休眠、不带说明。
  - **在子进程里停着等用户**：现在只有审批。守卫接入经 `userWaits`（接口 `UserWaits`：`userWaitStarted` / `userWaitEnded`，管家实现）报开始和结束；16、17 号票的等澄清要是在子进程里等，照审批的样子报。
  - **说明是结构化的**：`ActivityDetail { kind, tool?, chars? }`，文字由协议包 `activityDetailText` 按表生成（照 `ACTIVITY_STATE_LABEL` 的做法），守护进程不写中文文案进事件，测试断言结构。落盘的 `activity` 事件只记状态和说明的变化（去重只在活动状态模块做一次，管家每次可能变了就报）；流式字数、正在调用哪个工具这种频繁的进度是临时事件 `activity_progress`，每个 agent 每 100 毫秒最多一条，不落盘、重连不补发，节流和流式增量共用 `util/throttle.ts`（钟可注入）。派生视图 `agent_activity` 加了一列说明（老库启动时 `ALTER TABLE` 补上，和任务视图补 `queued_seq` 一样），重启时据此判断要不要重记。
  - **消息归属只定义一份**：协议包 `schema.ts` 的 `MessageScope`（任务、项目、阶段、agent），消息事件、历史分页、时间线记录都摊开带着，取值用 `message-scope.ts` 的 `pickMessageScope`；守护进程的 `MessageScope` 就是它，Web 的条目和记录也用它。`agentId` 现在不写，留给 20 号票（一个会话里有子 agent 时写明是谁说的）。和 24 号票合并时，它给消息加的定时作业 `scheduledJobId` 也并进了这一份归属（守护进程会话视图里存的输入归属同样用 `pickMessageScope` 取），token 账本记阶段时的"当前阶段"也改成取 `taskMessageScope`（判断条件不变）。
  - **"当前阶段"只在一处算**：`tasks/stages.ts` 的 `taskMessageScope(task, stageId?)`，执行控制器的说明（说某个阶段的写那个阶段）、用户发给维护者的消息、维护者会话里的消息都用它。工具调用记录在守卫判定那一刻取一次会话的归属（`GuardedSession.messageScope` 是函数，记在这次调用的状态里），所以宣布阶段完成的那次调用仍算在原阶段；守卫接入不再自己算阶段。
  - **偏离、范围变更、越界的事件形状由本票定**（14、18 号票还没做）：会话频道上的 `timeline_record`（协议包 `timeline.ts`，带归属）。守护进程追加用 `conversation/messages.ts` 的 `buildTimelineRecord`（在 `buildMessage` 旁边，写进了 docs/dev.md），14、18 号票照它追加；加新的种类只往 `TIMELINE_RECORD_KIND_INFO` 加一行（中文名、要不要进要点层、严重度；界面按严重度取样式）。前端回放用按 schema 构造（先过 `schemaChecker`）的事件验证。
  - **往上翻带回时间线记录**（评审后补）：历史分页的 `HistoryPage` 多了 `records`：落在这一页里的 `timeline_record` 和 `quick_action_executed`（序号从这一页第一条消息起、小于 `before`，更早没有了的从头起）；工具调用记录本身是消息。前端并进来（按序号去重），要点层、全局层都看得到旧页里的偏离和操作记录，全局层按已加载的部分聚块。主切面 `history.test.ts` 录成 `timeline-history` 回放。录好的 `memory-purge`、`secretary-history` 两段里的历史分页按现在的守护进程补上了 `records`（前者是那时已有的那条操作记录，后者为空），没有重新录。
  - **三种样式和更细的说法都在状态层推**：要点带样式（授权内、做完告诉我、被拦下或问过）和说法（被拦下、问过、你点明的、你确认后），以及结果的文字，界面不再看 `blockedBy`、`disposition`；审批要点带审批卡，界面用 `outcomeLabel` 写批了没有。工具调用的优先级：被拦下或问过 > 做完告诉我 > 授权内（同时是做完告诉我和授权内的按"做完告诉我"）；"计划里列了才做"而在授权内的算授权内；直接做的通用 bash、命中类别但直接做的调用不带样式，只带"通用 bash"或类别的标记。要点层收进不命中类别但被硬拒绝的调用（评审确认保留）。
  - **21 号票转来的"操作记录在时间线上可见"**：操作记录在完整视图里按序号显示一行，每次执行都进要点层、标在全局层的色块上。`quick_action_executed` 加了 `basis`（用户点明的 / 在已有授权内 / 用户确认后，`QUICK_ACTION_BASES`），时间线按它取样式：点明的、确认后的算问过或用户决定的（"被拦下或问过"那一档，说法是"你点明的""你确认后"），授权内的算授权内；25 号票之前的记录没有这一项，推断出来的不带样式。操作记录跟着它的快速动作卡：彻底删除时卡片换成去掉原话的新版本，前端手里的操作记录一起换掉，不留原话。21 号票文件里那条验收标准由本票勾上，并在那边记了一行。
  - **项目维护者会话的色块**：16 号票还没做，按段聚块用共享协议里已有的工单分隔 part 构造的事件验证；第一条分隔线之前（15 号票的立项问答）算一个对话段。项目列表的小圆点接的是项目维护者的活动状态，没收到过的是休眠（默认值只在状态层 `agentActivity` 一处）。
  - **界面**：缩放用分段按钮切三层（AgentSense 是捏合连续缩放、四档吸附，这里只取它"要点层是色块加一句话、全局层是纯色块旁边标关键风险"的分层，没搬连续缩放）；秘书页、项目页顶栏的小圆点，点回完整视图跳到那一条，按需 agent 就绪后 2 秒内还算被唤起（`READY_HOLD_MS`），评审确认保留；页面靠用户评审。
