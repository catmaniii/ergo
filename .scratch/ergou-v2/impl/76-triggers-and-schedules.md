# 76 — 触发底座和定时触发：定时作业并进来，普通任务和流程都能定时

Status: done
Blocked by: 75
Spec: ADR 0025（任务分两个维度）、ADR 0017（定时作业的运行）；19 号票

## What to build

用户 2026-10-10 定：任务的第二个维度是**触发**：一次性、定时、事件（ADR 0025）。本票做触发底座和**定时触发**，事件触发留给 77 号票。

- **触发底座**：
  - 任务带一个触发方式：一次性、定时、事件；
  - 每次触发是一次**运行**；
  - 底座处理"上一次还没跑完"：**排队合并**，等这次结束再跑一次，期间来的触发合成一批交给它，不并行、不丢；
  - 时间到了也作为一种事件进底座，77 号票的事件来源接在同一个口子上。
- **组合**：普通任务、流程能定时；长程任务只能一次性；简单提醒照旧能定时，并统一用这套时间表。
- **反复运行接着用同一段上下文**（用户要求）：同一个任务的各次运行接着同一段会话，后面的运行知道前几次做了什么、结果如何；会话长了靠 pi 的压缩。属于项目的照旧是项目维护者的一张工单（项目维护者的会话本来就接着）。
- **流程定时**：计划卡授权一次，之后每次运行都按步骤核对（59 号票）。
- **定时作业并进来**：
  - 不再有单独的"定时作业"，它就是"定时触发的普通任务或流程"；
  - 长程任务的计划里去掉 `scheduledJobs`，维护者的起草说明一并改掉；
  - ADR 0017 的机制照旧复用：作业自己的维护者、运行记录、开始时才占名额、失败计数和连续失败自动暂停、暂停、恢复、取消、日历页、消耗页按任务记账；
  - 已有的定时作业迁移成定时触发的普通任务，保留维护者、会话、授权、运行记录。**迁移不改写事件日志**：用新事件或派生视图表达；要是做不到，停下回报，不要自己开第四个例外。
- **界面**：
  - 发起对话框加"什么时候做"：现在做一次、定时（时间表，含工作日历）；"只提醒我"也放进这个对话框（不用 agent，只发通知）。
  - 看板上定时的任务在"运营中"一组，卡上显示时间表、下一次、最近一次运行的结果，能暂停、恢复、取消。
  - 任务详情按运行分段，能看每一次运行。
