# 58 — 流程：起草步骤和条件、审查修补、一次授权，只有点明才发起

Status: ready-for-agent
Blocked by: None — can start immediately（决定已定：ADR 0019）
Spec: [第一阶段规格](../spec.md) 第 7 节"任务的发起"、第 8 节"两种任务"；ADR 0019；调研 `docs/research/15-agentsense-zoom-detail-task-modes.md` §4

## What to build

任务分成两种（ADR 0019）。本票做两件事：

1. **流程的前半段**：发起、起草、审查、授权。执行时的比对在 59 号票。
2. **只有用户点明了才发起**。

流程照搬 AgentSense 的固定计划：

- 维护者按任务书，把要做的事排成一串**步骤**。每一步是一次工具调用（工具和参数），连同这一步要满足的条件。
- 条件用二狗已有的时序规则写（ADR 0005），四种：之前必须做过、之前不能做过、当下必须满足、一律禁止。用户原话：每一步、连同每一步要满足的条件（时序逻辑），都要写出来。
- 计划先过审查修补（参照 AgentSense 的 `planguardReviewer`，审查可能插入步骤、改写步骤），再由用户在计划卡上一次授权。

## Acceptance criteria

- [ ] **任务的种类**：
  - 任务加"种类"：流程 / 长程任务。建卡时定下，不能换。
  - 原有任务一律算长程任务：数据补默认值，不迁移。
  - 看板和任务详情显示种类。
- [ ] **只有点明了才发起**：
  - 秘书加 `start_workflow` 发起流程；`create_task` 专管长程任务。
  - 只有用户点明了才调用：
    - 消息里说了"发起任务""长程任务""按流程做"之类；
    - 输入 `/流程`、`/任务`；
    - 在发起对话框里先选了种类。对话框照 AgentSense 的 `ScenarioPicker`：两个页签，副标题说清两种的区别。
  - 说"发起任务"没说种类的，按长程任务。
  - 没点明的一律按普通对话处理。秘书觉得该发起时，最多给一张"建议发起任务"卡，卡上两个按钮："作为流程""作为长程任务"。
  - 主切面用 faux provider 的剧本覆盖：点明流程、点明长程任务、没点明（只出建议卡）、点建议卡上的两个按钮。
- [ ] **流程的计划**：维护者起草的是步骤列表。
  - 每一步有 id、标题、工具、参数、前置步骤。
  - 计划的约束用时序规则写，格式与 AgentSense planguard 兼容。
  - 工具按二狗的工具粒度写：通用 bash、读、改文件、带类型的特殊 bash 工具等。
  - 计划有版本。
- [ ] **审查修补**：起草后由运行时审查，参照 AgentSense 的 planguard 审查。
  - 敏感步骤加标注。
  - 违反规则的，插入前置步骤或改写步骤。
  - 审查结果随计划给用户看。
  - 用 AgentSense 的 `scenarios/*.planguard.json` 场景搬一部分用例做测试。
- [ ] **计划卡**：
  - 列出步骤，以及每一步的条件（写成人话）。
  - 显示审查结果，以及审查插入、改写过的步骤。
  - 需要确认的事项逐条勾，最后一次授权。
  - 确认后进入执行。执行时的比对在 59 号票；本票先让执行能跑起来：按步骤让维护者做，`report_step` 自报进度。
- [ ] **主切面测试**：
  - 起草 → 审查 → 计划卡 → 确认 → 执行到完成；
  - 审查插入了步骤；
  - 用户拒绝计划。
- [ ] 所有测试通过（vitest），lint（oxlint）无报错。
