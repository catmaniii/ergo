# 14 — 偏离、阈值与计划变更

Status: ready-for-agent
Blocked by: 13（任务执行与阶段验收）
Spec: [第一阶段规格](../spec.md) 第 8 节（任务、计划与阶段）、第 9 节（守卫）、第 13 节（调度）、第 5 节（前端协议）、第 15 节（素材）

## What to build

做完后，任务跑偏时，二狗打扰用户的程度和偏离的代价成正比。阈值（默认值，可配置）：调用不在所属阶段的授权、被拉回 3 次还不行；无进展被催促 3 次还不行；阶段验收退回 2 次、第 3 次还不过；预算超出 2 倍——这几种都要用户拍板，任务转"等我"，原因写"卡住求助"（前三种）或"超预算"（预算）。预算按 token 加工具调用次数计算，超出 1 倍只让维护者说明进展。agent 还活着、但 20 分钟内没有成功的工具调用也没有阶段推进，算无进展，触发一次催促。

偏离按级升级：计划外但在授权范围内的，只在时间线记一笔摘要；超出授权的（计划对这个类别有授权，但这次超出了对象范围或次数），先问用户；出现计划没预料到的类别（计划里完全没涉及这个类别），先问用户并暂停这一支；同一任务累计被用户拒绝 5 次，整个任务转"已暂停"。"先问我"类别的操作不在此列：计划里列了也照样当场问，"授权内只记一笔"只对"计划里列了才做"那一档成立。

维护者要扩大授权、加能力、加项目、改目标或验收时，提交一张计划变更卡进待我处理，只有受影响的阶段停下来等，其余阶段照常推进；被拒后，维护者在现有授权内重排受影响的阶段，做不到就标"做不了"、任务转等我。拆阶段、调顺序这类不扩大授权的调整，维护者自己改，记进时间线。授权项默认有效期 7 天，到期前一天待我处理里出现续期事项，过期的授权项不再生效。演示：用可注入时钟和 faux provider 剧本分别触发"20 分钟无进展 → 催促""预算超 2 倍 → 任务转等我（超预算）""提交计划变更 → 只有受影响的阶段停下 → 用户拒绝 → 维护者在现有授权内重排"，看待我处理和任务详情的变化。

## Acceptance criteria

- [ ] 主切面：维护者用到不在当前阶段的授权时被拉回，满 3 次后再犯，这一支停下、任务转等我（原因"卡住求助"），待我处理出现卡住求助事项；阶段验收前 2 次退回只交回维护者，第 3 次仍不过时同样转等我（原因"卡住求助"）。
- [ ] 主切面（可注入时钟）：维护者活着但 20 分钟内没有成功的工具调用、也没有阶段推进时，运行时催促它一次（正在干活时以插话送达）；同一次停滞里催满 3 次仍无进展，任务转等我（原因"卡住求助"）；中间出现成功的工具调用或阶段推进，催促计数清零。
- [ ] 主切面：每个阶段按 token 加工具调用次数累计预算（token 取自子进程上报的用量）；超出 1 倍时运行时让维护者说明进展（一条消息进它的会话），任务状态不变；超出 2 倍时任务转等我（原因"超预算"），待我处理出现对应事项。pi 契约测试里要有"能拿到每次调用的用量"的用例（24 号票若还没加，在本票加上）。
- [ ] 守卫切面 + 主切面：计划外但在授权范围内的调用放行，只在时间线记一条摘要；落在"先问我"类别的调用即使在授权范围内也当场问（"交给我做""永不"照旧）；计划对这个类别有授权项、但这次超出了对象范围或次数的，判为超出授权，先问用户（审批卡）；命中的类别在计划里没有任何对应的授权项的，判为没预料到的类别，先问用户并暂停这一支；同一任务累计被用户拒绝 5 次（默认）时，整个任务转已暂停，看板写明原因。
- [ ] 主切面：维护者提交计划变更（扩大授权、加能力、加项目、改目标或验收）时，待我处理出现计划变更卡，卡上只列出相对当前计划新增或改动的部分；只有受影响的阶段停下等确认，其余阶段继续执行；用户确认后计划和授权项随之更新，受影响的阶段恢复。用户拒绝后，维护者在现有授权内重排受影响的阶段（重排记进时间线、不出卡）；做不到时把这些阶段标"做不了"，任务转等我。
- [ ] 主切面：拆阶段、调顺序这类不扩大授权的调整，维护者直接改计划、不出卡，时间线记一笔；想借这条路扩大授权（新增授权项、放宽对象范围或次数、加工具包能力）的调整被拒，提示改走计划变更；运行中的授权项只能收窄。
- [ ] 主切面（可注入时钟）：授权项默认有效期 7 天；到期前一天待我处理出现续期事项，用户续期后有效期延长；过期没续的授权项不再生效，相应操作执行到那一步时再问用户。
- [ ] 主切面：产生对应的素材事件——用户在计划变更卡和续期事项上的批准、拒绝（审批决定）。由 08 号票采集；若 08 尚未完成，至少事件类型和负载就绪。
- [ ] Web UI：待我处理里显示计划变更卡（只列变化部分）、续期事项、卡住求助和超预算事项；任务详情的时间线上能看到授权内偏离的摘要、催促、维护者自己调整或重排计划的记录；看板任务卡写明等我（卡住求助、超预算）或已暂停（累计被拒）的原因。前端状态层回放主切面录下的对应事件流，显示正确。
- [ ] 所有测试通过（vitest），lint（oxlint）无报错。

## Notes

- **不在本票**：
  - "拉回"和"验收退回"本身、等我的事项永不自动批准、"部分阶段等用户时任务仍是执行中，所有能推进的分支都在等用户才转等我"的规则、恢复执行时名额满回排队中，已由 13 号票做好；本票只加计数、阈值和升级。阈值触发时"任务转等我"按 13 号票的规则落地：并行时其他分支还能推进，就只停这一支。
  - 计划变更里"加能力"（开 bash、加 MCP、开联网）对应的工具包装配和页面归 27；维护者不在任务里时要加能力提交的"工具包变更"卡（计划变更的一种）也归 27；用户自己在页面上扩大能力不走计划变更。"加项目"确认后向新项目派工单走 17 号票的派单。本票只做计划变更卡和"只停受影响阶段"的机制。
  - token 账本和消耗页归 24；本票只用用量做预算计数，24 先完成时直接用它的记录。
  - 时间线上授权内 / 做完告诉我 / 被拦下或问过的样式归 25。
  - "先问我"一定当场问、默认处置表由 03 号票的判定函数实现，本票只在偏离分级里遵守它。
- 这些迁移由系统发起，在任务模块里按"谁能改"表校验：表里系统的"卡住或超预算时暂停"落实为阈值触发转等我（卡住求助、超预算），只有累计被拒 5 次才转已暂停。
- 授权项到期提醒是调度器的内部作业，用 06 号票的调度器和可注入时钟。
- "重新规划时只问新增的部分"（第 9 节授权项）落在计划变更卡只列变化部分上。
- 对应用户故事：54–60、62。
