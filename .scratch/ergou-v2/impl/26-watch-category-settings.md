# 26 — 关注类别设置与自定义类别

Status: ready-for-agent
Blocked by: 05（时序规则引擎与 v1 规则模板）, 12（任务发起与计划确认）
Spec: [第一阶段规格](../spec.md) 第 9 节（守卫）、第 8 节（任务、计划与阶段）、第 19 节（Web UI）、第 18 节（数据目录与备份）、第 21 节（实现细节补充）

## What to build

设置页（更多 → 设置）有一栏关注类别：列出全部内置类别和用户自定义的类别，每个类别有对话、任务两套处置。内置类别只能往严里调——任何比默认更松的选择都不被接受。默认值按第 9 节的表（任务里的"越出项目目录"是"计划里列了才做"）。"先问我"的意思是执行时一定当场问，计划里写了、授权项里列了也照样问；"计划里列了才做"才是靠计划一次授权，所以把某个类别从"计划里列了才做"调到"先问我"，计划里的授权项就不再替它放行。两条底线（付款转账、创建账户、改密码或两步验证固定"交给我做"；把凭据写进对外内容固定"永不"）只显示、不能改。用户还可以用确定的规则自定义类别——匹配工具、路径、收件人、金额，比如"往某个邮箱发邮件""动某个目录"——并给它设对话和任务两套处置。自定义类别是用户自己的，随时可以在设置里改规则、改处置（往松往严都行）或删除；它放宽不了别的类别，因为一次调用命中多个类别时取最严。关注类别注册表是数据，放在数据目录的配置区；配置区是受保护区域，任何 agent 用任何方式（文件工具、bash、脚本）写入都是"永不"，用户批准也不行。改完后下一次判定就按新设置走。

计划卡上多出一栏"本任务要提醒的关注类别"，默认取全局设置，只能增加、不能删：用户可以在确认计划时用同样的确定规则加一条只对这个任务生效的类别。想让任务少停几次，办法是在计划里给对应操作预先授权，这只对"计划里列了才做"那一档有效。用户在对话里说过的限制（以及任务书里的约束），由起草计划的维护者编译成时序规则或授权收窄，和用户的原话一起显示在计划卡上。

演示：在设置里新建一个类别"动工作目录里的数据库迁移目录"，任务里设"先问我"；让维护者在工作目录别处写文件，照常直接做；一写进那个目录，即使计划里有覆盖它的授权项，待我处理也出现审批卡，写明命中了这个类别。把这个类别的任务处置改成"直接做只记录"，或者干脆删掉它，同样的写入又照常直接做。再想把内置的"删除或覆盖"的任务处置从"做完告诉我"往松里调，界面不提供这个选项。

## Acceptance criteria

- [ ] 守卫切面（表格测试）：处置按六档的顺序比较严格程度（直接做只记录、做完告诉我、计划里列了才做、先问我、交给我做、永不，越往后越严）；某个内置类别某场景设得比默认更严时，判定随之变严；内置类别设得比默认更松的请求被拒绝，注册表不变。
- [ ] 守卫切面：任务里某类别为"计划里列了才做"时，有覆盖它的授权项就放行并标"属于授权内"；把它调到"先问我"后，同样的调用即使有授权项也判"先问我"。默认值按第 9 节的表，其中任务里的"越出项目目录"为"计划里列了才做"。
- [ ] 守卫切面：任何设置下两条底线都不变——付款转账、创建账户、改密码或两步验证始终判"交给我做"，对外内容里出现凭据形态始终判"永不"；设置接口改不动它们。
- [ ] 守卫切面（表格测试 + 场景文件）：自定义类别的确定规则按工具、路径、收件人、金额匹配，从 bash 拆出的伪工具调用同样适用；自定义类别的两套处置可以是六档中的任何一档，命中后和其他命中的类别一起取最严的处置，所以即使设成"直接做只记录"也放宽不了一同命中的内置类别和两条底线；没命中不影响判定。
- [ ] 主切面：在设置页新建自定义类别、改它的规则或处置（包括往松里改）、删除它，或调严某个内置类别的处置后，不重启守护进程，下一次工具调用就按新设置判定，删掉的类别不再命中；注册表写在数据目录的配置区，任何 agent 用文件工具、bash 或脚本写配置区都判"永不"，不出审批卡。
- [ ] 主切面：计划卡上"本任务要提醒的关注类别"默认等于全局设置；用户在计划卡上加的类别写进计划，只影响这个任务的判定（同一调用在这个任务和另一个任务里判定不同）；计划卡上没有删除选项，维护者提交的计划里本任务关注类别少于全局设置的，提交失败并返回原因。
- [ ] 主切面：维护者提交的计划可以带上由用户的限制编译出的时序规则和授权收窄，每条附上对应的用户原话；规则先过 05 号票的规则校验，不过的提交失败；计划卡上把它们和原话一起列出；确认后执行中违反这些规则的调用被拦下。编译本身靠维护者的模型，faux provider 下只测运行时一侧，真实效果放进 DeepSeek 计划起草的手动冒烟。
- [ ] 计划卡上加的关注类别，随计划确认产生的审批决定素材事件一起记下（由 08 号票采集，若 08 尚未完成，至少事件类型和负载就绪）。
- [ ] 界面：设置页的关注类别栏显示每个类别对话和任务两套处置（"计划外工单"的对话一栏显示"—"），内置类别的每个下拉只提供不比默认更松的选项；自定义类别能新建、改规则、改处置（下拉给全部六档）、删除；计划卡展开细节后能看到本任务要提醒的关注类别并新增，能看到由用户的限制编译出的规则和收窄及其原话。
- [ ] 所有测试通过（vitest），lint（oxlint）无报错。

## Notes

- **不在本票**：判定函数、工具注册表、内置类别和默认处置表、两条底线、"取最严"、受保护区域的硬边界归 03 号票；时序规则引擎和规则校验归 05；计划卡本身和计划确认归 12。本票只加设置页、自定义类别、计划卡上新增本任务的关注类别，以及把用户的限制编译后显示在计划卡上。
- 自定义类别随时可改可删：改规则、改两套处置（可以往松里改）、删除，都在设置页直接生效。"只能往严里调"只约束内置类别，两条底线任何时候都动不了；计划卡上"只能加不能删"是另一回事，不受影响。
- 已确认的计划里，本任务关注类别中来自全局的那部分跟着全局设置走：用户改了或删了某个自定义类别，正在执行的任务下一次判定也按新设置；计划卡上为这个任务加的类别只存在计划里，不受全局改动影响。
- 计划卡上新加的类别用和设置页同一套确定规则写法，只存在这个任务的计划里，不进全局注册表。
- 用模型判断的自定义关注类别、批准率监测、规则建议不做（Out of Scope）。"使用授权范围外的记忆"类别照常显示，但第一阶段不会触发。
- 对话里没有计划，"计划里列了才做"等同"先问我"（03 号票已实现），设置页按原样显示即可。
- 自定义类别的规则作用在工具注册表登记的参数种类上（路径参数、收件人参数等）；路径怎么通配、金额怎么比较，按 03 号票参数规则的形状来。
- 用户的限制编译出的规则走 05 号票的格式和校验；授权收窄走 03 号票"只能收窄"的校验。
- 对应用户故事：34、64、68–70、154。
