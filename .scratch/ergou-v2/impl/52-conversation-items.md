# 52 — 会话条目层：把会话拆成条目（前端状态层）

Status: ready-for-agent
Blocked by: None — can start immediately
Spec: [第一阶段规格](../spec.md) 第 19 节"会话区照搬 AgentSense"；调研 `docs/research/15-agentsense-zoom-detail-task-modes.md` §3、§5.3、§6.1 的 T1

## What to build

照 AgentSense 的 `ChatItem`，给二狗做一层纯函数的"会话条目"，作为后面三张票的共同底座：缩放（54）、详情页（56）、聊天区精简（57）。

会话里的东西拆成这几种条目：

- 用户消息
- 思考
- 回复
- **工具调用组**：一轮里两段话之间，连续的、顺利执行的工具调用合成一组。被拦下、问过你、你拒绝了、出错的调用不并进组，各自单独成一条。
- 卡片
- 系统说明
- 时间线记录
- 工单分隔
- 语音

每条推出这些属性：

- 种类；
- 稳定的 id（详情页按它存）；
- 要点层的那一行字；
- 性质色（授权内、做完告诉我、被拦下或问过，三种样式）；
- 两侧标注要的信息（复用现有的 `marksOf` 等）；
- 能否打开详情，以及详情的种类。

## Acceptance criteria

- [ ] 条目层是 `packages/web/src/state/` 下的纯函数：输入是现有的会话状态（消息、记录、卡片），输出是条目列表，不碰 DOM。
- [ ] 回放测试：用主切面现有的录像（秘书会话、任务的维护者会话、项目的维护者会话）回放成条目，断言：
  - 工具调用组的切法：两段话之间的连续调用成一组；被拦下、问过、拒绝、出错的单独成条；
  - 每条的种类、要点那一行和性质色；
  - 语音、卡片、时间线记录、工单分隔各自成条。

  现有录像覆盖不到的情形，按共享协议的 schema 构造事件来测。
- [ ] 条目 id 稳定：同一条内容在往上翻加载更早的一页、实时追加之后，id 不变。有测试。
- [ ] 本票只做状态层，不改界面。现有的 25 号票三层渲染照旧能跑。
- [ ] 所有测试通过（vitest），lint（oxlint）无报错。
