# 106 — 页面顶上的通知：框的大小固定、字多了省略，多条在同一个框里轮播

Status: ready-for-agent
Blocked by: 无
Spec: [第一阶段规格](../spec.md) 第 19 节（Web UI）；105 号票（顶上的通知只露最新一条、8 秒收起）、06 号票（待我处理）

## What to build

用户 2026-10-13 原话："通知里面的文字多的时候，它会把那个框撑的很大，导致我看不清楚或者按钮按不到……把那个提醒框里的文字或者提醒框的大小限制死，如果文字太多就用省略号……多个提醒消息那个框不要互相叠起来，应该放到同一个框里面去……我不点的话，它在里面滚动展示多个消息，就同一个框里面滚动展示多个消息，然后我点查看的话，它就会跳到待办的那个里面去。现在框太多了，会遮住那个内容。"

现在（105 号票）`ui/alerts.tsx` 的 `AlertsView` 只露最新一条，下面加一行"还有 N 条，在待办里 ›"；框的高度跟着字走，标题、正文长了会撑高，按钮被挤。

改成：

- **框的大小固定**：宽度照旧（`min(94%, 460px)`），高度固定，不随字数变。标题一行、正文一行（或标题和正文合成一行，挑看得清的），放不下在末尾用省略号。"查看""关闭"始终在右边、不被挤走、手指点得到。
- **多条在同一个框里轮播**：只有一个框。同时有几条时，框里每隔几秒换下一条（比如 3–4 秒一条，往上滚动换过去的样子；系统设了减少动效时直接换，不滚）。框上标出"第几条 / 共几条"（比如 `2/3`）。新来的一条排进去。原来那行"还有 N 条，在待办里 ›"去掉。
- **"查看"**：去待办里**框里此刻显示的这一条**（`onOpen(itemId)`）；这一条没有对应的待办事项时去待办列表。点了整个收起（照 105）。
- **自动收起**：照 105 的意思（不一直挂在顶上），改成轮播的版本：每条都至少露过一次、且总共露了不少于 8 秒之后收起；新来一条从头算；手指、鼠标、键盘焦点停在上面时停住不换、不收，离开后接着。收起只是不在顶上显示，待办里那一项、红点、浏览器通知照旧（同 105）。
- **"关闭"**：整个收起（同 105）。
- 什么时候换下一条、什么时候收起照 105 的做法放状态层纯函数（`state/alerts.ts`），计时器在页面上；状态层有测试。
- 11 套风格里自己画了 `.alert-banner` 的（软糖、玻璃、格栅、像素、贴纸……）一起查，固定大小、省略号在每套里都成立，字不溢出框。

## Acceptance criteria

- [ ] 框高度固定，长标题、长正文都在一行内省略，按钮始终可点（390、1280 宽都看）。
- [ ] 多条只有一个框，轮播、标"n/共几条"；停在上面不换不收；"查看"去当前这一条在待办里的详情。
- [ ] 自动收起照上面的规则；待办和红点不受影响；状态层有测试（换条、收起、停住 / 离开、新来一条）。
- [ ] 截图：经典浅色 390、1280（一条长字、三条轮播中），另挑 2 套风格（含像素小屋或贴纸便当）。原型的 `?demo-alerts=N` 可以接着用，长字的样例也可以加。示例数据里不要出现日本相关的内容。
- [ ] 只动 Web：跑 web 包全量一次，typecheck、oxlint 通过；`docs/dev.md` 里 105 那段跟着改。
