# 97 — 发起任务时写了几点，定时就按几点（不能写 8 点定成 9 点）

Status: ready-for-agent
Blocked by: 无（只改 Web，小功能，轻流程）
Spec: [第一阶段规格](../spec.md) 第 19 节；76 号票（"什么时候做"：定时、某个时间做一次）、77 号票（事件发生时）

## What to build

用户 2026-10-12：昨晚在"发起任务"里写"明天早上8点调研一下最新的AI的新闻，总结成文本发给我，加上超链接"，选了"定时"，没动下面的时间。定时那一栏默认是"按时间表反复做 · 每天 09:00"（`DEFAULT_TRIGGER_SCHEDULE`），建出的作业 j-1 是每天 09:00，今天 9 点才跑、明天还会再跑。用户原话："我说了几点钟的，他就得把我按照那个几点钟做了……这肯定是 bug"。

改成：**写的那段话里说了时间，定时就按那个时间定**。

1. **从写的话里认出时间**（状态层纯函数，`now` 注入）：
   - 哪天：今天 / 今晚 / 明天 / 明早 / 明晚 / 后天 / 大后天、（下）周一…周日 / 星期X / 礼拜X、X月X日 / X月X号 / X号；
   - 反复：每天 / 每日 / 天天、每周X（可以几个：每周一三五、每周一和周四）、工作日 / 每个工作日（按我的工作日）、每月X号；
   - 时段：凌晨、早上 / 早晨 / 上午、中午、下午 / 傍晚 / 晚上 / 夜里（下午、晚上的 1–11 点加 12；中午 12 点、中午 1 点是 13 点；晚上 12 点是 0 点）；
   - 钟点：8点、8点半、8点一刻、8点15（分）、8:30 / 8：30、阿拉伯数字和中文数字（一到十二、两点、十点半、二十点）；24 小时写法（20:00）。
   - 只有钟点没有哪天：今天这个钟点还没过就是今天、过了就是明天（和 `nextClockTime` 一样）。只有哪天没有钟点：认不出，不改。
   - 认出来的是一次（有具体哪天，或者只有钟点）→ "定时 · 某个时间做一次"；认出来的是反复（每天、每周X、工作日、每月X号）→ "定时 · 按时间表反复做"。
2. **发起任务的对话框**：写的话变了就重认一遍。认出来了，而且用户还没自己动过"什么时候做"、定时这几栏：自动切到"定时"、选好"某个时间做一次 / 按时间表反复做"、填好日期时间，下面一行写"按你写的「明天早上 8 点」定在 10 月 13 日（周二）08:00"。用户自己改过这几栏之后不再自动改；这时写的话里的时间和定的不一样，标出来"你写的是「明天早上 8 点」，这里定的是每天 09:00"（还能照样发起）。"只提醒我"的提醒时间同样处理。选了长程任务（不能定时）而话里有时间：提示一句"长程任务只能现在做；要按时间做选普通任务或流程"。
3. 秘书那条路（在聊天里说"明天早上 8 点……"，秘书建任务）不在本票：秘书照它的工具参数定时间。

## Acceptance criteria

- [ ] 认时间的纯函数有表格测试：上面列的说法各几条，含边界（今天的钟点已过、中午 12 点、晚上 12 点、8点半、两点、十点、20:00、每周一三五、工作日、每月15号、写了哪天没写钟点不认、一段话里有不相干的数字不误认）。
- [ ] 对话框：写"明天早上8点……"自动定在明天 08:00 一次；写"每天早上8点……"定成每天 08:00；手动改过不再被覆盖、不一致时有提示；有状态层测试；截图（经典浅色 390、1280）。
- [ ] web 包测试、typecheck、oxlint 通过。
