# 21 — 记忆命令、素材删除与快速动作

Status: ready-for-agent
Blocked by: 08（素材采集与索引）
Spec: [第一阶段规格](../spec.md) 第 14 节（快速动作）、第 15 节（素材）、第 9 节（守卫）、第 7 节（秘书）、第 5 节（前端协议）、第 4 节（存储与事件）、第 21 节（实现细节补充）

## What to build

秘书的"快速动作"这种回复形态打通：秘书用"提议快速动作"工具写清做什么、对谁做，生成一张快速动作卡。用户这一轮明确点了对象和内容的，卡片只展示规范化后的动作、直接执行；秘书自己推断出来的，按关注类别的对话处置决定（通常先问）。"明确点了"由运行时判定，不由秘书自报：动作的对象和内容必须原样出现在用户这条消息里（或用户引用的卡片里），否则一律按推断处理。执行由守护进程里按动作类型注册的执行器直接完成，不拉起 agent、不上任务看板、不占并发名额；每次执行是事件日志里的一条执行事件，也就是"操作记录"，在时间线上可见，聊天里留一张"已执行"的动作卡。

第一种动作是记忆命令。用户说"记住……"，作为显式记忆命令素材入库。用户说"忘掉这件事""彻底删除""别推断这个"，秘书用素材检索工具（关键词 + 向量）找出匹配的素材，生成一张记忆删除卡供用户核对，确认后执行：**忘掉**——从素材库和索引里删除，聊天记录里仍看得到原话；**彻底删除**——连事件日志和会话文件里的原文一起改写成删除标记；**别推断**——素材保留，标记为不参与推断。设置页还能按会话或按时间段批量做这三种删除。聊天的附件菜单里加一项"作为材料投喂"，用户这样发的内容记为"用户主动投喂的材料"。

演示：在秘书页说"忘掉我昨天说的搬家的事"，聊天里出现记忆删除卡、列出匹配的素材，确认后关键词检索不再命中，聊天里原话还在；同样的话换成"彻底删除"，刷新后聊天里那条原话变成删除标记。

## Acceptance criteria

- [ ] 主切面：秘书调用"提议快速动作"工具后，聊天里出现一张快速动作卡；动作类型必须是执行器注册表里登记过的，未登记的类型不出卡，工具向模型返回错误。
- [ ] 主切面："明确点了"由运行时判定：规范化后动作的对象和内容都原样出现在用户这条消息里（或用户引用的卡片里）时，卡片只展示规范化后的动作并直接执行，聊天里留"已执行"卡；任一项对不上（faux 剧本里秘书提议的收件人或内容不在用户消息里），就按推断处理——按该动作类型登记的关注类别和对话处置判定，判为"先问我"时卡片带确认按钮、同时进待我处理，点确认后才执行。秘书在工具参数里自称"用户点明了"不影响判定。执行期间不拉起任何 agent 子进程，任务看板不变。
- [ ] 主切面：每次执行都在事件日志里追加一条执行事件（动作类型、规范化后的动作、结果、对应的卡片），即"操作记录"，时间线上可见；快速动作卡和记忆删除卡的按钮都带幂等键，同一请求重发只执行一次、只有一条执行事件，两个前端同时点时先到先得，后到的得到"已被处理"。
- [ ] 主切面：用户说"记住……"时，执行器把它作为"显式记忆命令"素材入库（来源本人，另存原文副本），聊天里留"已执行"卡；第一阶段不产出任何记忆。每条记忆命令（记住、忘掉、彻底删除、别推断）都产生"显式记忆命令"素材事件。
- [ ] 主切面：秘书有一个只读的素材检索工具，用关键词（FTS5 trigram，3 个字以下的词退回子串扫描，沿用 08 号票）加向量检索返回匹配的素材；用户说忘掉、彻底删除或别推断时，秘书据此生成记忆删除卡，卡上列出匹配到的素材和要执行的删除方式，卡同时进待我处理，用户确认后才执行。
- [ ] 主切面：**忘掉**执行后，素材及其原文副本从 `memory.db` 删除，关键词和向量检索都不再命中，聊天历史分页里原话仍在；**别推断**执行后，素材和索引保留，素材上带"不参与推断"标记。
- [ ] 主切面：**彻底删除**执行后，事件日志和对应 pi 会话文件里的原文都改写成删除标记，历史分页和重连补发只返回删除标记，从事件日志整体重建派生视图后原文也不会回来；素材和索引按"忘掉"一样删除。
- [ ] 主切面：在设置页（更多 → 设置）选一个会话或一个时间段，再选三种删除方式之一，确认后对范围内的全部素材执行，效果分别同上。
- [ ] 主切面：用户经附件菜单的"作为材料投喂"发出的消息和附件，产生"用户主动投喂的材料"素材事件（由 08 号票采集，来源按 08 的切段规则标）；普通方式发的附件不产生这类事件。界面上秘书页的附件菜单里有这一项。
- [ ] 所有测试通过（vitest），lint（oxlint）无报错。

## Notes

- **不在本票**：任务控制（按用户要求暂停、继续、取消）这种快速动作归 22 号票；第 14 节的第三种内置动作"调用一个已登记并授权给秘书快速动作的 MCP 工具（参数固定）"归 27 号票。两者都登记进本票的执行器注册表、走本票的确认规则。
- 执行器注册表里每种动作类型登记它落入的关注类别（形状同工具注册表），推断出的动作据此按对话处置判定。推断出来的任务控制动作一律先问，由 22 号票登记。
- 卡片实体、按钮闭环、"已被处理"、卡片频道、待我处理沿用 06 号票；素材采集、切段、来源标记、原文副本、索引和检索函数沿用 08 号票，本票只把检索包成秘书的只读工具，并加上三种删除。
- 记忆删除总要过一张核对卡（第 15 节），因为要删哪些素材是秘书检索出来的，不是用户点明的。
- "忘掉"要顺着证据边删掉由它推出的判断，第一阶段还没有任何派生内容，不用做。
- "彻底删除"是事件日志不可修改的唯一例外，改写入口只开给它。
- "作为材料投喂"挂在 09 号票的附件菜单上；本票不依赖 09，若 09 尚未完成，主切面用例在协议层直接发带"作为材料投喂"标记的消息验证，界面入口等 09 完成后接上。
- 对应用户故事：20–23、127（主动投喂的材料部分）、132–134。
