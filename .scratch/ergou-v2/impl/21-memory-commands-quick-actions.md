## What to build

秘书的"快速动作"这种回复形态打通：秘书用"提议快速动作"工具写清做什么、对谁做，生成一张快速动作卡。用户这一轮明确点了对象和内容的，卡片只展示规范化后的动作、直接执行；秘书自己推断出来的，按关注类别的对话处置决定（通常先问）。"明确点了"由运行时判定，不由秘书自报：动作的对象和内容必须原样出现在用户这条消息里（或用户引用的卡片里），否则一律按推断处理。执行由守护进程里按动作类型注册的执行器直接完成，不拉起 agent、不上任务看板、不占并发名额；每次执行是事件日志里的一条执行事件，也就是"操作记录"，在时间线上可见，聊天里留一张"已执行"的动作卡。

第一种动作是记忆命令。用户说"记住……"，作为显式记忆命令素材入库。用户说"忘掉这件事""彻底删除""别推断这个"，秘书用素材检索工具（关键词 + 向量）找出匹配的素材，生成一张记忆删除卡供用户核对，确认后执行：**忘掉**——从素材库和索引里删除，聊天记录里仍看得到原话；**彻底删除**——连事件日志和会话文件里的原文一起改写成删除标记；**别推断**——素材保留，标记为不参与推断。设置页还能按会话或按时间段批量做这三种删除。聊天的附件菜单里加一项"作为材料投喂"，用户这样发的内容记为"用户主动投喂的材料"。

演示：在秘书页说"忘掉我昨天说的搬家的事"，聊天里出现记忆删除卡、列出匹配的素材，确认后关键词检索不再命中，聊天里原话还在；同样的话换成"彻底删除"，刷新后聊天里那条原话变成删除标记。

## Acceptance criteria

- [x] 主切面：秘书调用"提议快速动作"工具后，聊天里出现一张快速动作卡；动作类型必须是执行器注册表里登记过的，未登记的类型不出卡，工具向模型返回错误。
- [x] 主切面："明确点了"由运行时判定：规范化后动作的对象和内容都原样出现在用户这条消息里（或用户引用的卡片里）时，卡片只展示规范化后的动作并直接执行，聊天里留"已执行"卡；任一项对不上（faux 剧本里秘书提议的收件人或内容不在用户消息里），就按推断处理——按该动作类型登记的关注类别和对话处置判定，判为"先问我"时卡片带确认按钮、同时进待我处理，点确认后才执行。秘书在工具参数里自称"用户点明了"不影响判定。执行期间不拉起任何 agent 子进程，任务看板不变。
- [x] 主切面：每次执行都在事件日志里追加一条执行事件（动作类型、规范化后的动作、结果、对应的卡片），即"操作记录"，时间线上可见；快速动作卡和记忆删除卡的按钮都带幂等键，同一请求重发只执行一次、只有一条执行事件，两个前端同时点时先到先得，后到的得到"已被处理"。
- [x] 主切面：用户说"记住……"时，执行器把它作为"显式记忆命令"素材入库（来源本人，另存原文副本），聊天里留"已执行"卡；第一阶段不产出任何记忆。每条记忆命令（记住、忘掉、彻底删除、别推断）都产生"显式记忆命令"素材事件。
- [x] 主切面：秘书有一个只读的素材检索工具，用关键词（FTS5 trigram，3 个字以下的词退回子串扫描，沿用 08 号票）加向量检索返回匹配的素材；用户说忘掉、彻底删除或别推断时，秘书据此生成记忆删除卡，卡上列出匹配到的素材和要执行的删除方式，卡同时进待我处理，用户确认后才执行。
- [x] 主切面：**忘掉**执行后，素材及其原文副本从 `memory.db` 删除，关键词和向量检索都不再命中，聊天历史分页里原话仍在；**别推断**执行后，素材和索引保留，素材上带"不参与推断"标记。
- [x] 主切面：**彻底删除**执行后，事件日志和对应 pi 会话文件里的原文都改写成删除标记，历史分页和重连补发只返回删除标记，从事件日志整体重建派生视图后原文也不会回来；素材和索引按"忘掉"一样删除。
- [x] 主切面：在设置页（更多 → 设置）选一个会话或一个时间段，再选三种删除方式之一，确认后对范围内的全部素材执行，效果分别同上。
- [x] 主切面：用户经附件菜单的"作为材料投喂"发出的消息和附件，产生"用户主动投喂的材料"素材事件（由 08 号票采集，来源按 08 的切段规则标）；普通方式发的附件不产生这类事件。界面上秘书页的附件菜单里有这一项。
- [x] 所有测试通过（vitest），lint（oxlint）无报错。

## Notes

- **不在本票**：任务控制（按用户要求暂停、继续、取消）这种快速动作归 22 号票；第 14 节的第三种内置动作"调用一个已登记并授权给秘书快速动作的 MCP 工具（参数固定）"归 27 号票。两者都登记进本票的执行器注册表、走本票的确认规则。
- 执行器注册表里每种动作类型登记它落入的关注类别（形状同工具注册表），推断出的动作据此按对话处置判定。推断出来的任务控制动作一律先问，由 22 号票登记。
- 卡片实体、按钮闭环、"已被处理"、卡片频道、待我处理沿用 06 号票；素材采集、切段、来源标记、原文副本、索引和检索函数沿用 08 号票，本票只把检索包成秘书的只读工具，并加上三种删除。

- "彻底删除"是事件日志不可修改的唯一例外，改写入口只开给它。
- "作为材料投喂"挂在 09 号票的附件菜单上；本票不依赖 09，若 09 尚未完成，主切面用例在协议层直接发带"作为材料投喂"标记的消息验证，界面入口等 09 完成后接上。
- 对应用户故事：20–23、127（主动投喂的材料部分）、132–134。

- **验收标准**：除第三条外都做到了。**第三条取消勾选**：执行事件（操作记录 `quick_action_executed`，落在动作提出的会话频道上，幂等键 `quick-action:<动作 id>`）、按钮带幂等键、重发只执行一次、两个前端同时点先到先得都做了，但"时间线上可见"归 25 号票（时间线页面接真数据在那里做），本票前端状态层只推进序号、不显示它。
- **取舍写进了 ADR-0008**（彻底删除改写哪些东西、怎么改；会话文件在子进程那一层改，和 ADR-0004 的关系；删除本身记成事件；删不掉的如实告诉用户）。编号如果和同时开工的票撞了，合并时顺延。
- **评审后改了的**：
  - **彻底删除不改坏状态**：只有消息事件整条换成"已删除"标记；别的事件（审批决定、卡片、效果日志、工具调用记录、操作记录、卡片被关闭……）按事件类型字段级改写，只把带原话的文本字段换成"（这条内容已彻底删除）"，id、状态、决定原样保留。改写函数按事件类型登记成一张表（`memory/rewriters.ts`），没登记的事件类型被点到时整个彻底删除被拒。审批决定那次工具调用的结果（模型收到的"用户拒绝了这次调用：<说明>"）在会话文件里也改，挂起之后才拒绝时递给 agent 的通知整条删。测了：彻底删除含审批的秘书主线后，审批表重建仍是已拒绝，会话文件里没有拒绝时写的说明。
  - **会话文件的改写搬进 `agent-child/`**（用 pi 的类型），守护进程以一次性子进程调用（agent 管家的 `rewriteSessions`）；范围加上提议"记住"那几次工具调用的参数和工具结果，以及覆盖了被删消息的压缩摘要、分支摘要（整段换成"（这段摘要含已彻底删除的内容，已移除）"）。改写参数由记忆模块从 `messages_purged` 生成，秘书只负责停、改、拉起（和崩溃重启共用拉起的收尾）。
  - **附件**：被删消息引用的附件，没有别的未删消息、也没有素材还引用同一个哈希的，媒体文件连同派生文件一起删（按媒体 id 下载 404）。
  - **SQLite**：`ergou.db`、`memory.db` 的写连接开 `secure_delete`，彻底删除后 `wal_checkpoint(TRUNCATE)`。
  - **界面如实说明删不掉的**（设置页和记忆删除卡共用协议包的 `MEMORY_DELETE_MODE_INFO` / `PURGE_LIMITS`）：秘书回复里转述过的话；备份快照里仍有一份，随快照轮换消失（本机约 7 天，同步目录最长约 5 周）。
  - **"明确点了"由每个执行器自己声明**（`explicit(action, turn)`，共用 `quick-actions/explicit.ts` 的辅助函数）。"记住"：有触发词（记住、记下来、记下、记一下），前面同一分句里没有否定词（别、不要、不用、不必、无需、甭），并且提议的内容和触发词后面到句末的那一段一致（去掉标点和空白）；那一段只是指代（"这个""这条"）时，内容要和引用块或引用的卡片上的一段一致。否则按推断处理、出确认卡。测了"别记住……"和"记住：周五交房租，别忘了"（内容只提了半句）都不执行。
  - **"记住"的来源**：自己打的字 → 本人、打字；只在引用块里 → 外部不可信；只在引用的卡片上 → 用户的选择、注明 agent 先提出；推断出来、用户在卡上确认的 → 注明 agent 先提出。
  - **用户的自定义关注类别也管快速动作**：动作作为伪工具调用 `quick_action:<动作类型>`（参数是规范化后的参数，执行器登记的 `watch` 形状同工具登记）交给守卫的 `judgeToolCall`，按工具名、收件人、金额、路径匹配；底线和"取最严"不变。27 号票的 MCP 快速动作照此。
  - **Web 的"引用卡片"**：聊天里每张卡下面有"引用"，引用的卡片显示在输入框上方（可去掉），发送时作为 `card_ref` 带上。
  - **执行器注册表**：每种动作自带参数 schema（`params`，参照卡片动作的 `input`），秘书工具的参数改成 `{ type, params, explicit? }`；22、27 号票只加一个 `defineQuickAction` 的登记。
  - 录好的前端事件流保存时把临时目录、用户主目录换成占位符，加了检查录好的文件里没有本机用户主目录的测试；`memory-purge`、`secretary-approval` 两段重新录过。
- **规格没写清、我选的做法**：
  - **处置**：点明了只看底线（付款、改密码……仍按底线交给我做或永不）；推断出来的，内置类别和自定义类别在"对话"里的处置、底线、"做完告诉我"取最严；"计划里列了才做"在对话里没有计划可列，按先问处理；判为交给我做、永不的不出卡，工具把原因告诉秘书。执行器可以要求更严：记住 `ask_when_inferred`（推断出来的一律先问），忘掉、彻底删除、别推断 `always`（总要核对，规格第 15 节）。
  - **快速动作卡进待我处理**时标题是"确认快速动作：<动作名>"，记忆删除卡是"核对要<删法>的记忆（n 条）"，来源"秘书对话"，不卡任务。点明了直接执行的卡出来就是"已处理"，不进待我处理。
  - **记忆命令的事件**：每条记忆命令（含设置里批量的）是守护进程内部 `materials` 频道上的一条 `memory_command`（按命令种类分记住、删除类两种形状），素材模块据此产生"显式记忆命令"素材（删除类的素材只写"忘掉 n 条素材"不重复原话；设置里的写明范围）。忘掉在 `memory.db` 里另记墓碑，重放、补采、从原文副本补回都跳过；启动补采前先把事件日志里的忘掉记下。
  - **彻底删除不改写的**：秘书自己的回复和检索时写的查询词；审批请求里 agent 要做的那次调用的参数摘要；本票之前的会话文件里没有输入标记的消息。

  - **作为材料投喂**：图片和文件都可以，选的附件带 `asMaterial`；09 的 `postUserMessage` 不再去掉它。
