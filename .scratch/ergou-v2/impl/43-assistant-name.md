# 43 — 个人助理的名字：设置里改名，名字带底色，宽屏竖栏变窄

Status: done
Blocked by: 36（"秘书"在界面上改叫"个人助理"）
Spec: [第一阶段规格](../spec.md) 第 19 节（Web UI）"名称"

## What to build

用户 2026-10-09 提了三点：

1. 设置里可以给个人助理起名字，比如"二狗"。之后界面上凡是说到它的地方都用这个名字，比如"和二狗说…"。
2. 名字随便起，容易和普通文字混在一起分不清，所以名字显示时要带一个专门的底色，和别的文字区分开。
3. 横屏（宽屏）时主导航在左边竖着排，"个人助理"要从中间换行，让左边这一栏窄一些。

## Acceptance criteria

- [x] **名字的设置和保存**
  - 设置里有"个人助理的名字"，默认"个人助理"。
  - 规则：去掉首尾空白后 1–8 个字，不能有换行；不合规的就地提示、不保存。
  - 名字存在守护进程，各设备看到的一样；改了以后，开着的页面实时更新（经频道推送）。
  - 恢复默认就回到"个人助理"。
- [x] **界面上用名字**
  - 界面上所有给人看的"秘书""个人助理"都换成这个名字：聊天页标题、主导航标签、输入框占位（"和二狗说…"）、消耗页、卡片上的"这是秘书推断的"、设置里的说明、待我处理里的事项、页面顶上的提示，以及守护进程生成、在界面上显示的话。
  - 守护进程生成的话里要提到秘书的，不把名字直接写死进事件，而是让前端按当前名字显示，这样改名后旧的也跟着变。写法自定，写进 Comments。
  - 本票之前存下的旧数据里，守护进程写死的那几句"秘书""待我处理"也按名字（"待办"）显示：只认这几句固定的话（逐句列出，配表格测试），用户和 agent 的原话不动（评审加）。
  - 代码、领域术语（CONTEXT.md）、给 agent 的提示词里照旧叫秘书。
  - 测试或扫描确保界面上不再残留"秘书"字样（例外列进 Comments）。
- [x] **名字的底色**
  - 名字出现的地方都显示成一个带底色的小标签（底色、圆角、左右留一点空），和普通文字明显不同。导航标签、标题、正文里都这样。
  - 输入框占位不能部分上色：用叠在输入框上的假占位实现，或者效果相同的做法。
  - 颜色用 token，浅色、深色下都看得清，对比度达标。39 号票的风格出来以后，每套风格可以覆盖这个 token。
- [x] **秘书知道自己叫什么**：名字写进秘书的系统提示，自我介绍、说到自己时用这个名字；改名后从下一轮起生效。
- [x] **主导航标签一律两个字**（2026-10-09 用户加，主会话并进本票；取代原来的"标签在允许换行的地方换行、自定义名字按两行排"）
  - 秘书那一项默认显示"助理"；起的名字不超过两个字（比如"二狗"）时显示名字，超过两个字时导航上仍是"助理"，完整名字只在标题和正文里。名字的底色标签在导航上照常带。
  - "待我处理"在界面上一律改叫"待办"：导航、页面标题，以及正文、卡片、提示里提到它的地方。代码和领域术语（CONTEXT.md）照旧。扫描"秘书"残留时，"待我处理"也一起扫。
  - 其余几项（任务、项目、日历、消耗、记忆、设置、更多）本来就是两个字。
- [x] **每一项都是图标在上、文字在下**：宽屏左侧竖栏和手机底部横栏都这样。
- [x] **未读数和红点放在图标右上角**：叠在图标上，不单独占横向位置；数字太大时显示"99+"，写进 Comments。
- [x] **宽屏左侧竖栏按"图标 + 两个字"收窄**，宽度写进 Comments。33 号票的导航自适应表格测试，按新的项高、项宽重算。
- [x] **所有风格都用这个结构**：导航的结构和 class 由本票定（写进 Comments 和 `docs/dev.md`），39 号票的风格只换样子。
- [x] 所有测试通过（vitest），lint（oxlint）无报错。
