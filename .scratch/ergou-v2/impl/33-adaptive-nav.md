# 33 — 主导航按空间自适应

Status: ready-for-agent
Blocked by: 02（Web UI 骨架与可点击原型）
Spec: [第一阶段规格](../spec.md) 第 19 节（Web UI 的主框架）

## What to build

主导航不再固定成"4 个 tab + 更多"，而是按空间自适应：导航项按固定顺序排——秘书、任务、项目、待我处理、消耗、记忆、设置——放得下的直接显示成 tab，放不下的从末尾起收进"更多"；全都放得下时不显示"更多"。横屏时主导航是左侧竖栏，比现在更窄，"待我处理"这类名字可以换行显示；竖排有空间时，消耗、记忆、设置直接显示在竖栏里。竖屏时是底部横栏，规则相同：宽度够就多显示几个，不够的收进"更多"。

## Acceptance criteria

- [ ] 前端状态层：一个纯函数按可用长度（横屏是高度、竖屏是宽度）、每个导航项占的长度和"更多"占的长度，算出直接显示哪些、收进"更多"的有哪些；顺序固定，从末尾起收；有收起的才出现"更多"，"更多"自己也要放得下。表格测试覆盖：全都放得下、刚好放不下一个、只放得下最少的几个。
- [ ] 横屏：左侧竖栏比现在窄（图标在上、名字在下，名字可以换成两行，比如"待我 / 处理"），竖栏高度够时消耗、记忆、设置直接显示；窗口变矮时末尾的项收进"更多"，变高时再放出来（随窗口大小和横竖屏切换实时变化）。
- [ ] 竖屏：底部横栏按宽度同样处理；常见手机宽度下至少显示秘书、任务、项目、待我处理（放不下时收进"更多"的从设置、记忆、消耗起）。
- [ ] "更多"页只列收进去的那些项；直接显示出来的项从"更多"里拿掉；设置下面的子页（关注类别、工作日历、skill 库、已配对设备、删除素材）照旧在设置里。记忆仍是第二阶段，点进去显示现在的"第二阶段"说明。
- [ ] 当前页高亮、待我处理的未读小红点和数字、键盘可达性（Tab 键顺序、`aria-current`）照旧；当前页如果在"更多"里，"更多"高亮。
- [ ] 前端状态层和组件测试通过；在本机浏览器（守护进程提供的页面）横屏、竖屏各看一遍，截图附在 Comments 里描述结果。
- [ ] 所有测试通过（vitest），lint（oxlint）无报错。
