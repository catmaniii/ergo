# 33 — 主导航按空间自适应

Status: done
Blocked by: 02（Web UI 骨架与可点击原型）
Spec: [第一阶段规格](../spec.md) 第 19 节（Web UI 的主框架）

## What to build

主导航不再固定成"4 个 tab + 更多"，而是按空间自适应：导航项按固定顺序排——秘书、任务、项目、待我处理、消耗、记忆、设置——放得下的直接显示成 tab，放不下的从末尾起收进"更多"；全都放得下时不显示"更多"。横屏时主导航是左侧竖栏，比现在更窄，"待我处理"这类名字可以换行显示；竖排有空间时，消耗、记忆、设置直接显示在竖栏里。竖屏时是底部横栏，规则相同：宽度够就多显示几个，不够的收进"更多"。

## Acceptance criteria

- [x] 前端状态层：一个纯函数按可用长度（横屏是高度、竖屏是宽度）、每个导航项占的长度和"更多"占的长度，算出直接显示哪些、收进"更多"的有哪些；顺序固定，从末尾起收；有收起的才出现"更多"，"更多"自己也要放得下。表格测试覆盖：全都放得下、刚好放不下一个、只放得下最少的几个。
- [x] 横屏：左侧竖栏比现在窄（图标在上、名字在下，名字可以换成两行，比如"待我 / 处理"），竖栏高度够时消耗、记忆、设置直接显示；窗口变矮时末尾的项收进"更多"，变高时再放出来（随窗口大小和横竖屏切换实时变化）。
- [x] 竖屏：底部横栏按宽度同样处理；常见手机宽度下至少显示秘书、任务、项目、待我处理（放不下时收进"更多"的从设置、记忆、消耗起）。
- [x] "更多"页只列收进去的那些项；直接显示出来的项从"更多"里拿掉；设置下面的子页（关注类别、工作日历、skill 库、已配对设备、删除素材）照旧在设置里。记忆仍是第二阶段，点进去显示现在的"第二阶段"说明。
- [x] 当前页高亮、待我处理的未读小红点和数字、键盘可达性（Tab 键顺序、`aria-current`）照旧；当前页如果在"更多"里，"更多"高亮。
- [x] 前端状态层和组件测试通过；在本机浏览器（守护进程提供的页面）横屏、竖屏各看一遍，截图附在 Comments 里描述结果。
- [x] 所有测试通过（vitest），lint（oxlint）无报错。

## Comments

实现概要（2026-10-08，子 agent，分支 `worktree-agent-a76a0f9464aa61372`）：

- 状态层 `packages/web/src/state/nav.ts`：`NAV_ITEMS`（固定顺序）、`fitNav({ available, sizes, more })` → `{ shown, folded }`、`navHighlight(fit, 当前页所属的项)`、`NAV_MIN_SHOWN = 4`。表格测试 `packages/web/test/state/nav.test.ts`（全都放得下、刚好全放得下、差 1 放不下且"更多"要占地方所以收两个、"更多"比末尾的项短只收一个、只放得下最少的四个、比最少的还挤、390/320 宽的横栏，高亮的三种情况）。
- 量长度 `packages/web/src/ui/main-nav.tsx`：导航条里藏一份全部导航项加"更多"的样本（`inert` + `aria-hidden`、`visibility: hidden`、竖栏里高 0 / 横栏里宽 0，不占地方，和真的 tab 同一套样式），挂上时在 `useLayoutEffect` 里量一次（第一帧就是量好的样子），之后 ResizeObserver 盯着放 tab 的 `.nav-list` 和样本里的每一项。显示哪些 tab 不影响样本和可用长度，不会来回跳；`useNavFit` 只在直接显示的项数变了时更新状态，拖动窗口时不白白重绘。
- `App.tsx` 只换了导航那一段（`TABS` 和两份 `<nav>` 换成 `<MainNav>`），`Page` 多传一个 `folded` 给"更多"页。`MorePage.tsx`：直接显示着的消耗、记忆各自一页（没有返回），设置直接显示时是"设置"一栏（宽屏左边五页、右边选中的页；竖屏点进去的页返回到设置）；收进来的才进"更多"的菜单（宽屏下收进来的设置照旧展开成一组）。`styles/layout.css`：竖栏 76 → 56 宽、名字 11px、只在零宽空格处换行（"待我 / 处理"）；横栏每项自然宽度至少 56。

决定（规格没写死的地方，选了最保守的做法）：

- **地址不变**：消耗、记忆、设置及设置下面的页仍是 `#/more/<页>`（新加 `#/more/memory`）。同一个地址显示在"更多"里还是自己一页，看它现在收没收起；这样别处已有的链接（待我处理里"去设置页修复"指向 `#/more/watch`）和正在并行开发的票里的 `navigate({ tab: "more", page })` 都不用改。当前页属于哪一项是 `app/route.ts` 的 `navItemOf(route)`。
- **再挤也直接显示前四项**（秘书、任务、项目、待我处理，`NAV_MIN_SHOWN`）：票里要求常见手机宽度下至少显示这四项；定成下限后待我处理的小红点总在导航条上，不用考虑"待我处理收进更多时提示挪到哪"。连这四项加"更多"都放不下时（窗口极矮），竖栏自己滚动；横栏的 tab 等比压窄。
- **横屏 / 竖屏仍按内容区宽度 600 分界**（原有的判断，没改）：手机横过来（844×390）是竖栏，按高度收放。
- 收进"更多"的记忆照旧是一条不能点的"第二阶段"菜单项（说明就写在上面）；记忆直接显示成 tab 时点进去是一页"记忆 · 第二阶段 · 第一阶段只积累素材，不推断，也不产出记忆"。
- 待我处理的灰色数字从图标右侧挪到图标右下角：竖栏窄了放不下原来的位置，原来的位置还会压住小红点；横栏也一起改，两处一致。数字原来是斜体（`<i>` 的默认样式），顺手改成正体。
- **组件测试（所以倒数第二条验收标准没勾：状态层测试通过、浏览器目测做了，组件测试没写）**：Web 包没有 DOM 测试环境（规格 Testing Decisions："Web UI 不单设切面"），没为这张票引入 jsdom。收放和高亮的规则都在状态层纯函数里测；组件只量长度、照结果渲染，靠下面的浏览器目测。
