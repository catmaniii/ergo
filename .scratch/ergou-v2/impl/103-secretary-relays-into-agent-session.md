# 103 — 秘书往已有的 agent 会话里插一句话（转达用户的话）

Status: ready-for-agent
Blocked by: 无（和 102 同时做：102 是维护者 → 秘书，本票是秘书 → 已有的会话；两张都动秘书的工具和提示，谁先合并后合并的照着改）
Spec: [第一阶段规格](../spec.md) 第 7 节（秘书）、第 12 节"星形通信"；52 号票（会话里的插话）、64 / 66 / 75 号票（项目内部、`delegate_task`）、90 / 100 号票（任务控制的快速动作和"点明了"的判法）、102 号票（`tell_secretary`）

## What to build

用户 2026-10-12："要支持秘书给已有的 Agent 会话里面插入消息。"

现在秘书只能派新活（`delegate_task`、`write_task_brief`）和管任务（暂停、继续、取消、立即运行一次、开关自动播报），没法往已经在跑的任务、项目维护者的会话里补一句话；"告诉 AI 新闻那个任务，以后把 GitHub 热门也加上"这种话，用户得自己去任务详情里说。改成：

1. **秘书能往已有的会话里转达一句话**：
   - 目标有两种：看板上的任务（普通任务、流程、长程任务，含定时 / 事件触发的；就是任务详情里用户能说话的那段会话）和项目的维护者会话（项目页"和维护者交流"那段）。
   - 项目内部的任务秘书看不到（64 号票），要转给它的话转给那个项目的维护者。
   - 照秘书控制任务的写法做成快速动作的一种（比如 `propose_quick_action` 加 `tell_task` / `tell_project`，参数是目标和要转达的话）；实现方觉得单独一个工具更顺也可以，但"点明了"的规矩要一样。
2. **点明了才直接发，否则出卡**：照 100 号票评审后改严的判法。用户这一轮的话里说的是这个任务 / 项目、而且要转达的意思清楚，由运行时直接发；否则出一张卡（写明发给谁、发什么），用户确认了才发。秘书不能自己主动去指挥别的 agent。
3. **怎么插进去**：走用户在任务详情 / 项目维护者会话里直接说话的现有路径（对方正在干活时作为插话、在下一步之前看到；闲着时唤起），只是来源标成"秘书转达"：
   - 对方会话里能看出这句是秘书转达用户的话（不是用户自己打的）。
   - 时间线、详情里有标记。
   - 不算"本人"原话的素材（用户的原话已经在秘书会话里采过）。
   - 对方怎么处理照现有规矩：
     - 普通任务：接着做（做完了的重新变成进行中）。
     - 长程任务：涉及改范围、授权的照常变成计划变更，等用户确认。
     - 流程：执行中不能改步骤，只当补充说明。
     - 定时 / 事件触发的任务：照用户在它的详情里说话现在的行为。
   - 已归档、已取消、不存在的目标拒绝，原因回给秘书，秘书告诉用户。
4. **回音**：对方要回话的用 102 号票的 `tell_secretary`，做完的照 99 号票自动告诉秘书。维护者的提示里加一句：收到秘书转达的话，需要用户知道结果的，用 `tell_secretary` 回。102 号票还没合并时先不写这一句，合并后 rebase 补上。
5. **秘书这边**：转达成功后在主线里说一声"已经转给「AI 新闻日报」了"。秘书提示里写清：什么时候用、点明的规矩，以及只转达用户的意思、不替用户加要求。
6. 规格第 12 节"星形通信"那句跟着改：秘书可以按用户的话往已有的任务、项目维护者会话里转达一句（经运行时、两边都有记录）。

## Acceptance criteria

- [ ] 用户点明了：秘书把话插进普通任务（在干活时是插话、闲着时唤起、做完的重新进行中）、长程任务、定时触发任务、项目维护者会话；对方会话里标成秘书转达；有守护进程主切面测试（faux 剧本断言对方收到的内容和来源）。
- [ ] 没点明：出卡，确认了才发；已归档、已取消、不存在的拒绝并说清原因；有测试（含"点明了"的表格测试）。
- [ ] 转达的话不进"本人"素材；有测试。
- [ ] Web：对方会话里"秘书转达"的样子、卡片；状态层测试；截图只截改动处（经典浅色 390、1280）。
- [ ] 全量测试一次，typecheck、oxlint 通过；`docs/dev.md`、规格第 12 节跟着改。
