# 15 — 项目立项与项目档案

Status: ready-for-agent
Blocked by: 12（任务发起与计划确认）
Spec: [第一阶段规格](../spec.md) 第 11 节（项目与维护者）、第 7 节（秘书）、第 8 节（任务、计划与阶段）、第 5 节（前端协议）、第 15 节（素材）、第 18 节（数据目录与备份）、第 19 节（Web UI）、第 21 节（实现细节补充）

## What to build

做完后，用户能把一件长期的事立成项目。立项有三个入口：在消息里明说或点"新建项目"；秘书给出"建议立项"卡（名字、一句话目标），用户点"立项"；把一个任务转为项目。点"立项"后项目立刻诞生（筹备中），维护者随之产生。用户进入"和维护者交流"，维护者和用户做立项问答，把规格、术语表、ADR 写进项目档案，最后交出立项书（范围、目标、首版要做到什么程度、项目类型是开发类还是其他、是否把工作目录绑定到一个外部路径）和它提议的工具包，作为立项书卡放进待我处理。开发类项目提议的工具包默认带 bash。立项书卡有两个按钮："确认并开工"（项目转建设中，同时发起首个建设任务）和"只确认，稍后开工"（留在筹备中，标"立项书已确认"）；不管点哪个，立项书里的项目类型和外部工作目录绑定在确认时即生效。任务转为项目时不新建维护者，原任务的维护者接着做立项问答，原任务以"已完成 · 已转为项目"结束。

项目档案是数据目录项目区里的一套最小文档：立项书、规格、术语表、ADR、进展、项目清单、范围记录，再加维护者会话；随数据目录备份，永不进外部仓库。工作目录默认在项目档案里面，立项书写明绑定外部路径的，确认后工作目录改到这个外部路径。项目状态机完整可用：首个建设任务完成后，项目自动从建设中进入使用中，不出卡、不等用户判定（不再区分"运营中"和"已完成"）；使用中 ⇄ 已停用，由用户停用、重新启用，已停用项目的维护者照常对话、接工单；放弃、归档、取消归档；删除只能从已归档发起并二次确认，删除时删掉项目档案和维护者会话，但用户在里面说过的话作为素材保留。除了首个建设任务完成这一次自动迁移，项目状态不随任务变，也不随服务在不在线变。

Web UI 上有项目列表（状态、进行中任务数）和简版项目页（状态、"和维护者交流"）。演示：faux provider 剧本走一遍"建议立项 → 立项 → 立项问答（开发类、绑定外部路径）→ 立项书卡'确认并开工'"，造出首个建设任务完成，项目自动转使用中，再停用、重新启用；再把另一个项目放弃到已归档、取消归档、再归档后删除。

## Acceptance criteria

- [ ] 主切面：秘书调用"建议立项"工具只产生一张卡（名字、一句话目标）；用户点"立项"后项目以"筹备中"出现在项目列表频道，同时产生它的维护者；用户点"新建项目"时不经"是不是项目"的判断，直接由秘书收口出卡。
- [ ] 主切面：用户在维护者会话里说话时唤起休眠的维护者；维护者能把规格、术语表、ADR 写进本项目的项目档案，写到项目档案和工作目录之外被守卫拒绝；它提交立项书（范围、目标、首版程度、项目类型、是否绑定外部工作目录及其路径）和提议的工具包后，待我处理出现由结构化数据生成的立项书卡；项目类型为开发类时，提议的工具包默认含 bash。
- [ ] 主切面："确认并开工"后项目转建设中，并建出属于本项目的首个建设任务（规划中，出现在任务看板上），提议的工具包成为项目的工具包；"只确认，稍后开工"后项目留在筹备中，并标"立项书已确认"。两种确认都让立项书里的项目类型和外部工作目录绑定立即生效。
- [ ] 主切面：新项目在数据目录的项目区建好最小文档集（立项书、规格、术语表、ADR、进展、项目清单、范围记录）和维护者会话；工作目录默认在项目档案里；立项书确认绑定外部路径后，维护者的文件工具围栏改为覆盖这个外部路径，备份不包含它。
- [ ] 主切面：项目状态按第 11 节迁移，非法迁移被拒——筹备中 →（确认并开工）建设中；首个建设任务完成时自动由建设中 → 使用中，不出卡、不等用户判定；使用中 ⇄ 已停用（由用户停用、重新启用）；筹备中、建设中可放弃 → 已归档；使用中、已停用 →（只能用户手动）已归档；取消归档回到归档前的状态；删除只能从已归档发起，并要二次确认。除首个建设任务完成外，任务状态变化（包括之后其他任务的完成）不改变项目状态。
- [ ] 主切面：已停用项目的维护者会话照常可以对话；已归档项目的维护者会话只读，用户在里面发话被拒并说明原因；删除项目后它的项目档案和维护者会话被删掉，但用户在该维护者会话里说过的话在素材库（含原文副本）里仍在。
- [ ] 主切面：用户把任务转为项目后，项目诞生（筹备中），不新建维护者，原任务的维护者在同一会话里接着做立项问答；原任务以"已完成 · 已转为项目"结束，出现在看板的最近结束分组里。
- [ ] 主切面：产生对应的素材事件——"建议立项"卡被关闭（回避信号）；立项书卡上的确认（用户对产出的反应）；用户在维护者会话里的发言。由 08 号票采集；若 08 尚未完成，至少事件类型和负载就绪。
- [ ] Web UI：项目列表显示每个项目的状态和进行中任务数，有"新建项目"入口；简版项目页显示状态、项目类型和"和维护者交流"（进入共用的会话组件，已归档时只读），按当前状态给出放弃、停用、重新启用、归档、取消归档、删除这些入口；待我处理里能处理"建议立项"卡、立项书卡（显示项目类型和外部工作目录绑定）和删除的二次确认。前端状态层回放主切面录下的立项和状态迁移事件流，项目列表和项目页显示正确。
- [ ] 所有测试通过（vitest），lint（oxlint）无报错。

## Notes

- 首个建设任务失败或取消时，项目留在建设中；用户可以再发起一个建设任务，或者放弃归档。首个建设任务完成时自动进入使用中，是"项目状态不随任务变"的唯一例外。

- **不在本票**：
  - 首个建设任务本票只建出来；由项目维护者起草计划和执行（单项目任务走工单）归 16。"首个建设任务完成 → 使用中"的触发在本票的测试里可以直接造出完成事件；本票给首个建设任务打上标记，只有它的完成会推动项目状态。
  - 停用时暂停本项目的定时作业、重新启用时恢复，以及项目页上列出本项目的定时作业及各自状态，归 19。项目自己的服务（项目页显示在不在线、停用时撤出 LSM、收回公网入口）是第二阶段。
  - 维护者会话分段（工单段、用户直接对话的"对话段"）、唤起时的固定上下文、每段结束检查进展文档写回和"上一段摘要"、重置维护者（入口在项目页）、发给已归档项目的工单直接退回、项目页的工单流水线归 16；本票的立项问答在 16 完成后就是一个对话段，本票先按一条会话实现。项目页的范围记录归 18；工具包的查看和修改归 27；项目列表上的活动状态小圆点归 25。秘书读项目档案的只读工具归 22。
- 第 11 节：项目状态不再区分"运营中"和"已完成"，首版做完一律进入使用中，没有运营判定卡，也没有"转运营"；项目有没有服务、定时作业不影响项目状态，只在项目页上显示。完整的项目规范模板是第二阶段，本票只建最小文档。
- 项目类型和外部工作目录由维护者在立项问答里问清、写进立项书，用户确认立项书即生效，不另设页面表单。开发类项目默认带 bash（第 9 节）在本票体现为提议的工具包默认含 bash；工具包的装配（noSkills + additionalSkillPaths）和项目页上的查看、修改归 27。
- 秘书收口时"提议记忆范围"（`CONTEXT.md` 的立项条目）第一阶段只占位。
- 立项问答是"grill-with-docs 式"的问答，靠维护者的系统提示；faux provider 下只测运行时一侧。
- 删除时保留用户原话依赖 08 号票的原文副本；08 未完成时至少断言删除项目不触碰事件日志里的用户发言事件。
- 对应用户故事：5、86–95。
