# 08 — 素材采集与索引

Status: ready-for-agent
Blocked by: 06（卡片、待我处理与简单提醒）
Spec: [第一阶段规格](../spec.md) 第 15 节（素材）、第 4 节（存储与事件）、第 13 节（调度）、第 18 节（数据目录与备份）、第 21 节（实现细节补充）

## What to build

从这张票起，用户说过的话开始作为素材入库：守护进程从事件日志确定性地产生素材，agent 没法挑选；每条素材有统一的信封，标明是说还是做、来源等级和情境；用户本人的原话另存一份不可修改、只追加的原文副本。素材写在单独的 `memory.db` 里，只由素材模块写，并建好中文可用的关键词索引（FTS5 trigram，3 个字以下的查询退回子串扫描）和向量索引（守护进程里用本机 CPU 跑量化版 bge-m3，后台异步补算，不出本机；模型文件不在时提示用户运行一条下载命令）。

除了用户发言，还要从卡片事件里产生回避信号：卡片被用户关闭，或建议卡、提问卡 7 天没处理。七类素材事件的采集接口全部立起来，其余来源（审批决定、澄清回答、任务结局等）的票落地时按这个接口接入。

第一阶段只积累和建索引，不做抽取和推断，也没有素材的页面。能演示的是：在秘书页说几句话，素材库里出现对应的素材和原文副本，按关键词和按语义都能检索到。

## Acceptance criteria

- [ ] `memory.db` 是单独的库（WAL），只有素材模块拿得到写入口。素材信封为 `{id, 类型, 说或做, 时间, 来源会话, 任务或项目, 来源等级（本人 / agent / 外部不可信 / 系统）, 指向原始记录的引用, 情境标签, 切段, 原文副本（仅本人）}`。
- [ ] 采集是确定性的：素材由守护进程从事件日志产生，agent 没有任何写素材或挑选素材的工具；同一段事件日志重复处理（包括守护进程重启后）不产生重复素材；清空 `memory.db` 后从事件日志重建，得到相同的素材。agent 之间的内部往来、从记忆召回的内容不产生素材。
- [ ] 七类素材事件（用户发言、用户对产出的反应、审批决定、澄清问题的回答、用户主动投喂的材料、显式记忆命令、任务结局）和回避信号都已定义类型，各自注明是说还是做；有一个采集接口，其他票能把自己的事件类型登记为某类素材。
- [ ] 用户发言：任何会话里的用户消息（现在是秘书会话；维护者会话出现后同样适用，包括附件引用）都产生素材。主切面：前端发一条消息后，`memory.db` 里出现对应的素材。
- [ ] 切段与来源标记是纯函数、按确定的规则，表格测试覆盖：用户自己打的字标"本人"；引用块、附件、抓取的网页标"外部、不可信"；用户接受了 agent 的提议算用户的选择，注明"agent 先提出"；语音转写标"本人"并注明"转写"（第一阶段只预留）；判断不了的纯文本默认"本人"。
- [ ] 原文副本：来源为"本人"的切段另存一份原文副本，放在数据目录的素材区，不可修改、只追加，素材模块不提供改写它的接口（删除只由用户发起，见 21 号票）；agent 的产出、附件和外部内容只存引用加内容哈希。
- [ ] 回避信号（时钟可注入）：卡片被关闭的事件产生一条回避信号素材；"建议发起任务"卡、"建议立项"卡、提问卡 7 天（默认，可配置）没处理时，由调度器的内部作业产生一条回避信号素材，7 天内处理了的不产生。
- [ ] 关键词索引用 SQLite FTS5 的 trigram 分词器，中文检索可用。trigram 查不了 3 个字以下的词，这类查询退回子串扫描：测试覆盖三个字以上和两个字、一个字的中文查询，都查得到。
- [ ] 向量索引：守护进程里用 CPU 跑量化版 bge-m3（transformers.js 加 ONNX 模型），模型文件放在数据目录的模型区；素材入库后后台异步补算，不卡写入和对话（测试：素材写入在向量算出之前就返回）；每条向量旁记下模型名，换模型时整批重算；相似度检索用暴力扫描。模型文件不存在时，守护进程提示用户运行一条下载命令（本票提供这条命令，把模型文件下载到模型区），期间素材入库和关键词索引照常，模型文件就位后补算缺的向量。素材模块对外提供关键词和向量两种检索；测试里可以注入一个假的向量函数。
- [ ] 所有测试通过（vitest），lint（oxlint）无报错。

## Notes

- 本票接上已经存在的来源：用户发言（04）、卡片被关闭（06）；若 07 已完成，也接上审批决定。其余来源由产生它们的票按本票的接口接入：审批决定（07，以及 12、14、20、27 里的各种确认）、澄清问题的回答和建议卡与提问卡的关闭（12）、任务结局、用户对产出的反应和维护者会话里的发言（13）、"建议立项"卡的关闭（15）、显式记忆命令（21）。批准设备配对不算素材（10）。
- "用户主动投喂的材料"的入口是聊天附件菜单里的"作为材料投喂"，由 21 号票做（复用 09 号票的上传）；本票只定义它的类型和采集接口。
- 不在本票：忘掉、彻底删除、别推断和按会话或时间段删除，秘书的素材检索工具（21）；`memory.db` 和素材区的备份（11）；抽取、推断、记忆页面（第二阶段）。
- 被素材引用的媒体永不回收（第 5 节），09、11 处理媒体时要遵守。
- 向量计算要放在不阻塞守护进程事件循环的地方。模型文件不随仓库分发、不自动下载，由用户运行下载命令放进模型区。
