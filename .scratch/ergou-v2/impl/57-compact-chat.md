## What to build

用户的要求：

- 聊天界面里显示的东西要尽量切中要害。
- 工具调用不要每一步、每个参数都列出来，归到一条里。这一条不是聊天气泡，而是高度很小的一行字，右边一个 ›，暗示能点开。点开后，右边的详情页再看调了哪些工具、什么参数、返回了什么。
- 有详情的气泡要有展开按钮，让人知道能展开。

## Acceptance criteria

- [x] **工具调用组**：一轮里两段话之间连续的、顺利执行的工具调用，显示成一行小字"调用了 N 个工具 ›"。
  - 不是气泡，高度很小。
  - 命中关注类别的加小签，比如"· 1 次做完告诉你"。
  - 点开进详情页（56 号票）。
- [x] **出问题的调用也在框里**（用户 2026-10-09 改）：被拦下、问过你、你拒绝了、出错、等你批准的调用不单独成横条，放在同一个"调用了 N 个工具 ›"的框里、按先后排；那一行加小签标出出了什么问题（比如"· 1 次被拦下""· 1 次出错"），颜色比顺利的组醒目；点开在详情里看是哪一次。审批卡本身照旧单独一张（要用户点）。
- [x] **连续的同类调用合成一条**（用户 2026-10-09，照 AgentSense 最新代码 `web/src/ui/ZoomHistory.tsx` 的 runs 折叠）：组的详情、展开后的列表里，连续 3 次以上、都顺利执行的同一个工具只留第一条，下面挂"还有 N 次同样的操作，都在授权内 ▾"，点开才逐条显示；默认收起。
- [x] **回复**（用户 2026-10-10 改）：照 AgentSense 整段展开，后面有内容时给"收起 ▴ / 展开细节 ▾"和"详情 ›"。~~只显示第一段~~作废。
- [x] **思考**：默认一行"💭 ……（点开看）"，加"详情 ›"。
- [x] **用户气泡**：可以点。
- [x] **展开标记**（用户 2026-10-10 改）：凡是有详情的条目都带 › 或 ▾。例外：用户气泡、系统说明和时间线记录照 AgentSense，整条可点，不带 ›。
- [x] **语音气泡**：照旧，沿用 36 号票的同框。
- [x] **测试**：前端状态层回放测试，覆盖各种条目的显示形态。
- [x] **和 AgentSense 不一致的地方先问用户**（2026-10-10 问过，见 Comments）。用户要的汇总行是在 AgentSense 之上加的。
- [x] 所有测试通过（vitest），lint（oxlint）无报错。
