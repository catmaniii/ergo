## What to build

做完后，一个任务可以同时改多个项目，而每个项目仍然只有它自己的维护者能改。涉及多个项目的任务在建卡时产生自己的维护者，它的工具包固定为三样：读项目档案、派工单、汇总回执。规划时它只读各项目档案、不发工单，计划里逐行列出每个项目改什么；用户在计划卡上确认时，这些改动建成发给各项目的工单，每张带自己的验收标准，在任务详情里就能看到；每张工单等它所属的阶段开始时才派出、进入项目维护者的队列。

项目维护者按队列一次做一件，完成或退回时交回执，回执进任务维护者的会话；项目维护者可以退回会伤害自己项目的改动，并说明理由。项目维护者做到一半要问的，工单转"等澄清"，问题交给派单的任务维护者回答，任务维护者答得了就直接答，答不了可以再转问用户。某个阶段的工单回执全部到齐后，任务维护者再跑一遍本阶段的验收；任何一张被退回或做不了，本阶段不通过，任务维护者可以调整做法（算一次验收退回），或转为等我。按依赖重开某个阶段时，向相关项目重新派工单。计划外的工单要用户确认，计划内的随计划一次确认。agent 之间只通过工单往来，全部记在任务时间线上。

任务详情页列出这个任务的所有工单。演示：faux provider 剧本建一个涉及项目 A、B 的任务——计划卡逐行列出 A、B 的改动；确认后两张工单出现在任务详情里，所属阶段开始时分别进入 A、B 的工单流水线；B 的维护者退回，阶段不通过；任务维护者调整后重新派单，两张都完成，阶段验收通过。

## Acceptance criteria

- [x] 主切面：涉及多个项目的任务在建卡时产生自己的维护者，它的工具包只有读项目档案、派工单、汇总回执三样（另有每个维护者都有的运行时控制工具，比如提交计划、宣布阶段完成），没有文件写入、bash、联网；它试图写任何项目的项目档案或工作目录都做不到。
- [x] 主切面：规划期间任务维护者只能读各项目档案，派工单被拒；计划卡逐行列出每个项目的改动；用户确认计划时每一行建成一张发往对应项目的工单（带自己的验收标准，写明所属任务和阶段），此时还不进项目维护者的队列；所属阶段开始时才派出、进入该项目维护者的队列。前置阶段没验收时，后面阶段的工单不会出现在项目的工单流水线里。
- [x] 主切面：项目维护者完成或退回时交回执，回执作为一条消息进任务维护者的会话；退回必须附理由；所有工单的建出、派出和回执都记在任务时间线上。
- [x] 主切面：项目维护者提问时工单转等澄清，问题作为一条消息进任务维护者的会话；任务维护者直接回答时，回答交回项目维护者、工单回到进行中；任务维护者转问用户时，问题以提问卡进待我处理，用户回答后经任务维护者交回项目维护者。项目维护者的问题不直接出给用户。
- [x] 主切面：某阶段的回执全部到齐且全部完成后，任务维护者跑本阶段验收（沿用 13 号票的验收流程）；任何一张被退回或做不了，本阶段不通过；任务维护者调整做法记为一次验收退回，或者转为等我。
- [x] 主切面：按依赖重开（返工）某个阶段时，向这个阶段涉及的项目重新派工单；没受影响的阶段不重派。
- [x] 守卫切面 + 主切面：执行中任务维护者派出计划外的工单时命中"计划外工单"类别（任务里默认先问我），工单处于"待你确认"，待我处理出现工单卡；用户确认后才进入项目维护者的队列，拒绝则不派；计划内的工单不再单独确认。
- [x] 主切面：产生对应的素材事件——用户对计划外工单的确认或拒绝（审批决定）；用户对转问过来的问题的回答（澄清问题的回答）。由 08 号票采集；若 08 尚未完成，至少事件类型和负载就绪。
- [x] Web UI：任务详情页列出该任务的所有工单（收件项目、状态、所属阶段，已建出未派出的也在列），回执和项目维护者的提问显示在任务维护者的会话里；工单卡能在待我处理里确认或拒绝。前端状态层回放主切面录下的"派单 → 一张退回 → 重派 → 全部完成"事件流，工单列表和阶段状态正确。
- [x] 所有测试通过（vitest），lint（oxlint）无报错。
