# 99 — 任务做完（含定时任务每次运行完）告诉秘书，秘书问要不要念出来

Status: done
Blocked by: 无（和 97、98 同时做；谁先做完谁先合并，后合并的照着改）
Spec: [第一阶段规格](../spec.md) 第 22 节（语音）、秘书的看板感知（22 号票）；86 号票（发语音 `send_voice`）、76 号票（定时触发的任务）、77 号票（二狗内部事件）

## What to build

用户 2026-10-12："这些任务完成的时候，包括定时任务完成的时候，都要告诉秘书二狗一下，通知二狗之后，他就可以问我要不要把这个合成语音播报出来。"

现在秘书不主动知道任务做完了：看板变化攒到用户下一条消息时才带给秘书（`board/board-watch.ts`），运行时的通知不带。改成：

1. **做完就告诉秘书**：任务变成已完成（普通任务、流程、长程任务），和定时 / 事件触发的任务每一次运行完（`scheduled_job` 的 `run_finished`，运行成功的），守护进程给秘书一条系统通知（照现有"系统通知标记"的写法），写明哪个任务（编号、标题、做法；定时的写第几次运行、什么时候触发的）和做出来的结果（维护者最后说的那段话、交付的文件名；太长截短并写明截了）。项目内部的任务、作业不告诉秘书（照 64 / 66 号票：秘书看不到项目内部的细节）。几件事差不多同时做完的并成一条。
2. **秘书主动在主线里说一声，问要不要念出来**：秘书收到这条通知后在和用户的主线会话里发一条（不等用户先开口）：用一两句话说哪个任务做完了、结果大概是什么，问"要我念给你听吗？"。用户说要（打字或语音），秘书照 86 号票用发语音（`send_voice`）把结果的口语稿合成成语音气泡；用户说不用就算了。秘书的系统提示（`packages/daemon/prompts/secretary.md`）里写清这条规矩：结果的原文在任务里，口语稿要像说话，念不出来的（链接、表格、代码）不念、说"链接在任务里"。
3. 失败、等我的照现在的规矩（待办通知），不在本票。
4. 秘书正在和用户说话（忙）时，通知排在后面，这一轮完了再说；秘书没起来时，起来后补说。

规格里"运行时给秘书的通知不带，变化攒到下一条用户消息"那句跟着改（主会话改规格）。
