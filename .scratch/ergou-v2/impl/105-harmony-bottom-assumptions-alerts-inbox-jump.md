## What to build

用户 2026-10-12 提了三件事：

### 1. 鸿蒙 App：界面拉满到屏幕最下方

原话："在鸿蒙手机上，不管是竖屏还是横屏，最下方都有一条白色的空白。希望可以利用起来，把界面下方拉满。哪怕最后左下角和右下角有一部分被挡住，问题也不大。"

- 现在 `frontend/harmony/entry/src/main/ets/pages/Index.ets` 的 Web 组件按系统避让区排版，底部手势条那一截留白。
- 改成 Web 组件延伸到底部系统避让区（比如 ArkUI 的 `expandSafeArea([SafeAreaType.SYSTEM], [SafeAreaEdge.BOTTOM])`，或窗口全屏布局再只避让顶部状态栏；照 API 版本选能用的）。竖屏、横屏都拉满。
- 顶部状态栏照旧不遮。
- 被手势条压住的那一小截：底部导航、输入栏能不能用要过得去，用户说角上挡一点不要紧。如果压住了导航文字或输入栏，可以经现有的原生桥（`NativeBridge`）把底部避让高度告诉页面，让页面底部留一点，但不要再留出整条白边。
- 浅色、深色下延伸出去的那截颜色跟页面底色一致，不能是白条。
- **子 agent 不碰设备**：只改代码，过 `tsc -p frontend` 的类型检查（照仓库做法）。主会话合并后自己 `npm run build:harmony`，用 hdc 装到手机、平板上看。
- 写清楚怎么在真机上核对。

### 2. 计划卡（立项、发起任务时）的假设：每条改成多行编辑

原话："立项的时候的多个假设，每一条都可以修改，但是都是单行输入框，第一看不全，第二内容长了要找到合适的修改位置也不方便。"

- `ui/cards/PlanCard.tsx` 假设栏现在每条是 `<input>`。改成随内容自动长高的多行文本框，内容全显示、能在任意位置改。
- 清空就是去掉这一条，照旧。
- 顺手查一遍卡片里别的"一条一条可改"的单行框，同样的问题一起改，比如立项书、任务书、计划卡里别的列表项。

### 3. 页面顶上的通知不堆着；待办里每一项都能跳到它从哪来的地方

原话："通知信息不要一直堆在上方，应该定时关闭或者收起来，因为待办那边也有红点提醒了。另外，从待办里面点击相关的通知或者是事务，应该给加一个按钮，跳转到对应的界面。例如，任务的提醒，有个按钮可以跳转到负责任务的 agent 的聊天界面。项目的提醒，有个按钮可以跳转到负责这个项目的 agent 的聊天界面。诸如此类，是哪里来的提醒，都要可以跳转过去。"

**页面顶上的通知**（`ui/alerts.tsx` 的 `AlertsView`，现在一条条叠在顶上、直到用户看或关）：
- 每条出来后过一会儿自动收起，比如 8 秒；手指或鼠标停在上面时不收。
- 同时好几条时只露最新一条，加一句"还有 N 条，在待办里"。
- 自动收起只是不在顶上显示，待办里那一项和红点照旧。
- 浏览器通知照旧。

**待办里每一项加"去看看 ›"一类的跳转按钮**，跳到这一项的来源：
- 任务的事项（计划确认、审批、验收、卡住求助、澄清、中断不确定、超预算……）→ 这个任务的整页，也就是负责它的 agent 的会话。能定位到那条调用、那个阶段、那张卡的，就定位过去。
- 项目的事项（项目内部任务的事项、计划外工单、立项、范围记录……）→ 这个项目的整页，也就是维护者的会话。能定位到工单 / 内部任务的就定位过去。
- 定时 / 事件触发任务某次运行的事项 → 这个任务的整页，定位到那次运行。
- 简单提醒到点 → 日历上那一天，或者提醒所在的地方，挑现有能去的。
- 秘书会话里来的（快速动作卡、建议卡……）→ 秘书会话里那条消息。
- 系统的（每周归档清单、节假日更新……）→ 对应的页面（看板、设置……）。

实现方先把待我处理里现有的所有事项种类列一张表：每种跳到哪，哪些已经有跳转、哪些没有。没有合适去处的写明原因，写在 Comments 里。

跳转用现有的地址路由（`#/tasks/<任务>`、`#/projects/<项目>`……）。缺数据（事项上没有记来源）的照仓库惯例补上，旧事项缺来源的不出按钮。
