# 102 — 维护者能主动给秘书发消息（`tell_secretary`），秘书转告用户

Status: ready-for-agent
Blocked by: 无
Spec: [第一阶段规格](../spec.md) 第 12 节"星形通信"、第 7 节（秘书）；99 号票（任务做完告诉秘书）、100 号票（自动播报）、64 / 66 / 75 号票（项目内部任务、秘书看不到项目内部、`delegate_task`）、ADR-0003（不设角色，工具包按项目或任务配）

## What to build

用户 2026-10-12："现在好像项目维护者缺乏一个工具去给秘书发消息，比如他任务完成之后，主动给秘书发消息通知，让秘书来通知用户……或者加一个不同的 agent 之间互相发消息的工具，然后我可以设定一个秘书的角色，这样他就用这个工具给秘书发消息。"

现在维护者没法主动找秘书：99 号票只在任务做完时由运行时自动告诉秘书（项目内部的任务、工单只收到一句不带结果的"项目「X」里交出去的一件事做完了"）；做到一半有用户该知道的事（发现了什么、阶段性结果、提醒用户看一眼），只能等用户自己来看。

主会话定的做法（不做通用的 agent 互发消息，见 Comments 第一条）：

1. **新工具 `tell_secretary`**：维护者（任务的维护者、项目的维护者——含工单、项目内部任务、定时 / 事件触发的运行）给秘书发一条消息。参数：`text`（必填，要告诉用户的话，最多 2000 字）。秘书、子 agent、评审子 agent 没有这个工具。
   - 收件人写成可扩展的形式（工具定义里收件人目前只有"秘书"一种，以后要加别的收件人只加登记项），但本票只做秘书。
   - **工具包里的一项能力开关**（和 bash、联网一样）：默认开；用户可以在任务 / 项目的工具包里关掉（"给秘书发消息"）。关掉时维护者看不到这个工具。
2. **运行时转交**：不直接进秘书会话，由守护进程给秘书一条系统通知（照 99 号票的写法和标记风格，比如开头`【维护者来信】`），写明谁发的（项目「X」的维护者 / 任务 t-3「…」的维护者，在做哪张工单、哪个任务、第几次运行时）和原话。和 99 号票同一套交法：秘书闲着才交、忙时排在这一轮后面、没起来时起来后补、处理到一半被打断起来后重交；幂等（同一次工具调用只交一次，重启不重复）；和差不多同时到的任务做完通知可以并成一条。
3. **秘书怎么做**：在主线里主动用自己的话转告用户（哪个项目 / 任务、说了什么、要用户做什么就说清楚），像 99 号票一样问"要我念给你听吗？"（用户说要就用 `send_voice`；这一类通知本身不放行发语音，照 100 号票只放行开了自动播报的任务做完）。秘书提示里写清这条规矩；项目内部的细节只到维护者愿意写进来的程度，秘书不追问内部细节。
4. **维护者的提示**：什么时候用——做到一半有用户现在就该知道的事、项目内部的任务或工单做完了想把结果告诉用户；不要用的——不属于项目的任务做完（运行时已经自动告诉秘书，带着你最后说的话，99 号票）、要用户批准或决定的事（走审批 / 待我处理）、闲聊。不要把密钥、密码写进去。
5. **防刷屏**：同一个维护者 10 分钟内最多 3 条，超了工具回"发得太频繁，攒一攒一起说"；和上一条一字不差的不再发。
6. **记录**：维护者那边照常是一条工具调用（时间线、工具调用详情里一句人话"给秘书发了消息：…"）；秘书主线里是秘书转告的那条回复。规格第 12 节"星形通信"那句改成：agent 之间只有工单，外加维护者给秘书的单向消息（经运行时转交，两边都有记录），不做 agent 群聊。

## Acceptance criteria

- [ ] 任务维护者、项目维护者（工单里、项目内部任务里、定时运行里）调 `tell_secretary`，秘书收到系统通知并在主线里转告、问要不要念；有守护进程主切面测试（faux 剧本断言秘书收到的通知内容）。
- [ ] 秘书、子 agent 没有这个工具；工具包里关掉"给秘书发消息"后维护者看不到它；有测试。
- [ ] 秘书忙时排后、没起来起来后补、中断后重交、重启不重复；10 分钟 3 条的上限和重复的拒发；有测试。
- [ ] Web：工具包设置里多一项开关；工具调用的人话写法；状态层测试；截图只截改动处（经典浅色 390、1280）。
- [ ] 全量测试一次，typecheck、oxlint 通过；`docs/dev.md`、规格第 12 节跟着改。

## Comments

- 2026-10-12 主会话：用户也提了"不同 agent 之间互相发消息的工具"。没做通用的，原因：规格第 12 节定的是星形通信（agent 之间只有工单，经派单器排队、记在任务时间线上），维护者之间互发消息会绕开工单的计划核对和执行权限、项目之间的内容隔离（64 / 66 号票），还可能来回刷、白耗 token。维护者 → 秘书这一条是单向、经运行时转交、内容由维护者自己挑，不破这些边界。收件人做成可扩展的，以后要别的收件人再加。
