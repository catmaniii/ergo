# 104 — 项目页照任务页改：项目一览全屏、点卡片全屏进项目，和任务看板有视觉差异

Status: ready-for-agent
Blocked by: 无
Spec: [第一阶段规格](../spec.md) 第 19 节（Web UI）；88 号票（宽屏任务看板全屏、点卡片全屏进任务）、15 / 16 / 64 号票（项目、工单、项目内部任务）、39 号起的视觉风格

## What to build

用户 2026-10-12："项目页面也和任务改成类似的风格吧：项目一栏页面全屏显示，点击项目卡片进入全屏的和项目维护者的对话和详情界面。不要把项目一览栏放在对话框的最左边，这样项目对话和详情部分的空间不够。但是全屏的项目一览和管理界面的风格要和任务一览和管理界面体现出一定视觉差异。"

现在宽屏的项目页是左边项目列表、右边项目（`ListDetail`），项目的维护者对话和详情挤在右边。照 88 号票任务页的做法改：

1. **项目一览全屏**：
   - 没点项目时，整个内容区是项目一览，每个项目一张卡。
   - 按项目状态分组：使用中、建设中、筹备中、已停用、已归档。已归档默认收起，照 90 号票看板分组能收起的做法。
   - 列数随宽度自适应。
   - 顶上照旧有"立项"入口，以及项目页现有的管理操作。
2. **点项目卡片 → 全屏进项目**：
   - 整页是这个项目：和维护者的对话，加上项目的详情（立项书 / 档案、工单流水线、内部任务、定时触发的、工具包、消耗等现有内容）。
   - 宽屏下对话占主区，详情照任务详情的做法放在能开合、能拖宽的侧栏或页签里，对话区要够宽。
   - 左上角 ‹ 返回一览；浏览器后退、鸿蒙返回键也回一览，回来保持滚动位置。
   - 从别处跳进项目（待我处理、聊天里的卡片、秘书的建议立项卡、通知、`#/projects/<项目>`）直接打开全屏的项目。
   - 窄屏（手机）照现在的一览 → 进项目，只跟着用新的卡片样子。
3. **和任务看板要有看得出的视觉差异**：
   - 任务看板：紧凑的多列小卡，带进度条、状态签、token。
   - 项目一览：做成"档案墙"的感觉。卡片更大、列更少（最小宽度比任务卡大，比如 360 左右）。每张卡像一份档案或文件夹：
     - 上沿有一个页签，写项目种类和状态；
     - 正文是项目名（大）和一句话目标；
     - 底下一行写维护者在干什么（休眠 / 干活中）、进行中的内部任务数、定时触发的有几个、服务在线没有、最近一次动静。
   - 一览顶上有一条概览："使用中 N · 建设中 N · 服务在线 N"之类。
   - 只用风格现有的 token，不给 11 套风格各加一套新配色。差异主要靠版式和卡片结构。可以用风格里已有的、和任务看板强调色不同的那个色做点缀；拿不准就先做经典，截图给主会话看。
   - 水墨国风、复古杂志的任务看板是一行一行的（用户定的），项目一览在这两套里也要排得好看，和它们自己的任务看板也有差异。
4. 只改项目页。任务页、待我处理不动。

- [ ] 点卡片进全屏项目，对话占主区、详情可开合；‹、浏览器后退回一览并保持滚动位置；从待我处理、聊天卡片、通知跳进项目直接全屏；有测试。
- [ ] 窄屏（390、360）一览 → 进项目照旧，卡片用新样子；有截图核对。
- [ ] 视觉差异：同一宽度下任务看板和项目一览并排一张对照图（经典浅色 1280），让主会话拿去给用户看。
