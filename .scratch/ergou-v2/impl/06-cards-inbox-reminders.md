# 06 — 卡片、待我处理与简单提醒

Status: ready-for-agent
Blocked by: 04（秘书聊天最薄端到端）
Spec: [第一阶段规格](../spec.md) 第 5 节（前端协议）、第 7 节（秘书）、第 8 节（任务、计划与阶段）、第 13 节（调度）、第 15 节（素材）、第 21 节（实现细节补充）

## What to build

用户对秘书说"明早 9 点提醒我交报告"，秘书直接建好简单提醒，聊天里出现一张提醒卡，可以改、可以取消；也能建重复的提醒（每天、每周几、每月几号；"按我的工作日"由 29 号票加进同一套重复规则）。到点时调度器直接通知前端，不拉起任何 agent：待我处理里出现一条置顶的提醒事项，页面内给出提示，用户允许时再发一条浏览器通知。用户也可以在对话里让秘书改时间或取消。

为此要立起卡片和待我处理这套通用机制，后面所有卡片都建在它上面：卡片是独立实体，消息里只放引用；同一张卡在聊天、待我处理（以后还有时间线）里只有一份状态，在哪里处理都同步。按钮闭环按版本条件更新、先到先得，两台设备同时点同一张卡，后到的看到"已被处理"。待我处理汇集要用户处理的卡和通知类事项，带紧急度三档，可标已读、归档、删除；有未读时 tab 亮小红点，看过没处理的显示灰色数字。

02 号票的待我处理页和秘书页里的卡片从这里起接真数据。调度器（含可注入时钟）也在本票立起，以后的定时作业、错过补发和各种内部作业都挂在它上面。

## Acceptance criteria

- [ ] 卡片实体 `{id, 类型, 版本, 状态, 负载, 紧急度?, 创建和处理时间, 处理结果}` 独立存储，消息里只放卡片引用；卡片的新建和更新在卡片频道推送。主切面（两个模拟前端）：在聊天里处理一张卡，待我处理里的同一张卡同步变化。
- [ ] 按钮闭环：前端发"对卡片做动作" `{卡片 id, 动作, 期望版本, 幂等键}` → 服务端按版本条件更新 → 回 ack → 卡片频道推送更新。两个模拟前端用同一期望版本点同一张卡，只有一个生效，另一个得到"已被处理"；同一幂等键重发不会做两次。卡片动作只接受来自前端的请求，秘书没有任何对卡片做动作的工具。
- [ ] 卡片类型注册表：每种卡登记类型、schema、版本和纯文本降级版本，负载按 schema 校验；前端遇到不认识的类型时显示纯文本加"去 Web 处理"的链接（前端状态层回放测试覆盖）。本票登记简单提醒卡，其他卡由各自的票登记。
- [ ] 待我处理：事项包括需要处理的卡和通知类事项；紧急度三档（卡住任务且有时限、卡住任务、不卡任务），按紧急度排序，置顶的事项排在最前；可标已读、归档、删除；紧急度为前两档（卡着任务）的事项在处理前归档或删除会被拒并说明原因（本票在模块层测，卡着任务的事项出现后由产生它的票补主切面场景）。已读和已处理状态在多个前端之间实时同步。
- [ ] 待我处理页接真数据：有未读时 tab 亮小红点；看过没处理的事项用灰色数字显示还剩几件；紧急度只在 Web 内体现（小红点和排序），不做手机推送。
- [ ] 简单提醒：建、改、取消简单提醒是秘书只产生卡片的自定义工具，秘书在同一轮里自己选用，不另加分类器。重复规则本票支持每天、每周几、每月几号，规则的写法留出让 29 号票加"按我的工作日"的位置。主切面（faux 剧本）：用户说"明早 9 点提醒我交报告" → 秘书调用建提醒的工具 → 提醒建好，聊天里出现提醒卡（显示时间或重复规则和内容，有"改"和"取消"）；用户点卡上的按钮能改时间或取消；秘书按用户的话也能改、能取消已有的提醒。一次性提醒：待触发 → 已触发；重复提醒一直待触发。
- [ ] 调度器在守护进程里，时钟可注入。主切面把时钟拨到点：前端收到提醒通知，待我处理里出现一条置顶的提醒事项，期间没有拉起任何 agent 子进程；一次性提醒卡变成已触发；三种重复规则各有一条用例，验证按规则在下一个该触发的时刻再次触发。提醒存在 `ergou.db` 的派生视图里，守护进程正常重启后，还没到点的提醒照常触发。
- [ ] 到点的前端提示（手动验证）：在 Web 的任意页面，到点时出现页面内提示，待我处理顶部是这条提醒；用户允许浏览器通知时，另外弹出一条浏览器通知；不允许时只有页面内提示和待我处理事项。
- [ ] 产生对应的素材事件：卡片被用户关闭时产生"卡片被关闭"事件（带卡片类型、id、时间），事件类型和负载就绪，供 08 号票产生回避信号。
- [ ] 所有测试通过（vitest），lint（oxlint）无报错。

## Notes

- 其他卡片由各自的票登记：审批卡和"交给我做"事项（07）、配对请求卡（10）、提问卡、"建议发起任务"卡和计划确认卡（12）、进度卡（13）、计划变更卡（14）、"建议立项"卡和立项书卡（15）、工单卡（17）、并行确认卡（20）、快速动作卡和记忆删除卡（21）、计划变更卡里的"工具包变更"（27）。
- 本票只提供通用的通知类事项（含置顶）；具体的通知（错过的提醒、中断不确定、越界通知、备份失败、快照校验失败、定时作业被自动暂停、归档清单、授权到期续期、卡住求助和失败后的抉择）由产生它们的票加。
- 不在本票：简单提醒在任务看板上显示为"运营中 · 待触发"（12 号票接看板时做）；启动时补发错过的提醒（60 分钟内照发并标明晚了多久、更晚的进待我处理、重复提醒错过多次只按最近一次）和定时作业（19）；建议卡、提问卡 7 天没处理的计时和回避信号素材（08）；秘书列出待我处理、把同一张卡放进聊天，"承诺即任务"（22）；时间线里的卡片（25）；个人工作日历和"按我的工作日"这种重复规则（29，加在本票的调度器和提醒工具上）；手机系统级推送（第二阶段）；"了解你"问题（第二阶段，不进待我处理）。
- 07 号票接通守卫后，这几个只产生卡片的工具在工具注册表里登记为不落入任何类别。
- 浏览器通知要先征得用户允许；不允许或浏览器不支持时，不影响页面内提示和待我处理事项。
