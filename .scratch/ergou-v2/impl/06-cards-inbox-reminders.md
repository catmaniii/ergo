# 06 — 卡片、待我处理与简单提醒

Status: ready-for-agent
Blocked by: 04（秘书聊天最薄端到端）
Spec: [第一阶段规格](../spec.md) 第 5 节（前端协议）、第 7 节（秘书）、第 8 节（任务、计划与阶段）、第 13 节（调度）、第 15 节（素材）、第 21 节（实现细节补充）

## What to build

用户对秘书说"明早 9 点提醒我交报告"，秘书直接建好简单提醒，聊天里出现一张提醒卡，可以改、可以取消；也能建重复的提醒（每天、每周几、每月几号；"按我的工作日"由 29 号票加进同一套重复规则）。到点时调度器直接通知前端，不拉起任何 agent：待我处理里出现一条置顶的提醒事项，页面内给出提示，用户允许时再发一条浏览器通知。用户也可以在对话里让秘书改时间或取消。

为此要立起卡片和待我处理这套通用机制，后面所有卡片都建在它上面：卡片是独立实体，消息里只放引用；同一张卡在聊天、待我处理（以后还有时间线）里只有一份状态，在哪里处理都同步。按钮闭环按版本条件更新、先到先得，两台设备同时点同一张卡，后到的看到"已被处理"。待我处理汇集要用户处理的卡和通知类事项，带紧急度三档，可标已读、归档、删除；有未读时 tab 亮小红点，看过没处理的显示灰色数字。

02 号票的待我处理页和秘书页里的卡片从这里起接真数据。调度器（含可注入时钟）也在本票立起，以后的定时作业、错过补发和各种内部作业都挂在它上面。

## Acceptance criteria

- [x] 卡片实体 `{id, 类型, 版本, 状态, 负载, 紧急度?, 创建和处理时间, 处理结果}` 独立存储，消息里只放卡片引用；卡片的新建和更新在卡片频道推送。主切面（两个模拟前端）：在聊天里处理一张卡，待我处理里的同一张卡同步变化。
- [x] 按钮闭环：前端发"对卡片做动作" `{卡片 id, 动作, 期望版本, 幂等键}` → 服务端按版本条件更新 → 回 ack → 卡片频道推送更新。两个模拟前端用同一期望版本点同一张卡，只有一个生效，另一个得到"已被处理"；同一幂等键重发不会做两次。卡片动作只接受来自前端的请求，秘书没有任何对卡片做动作的工具。
- [x] 卡片类型注册表：每种卡登记类型、schema、版本和纯文本降级版本，负载按 schema 校验；前端遇到不认识的类型时显示纯文本加"去 Web 处理"的链接（前端状态层回放测试覆盖）。本票登记简单提醒卡，其他卡由各自的票登记。
- [x] 待我处理：事项包括需要处理的卡和通知类事项；紧急度三档（卡住任务且有时限、卡住任务、不卡任务），按紧急度排序，置顶的事项排在最前；可标已读、归档、删除；紧急度为前两档（卡着任务）的事项在处理前归档或删除会被拒并说明原因（本票在模块层测，卡着任务的事项出现后由产生它的票补主切面场景）。已读和已处理状态在多个前端之间实时同步。
- [x] 待我处理页接真数据：有未读时 tab 亮小红点；看过没处理的事项用灰色数字显示还剩几件；紧急度只在 Web 内体现（小红点和排序），不做手机推送。
- [x] 简单提醒：建、改、取消简单提醒是秘书只产生卡片的自定义工具，秘书在同一轮里自己选用，不另加分类器。重复规则本票支持每天、每周几、每月几号，规则的写法留出让 29 号票加"按我的工作日"的位置。主切面（faux 剧本）：用户说"明早 9 点提醒我交报告" → 秘书调用建提醒的工具 → 提醒建好，聊天里出现提醒卡（显示时间或重复规则和内容，有"改"和"取消"）；用户点卡上的按钮能改时间或取消；秘书按用户的话也能改、能取消已有的提醒。一次性提醒：待触发 → 已触发；重复提醒一直待触发。
- [x] 调度器在守护进程里，时钟可注入。主切面把时钟拨到点：前端收到提醒通知，待我处理里出现一条置顶的提醒事项，期间没有拉起任何 agent 子进程；一次性提醒卡变成已触发；三种重复规则各有一条用例，验证按规则在下一个该触发的时刻再次触发。提醒存在 `ergou.db` 的派生视图里，守护进程正常重启后，还没到点的提醒照常触发。
- [ ] 到点的前端提示（手动验证）：在 Web 的任意页面，到点时出现页面内提示，待我处理顶部是这条提醒；用户允许浏览器通知时，另外弹出一条浏览器通知；不允许时只有页面内提示和待我处理事项。
- [x] 产生对应的素材事件：卡片被用户关闭时产生"卡片被关闭"事件（带卡片类型、id、时间），事件类型和负载就绪，供 08 号票产生回避信号。
- [x] 所有测试通过（vitest），lint（oxlint）无报错。

## Notes

- 其他卡片由各自的票登记：审批卡和"交给我做"事项（07）、配对请求卡（10）、提问卡、"建议发起任务"卡和计划确认卡（12）、进度卡（13）、计划变更卡（14）、"建议立项"卡和立项书卡（15）、工单卡（17）、并行确认卡（20）、快速动作卡和记忆删除卡（21）、计划变更卡里的"工具包变更"（27）。
- 本票只提供通用的通知类事项（含置顶）；具体的通知（错过的提醒、中断不确定、越界通知、备份失败、快照校验失败、定时作业被自动暂停、归档清单、授权到期续期、卡住求助和失败后的抉择）由产生它们的票加。
- 不在本票：简单提醒在任务看板上显示为"运营中 · 待触发"（12 号票接看板时做）；启动时补发错过的提醒（60 分钟内照发并标明晚了多久、更晚的进待我处理、重复提醒错过多次只按最近一次）和定时作业（19）；建议卡、提问卡 7 天没处理的计时和回避信号素材（08）；秘书列出待我处理、把同一张卡放进聊天，"承诺即任务"（22）；时间线里的卡片（25）；个人工作日历和"按我的工作日"这种重复规则（29，加在本票的调度器和提醒工具上）；手机系统级推送（第二阶段）；"了解你"问题（第二阶段，不进待我处理）。
- 07 号票接通守卫后，这几个只产生卡片的工具在工具注册表里登记为不落入任何类别。
- 浏览器通知要先征得用户允许；不允许或浏览器不支持时，不影响页面内提示和待我处理事项。

- **没勾的一条**："到点的前端提示（手动验证）"。代码已就绪（任意页面顶上的提示条 `ui/alerts.tsx`、待我处理页的"允许浏览器通知"、浏览器通知用通知 id 作 tag 去重），状态层回放测试覆盖了"到点 → 待我处理置顶 + 待提示的通知"。但浏览器里的实际效果要经 LSM 启动守护进程后手动看：Claude in Chrome 打不开 `file://`，我也没有起任何服务。验证步骤写进了 `docs/dev.md` 的"LSM 登记"第 6 步。
- **协议上的增改**（共享协议包）：
  - 卡片实体加 `typeVersion`（负载版本）和 `text`（纯文本降级，守护进程按注册表生成、存在卡上，以后的 Telegram 之类也能直接显示）。`CARD_TYPE_VERSIONS` 放在协议包里，注册表登记时核对；前端遇到不认识的类型、或比自己认识的版本新的卡，都显示 `text` 加"去 Web 处理"（链接到新加的 `#/card/<id>` 页面，点了会刷新成最新的 Web）。
  - "对卡片做动作"加可选的结构化输入 `input`（提醒卡"改"要带新时间），按注册表里这个动作的 schema 校验。
  - 新方法 `inbox_action { itemIds, action, choice? }`（`read` / `unread` / `archive` / `unarchive` / `delete` / `handle`），一次多项时全部生效或全部不生效。新错误码 `not_found`、`not_allowed`。
  - 新事件：`card_dismissed`、`card_stale`（只定义了类型和负载，计时在 08）、`inbox_item`、`notify`（临时事件）、看板频道上的 `reminder`。都是"最新状态"式的事件，和 04 号票的 `card` 一样。
  - `validate.ts`：`schemaChecker` 和转出去的 `Type`，守护进程不另外引用 TypeBox（根目录装的是 pi 的 1.3.27，协议包是 1.3.36，免得混用），所以没有改依赖和 lockfile。
- **守护进程代为执行的工具**：秘书的"只产生卡片的工具"要在守护进程里改状态，所以扩展了 agent 宿主协议：装配参数 `hostTools`、子进程 → 守护进程 `host_tool_call`、守护进程 → 子进程 `host_tool_result`，子进程里登记成 pi 的自定义工具。是 ADR-0004 宿主协议的扩展，没有另写 ADR；加了一个 pi 契约测试文件。09 号票的"读取附件"工具也可以用这套（如果 09 自己另做了一套，合并时二选一）。
- **秘书不知道今天几号**：没有给每条用户消息加时间（那会改 09 号票负责的"发给模型前的投影"，也会让现有用例全改）。建、改提醒的工具改为接受"几天后（inDays）+ 几点""几分钟后（inMinutes）""MM-DD 或 YYYY-MM-DD"，日期由守护进程按可注入的时钟算，工具结果里写明落到了哪天几点让秘书复述；给了已经过去的时间会被拒并说明现在几点。系统提示里写了这条用法。
- **规格没写清、我选的做法**：
  - 提醒卡不进待我处理（它不需要用户处理）；到点时放的是通知类事项 `reminder_due`：置顶、不卡任务、动作"知道了"，相关的卡指向提醒卡（详情里显示在通知下面）。
  - 一次性提醒到点后提醒卡的状态是 `expired`（界面上写"已触发"），不能再改；秘书要改已经响过的提醒，工具会告诉它"建一条新的"。重复提醒到点后卡片仍待处理，负载里是下一次的时间。
  - "每月几号"遇到这个月没有的日子（2 月 30 号），在这个月的最后一天响（不漏掉提醒）。
  - 秘书改提醒时只给了几点：重复的保持原来的规则，一次性的保持原来那天。
  - 提醒的编号是递增的 `r-1`、`r-2`（短，秘书好引用）。
  - 到点的通知是临时事件，只提示开着的页面；没开页面的，打开后在待我处理里看到置顶的那条。浏览器通知只在页面开着时能弹（第一阶段没有 Service Worker 推送）。
