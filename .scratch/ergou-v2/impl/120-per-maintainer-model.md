# 120 — 每个负责人能单独配模型

Status: done
Blocked by: 无
Spec: [第一阶段规格](../spec.md) 第 19 节（设置）；73 号票（设置 · 模型）、83 号票（换模型与交接摘要）、114 号票（每个 agent 的 ⚙）

## What to build

用户 2026-10-14 定：要能说"每个专门的 agent 有独立的上下文、工具、skill 和**模型**"，所以把"每个负责人单独配模型"做出来。

现在：设置 · 模型（73 号票）只能按**角色**配，秘书、任务维护者、项目维护者、子 agent、评审、范围审视各一行，选"跟随默认"或者选定模型和思考档位。所以所有项目的维护者共用一个模型，所有任务的维护者也共用一个。

要做的：**某个项目的维护者、某个任务的维护者能单独选模型和思考档位，覆盖角色那一行的设置。**

1. **在哪改**：在这个项目、这个任务的 agent ⚙（114 号票的每个 agent 设置）里加一项"模型"。
   - 选项：跟随"项目维护者 / 任务维护者"的设置（默认，显示现在实际用的是哪个模型），或者选定一个模型加思考档位。
   - 模型清单、看图能力的提示和设置 · 模型页用同一套。
   - 设置 · 模型页里项目维护者、任务维护者那一行下面加一句：哪几个项目、任务单独配了模型，点了能去它的 ⚙。
2. **生效时机**：照 83 号票的规矩，一个会话固定一个模型。
   - 改了以后，这个维护者下一个新会话生效：项目维护者是下一张工单 / 下一个对话段，定时触发的任务是下一次运行开头。
   - 任务执行中途不换。
   - 长会话换模型时照样写交接摘要，聊天里记一条"已换成 X 模型"。
3. **这个维护者派出的子 agent、评审**：仍按各自角色那一行，不跟着维护者走。
4. **存储**：存在守护进程里，各设备一样，和 73 号票的模型设置放在一起或挂在项目、任务上都行，由你按现有结构定。
   - 项目归档、任务删除时这条覆盖一起清掉。
   - 被覆盖的模型从配置里删掉了：退回跟随角色的设置，界面上说明原因。
5. **token 账本、消耗页**：照旧按实际调用的模型记账；单价按实际模型算。
6. 秘书本来就能单独配（它是一个角色只有一个），不用改。

## Acceptance criteria

- [x] 项目、任务的 agent ⚙ 里能选"跟随角色设置"或指定模型 + 思考档位，显示当前实际用的模型
- [x] 改了以后下一个新会话生效、执行中途不换、长会话写交接摘要并在聊天里记一条，照 83 号票
- [x] 子 agent、评审仍按各自角色
- [x] 设置 · 模型页能看到哪些负责人单独配了模型
- [x] 配的模型不存在了退回跟随角色、有说明；项目归档、任务删除时清掉
- [x] 账本按实际模型记
- [x] 相关测试、typecheck、oxlint 通过（不跑全量，只跑相关文件）；原型里能演示（某个假项目单独配了模型），截图给主会话看
