## What to build

做完后，二狗每晚（默认 03:30）自动给数据目录做一份一致性快照，放进本机备份区的日期目录，再复制到配置里的同步目录（本机配置为华为家庭存储同步目录下的 Ergou_projects）的日期子目录，由华为客户端去同步。本机保留最近 7 份；同步目录保留每日 7 份、每周 4 份（每周那份取周日的快照），不加密。密钥目录、临时区、外部工作目录不进备份。备份写不进去，或者每周对最新快照做的完整性检查没通过，待我处理里出现一条事项。电脑在 03:30 关着、错过了当晚的备份，开机后守护进程启动时补做一次。出事时，用户经 LSM 停掉守护进程，用一条恢复命令从指定日期的快照恢复。

同一批内部作业里还有临时区清理：每天删掉临时区（包括秘书草稿区）里 7 天前的文件。

演示：用可注入时钟把时间拨到 03:30，本机备份区和同步目录各多出一个日期目录；把同步目录改成一个不存在的路径再拨一天，待我处理里出现"备份失败"；停掉守护进程，把时钟拨过两个 03:30 再启动，看到只补做了一份备份；用恢复命令回到某一天，再经 LSM 起守护进程，看到那天的会话和看板。

## Acceptance criteria

- [x] 主切面（可注入时钟）：到 03:30 调度器触发备份，本机备份区出现当天的日期目录：`ergou.db` 和 `memory.db`（存在时）用 `VACUUM INTO` 生成、能通过完整性检查，其余文件已复制；同一备份也能通过"立即备份"接口手动触发。
- [x] 主切面：快照进行中守护进程照常追加事件、不报错；快照里的数据库包含快照开始前已提交的全部事件。pi 会话 JSONL 的最后一行只写了一半时备份不失败，从这份快照恢复后会话文件能被正常读出。
- [x] 主切面：快照里没有密钥目录、临时区的任何文件，也没有外部工作目录里的文件（即使有项目绑定了外部路径），也不包含本机备份区自己。
- [x] 主切面：其他文件增量复制，媒体按内容哈希只存一份——连续两天的快照里同一个媒体只占一份存储；保留期内任一日期的快照都能单独完整恢复，更早的快照被清掉后也一样。
- [x] 主切面（可注入时钟）：连续跑若干周后，本机备份区只剩最近 7 份；同步目录只剩每日 7 份加每周 4 份，每周留下的那份都是周日的快照。快照写进同步目录即记为成功，二狗不等待也不检查华为客户端的同步。
- [x] 主切面：同步目录不存在、空间不够、复制出错（用可替换的文件写入模拟）时，待我处理里出现一条"备份失败"事项（紧急度：不卡任务），本机快照仍然保留；每周的校验打开最新快照的数据库做完整性检查，人为损坏最新快照后，待我处理里出现"快照校验失败"事项。
- [x] 主切面（停掉守护进程、拨动时钟后再启动）：停机期间错过了当晚 03:30 的备份，启动后补做一次；错过好几晚也只补一次。每周校验和每天的临时区清理错过时同样在启动后补一次。补做是幂等的：补完再重启一次，不会再补。
- [x] 恢复命令：守护进程在运行时拒绝执行；守护进程停止后，从本机备份区或同步目录里指定日期的快照恢复数据目录，再起守护进程，事件、看板、待我处理和会话都和那份快照一致；密钥目录不被改动。
- [x] 主切面（可注入时钟）：每天清理临时区里 7 天前的文件，7 天内的保留；媒体库里的文件（包括秘书从草稿区发进聊天的附件）不受影响。
- [x] 所有测试通过（vitest），lint（oxlint）无报错。

## Comments

2026-10-08 实现（worktree 分支）。规格没写死、按最保守最贴近规格的做法定下的：

- **快照的样子分两层**（ADR-0007，评审后改；原先占的 0006 让给了先合并的 08 号票）：都是 `<备份区>/<YYYY-MM-DD>/manifest.json` + `data/`，按清单还原。本机备份区：每个日期目录自成一体；没变的文件（大小和修改时间同上一份清单）硬链接到上一份，复制完内容（sha256）和已有的 ≥ 64 KB 文件一样的也换成硬链接——按内容去重不限于媒体库，所以不依赖 09 号票把媒体放在素材区的哪个子目录；做不了硬链接时整份复制并记一条日志；快照文件都设成只读（Windows 上删掉只读文件的一个链接不会去掉别的链接的只读属性，实测过）。同步目录：同步客户端不认硬链接，所以不用硬链接，≥ 64 KB 的文件（含数据库、媒体）按内容放进公共池 `pool/<sha256>`，云端也只存一份；日期目录里只有清单和小文件；保留策略清掉日期目录后回收池里没人引用的文件（有读不出清单的日期目录时这次不回收）。数据库每次用 `VACUUM INTO` 重新生成。
- **周快照补写**：周日那份当时没写进同步目录（目录不在等）的，之后同步目录写得进去时，从本机备份区补写最近缺的那个周日快照；补写不进去也放一条"备份失败"。
- **数据库**：数据库区里所有 `*.db` 都按 SQLite 处理（`ergou.db`，08 号票建了就有 `memory.db`）；`VACUUM INTO` 和完整性检查在一个常驻的工作线程里做（`storage/sqlite-worker.ts`，只转手给 `sqlite.ts`），不卡事件循环。
- **会话 JSONL**：`.jsonl` 只复制到最后一个换行。pi 读会话时自己也跳过坏行，但截掉之后恢复出来的文件每行完整，之后追加的新行不会和半行粘在一起。
- **不进备份**：密钥区、临时区、本机备份区、pid 文件、模型区（08 号票的向量模型，几百 MB，能重新下载；恢复时也原地不动）、`*.db-wal` / `-shm`；素材区的原文副本（本人素材的真相）进备份，只读属性恢复后保留；符号链接和目录联接一律不跟进、也不记下。日志区进备份（规格只排除了密钥、临时区、外部工作目录）。15 号票如果用目录联接表示外部工作目录的绑定，绑定关系要另记在项目档案里，恢复后据此重建。
- **同步目录的"每周 4 份"**：比每日 7 份更早的快照里最近的 4 个周日（不和每日的重叠，稳定后共 11 份）；哪个周日关机没有快照，就往前多取一个周日。
- **时间**：每周校验周日 04:30（当天 03:30 的快照做完之后），清理临时区每天 04:00。规格没给，先写成常量，没进配置。
- **当天已经有快照**：到点的和启动补做的只补齐当天缺的（本机没有就做，同步目录没有就复制），不覆盖已有的——这样从旧快照恢复之后启动补做，不会把当天那份（恢复前的状态）冲掉；手动的"立即备份"才换掉当天的。副作用：同一天先手动备份、03:30 那次就不再做。
- **"立即备份"接口**：模块接口 `daemon.backup.backupNow()`；另外"备份失败"事项带"重试""知道了"两个动作（原型里就是这样），点"重试"马上手动备份一次——经待我处理新加的 `onNoticeHandled(通知种类, 动作, fn)` 接上（用户第一次选这个动作时叫一次）。没有新增前端协议方法（设置页还是原型，也免得和同时开工的票抢着改协议包）。
- **同步目录没配**：只做本机备份，记日志，不进待我处理（测试、别人用框架时可以不配）。示例配置里是占位符 `<同步目录的绝对路径>`：配置照样能加载，备份时每次报"备份失败：没写进同步目录"提醒换掉；`backup.syncDir` 不是绝对路径或放在数据目录里时配置报错，`backup.time` 用协议包的 `ClockTime` 校验。
- **校验**：本机备份区和同步目录各自最新的那份都查：数据库 `PRAGMA integrity_check`，其余文件核对大小，清单读不出来也算失败。同步目录不在时只查本机的（那边已经报了备份失败）。
- **错过的内部作业**：做成通用的 `scheduler/internal-jobs.ts`，时间表用简单提醒那一套（`ReminderSchedule` + `nextOccurrence`），上一次开始跑的时间记在事件日志的内部频道 `internal`（不在前端协议里）。第一次见到某个作业只记"从现在起算"，不马上跑（新数据目录不会一启动就备份）；中止用 Node 自带的 `AbortSignal`，被守护进程停止中止的不算跑过。"上一次之后的下一次过没过点"是导出的纯函数 `nextDue`，19 号票的定时作业直接调用；19、08、14 号票的内部作业照这个登记。
- **恢复命令**：`node packages/daemon/src/restore.ts <日期> [--from local|sync|<目录>]`、`--list`。守护进程在运行（pid 文件里的进程没退出且启动时间对得上，或本机端口上有进程在听）就拒绝；先校验快照，不通过拒绝。数据目录现有内容先挪到 `backups/pre-restore-<时间>/`，再按清单复制快照进来（同步目录的从公共池取，复制出来的去掉只读；源文件本来就只读的——清单记 `readOnly`，比如 08 号票的原文副本——照样只读）；中途出错撤回。`pre-restore-*` 只留最近 2 份，更早的在恢复时删掉。"不进备份的区"和"恢复时不动的区"是同一份 `nonBackupEntries`。
- **和 04 号票的"重新同步"配合**：`test/main/restore.test.ts` 里恢复成旧快照再起来，前端带着更大的序号重连，四个频道都重新同步，补发的事件和快照那一刻前端看到的逐条一致；秘书接着快照里的 pi 会话（看得到快照前的那轮，看不到之后的）。
- **临时区清理**：按修改时间算 7 天；临时区下第一层的目录（各模块自己那一格）留着，更深的空目录 7 天没动才删；符号链接不动。

- 2026-10-08 完成：经两轴代码评审并按意见修改（同步目录按内容哈希的公共池、周快照补写、本机快照只读、pre-restore 留 2 份、内部作业改用统一的时间规则和 AbortSignal）后压缩合并进 main。ADR 顺延为 0007。
