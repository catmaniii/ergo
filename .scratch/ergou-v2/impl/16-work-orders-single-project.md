# 16 — 工单与派单：单项目任务

Status: ready-for-agent
Blocked by: 13（任务执行与阶段验收）, 15（项目立项与项目档案）
Spec: [第一阶段规格](../spec.md) 第 12 节（工单与派单）、第 11 节（项目与维护者）、第 8 节（任务、计划与阶段）、第 4 节（存储与事件）、第 5 节（前端协议）、第 19 节（Web UI）、第 21 节（实现细节补充）

## What to build

做完后，只涉及一个项目的任务（包括立项后的首个建设任务）由这个项目的维护者起草计划并执行，维护者要做的事都以工单的形式送达。工单写进事件日志时注明收件项目，派单器把它放进项目维护者的工单队列：维护者休眠就唤起，正忙就排队，一次只做一件、先来先做；被挡住的任务留在排队中，看板上标"等项目 X"。发给已归档项目的工单直接退回并说明原因；已停用的项目照常接单。任务的执行权限是任务授权和项目权限的交集。维护者干活中遇到要问的，工单转"等澄清"，由派单方回答——用户发起的单项目任务就问用户。

维护者会话分段，每段是一个新的 pi 会话，从固定上下文重新开始：工具包说明、项目规范（第一阶段是一段内置的简短说明）、项目档案快照（规格摘要、进展、术语表）、上一段的摘要、这次的工单（对话段没有），再加上重注入块；更早的分段不进上下文。段有两种：每张工单一段；用户在维护者手上没有进行中的工单时直接和它说话（包括立项问答），开一个"对话段"。维护者干活时用户发来的话作为插话进当前段。每段结束时，维护者把新的理解写回项目档案，并一并写一段摘要，作为下一段的"上一段摘要"；运行时检查进展文档的内容哈希变没变、摘要有没有写，没写回就催维护者，这段不算完成。用户可以在项目页上重置维护者：新开一段会话，只凭项目档案重建理解，旧会话保留可查。

前端把各段拼成一条连续的聊天，用工单分隔线隔开；简版项目页出现工单流水线（排队中、进行中、已结束），每张工单显示来源、所属任务和当前阶段。演示：给同一个项目连发两个单项目任务，第二个标"等项目 X"，第一个结束后它自动开始；项目页流水线随之流动，维护者会话里出现工单分隔线。

## Acceptance criteria

- [ ] 主切面：只涉及一个项目的任务，起草计划和执行都由该项目的维护者做，不新建任务自己的维护者；任务的执行权限是任务授权和项目权限的交集——项目工具包里没有的能力，任务授权也放不开。
- [ ] 主切面：工单按"待接 → 进行中 ⇄ 等澄清 → 已结束（完成、退回、做不了）"迁移，每次迁移都是事件；派单器把工单送进收件项目维护者的队列，维护者休眠时唤起、正忙时排队；同一项目同一时刻只有一张进行中的工单，先来先做。
- [ ] 主切面：项目正忙时，后到的任务留在排队中，看板上的任务卡标"等项目 X"；前一张工单结束后它自动开始。工单不在看板上单独占卡。
- [ ] 主切面：每张工单开一段新的 pi 会话（新的会话文件），开头的固定上下文包含工具包说明、内置的项目规范说明、项目档案快照（规格摘要、进展、术语表）、上一段的摘要、这次的工单和重注入块；更早分段的内容不在这段的上下文里。维护者手上没有进行中的工单时，用户直接对它说话开一个对话段（同样的固定上下文，没有工单）；对话段在维护者闲置退出或下一张工单开始之前结束。维护者干活时用户发来的话作为插话进当前段，不另开段。
- [ ] 主切面：一段（工单段或对话段）结束时，进展文档的内容哈希没变、或维护者没写这一段的摘要，运行时催促维护者写回，这段不算完成、工单不结束；写回之后才结束，下一段固定上下文里的"上一段摘要"就是它写的这段摘要。
- [ ] 主切面：用户重置维护者后新开一段会话，上下文只来自项目档案（没有上一段的摘要）；旧会话文件原样保留，前端仍能查看。
- [ ] 主切面：用户发起的单项目任务里，维护者提问时工单转等澄清，问题以提问卡进待我处理；没有其他能推进的阶段时任务转等我（原因"澄清"）；用户回答后回答交回维护者，工单回到进行中、任务回到执行中（名额满则排队中）。回答照常作为"澄清问题的回答"产生素材事件（由 08 号票采集）。
- [ ] 主切面：发给已归档项目的工单直接以"退回"结束并附原因，维护者不被唤起；发给已停用项目的工单照常执行。
- [ ] Web UI：维护者会话把各段拼成一条连续聊天，用工单分隔线（工单分隔 part）隔开，对话段也有分隔；简版项目页显示工单流水线（排队中、进行中、已结束），每张工单显示来源、所属任务和当前阶段；项目页上有重置维护者的入口。前端状态层回放主切面录下的"两个任务排进同一项目"事件流，流水线和"等项目 X"标记正确。
- [ ] 主切面（端到端）：项目的首个建设任务由项目维护者自己经计划提交和执行工具走完、在守卫下执行，全部阶段验收后任务以已完成结束，项目自动进入使用中（13 号票只验了执行控制器和项目模块之间的接口衔接）。
- [ ] 所有测试通过（vitest），lint（oxlint）无报错。

## Notes

- **不在本票**：
  - 本票的工单来源只有"用户发起的单项目任务"。别的任务的维护者派来的工单、回执、任务维护者回答项目维护者的"等澄清"、计划外工单的"待你确认"和工单卡、任务详情里的工单列表归 17；定时作业的一次运行作为工单归 19。
  - 每张工单结束时的范围审视和系统提示末尾的"近期范围记录"归 18；本票在工单结束处（子进程退出前）留好调用点。
  - 子进程上限和维护者闲置退出归 12；插话和重注入块归 13；已归档项目的会话只读、项目状态机和立项问答本身归 15；工具包装配（noSkills + additionalSkillPaths）归 27。
- 15 号票的立项问答在本票之后就落在一个对话段里。
- 用户在维护者会话里的发言照常产生素材事件（13、15 号票已覆盖）。
- Solution 一节写"维护者要做的所有事都是工单"，本票按这个理解，让单项目任务的计划起草也经派单器排进队列。
- 对应用户故事：96–99、104、107、151（工单分隔线部分）。
