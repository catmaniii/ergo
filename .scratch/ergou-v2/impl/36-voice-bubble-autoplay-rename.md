# 36 — 语音气泡：自动播放、文字和语音同框；"秘书"改叫"个人助理"

Status: ready-for-agent
Blocked by: 31（语音输入与识别）, 32（agent 用语音回复）, 33（主导航按空间自适应）, 34（外观）
Spec: [第一阶段规格](../spec.md) 第 22 节（语音消息）、第 19 节（Web UI）

## What to build

用户 2026-10-08 用真机试过语音后提的几条：

1. agent 发来的语音到了前端就自动播放；设置里加一个"自动播放 agent 的语音"开关，默认开（按设备记住，和外观一样）。
2. 文字的显示规则：用户发的语音，识别完成就在气泡里显示识别出的文字；agent 发的语音，文字默认不显示，长按（桌面右键）"转文字"才展开。
3. 不管是用户的还是 agent 的，语音下面显示文字的那一块和语音本身在**同一个气泡框**里（上面是播放条和时长，下面是文字），不再是气泡下方另外一个框。
4. 界面上"秘书"改叫"个人助理"：秘书聊天页顶上的标题、主导航的标签都改；领域术语（代码、CONTEXT.md、给 agent 的提示词）照旧叫秘书。

## Acceptance criteria

- [ ] 自动播放：会话里新到一条 agent 的语音（合成完成），页面在前台、开着这个会话、开关是开的，就自动播放这一条；同一时间只播一条（新来的接在正在播的后面，或者按规格"同一时间只播一条"打断旧的——选一种写进 Comments）；用户正按着"按住 说话"时不播，松手后再播。打开页面、翻历史、断线重连补发的旧语音不自动播。浏览器拦截自动播放时（手机浏览器要有用户手势才允许出声），利用用户按住说话、点发送这些手势预先解锁音频，仍被拦就在气泡上提示"点一下播放"，不报错。
- [ ] 设置：设置里有"自动播放 agent 的语音"开关，默认开，按设备记住（存储不可用时按默认），改了立即生效；前端状态层有纯函数决定"这条该不该自动播"，表格测试覆盖：开关、前台与否、是不是新到的、是否正在录音。
- [ ] 文字显示：用户语音识别完成后文字直接显示在气泡里（识别中、失败、没识别出文字的说法沿用 31 号票）；agent 语音默认只显示播放条和时长，长按"转文字"展开送进 TTS 的原文、再点收起。长回复（口语总结）的完整文字照常是单独的文字消息，语音气泡里展开的是总结的原文。
- [ ] 同框：语音气泡是一个框，播放条和时长在上、文字在下，用户和 agent 两侧都这样；宽度规则照旧随时长变，有文字时按文字和最小宽度取大的；浅色、深色外观下都看得清。前端状态层或组件测试覆盖展开、收起、识别中的几种样子。
- [ ] 改名：秘书聊天页的标题、主导航标签显示"个人助理"；33 号票的导航状态层表格测试按新标签长度补上；其余代码和术语不改。
- [ ] 所有测试通过（vitest），lint（oxlint）无报错。
