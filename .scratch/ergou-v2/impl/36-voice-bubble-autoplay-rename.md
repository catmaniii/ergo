# 36 — 语音气泡：自动播放、文字和语音同框；"秘书"改叫"个人助理"

Status: done
Blocked by: 31（语音输入与识别）, 32（agent 用语音回复）, 33（主导航按空间自适应）, 34（外观）
Spec: [第一阶段规格](../spec.md) 第 22 节（语音消息）、第 19 节（Web UI）

## What to build

用户 2026-10-08 用真机试过语音后提的几条：

1. agent 发来的语音到了前端就自动播放；设置里加一个"自动播放 agent 的语音"开关，默认开（按设备记住，和外观一样）。
2. 文字的显示规则：用户发的语音，识别完成就在气泡里显示识别出的文字；agent 发的语音，文字默认不显示，长按（桌面右键）"转文字"才展开。
3. 不管是用户的还是 agent 的，语音下面显示文字的那一块和语音本身在**同一个气泡框**里（上面是播放条和时长，下面是文字），不再是气泡下方另外一个框。
4. 界面上"秘书"改叫"个人助理"：秘书聊天页顶上的标题、主导航的标签都改；领域术语（代码、CONTEXT.md、给 agent 的提示词）照旧叫秘书。

## Acceptance criteria

- [x] 自动播放：会话里新到一条 agent 的语音（合成完成），页面在前台、开着这个会话、开关是开的，就自动播放这一条；同一时间只播一条（新来的接在正在播的后面，或者按规格"同一时间只播一条"打断旧的——选一种写进 Comments）；用户正按着"按住 说话"时不播，松手后再播。打开页面、翻历史、断线重连补发的旧语音不自动播。浏览器拦截自动播放时（手机浏览器要有用户手势才允许出声），利用用户按住说话、点发送这些手势预先解锁音频，仍被拦就在气泡上提示"点一下播放"，不报错。
- [x] 设置：设置里有"自动播放 agent 的语音"开关，默认开，按设备记住（存储不可用时按默认），改了立即生效；前端状态层有纯函数决定"这条该不该自动播"，表格测试覆盖：开关、前台与否、是不是新到的、是否正在录音。
- [x] 文字显示：用户语音识别完成后文字直接显示在气泡里（识别中、失败、没识别出文字的说法沿用 31 号票）；agent 语音默认只显示播放条和时长，长按"转文字"展开送进 TTS 的原文、再点收起。长回复（口语总结）的完整文字照常是单独的文字消息，语音气泡里展开的是总结的原文。
- [x] 同框：语音气泡是一个框，播放条和时长在上、文字在下，用户和 agent 两侧都这样；宽度规则照旧随时长变，有文字时按文字和最小宽度取大的；浅色、深色外观下都看得清。前端状态层或组件测试覆盖展开、收起、识别中的几种样子。
- [x] 改名：秘书聊天页的标题、主导航标签显示"个人助理"；33 号票的导航状态层表格测试按新标签长度补上；其余代码和术语不改。
- [x] 所有测试通过（vitest），lint（oxlint）无报错。

## Comments

实现时选的细节（2026-10-08，实现本票的子 agent）：

- **同一时间只播一条：选"排队"，不打断。** 新到的 agent 语音在播别的时接在后面，播完一条接一条（agent 连着回的几条、以及 38 号票的分段，都不该被腰斩）。暂停在半路的不算在播，新到的直接播；用户自己点了别的气泡，排着的自动播放就不播了（用户挑了要听的）；放不了的（文件坏了）跳过接着播。点气泡的规矩照旧：点另一条，正在播的停下。
- **"新到的"怎么认，不改协议：** 连接发订阅（含打开维护者会话时的多订阅）时紧跟着发一个空订阅（`cursors: {}`）当回执，不等订阅的响应；回执的响应到之前这几个频道上的帧标成补发的（`catchUp`）。成立的前提是守护进程按顺序处理同一条连接上的请求、补发在处理订阅时同步推完——现有实现就是这样，守护进程主切面加了一个用例钉住（`test/main/reconnect.test.ts`），`docs/dev.md` 网关一节写明了"改补发推法时要保住"。状态层只把实时推来、让 agent 语音变成"完成"的那一帧算新到的；往上翻取回的不经事件帧。没选按时间戳比（手机和电脑的钟可能差几秒到几十秒）；也没在协议里加"补发到哪为止"的字段（要动协议包和守护进程，和并行的票抢协议版本）。代价：服务端处理完订阅、还没处理回执的那一小会儿里实时推来的语音也按补发算，不自动播（两条请求紧挨着到，窗口很小；评审后从"等订阅响应再发回执"改成紧跟着发）。
- **按住说话：** 按下（等麦克风、正在录）时在播的语音停下，松手后不接着放它（不然会录进去）；这期间新到的不播，松手时按那一刻的样子再判一次（那时页面到了后台、开关关了就不播）。
- **解锁音频：** 整个页面改成共用一个 `<audio>`（原来每播一条 `new Audio()`），在"按住 说话"抬手时和点发送时静音出一次声（解锁过、或者已经出过声就不再做）。不在按下时做：手机上按下不算用户手势，也免得和按下就开录（37 号票的麦克风预热）挤在一起。仍被拦下（`NotAllowedError`）就在气泡框里标"点一下播放"，排在后面的一起标上，不报错、不弹提示，点一下就播；这时随时长的宽度只当最小宽度、提示不折行，1 秒左右的短语音框按这行字撑开。真机上还没验证 iOS 的效果。
- **前台、开着的会话：** 前台看 `document.visibilityState`；页面在后台时到的不播，回到前台也不补播。开着的会话是挂着的会话组件（秘书页、任务详情和项目页里的维护者会话）。两台设备同时开着同一个会话、都在前台时，两边都会播（规格没限定哪台）。手机锁屏后连接没断、帧在解锁后才处理的，那时页面已在前台，会当新到的播。
- **设置开关的位置：** 放在设置列表里外观下面（同样只对这台设备生效），没放进"语音"页（那页是参考音色，个人数据）。localStorage 键 `ergou-voice-autoplay`，只在关掉时写 `off`，打开就擦掉；存储用不了按默认（开）。
- **同框的宽度：** 没有文字时框宽随时长；有文字时随时长的宽度是最小宽度，框按文字撑开，最宽和文字气泡一样（agent 一侧 92%）；播放条里的波形不撑宽框，所以"识别中…"这类短字的框仍是随时长的宽度。框里文字那一块和播放条之间一道细线，颜色跟着框里的字色走（`currentColor`），所以用户的蓝框和 agent 的框、浅色深色都看得清，没加新的颜色 token。"识别失败"在框里加粗、后面跟"（长按语音可以重新识别）"。没有 DOM 的组件测试底座，展开、收起、识别中的几种样子由状态层的 `voiceBubbleLook` / `agentVoiceBubbleLook` 表格测试覆盖；截图看过：原型页面（390 宽、浅色和深色）里用户一侧的框；原型里没有 agent 语音的假数据，agent 一侧的收起、展开、"点一下播放"和用户一侧的识别中、识别失败用同一套样式的静态页在浅色、深色下看过，都看得清。
- **改名只改两处：** 秘书聊天页标题、主导航标签。竖栏里"个人 / 助理"在零宽空格处换行（和"待我 / 处理"一样，导航表格测试按两行 70 高补上），底部横栏四个字刚好一格最小宽度 56。别处界面文字里的"秘书"没改：输入框占位"和秘书说…"、待我处理和项目页等处的说明、消耗页"系统开销（秘书）"、卡片上"这是秘书推断的"——要不要一起改由用户定。
- **改动范围：** 生产代码只改了 Web 包，协议没动；守护进程包只动了测试：上面那个主切面用例，以及录像骨架（`test/helpers/recording.ts`）把新的界面输入 `agent_voice_arrival_seen` 归到"界面自己的输入"（不然类型检查不过）。守护进程测试底座 `TestFrontend` 录下的帧不带 `catchUp`，录像回放里补发的帧都按实时算（现有录像里没有补发 agent 语音的流程，不影响）。
- **37 号票留下的风险：语音模式里麦克风一直开着、回声消除也开着，可能影响自动播放（评审时提出，待真机验证）。** 浏览器为了回声消除可能把整个页面的音频切进"通话"模式，播放跟着变样。真机上要验证：
  - 安卓：进语音模式（麦克风预热着）时 agent 语音的播放是不是走了通话音量（音量键调的是通话音量）、是不是从听筒而不是扬声器出声；
  - 蓝牙耳机：是不是切到了 SCO（通话音质，听起来发闷、单声道），退出语音模式后能不能回到 A2DP；
  - iOS：录音会话开着时（语音模式里），播放的声音是不是明显变小、或者走了听筒。
  - 两种兜底，代价各不同，做成了前端常量开关 `app/voice-fallbacks.ts` 的 `VOICE_FALLBACKS`，**默认都不开**（不开时就是 37 号票原样的"按下即录"），改值重新构建就能在真机上对比：
    - (a) `releaseMicWhilePlaying`：有语音在播（点气泡或者自动播放）时先关麦克风，播完再预热。代价：播放期间按下"按住 说话"要等"准备中"（麦克风重新打开，开头可能丢一点）；iOS 上反复开关麦克风，系统设置里没有一直允许时可能多弹权限框。实现：播放器报"有没有在播"（`anyPlaying`），`VoiceInput` 交给 `VoiceSession.setPlayback`，麦克风的开关时机（`state/voice-mic.ts`）多了"在播"这一条；开关没开时 `setPlayback` 什么也不做。
    - (b) `disableEchoCancellation`：要麦克风时关掉回声消除（降噪、自动增益照旧开着）。代价：外放时可能把正在播的 agent 语音录进自己的语音里（我们自己停了在播的，但别的声音、刚播完的尾音照样会进来）。
  - 两种都有测试（`test/state/voice-mic.test.ts`、`test/app/voice-session.test.ts` 的"兜底"），默认值下的行为也测了（在播时麦克风照样开着、按下即录、回声消除开着）。用户实测后定开哪个，再把默认值改掉、这一条更新。
- **给 38 号票：** 现在"新到的"认的是"变成完成的那一帧"；分段推送后要改成第一段到了就算新到的，播放器（`app/voice-playback.ts`）的排队可以接着用，段与段的无缝衔接要换成 Web Audio 排程。
