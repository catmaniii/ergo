## What to build

做完后，手机等其他设备可以经 VPS 的 HTTPS 域名使用二狗，但必须先完成设备配对。新设备第一次打开页面时停在配对等待页，上面显示设备名、6 位短码和 8 位十六进制短指纹；设备名默认取自浏览器和系统信息，用户可以在新设备上改。同时，PC 本机或任何已配对设备的待我处理里出现一张配对请求卡，显示同样的设备名、短码和短指纹。用户核对后批准，新设备拿到一个长期凭证（cookie），进入正常页面；以后在设置的"已配对设备"里能看到它，也能随时吊销，吊销后它立刻被断开。

守护进程新增第二个监听端口——外网端口。它是隧道的唯一目标，永远不享受本机信任：不管请求从哪个 IP 来、Host 写的是什么，从外网端口进来的每个 HTTP 请求和 WebSocket 连接都要带有效的设备凭证，没有凭证只能看到配对页。经隧道来的请求，TCP 对端都是本机，以 nginx 覆盖写的 `X-Real-IP` 作为来源（用于配对请求的限频）。本机端口照旧自动信任，不需要配对。

另外交付公网入口要用的两样东西：`ergou-tunnel` 的 LSM 条目（照抄现有的 `agentsense-tunnel`，换端口，只连守护进程的外网端口），以及 nginx 站点配置的生成和一条部署命令——部署由用户在本机运行这条命令完成，运行命令即为确认，不另出卡。演示（守护进程经 LSM 启动）：在外网端口上走一遍"新设备请求配对 → 本机在待我处理里核对并批准 → 新设备可用 → 在设置里吊销 → 新设备被断开"。

## Acceptance criteria

- [ ] 主切面：守护进程同时起本机端口和外网端口。外网端口上不带凭证的 HTTP 接口（含历史分页、媒体上传下载）和 WebSocket 握手一律被拒，只有配对页和配对请求接口可用；即使请求来自 127.0.0.1、Host 和 Origin 写成本机地址，也不享受本机信任。本机端口的行为不变。
- [ ] 主切面：新设备在外网端口发起配对请求，拿到设备名（默认由请求里的浏览器和系统信息生成）、6 位数字短码和 8 位十六进制短指纹；新设备改了设备名后，本机端口上的前端订阅的待我处理里那张配对请求卡显示改过的设备名，以及同一个短码和短指纹。
- [ ] 主切面：在本机或已配对设备上批准配对请求卡后，新设备拿到 cookie：HttpOnly、Secure、SameSite=Strict，值是 256 位随机数；`ergou.db` 里只存它的哈希，数据目录的任何文件里都搜不到原值。之后这台设备在外网端口上的 HTTP 请求和 WebSocket 连接都被接受。两台已信任设备同时批准同一张卡时，后到的得到"已被处理"。批准配对不产生素材事件。
- [ ] 主切面（可注入时钟）：待批的配对请求 5 分钟后过期，过期后批准不发凭证、卡片不能再处理；以 `X-Real-IP` 认定来源，同一来源 10 分钟内的第 6 个配对请求被拒，换一个 `X-Real-IP` 的请求不受影响。
- [ ] 主切面（可注入时钟）：凭证有效期 365 天、每次使用都续期——第 300 天用过的凭证到第 400 天仍然有效；连续 365 天没用过的凭证失效，再访问回到配对页。
- [ ] 主切面：设置里能列出已配对设备；吊销某台后，它已经打开的 WebSocket 立即被服务端关闭，后续请求被拒，其他设备不受影响。前端状态层回放：吊销事件之后，已配对设备列表少了这一台。
- [ ] Web UI：新设备上的配对等待页（显示设备名并可修改、短码、短指纹）、已信任设备上的批准页（显示设备名、短码、短指纹供核对）、设置页里的"已配对设备"列表和吊销按钮都可用；页面脚本里不出现私钥或令牌（凭证只在 HttpOnly cookie 里）。
- [ ] nginx 配置生成：生成的站点配置支持 WebSocket、放大了 `client_max_body_size`、加长了 `proxy_read_timeout`、每个 location 都覆盖写 `X-Forwarded-For` 和 `X-Real-IP`、带 HSTS，上游指向 VPS 上只绑本机地址的隧道端口，域名按 `ergou.<VPS>.sslip.io`；用断言逐项验证。
- [ ] 部署命令（ssh 用可替换的执行器测试）：守护进程和任何 agent 都不会自己发起部署，只有用户在本机运行部署命令时才执行一次 ssh 部署；`ergou-tunnel` 的 LSM 条目存在，目标是守护进程的外网端口。
- [ ] 所有测试通过（vitest），lint（oxlint）无报错。
