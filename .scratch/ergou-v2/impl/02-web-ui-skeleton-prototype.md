# 02 — Web UI 骨架与可点击原型

Status: ready-for-agent
Blocked by: 01（工作区骨架与 agent 子进程 spike）
Spec: [第一阶段规格](../spec.md) 第 19 节（Web UI）、第 5 节（前端协议）、第 8 节（任务、计划与阶段）、第 21 节（实现细节补充）、Testing Decisions（Web UI）

## What to build

从 AgentSense 复制 `web/src` 进 Web 包，视觉 token 沿用它的 `look.css`，在此基础上做出二狗第一阶段的全部页面，全部用假数据、可以点。用户在手机竖屏宽度和电脑宽屏下各点一遍，评审交互：竖屏时底部 5 个 tab（秘书、任务、项目、待我处理、更多），宽屏时 tab 变成左侧竖栏、内容区按 AgentSense 的做法分栏。评审后的修改按普通需求变更处理。

这时还没有守护进程（网关和它在 LSM 的登记从 04 号票起才有），所以本票的原型是一份构建产物，直接在浏览器里打开就能点，不起开发服务器或任何常驻进程。

同时立起前端状态层的骨架：把事件流归并成界面状态的那一层单独成模块，全部是纯函数，以后用主切面录下来的真实事件流回放来测。页面本身不单设测试切面，主要靠这次评审。

## Acceptance criteria

- [x] Web 包由 AgentSense 的 `web/src` 复制而来，用 React 19 + Vite + TypeScript、手写 CSS，视觉 token 来自 AgentSense 的 `look.css`；没有引入组件库和状态管理库；能在工作区里构建，构建产物不依赖任何服务进程，直接在浏览器里打开就能使用。
- [x] 主框架：竖屏底部 5 个 tab：秘书、任务、项目、待我处理、更多；"更多"里有消耗、记忆入口（标明第二阶段、不可用）、设置。宽屏时 tab 变成左侧竖栏，内容区分栏。在浏览器里分别以手机竖屏宽度和桌面宽度打开，都能完整使用。
- [x] 第一阶段的页面都在、都能从导航点到，并填了假数据：秘书聊天（附件菜单里有"作为材料投喂"）；待我处理；任务看板；任务详情（维护者会话、阶段抽屉、工单列表、计划卡、工具包）；项目列表（状态、活动状态小圆点、进行中任务数）；简版项目页（状态、定时作业及各自状态、"和维护者交流"、工单流水线、工具包、范围记录、重置维护者的入口）；消耗页；设置（关注类别、工作日历、已配对设备、按会话或时间段删除素材、skill 库页及导入 skill 的入口）；配对等待页（设备名默认取浏览器和系统信息、可以改，显示 6 位短码和 8 位十六进制短指纹）和批准页（显示设备名、短码和短指纹供核对）。"发起任务"按钮出现在秘书页和任务页。
- [x] 会话组件只有一个，秘书聊天和维护者会话共用；维护者会话多出工单分隔线、阶段抽屉和直接下指令的输入框。消息按 part 渲染：文本、推理（默认折叠）、图片、文件、工具调用（工具名、参数摘要、命中的关注类别、判定、是否授权内、是否通用 bash）、卡片引用、工单分隔。
- [x] 第一阶段的 14 种卡片（计划确认卡、审批卡、提问卡、进度卡、快速动作卡含"已执行"、"建议发起任务"卡、"建议立项"卡含名字和一句话目标、简单提醒卡、立项书卡、工单卡、计划变更卡含"工具包变更"、并行确认卡、记忆删除卡、配对请求卡）各至少在聊天、待我处理或任务详情里出现一次，点按钮后在本地假状态里变成已处理。计划卡按规格：一个"确认"按钮、可逐行勾掉或收窄授权、可附意见打回、逐行列出涉及的项目和改动、可增加本任务要提醒的关注类别（默认取全局，只能加不能删）、列出由对话里说的限制编译出的时序规则或授权收窄、预告"授权后还会在 N 处停下来"和 token 粗估、细节默认折叠。提问卡每题带推荐，有"全按推荐"。立项书卡有"确认并开工"和"只确认，稍后开工"。
- [x] 任务看板按"等我（等我、待确认）→ 进行中（规划中、排队中、执行中、已暂停）→ 运营中（简单提醒、定时作业）→ 最近结束（已完成、失败、已取消）→ 已归档"分组，简单提醒显示为"运营中 · 待触发"；任务卡显示"第 N/M 阶段"、活动状态小圆点（休眠、干活中、等你、排队）和 token 总量；"等我"写明原因（审批、澄清、由我验收、卡住求助、超预算、中断不确定）。待我处理有未读时 tab 亮小红点，看过没处理的显示灰色数字；事项按紧急度三档排序，到点的简单提醒置顶；可标已读、归档、删除。
- [x] 项目、提醒和设置的假数据按第一阶段的定法：项目状态只有筹备中、建设中、使用中、已停用、已归档五种，简版项目页列出这个项目的定时作业及各自状态（运营中 / 已暂停）；简单提醒卡的重复规则可选每天、每周几、每月几号、按我的工作日；设置的关注类别里，内置类别的处置下拉只给不比默认更松的选项、两条底线只显示不能改，用户自定义的类别可以新建、改规则、改处置、删除；工作日历页按月显示，每天标明上班或休息及原因（新加坡工作日、国内工作日、调休补班、额外规则、手动标记），能加额外上班规则、点某天改成上班或休息。
- [x] 前端状态层是独立模块、纯函数，不依赖 React 和 DOM：输入事件帧 `{频道, 序号, 类型, 负载}`，按频道记下最后收到的序号，重复或更旧的序号被丢掉；乐观显示的尾巴在收到对应的权威事件后被替换。用手写的事件序列做回放测试（前端状态层回放）。
- [ ] 用户在 PC 浏览器里直接打开构建产物，以手机竖屏宽度和宽屏各点过一遍，评审意见记在本票末尾 `## Comments` 下。
- [x] 所有测试通过（vitest），lint（oxlint）无报错。

## Notes

- 本票只做假数据原型和状态层骨架。各页面接真数据由对应的票做：秘书页 04；待我处理和卡片 06；任务看板 12；任务详情 13；项目列表和项目页 15、16（重置维护者 16，项目页上的定时作业 19）；消耗页 24；设置里的关注类别 26，工作日历 29，已配对设备和配对等待页、批准页 10，按会话或时间段删除素材 21，skill 库页 27；聊天附件菜单里的"作为材料投喂" 21。
- 不在本票：卡片类型注册表、不认识的卡片显示纯文本加"去 Web 处理"链接（06）；会话缩放到要点层和全局层（全局层任务按阶段、项目维护者会话按工单段、秘书主线按天着色）、授权内 / 做完告诉我 / 被拦下或问过的不同样式、活动状态的真实数据（25）；正式的 TypeBox 协议（04——本票的状态层先按规格第 5 节的帧形状写，04 落地后改用共享协议包生成的类型，测试不用改）；用主切面录下的真实事件流回放（04 起）。
- 记忆页和全景页不在第一阶段，只在"更多"里留记忆入口。
- 怎么打开给用户评审：按规格第 1 节和用户的约定，二狗的服务进程只能在 Local Service Manager 登记、由它启动，而 `ergou-daemon` 从 04 号票起才登记。所以本票不起开发服务器或预览服务器，评审用的是直接在浏览器里打开的构建产物；手机竖屏宽度在 PC 浏览器里按手机宽度查看。04 起 UI 由经 LSM 启动的守护进程提供，之后的演示都走那条路；真机访问要等 10 号票的外网端口和隧道。

## Comments

2026-10-07 实现说明（子 agent，分支 `worktree-agent-aa254d6634b66d95c`）：

- **怎么打开评审**：`npm install` 后 `npm run build:web`，在浏览器里直接打开 `packages/web/dist/index.html`（单文件，JS 和 CSS 全内联，不起任何服务）。窗口宽于 760 时顶上有一条原型工具条，点"手机竖屏 390"在 390×844 的框里看竖屏布局；也可以把窗口拉窄或用开发者工具的设备模式。详见 `docs/dev.md` 的"Web 包"一节。
- **从 AgentSense 拿了什么**（按主会话的指示"只拿需要的部分，不搬业务逻辑"，验收标准第 1 条按"以它的 web/src 为起点"理解）：
  - `look.css` 的 token 和四条视觉规矩，原样沿用，只去掉只属于 AgentSense 页面的选择器；
  - `index.css` 的颜色 token（含暗色）和通用控件（按钮、小签、气泡、工具调用、卡片底板、弹层、输入框、表单）；
  - `layout.css` 的宽屏分栏（panes、splitter）、里程碑抽屉（改成阶段抽屉：竖屏收起 / 半开 / 全开、宽屏左侧栏）、阶段条和阶段标签；
  - `App.tsx` 的 Splitter、宽窄断点 600、单文件构建（vite-plugin-singlefile）。
  - 没有搬 `agent/`、planguard、ZoomHistory、里程碑控制器等业务代码。
- **做了的决定**：
  1. 宽窄按内容区的实际宽度（ResizeObserver）判断，不按窗口宽度，原型的"手机竖屏"框因此能直接用。
  2. 前端连接接口 `Connection`（`src/app/connection.ts`）是状态层和服务端之间的接缝：收到的事件帧和失败的请求都变成状态层输入，发出的请求带幂等键（卡片动作带期望版本）。原型用假连接，04 号票写 WebSocket 实现。
  3. 帧、消息、卡片的类型暂时手写在 `src/state/protocol.ts`（按规格第 5 节），没有动共享协议包；04 号票落地 TypeBox 后改成从 `@ergou/protocol` 取类型。
  4. 维护者会话的"对话段"（规格第 21 节：用户直接对话、立项问答开的段）用 `work_order_divider` part、工单号为空表示，没有另加 part 类型。
  5. 看板、项目、待我处理、设置的假数据放在原型的本地状态（`src/prototype/proto-store.tsx`），没进前端状态层：这些频道的事件形状由各自的票定（06、12、15……），到时候往状态层的 `eventHandlers` 里加。会话和卡片走了状态层，所以同一张卡在聊天、待我处理、任务详情里状态同步；卡片处理后看板等假数据跟着变，也是看状态层里卡片的变化，不认具体的连接。
  6. 卡片的处理结果是结构化的 `outcome: { action, note? }`，显示文字由 `model/cards.ts` 按动作名生成；假连接把"不用了""取消"记为已关闭（dismissed，对应回避信号）。
  7. 待我处理的 tab：有未读亮小红点，同时显示看过没处理的灰色数字；打开某一项就算看过。
  8. oxlint 加了 react 插件（rules-of-hooks 等），关掉过时的 react-in-jsx-scope，CSS 的副作用 import 不报警告；根 `package.json` 加了 `build:web`。
- **依赖**（都精确锁定）：react / react-dom 19.3.0，@types/react / @types/react-dom 19.3.0，vite 8.3.3，@vitejs/plugin-react 6.1.2，vite-plugin-singlefile 2.3.3。`npm audit` 报 3 个 high：vite-plugin-singlefile → micromatch → braces 的栈耗尽问题，只在构建时匹配我们自己的配置，不进运行时；没修（audit 给的修法是降到 0.9）。
- **原型的局限**：只有「家庭照片整理与去重」「每周汇总银行账单」「博客迁移到 Astro」三个任务、「记账本」「个人博客」「家电档案」三个项目配了会话假数据；工作日历只带 2026 年 9–12 月的节假日；发消息只回一句固定的"（原型）收到"；刷新页面回到初始假数据。
- **没勾的验收标准**：用户在 PC 浏览器里以手机竖屏宽度和宽屏各点一遍、评审意见记在下面——要用户自己做。实现时用无头浏览器以 390×844、1280×820、1440×900 打开构建产物逐页点过，没有页面错误。
