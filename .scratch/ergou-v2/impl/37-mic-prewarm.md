# 37 — 麦克风预热：进语音模式就备好麦克风，按下立刻开录

Status: ready-for-agent
Blocked by: 31（语音输入与识别）
Spec: [第一阶段规格](../spec.md) 第 22 节（语音消息）

## What to build

用户真机实测：按下"按住 说话"的同时念"ABCDEFGHIJKRLN"，只识别出"FGHIJKRLN"。原因是按下时才 `getUserMedia` 打开麦克风、再建音量分析和 MediaRecorder，手机上要几百毫秒到一秒多，这段时间说的话没录进去。

用户定（2026-10-08）：**提前加载麦克风，但不记录**。切到语音模式时就打开麦克风流、接好音量分析，MediaRecorder 不启动（不录、不存、不上传）；按下时只启动录音，立刻开录。代价是语音模式期间浏览器和系统的麦克风指示灯亮着，所以切回文字模式、页面切到后台、语音模式里闲置超过 10 分钟（可配，前端常量即可），都立刻关掉麦克风；再按下时重新打开（这一次照旧显示"准备中"）。

## Acceptance criteria

- [ ] 预热：进入语音模式（包括页面打开时恢复成语音模式）就请求麦克风并保持流开着、音量分析就绪；不启动录音器，不产生任何录音数据。离开语音模式、页面切到后台（visibilitychange）、组件卸下、闲置超过阈值时立刻停掉所有音轨（指示灯熄灭）；回到前台且仍在语音模式时重新预热。
- [ ] 按下即录：流已就绪时，按下的那个 pointer 事件里同步启动录音器，"准备中"不出现、计时从按下那一刻开始；流还没就绪（刚进语音模式就按、或者预热被关掉了）时照旧"准备中"、就绪后开始。抬手、上划取消、太短、60 秒自动发送的行为不变；录完一条后流不关，接着下一条。
- [ ] 不录的保证：预热期间录音器不存在或没启动；音量面板只在按住时显示。测试覆盖：进语音模式后没有 MediaRecorder.start 调用、按下才有；离开语音模式 / 切后台 / 闲置后音轨都停了。
- [ ] 测量：每条语音带上"按下 → 录音器真正开始"的毫秒数，以及这次是不是预热命中（流已就绪），随语音一起发给守护进程，存在语音对象里（协议加一个可选的诊断字段，宽松向后兼容）；本机接口取得到，方便在用户手机上看实际数字。
- [ ] 权限：第一次进语音模式时请求麦克风权限；被拒时照旧提示怎么开，不反复弹。
- [ ] 前端状态层（voice-gesture 等）表格或回放测试覆盖新的状态；所有测试通过（vitest），lint（oxlint）无报错。
