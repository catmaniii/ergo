# 03 — 守卫判定核心

Status: ready-for-agent
Blocked by: 01（工作区骨架与 agent 子进程 spike）
Spec: [第一阶段规格](../spec.md) 第 9 节（守卫）、第 7 节（秘书）、第 21 节（实现细节补充）、Testing Decisions（守卫判定）

## What to build

做出守卫的判定核心：一个纯函数，输入一次工具调用（真实工具，或从 bash 拆出来的伪工具调用）、发起的 agent 及其工具包、所属任务的计划、当前阶段和授权项、效果日志、全局与本任务的关注类别设置，以及调用方现取后传入的环境事实（文件元数据、git 状态、要跑的脚本用到了哪些联网的库或函数）；输出处置、命中的关注类别、是否通用 bash、命中的时序规则、是否属于授权内、给模型的说明。同样的输入永远得到同样的判定。

围绕它的是几份数据：工具注册表（每个工具的类别标签、参数规则、可选的"做完告诉我"标记和"只读或幂等"标记）、关注类别注册表（内置九类）、默认处置表和两条底线。"先问我"的意思是执行时一定当场问，计划里写了、授权项里列了也照样问；只有"计划里列了才做"那一档靠计划一次授权。通用 bash 用现成的 POSIX shell 语法解析库拆开，映射成伪工具调用后逐个判定；拆不开的先问用户。再加上三道硬边界：路径围栏（文件工具越界写入一律拒绝）、受保护区域（配置区、密钥区、数据库区、二狗程序目录，写入为"永不"，密钥区连读都拒绝）、联网开关（关着时联网的工具和命令直接拒绝，秘书一律视为关着）。

本票不接任何运行时。做完后能用守卫切面（切面 2）的表格测试演示"某个 agent 在对话里或任务里做某件事，守卫给出什么判定、为什么"。

## Acceptance criteria

- [ ] 判定函数是纯函数：不读文件、不跑命令、不看时钟（当前时间也由调用方传入）；输入输出字段按规格第 9 节。每个判定都带给模型的说明：命中了什么、为什么、接下来该怎么做（例如越界写入被拒的原因、要联网就发起任务）。守卫切面的测试只调用这个函数，表格驱动，表格格式留出给 05 号票加时序规则场景的位置。
- [ ] 工具注册表：内置工具、带类型的特殊 bash 工具（git 状态和差异（只读）、git 提交、git 推送、建远端仓库、git 合并、跑测试、在工作目录里装依赖、启动构建）、MCP 工具都能登记类别标签、参数规则（哪个参数是路径、哪个是收件人等）、可选的"做完告诉我"标记和"只读或幂等"标记，联网的工具在注册表里标明；git 提交、在工作目录里装依赖带"做完告诉我"标记，git 状态和差异标"只读或幂等"。"只读或幂等"标记本票只登记、不参与判定，供 23 号票被杀后的恢复使用。
- [ ] 关注类别注册表是数据，从数据目录的配置区读，判定按注册表走；内置九类：花钱；以我的名义对外发送或发布（含建 GitHub 仓库、推送）；删除或覆盖（项目档案和工作目录内）；不可逆的提交；账户与安全（凭据、权限、全局装软件）；越出项目目录；使用授权范围外的记忆；计划外工单；未知的写操作。
- [ ] 默认处置按规格第 9 节的表（任务里"越出项目目录"为"计划里列了才做"），表格测试覆盖每个类别 × 对话 / 任务。不落在任何类别的调用为"直接做只记录"，带"做完告诉我"标记的为"做完告诉我"；对话里"计划里列了才做"等同"先问我"；一次调用落在多个类别时取最严的处置；对内置类别，传入的设置只会让处置更严（判定取默认和设置里更严的那个）；用户自定义的类别没有默认，按传入设置里它的处置判，但同样参与"取最严"，所以放宽不了一同命中的内置类别和两条底线；本任务的关注类别只在全局之上增加。
- [ ] 两条底线：付款转账、创建账户、改密码或两步验证固定为"交给我做"；对外内容里出现密钥形态（正则检查）固定为"永不"。不论设置、授权项，也不论对话还是任务，都放宽不了，表格测试逐条验证。
- [ ] 授权项（操作种类 + 对象范围 + 次数 + 所属阶段 + 有效期）只对"计划里列了才做"那一档起作用：任务里这一档的调用，有一条属于当前阶段、未过期、次数没用完、对象范围覆盖它的授权项时放行，并标"属于授权内"；不属于当前阶段、已过期（默认有效期 7 天）、次数用完（按效果日志里实际生效的效果计数）或超出对象范围时，改为先问用户。处置为"先问我"的调用一律当场问：表格测试里，任务中有一条覆盖它的授权项的"账户与安全"调用仍判"先问我"。另有一个纯函数校验对授权项的修改：收窄通过，放宽被拒。
- [ ] bash：只认 Git Bash。通用 bash 用现成的 POSIX shell 语法解析库拆开管道和子命令，映射成伪工具调用后逐个判定、取最严：`rm` → 删除，`git push` → 推送，`npm install -g` → 全局装软件，`curl`、`wget` 这类 → 发 HTTP 请求（按请求方法区分 GET 和非 GET，见联网开关一条）；命令里出现项目外的路径落入"越出项目目录"。拆不开的（`eval`、内联脚本、编码过的命令）按"未知的写操作"先问用户。所有通用 bash 调用的判定都带"通用 bash"标记，拆得开、又不落在任何类别里的不打断。
- [ ] 路径围栏和受保护区域：维护者和子 agent 的文件工具写项目档案和工作目录以外一律拒绝、不问用户，读项目档案和工作目录以外落入"越出项目目录"、按处置走；它们的 bash 碰到项目外的路径同样落入"越出项目目录"。秘书的文件工具只能写草稿区、项目档案对它只读：写草稿区以外一律拒绝；读草稿区和项目档案以外的文件、bash 碰到草稿区外的路径，落入"越出项目目录"（对话里即先问用户）；草稿区里的写、改、删不落入"删除或覆盖"等任何类别。受保护区域（数据目录里的配置区、密钥区、数据库区和二狗程序目录）：任何 agent 用文件工具或 bash 写入都判"永不"，设置、授权项和用户批准都放宽不了；密钥区连读都拒绝。
- [ ] 联网开关（判定输入里工具包的一项）：关着时，联网的工具、从 bash 拆出的发 HTTP 请求的伪工具调用直接拒绝；调用方传入的环境事实表明要跑的脚本用到联网的库或函数的，同样拒绝；说明里都提示"联网请发起任务"。秘书不论传入什么工具包，一律按关着判。开着时，只读的 GET 请求不落入任何关注类别，非 GET 的请求落入"以我的名义对外发送或发布"。
- [ ] 所有测试通过（vitest），lint（oxlint）无报错。

## Notes

- 六档处置的严格程度：规格始终按"直接做只记录、做完告诉我、计划里列了才做、先问我、交给我做、永不"的顺序列出，本票按这个顺序由松到严取最严（26 号票的设置也按同一顺序比较）。
- 效果日志：本票只把它当判定输入（字段按规格第 9 节），用于授权项计次；规范化参数和时序规则在 05；落进 `ergou.db`、只追加执行成功的调用在 07。
- 不在本票：时序规则和 v1 模板（05）；把判定接进子进程的 `tool_call`、审批表和审批卡、5 分钟等待、按调用指纹的一次性放行、"交给我做"事项（07）；"前置阶段须已验收"、"某个对象被判过'永不'之后，再对它做对外动作要先问"等控制器硬检查和拉回（13），拉回计数、偏离的逐级升级、累计被拒暂停（14）；设置页、拒绝放宽内置类别的设置接口、用确定规则（工具、路径、收件人、金额）自定义类别及其修改和删除、计划卡上增加本任务的关注类别（26，加在本票的注册表上）；计划外工单的实际触发（17）；MCP 的登记和联网开关在会话装配上的落实（27）。
- 带类型的特殊 bash 工具，本票只登记它们在注册表里的类别标签、参数规则和两种标记；工具本身的执行实现在 28 号票（带类型的特殊 bash 工具）。"只读或幂等"标记的使用（被杀重启后告诉模型"这次调用被中断了"，或转"中断：不确定 X 是否已执行"）在 23。
- 秘书不联网是尽力而为，不是硬隔离：本票只负责按传入的事实判定。草稿区里的脚本执行前先扫一遍、把用到的联网库或函数作为环境事实传进来，以及给脚本进程设无效的代理地址，在 07 号票做；联网开关关着的维护者同样适用，随 27 号票的联网开关接上。真正挡死要等以后加系统级沙箱。
- 围栏越界写入、联网关着时的联网调用是直接拒绝；受保护区域写入是"永不"。两者都不出审批卡。
- "使用授权范围外的记忆"类别存在，但第一阶段不会触发。
