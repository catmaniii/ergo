# 59 — 流程执行：每次调用和计划比对，能修的自动修回

Status: ready-for-agent
Blocked by: 58（流程：起草、审查、授权）
Spec: [第一阶段规格](../spec.md) 第 8 节"两种任务"、第 9 节（守卫）；ADR 0019；调研 `docs/research/15-agentsense-zoom-detail-task-modes.md` §4.5

## What to build

照搬 AgentSense 固定计划的执行守卫：`W/agent/guard.ts` 的 `evaluateCall` 和自动修回，以及 `runtime.ts` 的收尾提醒。

## Acceptance criteria

- [ ] **比对**：流程执行时，守卫把每次调用和计划比对，判出以下几种：
  - 计划外；
  - 超范围：参数超出步骤写的；
  - 顺序错：前置步骤或时序规则没满足；
  - 重复；
  - 禁止。

  比对排在现有的守卫判定（关注类别、处置）之后，两道都要过。
- [ ] **自动修回**：能修的不打扰用户，两种修法：改回参数（rewrite）、引回前置步骤（redirect）。
  - 每一步最多修 2 次（`MAX_AUTO_FIX`）。修不了或超过次数的，问用户。
  - 每次修回都进时间线，记成偏离记录，口径同 14 号票。
- [ ] **进度和收尾**：维护者用 `report_step` 自报进度，视图里再推断一次，照 AgentSense 的 `sessionView`。一轮要收工时还有没做的步骤，提醒一次。
- [ ] **执行中不能改步骤**：要改就重新发起。维护者想改计划时，告诉它不行。
- [ ] **参数比对的粒度**：通用 bash 的步骤只比到命令这一层；带类型的特殊 bash 工具按字段比。
- [ ] **主切面测试**，覆盖这些情形：
  - 计划外的调用被拉回；
  - 参数被改回；
  - 前置步骤没做，被引回；
  - 修回超过次数后问用户；
  - 重复调用；
  - 收尾时有没做完的步骤，提醒一次；
  - 维护者想改步骤，被拒。
- [ ] 所有测试通过（vitest），lint（oxlint）无报错。
