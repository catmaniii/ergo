# 90 — 任务和待办的管理：任务操作菜单、看板多选和分组收起、任务详情顶部并成一行、待办多选

## What to build

用户 2026-10-11 提了四条：看板上长按 / 右键任务卡片要能操作这个任务，最好能批量管理；任务详情顶部四排太占地方，要并成一行或收进管理菜单，关键信息留在标题栏；看板每个分组能展开收起；待办也要批量管理。用户嫌票拆得太多，这四条并成一张票。下面没答的取舍先照主会话的建议做（见末尾"取舍"），用户改了再跟。

1. **任务操作菜单（一份，三处用）**：看板卡片长按 / 右键、任务详情标题栏的"⋯"、多选的操作栏，都用同一份"这个任务现在能做什么"（照现有的可做动作规则算，按种类和状态变）。菜单项：打开（看板上才有）、暂停、继续 / 追加预算继续、重试、取消任务、从某阶段重做（长程任务）、归档、多选（看板上才有）。简单提醒、定时作业卡照它们现在能做的（改、取消、暂停 / 恢复）。长按手势从语音气泡里抽出来共用，菜单用现有的浮层菜单。
2. **结束了的任务随时能直接归档**：完成、取消、失败的任务（全局的、项目里的都行）能从菜单、多选里直接归档；没结束的要先取消。每周的归档清单卡照旧。
3. **看板多选**：标题栏"多选"按钮（"发起任务"左边）；菜单里点"多选"进入并勾上这一张。卡片出勾选框，点卡片就是勾选；每组标题右边"全选"；底部一条操作栏"已选 N 个 · 暂停 · 继续 · 取消 · 归档 · 完成"，每个操作只对能做的生效，按钮上写个数（比如"取消（3）"），一个都不能做时灰掉；取消先确认一次（写清几个会取消、几个跳过）；做完提示结果（成功几个，失败几个、为什么）。守护进程要有一次处理多个任务的接口，各条独立成败、逐条回报。
4. **看板分组收起**：每组标题点一下收起 / 展开（▾ / ▸），收起后标题行照样有个数；每台设备记住；默认"已归档"收起、其它展开（原来"已归档 N 展开 ▸"并进这个做法）。
5. **任务详情顶部并成一行**（宽屏、手机都只有一行）：
   ```
   宽屏：‹ [阶段标签] 标题  [状态签 ▾] ●活动        [关键按钮] [⋯]
   手机：‹ 标题…  [状态签 ▾] [阶段标签 / 流程进度] [⋯]
   ```
   - 状态签点开是小浮层：原来第 3 排的原因说明（超预算用了多少、预算多少，卡住求助、失败原因、中断不确定的说明……）、token 数、这个状态能做的按钮。
   - 关键按钮只在"等我"时出一个最要紧的（追加预算继续 / 继续执行 / 验收通过 / 重试），只在宽屏标题栏；手机放进状态签浮层和"⋯"。
   - "⋯" 管理菜单：上半是计划、工单 N（有才有）、工具包、消耗、运行 N（定时任务）——宽屏在右边详情栏打开（56 号票的详情栏），手机整页打开、‹ 回到会话；下半是第 1 条的任务操作。
   - 页签那一排去掉，会话占满。退回 / 返工要写原因的输入框改成点了按钮弹出的对话框。流程任务标题栏的进度照旧（点它看计划）。一次性的普通任务也一样一行。
   - 阶段标签在宽屏的位置、开合阶段栏的做法（88 号票）不动——阶段栏本身由 91 号票改。
6. **待办多选**：标题栏"多选"，行的长按 / 右键菜单（现有的"⋯"菜单）里也有"多选"；勾选、全选（当前页签）；底部操作栏：标已读、标未读、归档、删除、一起处理（所选通知有同一个选项时，比如"知道了"）。审批、提问、计划确认这类卡片只能一起标已读 / 未读，批准、拒绝、回答还是一张张来。卡着任务、还没处理的事项不能归档或删除，批量时跳过并说明跳过了几条（现有的批量接口是全部生效或全部不生效，跳过的先剔掉）。
7. 11 套视觉风格都看一遍：菜单、勾选框、操作栏、状态签浮层、标题栏一行。
