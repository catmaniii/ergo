## What to build

维护者干开发类的活时，常用的 bash 操作不再走通用 bash，而是调用带类型的工具：git 状态和差异（只读）、git 提交、git 推送、建远端仓库、git 合并、跑测试、在工作目录里装依赖、启动构建。每个工具的参数是结构化的（仓库路径、分支、提交说明、远端、仓库名和可见性等），在 Git Bash 里、以工作目录（或建在工作目录里的 worktree）为当前目录执行，结果以结构化的形式交回模型。类型事先定好，守卫不用拆命令就知道它落在哪些关注类别里，时序规则也能直接套用；时间线上它们不带"通用 bash"标记。

每个工具在工具注册表里登记类别标签、"做完告诉我"标记和"只读或幂等"标记（登记表见 Notes）：git 提交、合并、装依赖做完告诉我；推送、建远端仓库落入"以我的名义对外发送或发布"，任务里要计划里列了才做；其余直接做、只记录。它们和 v1 时序规则模板配合：push 之前必须跑过测试，删除或覆盖工作目录里的文件之前必须已提交，force push 一律禁止。带类型的工具和通用 bash 里的同一操作规范化成同一种形式，绕到通用 bash 去做也一样受约束。

演示：faux provider 剧本里，一个任务的维护者在工作目录（一个临时 git 仓库）里改完代码，先看状态和差异，再提交（时间线上标"做完告诉我"）；没跑测试就推送，被拦下，说明里写着要先跑测试；跑测试通过后再推送，按计划里的授权项放行；试一次 force push，一律被拦下。

- [x] 主切面：跑测试、启动构建、装依赖以退出码判成败，退出码非零算执行失败，不进效果日志；单次调用超时（默认 10 分钟，这三个工具可以声明更长，可配置）被中止，同样算执行失败。工具起的进程在 Job 对象里，环境里没有任何密钥（测试脚本里查环境变量看不到）。
- [x] 守卫切面（场景文件）+ 主切面：没跑过测试就推送 → 拦下，说明写明"push 之前必须跑过测试"；测试没通过（不进效果日志）后推送 → 仍拦下；测试通过后推送 → 按处置放行。带 force 的推送（含 `--force-with-lease` 这类等价写法）一律禁止。工作目录里有未提交改动的文件，删除或覆盖前被拦下，提交之后放行。同样的序列换成通用 bash 的 `git push`、`git push --force`，判定一致。
- [x] 主切面：合并把指定分支（比如 20 号票子 agent 在 worktree 里的分支）合并进工作目录的当前分支；有冲突时中止合并，工作目录回到合并前的状态，冲突文件列在给模型的结果里，这次调用算执行失败、不进效果日志。
- [x] 守卫切面：工具的仓库路径参数按 03 号票的参数规则过路径围栏——工作目录（含建在里面的 worktree）之内照常判定，工作目录之外落入"越出项目目录"；按规格第 9 节，写入受保护区域（配置区、密钥区、数据库区、二狗程序目录）的一律"永不"，密钥区连读都拒绝，只读的状态和差异读配置区、数据库区、程序目录落入"越出项目目录"。跑测试、启动构建、装依赖不接受任意命令：执行的是工作目录里已有的项目约定（比如 package.json 里的脚本），模型只能传 npm 脚本的附加参数（make、cargo、go 不收附加参数）；装依赖只装进工作目录，只收注册表里的包名，不接受全局安装。（2026-10-08 评审后改了措辞，见 Comments）
- [x] 主切面：这些工具随工具包的 bash 开关一起出现在会话里，bash 关着时一个都没有；秘书的固定工具里没有它们。推送、建远端仓库、装依赖要联网：工具包的联网开关关着时直接拒绝，说明里写明要开联网；开着时按上面的类别判定。推送和建远端仓库的对外一侧在测试里换成可替换的执行器，不真的连网。

规格没写清、按最保守做法定下的：

- **执行放在守护进程**（代为执行的工具），不放进 agent 子进程：工具的实现和权限判断留在守护进程一侧（ADR-0004 的边界），参数照样先经守卫判定。`AgentSession` 往会话注册表里加代为执行的工具时，跳过来源是 `typed_shell` 的登记（框架自带的注册表里已经有了，`agent-session.ts` 一行）。
- **每次调用一个 Job 对象，不放进 agent 管家的那个**：管家的 Job 按"从活着的 agent 子进程走不到"回收孤儿，守护进程直接起的进程会被当成孤儿结束。每次调用的 Job 同样 `KILL_ON_JOB_CLOSE`、不允许脱离、句柄只在守护进程手里；先起一个 Node 闸门进程、放进 Job 之后才让它起 Git Bash（Git 的 `bin/bash.exe` 是启动器，一起来就再起真正的 bash，等不到放进 Job 就会脱离出去）。跑完、超时、被中止都关掉这个 Job，整棵进程树（含孤儿）一起结束。主切面和工具测试都验了（去掉 Job 时用例确实失败）。
- **`HostToolCall.signal`**（`agent-manager/host-tools.ts`）：子进程那边已经结束了这次调用（这一轮被中止、管家按超时中止）或 agent 退出时中止。管家的超时机制不变；跑得久的工具据此结束进程。工具自己另有一个多 5 秒的兜底计时。
- **更长的超时**：跑测试、启动构建、装依赖声明配置里的 `shellTools.longCallMinutes`（默认 30 分钟，规格只说"可以声明更长"）；别的带类型的工具按 `agents.toolCallMinutes`。

评审后修改（2026-10-08，两路评审）：

- **值不上命令行**（安全）：Git Bash 是 MSYS 程序，命令行上的参数会被它的运行时当通配符展开、当响应文件读进来（评审实测 `["*.ts","@secret.txt"]` 到脚本变成文件名列表和文件内容）。现在命令行上只有固定的脚本，模型给的值（分支名、提交说明、附加参数、包名、路径）经 stdin 按 NUL 分隔送进去，脚本开头 `mapfile -d ''` 读进 `"$@"`（`runner.ts`、`runner-main.ts`）；另设 `MSYS_NO_PATHCONV=1`、`MSYS2_ARG_CONV_EXCL=*`，Git Bash 起 Windows 程序时不把 `/x/y` 改成 `X:/y`。测试：提交说明、合并和推送的分支名、跑测试的附加参数、装依赖的包名分别用 `*`、`?`、`@工作目录里的文件`、`@另一个临时目录里的文件`、`$(id)`、`%PATH%`、反引号、`/x/y`，断言原样到达、文件内容和命令输出都不出现；把值放回命令行时这四条用例都失败（实测过）。
- **附加参数不能执行任意命令**（安全）：make 的"变量=值"会展开进配方，cargo 的 `--config` 能设 runner，go test 的 `-exec` 能跑任意程序。make、cargo、go 现在只跑约定的目标，一律不收附加参数；npm 脚本的附加参数照收（交给项目自己的测试工具）。
- **推送只收已配置的远端名**（先 `git remote` 核对），不收网址和本机路径。**装依赖只收注册表里的包名**（可以带版本号或版本范围；npm 包名、crates.io 包名、Go 模块路径各一个正则），选项、本机路径、`file:`、`link:`、git 网址、绝对路径、`..` 一律不收、什么都不跑。测试里的装依赖用 PATH 上一个假的包管理器（不连网），不再装本地包。
- **所有 git 调用固定加 `-c core.fsmonitor=`**（脚本里的函数 `g`）：`core.fsmonitor` 可以是一条命令，状态和差异是"只读或幂等"，不能被仓库配置变成执行命令。测试：仓库配置里设一个会留下标记文件的 fsmonitor 钩子，看状态和差异后标记文件不在（去掉这个参数时用例失败，实测过）。
- **固有缺口：项目代码本身能执行**。提交会跑仓库的 git 钩子，跑测试、构建会跑项目里的脚本和 Makefile，agent 能用文件工具或 bash 改它们；带类型的工具只负责分类（守卫按类别判），不额外提供隔离。写进了 `docs/dev.md` 的"带类型的 bash 工具"和 `tools.ts`、`conventions.ts` 开头。收紧的一处：用文件工具或 bash 写工作目录（或秘书草稿区）里的 `.git/config`、`config.worktree`、`.git/hooks/` 下的文件（worktree 和子模块在 `.git/worktrees/`、`.git/modules/` 下的同样算），守卫按"越出项目目录"判（`guard/paths.ts` 的 `isGitControlPath`，`judge.ts` 的路径规则里加了一条，属于既有类别的范围扩展；对话里先问，任务里计划列了才做，不是硬拒绝）；读照常。时序规则看到的路径区域（`rule-steps.ts` 的 `area`）没改，免得 `rm -rf .git/hooks` 被"项目外 rm -rf 一律禁止"判成永不。表格用例在 `test/guard/fence.test.ts`。
- **规范小修**：`guarded()` 改名 `reportFailures()`、在 `typedTool` 里统一套上；跑测试、构建的工具名、说法、说明并成 `conventions.ts` 的 `PROJECT_TASKS` 一张表；`runProjectCommand` 复用 `sh()` 的计时、`stoppedReason` 和 signal 传递；失败结果统一经 `failed()`（`ToolFailure` 带结构化字段和输出）；`agent-session.ts` 的重复登记判断改成看来源（`d.source !== "typed_shell"`）。
- **录制先换路径再截短**：守护进程截短结果摘要时可能截在路径中间，完整路径的写法匹配不上，原来只是因为临时目录在用户主目录下才碰巧换掉主目录那一段。`test/helpers/recording.ts` 的 `scrubLocalPaths` 现在按占位符分组，每组先换完整的、再把"路径的一段开头紧跟省略号"换成占位符加省略号，结果和先换路径再截短一样；`test/recordings-privacy.test.ts` 加了用例。重录了 `typed-shell-tools`。
