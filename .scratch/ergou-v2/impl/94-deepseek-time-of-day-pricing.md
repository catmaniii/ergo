# 94 — 消耗页的成本按 DeepSeek 官网价格分时段估算

Status: ready-for-agent
Blocked by: 无（小功能，走轻流程）
Spec: [第一阶段规格](../spec.md) 消耗一节；24 号票（账本、单价）、29 号票（节假日数据）

## What to build

用户 2026-10-12 提："从 https://api-docs.deepseek.com/zh-cn/quick_start/pricing 读一下价格，刷新消耗统计里面的成本估计。目前成本估计都是 0。deepseek 的价格是分时间段的，所以你得把这个考虑进来。"

现在成本 = 用量 × 配置文件里 `tokenPrices` 的单价，用户的配置里没写单价，所以全是 0；而且不分时段。改成：

1. **框架自带 DeepSeek 的价格表**（主会话 2026-10-12 从官网读到的，单位：元 / 百万 tokens）：

   | 模型（配置里的键） | 时段 | 输入·缓存命中 | 输入·缓存未命中 | 输出 |
   |---|---|---|---|---|
   | `deepseek/deepseek-flash` | 空闲 | 0.02 | 1 | 4 |
   | | 高峰 | 0.04 | 2 | 8 |
   | `deepseek/deepseek-v4-pro` | 空闲 | 0.15 | 4.5 | 13.5 |
   | | 高峰 | 0.30 | 9.0 | 27.0 |

   - 旧模型名 `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 官网说按 Flash 价格计费，照 `deepseek-flash` 算。
   - 价格表写明"取自官网，2026-10-12"，官网会改价，放在一个好改的地方。
2. **分时段**：高峰时段是北京时间（UTC+8）周一至周五（不含中国法定节假日）的 9:00–12:00、14:00–18:00；其余时间（含周末、法定节假日全天）是空闲时段，价格是高峰的一半。是不是法定节假日用现有的节假日数据（29 号票，中国 `cn-<年>.json`，框架自带 + 用户导入的合起来）；某一年没有数据时只按周一至周五算，消耗页写明那一年没有节假日数据。每一笔用量按它记账的时间落在哪个时段算价。
3. **配置里的单价照旧优先**：用户在配置里给某个模型写了 `tokenPrices`，就用配置的（不分时段，和现在一样）；没写的用框架自带的价格表；两边都没有的照旧列在"没配单价"。
4. **消耗页**：成本照旧标"粗估"；去掉"不按时段计价"的说法，单价那块列出每个模型的高峰 / 空闲价、高峰时段怎么算、价格取自官网哪天；以前的用量也按新价格算（成本本来就是查的时候现算的）。
5. 示例配置里 deepseek-flash 那份过时的示例单价去掉或改成说明"不写就用框架自带的价格表"；`docs/dev.md` 跟着改。

## Acceptance criteria

- [ ] 没配单价时，deepseek-flash、deepseek-v4-pro（和两个旧名字）按自带价格表算出成本；有测试。
- [ ] 同样的用量，高峰时段（工作日 9–12、14–18 北京时间）是空闲时段的两倍；周末、法定节假日（用节假日数据）全天按空闲；时段边界（9:00、12:00、14:00、18:00 整点）和跨时区（记账时间不是 +08:00 的）算对；有测试。
- [ ] 配置里写了单价的模型以配置为准；有测试。
- [ ] 消耗页单价那块写明分时段规则和价格来源；截图（经典浅色 390、1280）。
- [ ] 相关测试、typecheck、oxlint 通过。
