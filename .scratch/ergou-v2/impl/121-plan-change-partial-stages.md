# 121 — 计划变更只交要改的阶段就行（修 AI 情报站卡死）

Status: done
Blocked by: 无
Spec: [第一阶段规格](../spec.md) 第 8 节（计划变更）；14 号票（计划变更）、112 号票（长程任务一律自动验收）

## 现象（2026-10-14 查 AI 情报站首版建设 t-6 卡住的原因）

- 第 6 阶段"周报样张"的验收标准写的是"覆盖完整一周（W42，10-12–10-18）"。项目还在建设期，没有定时跑日报，10-14 以后的日报不可能有，评审按标准判了三次都不过。
- 用户在对话里两次说过"不用等满一周"，维护者也同意改验收口径，但它**改不了**：
  - 维护者用计划变更交了全部阶段：被拒，回的是"已验收的阶段不能改"。9 个阶段的长计划要它一字不差地抄回已验收的那几段，很容易有细小出入，被判成"改了已验收的阶段"。
  - 只交 s6：又被拒，回的是"阶段 s6 的前置阶段 s5 / s7 不存在"，因为计划检查要求一份完整的计划。
- 结果维护者只能请用户去任务详情里点"返工"，自己改验收标准。用户没找到入口，任务从 10-13 13:51 起一直停在"卡住求助"。

## What to build

维护者提计划变更时，**只交要改的、还没验收的阶段就行**，其余阶段从当前计划原样带上：
1. `propose_plan_change`（以及自行调整计划那条路，`execution-tools.ts` 里对应的工具）：
   - 交来的计划里**没写到的阶段**，从当前确认的计划原样补上，编号、前置关系、已验收状态都不变。
   - 前置检查在补全之后的完整计划上做。
2. 交来的计划里**带了已验收的阶段**：
   - 和当前定义一样的，照常；
   - 有出入的，**以当前定义为准、忽略交来的那份**，不再整份拒掉。
   - 维护者看到的结果里写一句："已验收的阶段 s1、s3 交来的定义和现在不一样，已按现在的定义保留；要改已验收的阶段请让用户返工"。
3. 其余规矩不变：
   - 扩大授权、改验收或交付件的照样走计划变更卡，等用户确认；
   - 只停受影响的阶段；
   - 时间线记一笔。
   - 改验收标准是"扩大"的那一类：用户在计划变更卡上一点确认就生效，**不用再去任务详情找返工**。
4. 被拒的时候，结果里要写清楚**具体是哪一处**不行。比如"s1 的验收标准第 2 条和现在不一样"，不要只说"已验收的阶段不能改"。
5. 维护者的工具说明（`execution-tools.ts` 里那段）改成：要改某个阶段，只交这个阶段就行。

## Acceptance criteria

- [x] 只交一个没验收的阶段（前置是已验收的阶段）能成功提出计划变更；改了验收标准的出计划变更卡，用户确认后生效，只停这个阶段
- [x] 交全部阶段、已验收阶段有细小出入时不再整份被拒，按现在的定义保留并在结果里说明
- [x] 被拒时结果写明具体哪一处
- [x] 自行调整计划（不扩大的）也能只交改动的阶段
- [x] 相关测试（`plan-change`、执行工具、计划检查）、typecheck、oxlint 通过，不跑全量
