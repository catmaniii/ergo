# 108 — 会话滚到最后一条就停；加"到最上面 / 到最下面"两个按钮

Status: ready-for-agent
Blocked by: 无
Spec: [第一阶段规格](../spec.md) 第 19 节（会话区照搬 AgentSense）；54 号票（`ZoomHistory`）、104 号票（项目整页）

## What to build

用户 2026-10-13 原话："项目的聊天框好像我能一直往下滚动，滚到屏幕上没有显示内容，这个是不对的，应该是滚到我的内容到头了就停止……把我最下面的内容都滚的超出屏幕了，那别人哪知道这里面是空的还是有内容呢？要把这个改掉。另外，可能要想办法加两个按钮，就是能够跳转到那个聊天框的最下面或者最上面。"

### 1. 滚到最后一条就停

- 先复现：项目整页（104 号票）的维护者会话，宽屏 1280（项目档案栏开着 / 收着）、窄屏 390，还有平板的尺寸（横屏约 1280×800、竖屏约 800×1280），三档缩放都试；用户是在鸿蒙平板 App 里看到的。任务整页、秘书会话也试一遍，看是不是同一个原因。
- 找到根因再改（猜测：`ZoomHistory` 的 sizer 撑出的高度比内容高——比如内容变矮、换档、条外标注 / 虚线框 / 书脊撑高之后没缩回来，或者某处给底部留了很大的空；以复现为准）。改完后往下滚到底时最后一条的下沿贴着可视区底部（加正常的下内边距），不能再往下滚出空白。三档缩放下都成立。
- 写一个能锁住这个问题的测试（状态层能算的放状态层；要靠真实排版的，写清楚截图 / 脚本怎么核对）。
- `ZoomHistory` 是照搬 AgentSense 的：修 bug 不算偏离；如果要改它的结构、数值，写在 Comments 里，主会话合并前问用户。

### 2. "到最上面 / 到最下面"两个按钮

位置（主会话给的建议，用户可能会改，等主会话的消息；先做第 1 部分，做完还没收到消息就照这个做）：

- 会话区右下角、输入框上沿往上一点，竖着一对小圆按钮：上面 ↑（到最上面）、下面 ↓（到最下面）。
- 只在用得着时出现：离开顶部才出 ↑，离开底部才出 ↓；停在底部、内容不满一屏时都不出。出现 / 消失淡入淡出。
- ↓：滚到最新一条，之后接着跟最新的走（和自己发了消息之后一样）。离开底部期间来了新消息，↓ 上带个小数字或圆点（能做就做）。
- ↑：到**整个会话的开头**——更早的历史还没加载的，连着往前加载到头再滚到顶（加载时按钮上转圈；会话很长时别一次把界面卡死，可以分批加载）。
- 秘书会话、任务整页、项目整页都有；三档缩放下都能用（缩小后输入框换成了图例，按钮跟着图例的上沿）。
- 不挡右侧的条外标注、不挡输入框、不挡 107 号票的"等你处理"栏（107 同时在做：会话和输入框之间会有一条栏，按钮要在栏的上面；合并时主会话处理冲突）。
- 窄屏按钮够大手指点得到（约 36–40px），宽屏可以小一点；11 套风格里跟着各自的颜色、边框（至少不突兀）。
