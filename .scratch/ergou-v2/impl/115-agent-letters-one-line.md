## What to build

### 1. 来信折成一行

用户 2026-10-13 原话："各个 agent 收到其他 agent 的来信，比如说二狗收到维护者的来信，你不要上来就把信全部展示出来吧，也是搞成一行，那一行上写一句总结，然后我可以点详情去查看嘛。"

现在：运行时交给 agent 的通知、别的 agent 的来信是会话里的系统消息，整段原文直接摊在会话里（比如秘书会话里"【任务做完】【跑完自动播报】后台有一件事做完了（运行时发来的，不是用户说的）：定时触发的普通任务……它最后说：……交付的文件……这件开了跑完自动播报……"一大段，后半段是写给秘书看的操作说明）。会话条目层（`state/chat-items.ts`）把系统消息当 `kind: "system"`，对话层画全文。

改成：

- **哪些算来信**：别的 agent 或运行时写给这个 agent 的消息——秘书会话里的【任务做完】（含【跑完自动播报】）、【维护者来信】；任务 / 项目维护者会话里的【秘书转达】；以及同类的、开头带【……】标记、写给 agent 看的运行时通知（实现方列一张表：哪些折、哪些照旧整段显示——比如"计划已确认，开始执行"这种给用户看的说明、工单分隔线、阶段框照旧）。
- **对话层一行**：图标 + 来信种类（"任务做完""维护者来信""秘书转达"……）+ **一句总结** + 时间，右边"详情 ›"。点"详情"打开全文（照"调用了 N 个工具 ›"那一行打开详情栏的做法：宽屏右边的详情栏、手机上的详情页；全文照 Markdown 渲染）。要点层 / 全局层照现有系统消息的画法（一行字的色块）。
- **一句总结从哪来**：
  - 运行时写的通知（任务做完）：运行时拼一句，比如"t-5「AI 日报」第 2 次运行做完了，交了 1 个文件"；
  - 维护者来信（`tell_secretary`）：工具加一个必填的一句话总结参数（30 字以内，工具说明里写清楚），信的正文照旧；
  - 秘书转达（`tell_task` / `tell_project`）：用转达的话本身的第一句（截到 30 字）；
  - 存成消息上的一个字段（协议里给消息加可选的 `summary`，或者照仓库惯例放在别处），旧消息没有就取正文去掉标记后的第一句截短。
- 模型那边看到的照旧是全文（这只改显示，不改交给 agent 的内容）。
- 11 套风格里这一行跟着各自工具调用那一行的样子（至少不突兀）。

### 2. 任务做完时，交付的 md 跟着变成附件卡片

用户 2026-10-13 想在聊天里点开日报看。今天 08:00 的 AI 日报，秘书只在文字里写了路径 `outputs/t-5/ai-news-2026-10-13.md`，没作为附件发，所以没有 113 号票的卡片、点不开。

- 任务做完告诉秘书时（99 号票的 `task-done.ts`），交付的文件里能预览的（113 的 `textPreviewOf`：md、纯文本），由运行时直接作为附件放进秘书会话（跟在秘书这一轮的回复后面，或者附在那条来信的那一行上——挑用户在秘书会话里一眼能看到、能点"预览"的地方，写在 Comments），不靠秘书记得调 `send_attachment`。不能预览的照旧只在来信全文里写路径。
- 文件太大（超过附件的上限）的照旧只写路径。
- 附件入库走现有的媒体存储（内容寻址），守护进程重启、重复通知不重复入库。
