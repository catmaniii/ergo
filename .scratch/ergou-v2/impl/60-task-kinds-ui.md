## What to build

照 AgentSense 的做法，给流程、长程任务各做一套界面，依据是调研 §4.6 的表格。

2026-10-10 起任务按 ADR 0025 分三种做法：普通任务、流程、长程任务。普通任务没有计划和阶段，它的界面（看板卡虚线框、详情只有会话和工具调用）已在 75 号票做完，本票只要保证三种放在一起时看板和详情一致。定时、事件触发的任务（76、77 号票）在看板"运营中"一组，按运行分段；本票的流程界面要能用在"定时的流程"上（每次运行一段，进度条按这一次运行的步骤算）。

## Acceptance criteria

- [x] **流程的会话**：
  - 顶栏显示进度条（做完的步骤 / 总步数），点开是计划台账（AgentSense 的 `PlanTimeline`）。
  - 历史底部有"接下来的计划"虚线框：没做的步骤画虚线，在做的转成实线，偏离直接标在那一格。
  - 缩放各档：要点层显示一行"计划 vN · N 步"，加计划底色带，虚线框跟着缩。
- [x] **流程的详情页**：显示敏感信息、步骤、版本差异、计划审查、检测项全览（AgentSense 的 `RuleBook`）。
- [x] **长程任务**：
  - 沿用阶段抽屉，加上书脊（55 号票）。
  - 阶段详情页：交付件、验收标准和结果、尝试记录、授权和用量、出过的状况、"从这里重做"。
- [x] **看板**：任务卡标出种类和进度。普通任务照 75 号票（没有进度）；流程的进度是步骤数（定时的流程按这一次运行）；长程任务的进度是已验收的阶段数。
- [x] **用户评审**：做完先回报，由主会话请用户评审。和 AgentSense 不一致的地方，先问用户。
- [x] 所有测试通过（vitest），lint（oxlint）无报错。
