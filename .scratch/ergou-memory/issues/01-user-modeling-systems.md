# 现成用户建模系统的细节

Type: research
Status: resolved

## Question

下面这三个系统具体是怎样建模用户的？逐个说明：
- **数据结构**：一条"关于用户的命题"包含哪些字段，比如置信度、证据、衰减、来源。
- **写入和修订流程**。
- **怎样提问或对话来求证**：Honcho 的 dialectic 方法是什么。
- **怎样在指令时使用**。
- **已知的失败案例**。

三个系统：
1. Honcho（Plastic Labs）：dialectic 用户建模，OpenClaw 和 Hermes 都把它当作插件使用。
2. GUM（General User Models）。
3. Behavior Latticing。

最后对照 intent-mining 的四层模型（L1–L4），说明哪些可以直接借鉴到二狗。

## Answer

详见 `docs/research/11-user-modeling-systems.md`。三个系统的源码都逐文件读过，论文读的是全文。

- **空白正是二狗的切入点**：三家都没有同时具备"命题状态 + 修订历史 + 用户裁决"。
  - Honcho 的 dialectic 是 agent 去问 Honcho，并不向用户求证。它常驻注入的用户卡已经禁止写人格特质和推断出来的偏好。
  - GUM 的代码和论文有三处对不上：隐私审计模块没有接上；修订是删掉旧命题、新建一条；decay 的方向和 prompt 相反。
  - Behavior Latticing 只能一次性生成，不能增量更新。
  - 用户主张的"判断可以低置信，但要配澄清问题"，正好落在这个空白上。
- **可以借鉴的部分**：
  - **素材存储（来自 Honcho）**：只有消息摄入能写 L1；证据之间用证据边相连，写入前剥离伪造的证据 ID；只从用户本人的消息里抽关于他的事实；删除素材时，沿证据边连带清理派生命题。
  - **命题记录**：一条记录包括层标签、推理过程、1–10 的保守置信度、适用情境、矛盾关系、强化计数。修订一律追加新版本，不删旧的。
  - **澄清问题有六个来源**：矛盾、低置信但高价值、张力、规范性判断（只能以问题形式出现）、预测落空、反常输入。
  - **夜间整合的调度（来自 Honcho）**：
    - 触发条件：新增 50 条 L1、冷却 8 小时、空闲 60 分钟，有新消息进来就取消。
    - 步骤顺序：更新与矛盾 → 带证据修订 → 按张力分组 → 预测记分 → 生成问题。
  - **注入**：每条指令只注入 2 条最相关的 insight。
- **不建议照搬**：Honcho 发现错误事实时只写更正、不删除；它的插件在群聊里给第三方建模。
- **待定**：Honcho 有官方的 pi 扩展 `pi-honcho`，要求 pi 1.0 以上。L1 层要不要直接交给它，留到「素材管理」票决定。
