# 素材管理

Type: grilling
Status: resolved
Phase: 1

## Question

动机挖掘用的素材怎么管理？用户明确说过要"好好讨论一下"。需要定下：

1. **采集粒度**：每类素材按什么粒度采集。
2. **存储分层**：原始素材是否作为不可变原文保存，派生内容怎样和原文分开。
3. **证据链接**：每条推断怎样指回它所依据的素材。
4. **保留期**：素材保存多久。
5. **查看与删除**：用户怎样查看和删除素材；删除时，依赖这条素材的推断怎样处理。
6. **区分说与做**："说的"和"做的"在素材层就分开记录，借鉴 intent-mining 里 GoT 的抽取规则。

## Context

- `docs/research/02-ref-intent-mining.md`：
  - 凭记忆写下的事实错误率约 15%，所以 LLM 生成的摘要不能当作事实层；
  - 推翻一个结论要保留记录。
- 主地图的「记忆边界」规定了素材的来源和交接格式。
- 「现成用户建模系统的细节」可借鉴的做法：
  - 只有消息摄入能写 L1；
  - 证据边，写入前剥离伪造的证据 ID；
  - 只从用户本人的消息里抽关于用户的事实；
  - 删除素材时，沿证据边连带清理派生命题。

  待定：L1 层要不要直接交给官方的 `pi-honcho` 扩展。详见 `docs/research/11-user-modeling-systems.md`。
- 「记忆边界」已定（`../../ergou-v2/issues/03-memory-boundary.md` 的 Answer §2、§4），本票在此基础上细化：
  - 七类素材事件和统一信封；只有来源等级为"本人"的素材能生成关于用户的判断；
  - 所有素材进入**短期记忆**，包括维护者会话里用户说的话；
  - 短期记忆**永不自动删除**，只有用户能删；被提炼进长期记忆后也保留作证据。所以第 4 问"保留期"已有答案，本票只需定删除和存储细节；
  - 检索按时效权重衰减：半衰期 1 个月，自动检索只看最近 3 个月，均可调；
  - 记忆 Web UI 里的纠正和删除按"显式记忆命令"处理，确定性地立即生效。
- 「项目生命周期、工作空间与维护者」已定（2026-10-07）：
  - 读记忆不经过记忆管理者，走运行时检索。素材入库时就要建好关键词索引和向量索引。

| Q6 向量怎么算 | 用 CPU 跑量化版的 bge-m3，不用显卡 | 同意 |

查到的事实：
- 本机的 LSM 里没有任何嵌入或向量服务，也没装 ollama。
- 显卡 RTX 4070 Ti 12 GB，和 audio.cpp 共用：audio.cpp 常驻时已用 7.2 GB（`nvidia-smi` 实测 7215 / 12282 MiB）。bge-m3 上显卡还要 1–1.5 GB，眼下放得下，但 audio.cpp 换更大模型或同时跑识别和合成时会抢；在 Node 里用显卡还要另装 CUDA 版运行库。
- CPU 是 i5-13600K（14 核 20 线程），内存 31.7 GB。量化版 bge-m3 占内存 1 GB 左右，一句话几十到一百多毫秒（估计）。
- 向量的用量不大：每条素材入库算一次（每天几百次），秘书查记忆时算一次查询向量，夜里做梦阶段批量用一些。显卡只在"换模型后整批重算"这种一次性大活上有优势。

## Answer

2026-10-07 定稿。

### 1. 原文存在哪里

- **"本人"来源的素材，素材库保存一份原文副本**：不可修改、只追加、只有用户能删。
- agent 的产出、附件和外部内容，只存引用加内容哈希。媒体本来就按内容哈希存。
- 原因：删除项目时维护者会话一起删、素材不删（「项目生命周期、工作空间与维护者」）。如果只存引用，项目一删，维护者会话里用户说过的话就断了引用。
- 已据此修订「记忆边界」Answer §4 的"只存引用，不复制原文"。
- 不接 Honcho。

### 2. 采集什么

- 「记忆边界」定的**七类素材事件从第一天起全部采集**，每条消息、每次反应各一条。
- **另加"回避"信号**：建议卡或提问长期没处理，或者被用户关掉。intent-mining 很看重"回避了什么"。
- **"说"和"做"按事件类型分开**：
  - 说：发言、回答、用户主动提供的材料；
  - 做：对产出的反应、审批决定、任务结局。
- **第一阶段只积累、建索引，不做抽取和推断**。抽取和动机推导是记忆管理者第二阶段的活。

### 3. 来源标记

入库时按确定的规则切段，不靠模型判断：

- 引用块、附件、抓取的网页：标"外部、不可信"；
- 用户自己打的字：标"本人"；
- 用户接受了 agent 的提议：算用户的选择，注明"agent 先提出"；
- 语音转写：标"本人"，注明"转写"；
- 判断不了的纯文本：默认"本人"。

"外部、不可信"这个标记以后的提示注入防护也会用。只有"本人"来源的素材能生成关于用户的判断（「记忆边界」已定）。

### 4. 证据链接与保留

- 每条推断都用证据边指回它依据的素材 id；写入前剥掉模型编造的证据 id（「现成用户建模系统的细节」的做法）。
- 素材永不自动删除，只有用户能删；被提炼进长期记忆后也保留作证据（「记忆边界」已定）。

### 5. 索引

- **关键词**：SQLite 全文检索，用 trigram 分词器（默认分词器切不了中文）。
- **向量**：守护进程里用 CPU 跑量化版的 **bge-m3**，不用显卡，不新增服务，数据不出本机。
  - 素材入库后在后台异步补算向量，不卡写入和对话；
  - 每条向量旁边记下模型名，以后换模型时可以整批重算。

### 6. 删除

三种删除：

- **忘掉**（默认）：从素材库删除，顺着证据边删掉由它推出的判断，并重建用户卡。聊天记录里用户仍然看得到这句话。
- **彻底删除**：连会话原文一起删。
- **别推断**：素材保留，但不参与推断。

第一阶段的删除入口：对话里的显式记忆命令，以及按会话或按时间段删除。精细管理留给「记忆 Web UI」。

### 留给规格

- 素材表的字段（在「记忆边界」统一信封的基础上加原文副本、切段、说/做类型）。
- "回避"信号的超时天数。
- 切段规则的细节。
- 嵌入模型的具体文件和运行库（transformers.js 或 onnxruntime-node）；向量检索用暴力扫描还是 sqlite-vec。
- 删除时沿证据边级联的实现；什么时候触发用户卡重建。
